1) Passo a passo (fechamento técnico)

Passo 1 — Garantir a fonte única de dados (MySQL) no Dashboard

Confirme que o Dashboard injeta IProdutoRepository e usa ProdutoRepositoryMySql. Isso evita divergência de dados entre abas. 

// FrmDashboard.cs
private readonly IProdutoRepository _repo = new ProdutoRepositoryMySql();

private void FrmDashboard_Load(object sender, EventArgs e)
{
    AbrirFormNaAba(new FrmProdutos(_repo), tabProdutos);
    AbrirFormNaAba(new FrmVendaSimples(_repo), tabVenda);
    AbrirFormNaAba(new FrmRelatorios(_repo), tabRelatorios);
}

Passo 2 — Conferir CRUD completo na UI (Produtos)

  • Cadastrar Lanche/Bebida (INSERT)
  • Alterar preço/estoque (UPDATE)
  • Excluir (DELETE) com confirmação
  • Reabrir o app e verificar persistência
Critério de pronto
Se fechar o app e os itens ainda estiverem no grid ao reabrir, sua persistência está OK.

Passo 3 — Conferir SQL seguro (Cap. 15 aplicado)

  • Busca por nome: LIKE com CONCAT('%', @texto, '%')
  • Comandos sempre parametrizados
  • ORDER BY com whitelist (nunca coluna livre do usuário)
// Exemplo (DAO): LIKE seguro
string sql = "SELECT * FROM produto WHERE nome LIKE CONCAT('%', @texto, '%')";
cmd.Parameters.AddWithValue("@texto", texto);

Passo 6 — Scripts do banco: create e seed

Gere dois arquivos para facilitar a instalação: create.sql (database + table) e seed.sql (dados iniciais).

create.sql (exemplo mínimo)
CREATE DATABASE IF NOT EXISTS lanchonete_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE lanchonete_db;

CREATE TABLE IF NOT EXISTS produto (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(120) NOT NULL,
  preco DECIMAL(10,2) NOT NULL,
  estoque INT NOT NULL DEFAULT 0,
  tipo ENUM('Lanche','Bebida') NOT NULL,
  tamanho VARCHAR(20) NULL,
  volume_ml INT NULL,
  alcoolica TINYINT(1) NULL,
  criado_em TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

2) Entrega 4 (Bimestre 4) — Integração com MySQL

Avaliação

A Entrega 4 avalia persistência real e segurança: conexão, DAO/CRUD, SQL seguro, integração na UI e documentação.

Requisitos mínimos (rubrica sugerida)

  • MySQL funcionando com tabela(s) e dados persistentes.
  • ConnectionFactory + connection string no App.config.
  • DAO + CRUD completo para produtos (Create/Read/Update/Delete).
  • SQL seguro: parâmetros em comandos e LIKE seguro; sem concatenação com input do usuário.
  • Whitelist para ORDER BY (se houver ordenação dinâmica).
  • Dashboard com abas e navegação (menu/toolbar/status) usando repositório MySQL.
  • Relatórios consumindo dados do banco + exportação CSV.
  • Scripts create.sql e seed.sql + README explicando execução.

Bônus (vale pontos extras)

  • Transação para venda (atualiza estoque + registra venda em tabela).
  • Paginação no grid (LIMIT/OFFSET).
  • Logs de erro (logs.txt) + mensagens amigáveis.
  • PrintPreview do cupom (Cap. 12).

O que entregar

  1. .zip do projeto (solution).
  2. create.sql e seed.sql.
  3. README.txt (como instalar/rodar).
  4. Evidências (prints ou vídeo curto) mostrando:
    • Teste de conexão OK
    • CRUD (inserir/editar/excluir)
    • Persistência (reabrir e manter dados)
    • Relatório + exportação CSV
    • Uma validação/erro tratado com mensagem amigável
Erros comuns
  • SQL com concatenação de texto (injection).
  • Dashboard criando repositórios diferentes por aba.
  • Connection string hardcoded no código.
  • Relatório lendo de lista antiga (não do banco).
  • Sem scripts do banco (avaliador não consegue reproduzir).
