4º Bimestre • Capítulo 13 (100 min/semana)

Conexão MySQL (WinForms + C#)

Chegou a hora de sair do “repositório em memória” e entrar em persistência real. Neste capítulo você vai instalar o conector, criar o banco, configurar connection string no app.config e criar uma camada simples de acesso para abrir conexões com segurança. O Capítulo 14 vai usar isso para implementar o DAO e o CRUD completo.

Roteiro Passo a passo Atividades

Objetivos de aprendizagem

  • Instalar o MySQL Server e um cliente (Workbench ou equivalente) e criar um banco.
  • Adicionar o pacote do driver MySQL ao projeto (.NET): MySql.Data ou MySqlConnector.
  • Configurar connection string via app.config (sem hardcode no código).
  • Criar uma ConnectionFactory para abrir conexões com using.
  • Criar uma tela “Testar conexão” e tratar erros comuns (host, porta, usuário, senha, firewall).
  • Preparar o terreno para o DAO/CRUD do Cap. 14.

Pré-requisitos

  • Projeto LanchoneteApp funcionando com Dashboard (Cap. 11/12)
  • Conhecer o conceito de Repository/DAO (sem implementar ainda)
Nota
No 4º bimestre, o foco é persistência: banco, DAO, SQL seguro e integração final.

1) Parte teórica (fundamentos de conexão)

1.1 O que é uma conexão?

Uma conexão é um “canal” entre sua aplicação e o servidor de banco. Em C#, ela é representada por um objeto (ex.: MySqlConnection). Você abre, executa comandos e fecha. Boas práticas: abra só quando precisar e feche sempre (use using).

1.2 Connection String

A connection string é um texto com parâmetros do acesso: servidor, porta, database, usuário, senha e opções. Ela deve ficar em arquivo de configuração (app.config) e não “hardcoded” no código.

1.3 Driver/Connector

Para C# falar com MySQL, você precisa de um driver. Duas opções comuns: MySql.Data (Oracle) e MySqlConnector (community). Neste material vamos exemplificar com MySql.Data (mais conhecido em cursos), mas a ideia é igual.

1.4 Erros comuns (e como pensar)

  • Access denied: usuário/senha ou permissões.
  • Unable to connect: host/porta/firewall/serviço parado.
  • Unknown database: banco não existe ou nome errado.
  • SSL: alguns ambientes exigem configurar SslMode.
Dica prática
Primeiro teste no Workbench. Depois use a mesma host/porta/usuário/database no app.config.

2) Passo a passo (MySQL + WinForms)

Vamos configurar o ambiente e criar uma camada de conexão reutilizável.

Passo 0 — Preparar o MySQL

  1. Instale o MySQL Server 8.x e o MySQL Workbench (ou outro cliente).
  2. Confirme que o serviço do MySQL está rodando.
  3. No Workbench, conecte como root (ou admin) e crie o banco e um usuário do sistema.
Script SQL (execute no Workbench)
CREATE DATABASE IF NOT EXISTS lanchonete_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'lanchonete'@'localhost' IDENTIFIED BY 'L@123456';
GRANT ALL PRIVILEGES ON lanchonete_db.* TO 'lanchonete'@'localhost';
FLUSH PRIVILEGES;
Segurança
Em projetos reais, não use senha fraca nem deixe usuário com ALL PRIVILEGES. Aqui é didático.

Passo 1 — Criar tabelas (modelo inicial)

Vamos usar uma tabela produto com um campo tipo (lanche/bebida) e campos específicos. Isso é suficiente para o curso e facilita o CRUD.

Script SQL (tabela produto)
USE lanchonete_db;

CREATE TABLE IF NOT EXISTS produto (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(120) NOT NULL,
  preco DECIMAL(10,2) NOT NULL,
  estoque INT NOT NULL DEFAULT 0,
  tipo ENUM('Lanche','Bebida') NOT NULL,

  -- específicos
  tamanho VARCHAR(20) NULL,
  volume_ml INT NULL,
  alcoolica TINYINT(1) NULL,

  criado_em TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_produto_nome ON produto(nome);
CREATE INDEX idx_produto_tipo ON produto(tipo);
Observação
No Cap. 14 você vai mapear essa tabela para classes (Lanche/Bebida) usando DAO.

Passo 2 — Adicionar o driver MySQL via NuGet

  1. No Visual Studio: clique com botão direito no projeto → Manage NuGet Packages.
  2. Pesquise e instale: MySql.Data.
  3. Se estiver em .NET 6/7/8, pode ser necessário instalar também: System.Configuration.ConfigurationManager.
Se preferir MySqlConnector, a API é muito parecida (MySqlConnection/MySqlCommand).

Passo 3 — Configurar connection string no app.config

Em projetos WinForms, use o arquivo App.config. Se não existir, adicione: Add → New Item → Application Configuration File.

Arquivo: App.config (connectionStrings)
<?xml version="1.0" encoding="utf-8" ?>
<configuration>
  <connectionStrings>
    <add name="LanchoneteDb"
         connectionString="Server=localhost;Port=3306;Database=lanchonete_db;Uid=lanchonete;Pwd=L@123456;SslMode=Preferred;" />
  </connectionStrings>
</configuration>
Dica
Se der erro de SSL, teste SslMode=None no laboratório (somente para aula).

Passo 4 — Criar uma ConnectionFactory

O objetivo é ter um único lugar para abrir conexão. Isso facilita manutenção e testes. Crie a pasta Data (ou Infra) e adicione MySqlConnectionFactory.

Arquivo: Data/MySqlConnectionFactory.cs
using System.Configuration;
using MySql.Data.MySqlClient;

namespace LanchoneteApp.Data
{
    public static class MySqlConnectionFactory
    {
        public static MySqlConnection Create()
        {
            string cs = ConfigurationManager.ConnectionStrings["LanchoneteDb"].ConnectionString;
            return new MySqlConnection(cs);
        }
    }
}
Se aparecer erro no ConfigurationManager, instale o pacote System.Configuration.ConfigurationManager.

Passo 5 — Criar um "teste de conexão" (Service/Controller simples)

Antes de CRUD, confirme que consegue abrir conexão. Vamos criar um método que abre e fecha com segurança.

Arquivo: Services/ConexaoService.cs
using System;
using MySql.Data.MySqlClient;
using LanchoneteApp.Data;

namespace LanchoneteApp.Services
{
    public class ConexaoService
    {
        public (bool ok, string mensagem) Testar()
        {
            try
            {
                using MySqlConnection conn = MySqlConnectionFactory.Create();
                conn.Open();

                using var cmd = new MySqlCommand("SELECT 1", conn);
                var r = cmd.ExecuteScalar();

                return (true, "Conexão OK! Resposta: " + r);
            }
            catch (Exception ex)
            {
                return (false, "Falha na conexão: " + ex.Message);
            }
        }
    }
}

Passo 6 — Criar a View FrmTestarConexao

Crie um Form simples com: Botão “Testar”, TextBox multiline para log, e um Label para status.

Arquivo: Views/FrmTestarConexao.cs (exemplo)
using System;
using System.Windows.Forms;
using LanchoneteApp.Services;

namespace LanchoneteApp.Views
{
    public partial class FrmTestarConexao : Form
    {
        private readonly ConexaoService _svc = new();

        public FrmTestarConexao()
        {
            InitializeComponent();
            this.Text = "LanchoneteApp • Teste de Conexão";
        }

        private void btnTestar_Click(object sender, EventArgs e)
        {
            var (ok, msg) = _svc.Testar();
            lblStatus.Text = ok ? "OK" : "ERRO";
            txtLog.AppendText(DateTime.Now + " - " + msg + Environment.NewLine);
        }
    }
}

Passo 7 — Integrar no Dashboard (menu Ajuda → Testar conexão)

Arquivo: Views/FrmDashboard.cs (menu)
private void menuTestarConexao_Click(object sender, EventArgs e)
{
    new FrmTestarConexao().ShowDialog();
}

Passo 8 — Checklist de diagnóstico (se der erro)

  • Servidor MySQL está rodando?
  • Host/porta corretos? (geralmente localhost:3306)
  • Usuário e senha corretos? (teste no Workbench com o mesmo usuário)
  • Database existe? (lanchonete_db)
  • Se for remoto: firewall liberando porta 3306?
Resultado esperado
Você consegue abrir conexão e executar SELECT 1. Pronto para DAO/CRUD no Cap. 14.

3) Atividades práticas

Faça 2 atividades (ou todas). O foco é conexão e preparação para o DAO.

Atividade A — Tela de Configuração
  • Crie um form FrmConfigDb com campos: host, porta, database, usuário, senha.
  • Monte a connection string e teste conexão.
  • Bônus: salvar em app.config (ou arquivo local) e recarregar ao abrir.
Atividade B — Inserção de teste (sem DAO)
  • Crie um método que execute um INSERT fixo em produto.
  • Use MySqlCommand com parâmetros (sem concatenar string!).
  • Mostre quantas linhas foram afetadas.
Atividade C — Script de Seed no banco
  • Crie um arquivo seed.sql para inserir 6 produtos (3 lanches, 3 bebidas).
  • Execute no Workbench e confirme que aparecem no SELECT.
  • Prepare para o CRUD do Cap. 14.

Critérios rápidos

  • Connection string no app.config (não hardcoded).
  • Conexão aberta/fechada com using.
  • Teste de conexão (SELECT 1) funcionando.
  • Boas práticas: parâmetros (se fizer INSERT/SELECT).

4) Pesquisas complementares

  • Qual a diferença entre conexão e transação?
  • Por que “abrir conexão cedo e deixar aberta” é ruim?
  • O que é pool de conexões (connection pooling)?
  • O que muda ao usar MySQL remoto (host, firewall, permissões)?
