1) Parte teórica (SQL Injection e defesa)

1.1 O que é SQL Injection?

SQL Injection é uma falha onde dados fornecidos pelo usuário são interpretados como parte do SQL. Ela acontece quase sempre quando alguém faz concatenação para montar comandos. Exemplo perigoso (NÃO faça):

Exemplo inseguro (didático): concatenação de texto no WHERE
// NÃO FAÇA ISSO
string sql = "SELECT * FROM produto WHERE nome LIKE '%" + txtFiltro.Text + "%'";
using var cmd = new MySqlCommand(sql, conn);
Se alguém digitar algo malicioso, o SQL pode mudar de significado.

1.2 Defesa principal: parâmetros

Com parâmetros, o MySQL recebe o valor separadamente do SQL. O valor não vira parte da “gramática” do comando. É a defesa mais importante na maioria dos casos.

Exemplo seguro: LIKE com parâmetro
string sql = "SELECT * FROM produto WHERE nome LIKE CONCAT('%', @texto, '%')";
using var cmd = new MySqlCommand(sql, conn);
cmd.Parameters.AddWithValue("@texto", texto);

1.3 Parâmetro não resolve tudo: ORDER BY e nomes de coluna

Parâmetros funcionam para valores (WHERE, VALUES, LIMIT/OFFSET). Mas você não pode parametrizar nome de coluna ou direção no ORDER BY. Para isso, use whitelist (lista de opções permitidas).

1.4 AddWithValue: o “atalho” que dá dor de cabeça

AddWithValue é prático, mas pode inferir tipos errados (por exemplo, tratar decimal como string). Em consultas grandes, isso prejudica performance e pode gerar bugs. Boas práticas: use MySqlDbType quando possível.

Resumo da defesa
  • 1) Parâmetros para valores
  • 2) Whitelist para ORDER BY/colunas
  • 3) Validação/normalização antes do banco
  • 4) Menos privilégios no usuário do banco

2) Passo a passo (deixando o DAO seguro)

Vamos melhorar o DAO do Cap. 14 com parâmetros corretos, LIKE seguro e ordenação/paginação seguras.

Passo 1 — Implementar busca por nome com LIKE seguro

Crie no ProdutoDaoMySql um método BuscarPorNome usando parâmetros.

Arquivo: Data/ProdutoDaoMySql.cs (BuscarPorNome seguro)
public List<Produto> BuscarPorNome(string texto)
{
    var lista = new List<Produto>();
    using var conn = MySqlConnectionFactory.Create();
    conn.Open();

    string sql = "SELECT id,nome,preco,estoque,tipo,tamanho,volume_ml,alcoolica " +
                 "FROM produto WHERE nome LIKE CONCAT('%', @texto, '%') ORDER BY id DESC";

    using var cmd = new MySqlCommand(sql, conn);
    cmd.Parameters.AddWithValue("@texto", texto ?? "");

    using var r = cmd.ExecuteReader();
    while (r.Read())
        lista.Add(Map(r));

    return lista;
}
Não use "%" + texto + "%" no SQL. Faça o “%” no banco com CONCAT.

Passo 2 — Trocar AddWithValue por parâmetros tipados (quando fizer sentido)

Em INSERT/UPDATE, prefira MySqlParameter com MySqlDbType. Isso evita inferência errada e deixa o código mais robusto.

Exemplo: parâmetros tipados em INSERT
cmd.Parameters.Add("@nome", MySqlDbType.VarChar, 120).Value = p.Nome;
cmd.Parameters.Add("@preco", MySqlDbType.Decimal).Value = p.Preco;
cmd.Parameters.Add("@estoque", MySqlDbType.Int32).Value = p.Estoque;
cmd.Parameters.Add("@tipo", MySqlDbType.Enum).Value = p.Tipo; // ou VarChar
Dica
Você pode manter AddWithValue em projetos pequenos, mas aprenda o padrão tipado para o mundo real.

Passo 3 — Ordenação segura com whitelist (ORDER BY)

Você não consegue usar parâmetro para nome de coluna no ORDER BY. A forma correta é criar uma whitelist de colunas permitidas.

Exemplo: ordenar por coluna e direção com whitelist
public List<Produto> ListarOrdenado(string coluna, string direcao)
{
    // whitelist de colunas permitidas
    var colunas = new Dictionary<string, string>
    {
        ["id"] = "id",
        ["nome"] = "nome",
        ["preco"] = "preco",
        ["estoque"] = "estoque",
        ["tipo"] = "tipo"
    };

    string col = colunas.ContainsKey(coluna?.ToLower() ?? "") ? colunas[coluna!.ToLower()] : "id";
    string dir = (direcao?.ToUpper() == "ASC") ? "ASC" : "DESC";

    string sql = $"SELECT id,nome,preco,estoque,tipo,tamanho,volume_ml,alcoolica FROM produto ORDER BY {col} {dir}";

    var lista = new List<Produto>();
    using var conn = MySqlConnectionFactory.Create();
    conn.Open();
    using var cmd = new MySqlCommand(sql, conn);
    using var r = cmd.ExecuteReader();
    while (r.Read()) lista.Add(Map(r));
    return lista;
}
Atenção
Aqui usamos interpolação no SQL, mas apenas com valores vindos da whitelist (não do usuário direto). Isso é o que torna seguro.

Passo 4 — Paginação segura (LIMIT/OFFSET com parâmetros)

Em grids grandes, paginar melhora performance. LIMIT/OFFSET aceitam parâmetros.

Exemplo: listar por página
public List<Produto> ListarPaginado(int page, int pageSize)
{
    page = Math.Max(1, page);
    pageSize = Math.Clamp(pageSize, 5, 100);
    int offset = (page - 1) * pageSize;

    string sql = "SELECT id,nome,preco,estoque,tipo,tamanho,volume_ml,alcoolica " +
                 "FROM produto ORDER BY id DESC LIMIT @limit OFFSET @offset";

    var lista = new List<Produto>();
    using var conn = MySqlConnectionFactory.Create();
    conn.Open();
    using var cmd = new MySqlCommand(sql, conn);
    cmd.Parameters.AddWithValue("@limit", pageSize);
    cmd.Parameters.AddWithValue("@offset", offset);

    using var r = cmd.ExecuteReader();
    while (r.Read()) lista.Add(Map(r));
    return lista;
}

Passo 5 — Validação/normalização antes de mandar para o banco

Parâmetros evitam injection, mas você ainda precisa validar regra de negócio. Ex.: preço > 0, nome obrigatório, estoque não negativo. Mantenha validações no Service (não no DAO).

Exemplo: normalizar texto no Service
string nome = (nomeInput ?? "").Trim();
if (nome.Length < 2) throw new Exception("Nome muito curto.");

Passo 6 — Integração no Controller e UI (sem quebrar MVC)

Se você implementou BuscarPorNome no DAO e expôs no repositório, o Controller pode chamar esse método e devolver ViewModels. A View apenas exibe.

Exemplo: no repositório e controller
// IProdutoRepository (opcional)
List<Produto> SearchByName(string texto);

// ProdutoRepositoryMySql
public List<Produto> SearchByName(string texto) => _dao.BuscarPorNome(texto);

// ProdutoController
public List<ProdutoListItemVM> FiltrarPorNomeDb(string texto)
{
    return _repo.SearchByName(texto)
                .Select(p => new ProdutoListItemVM { Id=p.Id, Nome=p.Nome, Preco=p.Preco, Estoque=p.Estoque, Tipo=p.Tipo, Detalhes=p.Detalhes })
                .ToList();
}
Resultado esperado
Seu sistema fica mais seguro: sem SQL montado com strings do usuário, com ordenação/paginação controladas e validação correta.

3) Atividades práticas

Faça 2 atividades (ou todas). O foco é fortalecer SQL seguro.

Atividade A — Filtro por tipo + nome (seguro)
  • Crie método Buscar(string? nome, string? tipo) no DAO.
  • Use parâmetros para nome e tipo.
  • Se tipo vier vazio, ignore filtro por tipo.
Atividade B — Ordenação segura na UI
  • Crie no UI um ComboBox com colunas permitidas (Nome/Preço/Estoque/Tipo).
  • Ao escolher, chame ListarOrdenado (whitelist) no DAO.
  • Nunca use texto livre do usuário como coluna no ORDER BY.
Atividade C — Paginação no DataGridView
  • Crie botões “Anterior/Próxima” e um Label “Página X”.
  • Use ListarPaginado (LIMIT/OFFSET com parâmetros).
  • Garanta que page e pageSize sejam validados.

Critérios rápidos

  • Nenhum SQL com concatenação de input do usuário.
  • LIKE sempre com parâmetro + CONCAT.
  • ORDER BY sempre com whitelist.
  • Validações no Service, SQL no DAO.
