Construtores e Sobrecarga (métodos e construtores)

Neste capítulo você vai aprender a criar construtores para garantir que um objeto já nasce válido, e vai usar sobrecarga para permitir diferentes formas de criar e usar um Produto. Na prática, você vai implementar um cadastro rápido (com ID automático) e criar métodos sobrecarregados.

Roteiro Passo a passo Atividades

Objetivos de aprendizagem

  • Explicar o que é um construtor e por que ele existe.
  • Aplicar sobrecarga de construtores para criar objetos de formas diferentes.
  • Aplicar sobrecarga de métodos para oferecer formas diferentes de executar uma ação.
  • Usar this(...) para reaproveitar lógica entre construtores.
  • Evoluir o sistema da lanchonete com ID automático (cadastro rápido) e métodos de cálculo.

Pré-requisitos

  • Capítulos 01 e 02 concluídos
  • Projeto LanchoneteApp funcionando com a classe Produto encapsulada
Você vai praticar
Criar objetos com diferentes “jeitos” (com ID manual ou automático) e calcular valores como subtotal.

1) Parte teórica (conceitos essenciais)

1.1 Construtor

Um construtor é um “método especial” da classe que é executado automaticamente quando você cria um objeto com new. Ele tem o mesmo nome da classe e não tem tipo de retorno. A principal função do construtor é garantir que o objeto já nasça em um estado válido, inicializando dados e aplicando regras desde o início.

No nosso Produto, o construtor impede, por exemplo, que o ID seja menor que 1, que o nome seja vazio ou que o preço seja negativo. Isso é muito importante porque evita que o sistema carregue objetos “quebrados”.

1.2 Sobrecarga (Overload) — métodos

Sobrecarga significa ter o mesmo nome para um método, mas com assinaturas diferentes. A assinatura é definida pelo conjunto de parâmetros (quantidade, tipos e ordem). Assim, você oferece diferentes formas de usar a mesma ideia de ação.

Exemplo: podemos ter um método CalcularSubtotal(int qtd) e outro CalcularSubtotal(int qtd, decimal desconto). Ambos calculam um subtotal, mas o segundo considera um desconto.

1.3 Sobrecarga de construtores

A mesma ideia de sobrecarga vale para construtores: você pode ter vários construtores com diferentes parâmetros. Isso permite criar um objeto de formas diferentes. Por exemplo: criar um produto com ID manual (para testes) ou com ID automático (para cadastro rápido).

Um cuidado importante: evite repetir a mesma lógica de validação em todos os construtores. Para isso, usamos o this(...), que chama outro construtor da mesma classe e reaproveita o código.

1.4 this em construtores

A palavra this representa o objeto atual. Em construtores, existe um uso especial: this(...) pode chamar outro construtor da mesma classe. Assim você centraliza validações em um único lugar.

No passo a passo, o construtor Produto(string nome, decimal preco) vai chamar o construtor principal Produto(int id, string nome, decimal preco, int estoque), reaproveitando as regras.

Overload x Override (não confundir)
Overload (sobrecarga) = mesmo nome, parâmetros diferentes (vamos usar aqui). Override (sobrescrita) = trocar o comportamento de um método herdado (veremos em herança mais à frente).

2) Passo a passo (construtores + sobrecargas no projeto)

Vamos evoluir o Produto com 3 melhorias: (1) construtores sobrecarregados, (2) ID automático para cadastro rápido, e (3) métodos sobrecarregados para calcular subtotal com e sem desconto. Depois vamos ajustar o formulário para aceitar ID opcional.

Antes de começar

  1. Abra a solução LanchoneteApp.
  2. Execute (F5) e confirme que o Capítulo 02 está funcionando.

Passo 1 — Adicionar sobrecarga de construtores + ID automático

  1. Abra Models/Produto.cs.
  2. Substitua pelo código abaixo (observe os construtores e o uso de this(...)).
Arquivo: Models/Produto.cs (construtores sobrecarregados + métodos sobrecarregados)
using System;

namespace LanchoneteApp.Models
{
    public class Produto
    {
        // Sequência interna para gerar IDs automaticamente (cadastro rápido)
        private static int _nextId = 1;

        // Campos privados
        private string _nome;
        private decimal _preco;
        private int _estoque;

        public int Id { get; }

        public string Nome
        {
            get => _nome;
            private set
            {
                if (string.IsNullOrWhiteSpace(value))
                    throw new ArgumentException("Nome não pode ser vazio.");

                _nome = value.Trim();
            }
        }

        public decimal Preco
        {
            get => _preco;
            private set
            {
                if (value < 0)
                    throw new ArgumentException("Preço não pode ser negativo.");

                _preco = value;
            }
        }

        public int Estoque
        {
            get => _estoque;
            private set
            {
                if (value < 0)
                    throw new ArgumentException("Estoque não pode ser negativo.");

                _estoque = value;
            }
        }

        // 1) Construtor principal (mais completo): valida e define tudo
        public Produto(int id, string nome, decimal preco, int estoque)
        {
            if (id <= 0)
                throw new ArgumentException("Id deve ser maior que zero.");

            Id = id;
            Nome = nome;
            Preco = preco;
            Estoque = estoque;
        }

        // 2) Sobrecarga: sem estoque (assume estoque = 0)
        public Produto(int id, string nome, decimal preco)
            : this(id, nome, preco, 0)
        {
        }

        // 3) Sobrecarga: sem ID (gera automaticamente) + estoque opcional
        public Produto(string nome, decimal preco, int estoque = 0)
            : this(_nextId++, nome, preco, estoque)
        {
        }

        // Métodos (ações) já existentes
        public void AlterarPreco(decimal novoPreco)
        {
            if (novoPreco < 0)
                throw new ArgumentException("Preço não pode ser negativo.");

            Preco = novoPreco;
        }

        public void Renomear(string novoNome) => Nome = novoNome;

        public void ReporEstoque(int quantidade)
        {
            if (quantidade <= 0)
                throw new ArgumentException("Quantidade para repor deve ser maior que zero.");

            Estoque = Estoque + quantidade;
        }

        public void BaixarEstoque(int quantidade)
        {
            if (quantidade <= 0)
                throw new ArgumentException("Quantidade para baixar deve ser maior que zero.");

            if (quantidade > Estoque)
                throw new InvalidOperationException("Não há estoque suficiente para baixar essa quantidade.");

            Estoque = Estoque - quantidade;
        }

        // -----------------------------
        // Sobrecarga de MÉTODOS: calcular subtotal
        // -----------------------------

        // A) Subtotal simples (sem desconto)
        public decimal CalcularSubtotal(int quantidade)
        {
            if (quantidade <= 0)
                throw new ArgumentException("Quantidade deve ser maior que zero.");

            return Preco * quantidade;
        }

        // B) Subtotal com desconto (desconto em %: 0 a 100)
        public decimal CalcularSubtotal(int quantidade, decimal descontoPercentual)
        {
            if (descontoPercentual < 0 || descontoPercentual > 100)
                throw new ArgumentException("Desconto deve estar entre 0 e 100.");

            decimal subtotal = CalcularSubtotal(quantidade);
            decimal desconto = subtotal * (descontoPercentual / 100m);
            return subtotal - desconto;
        }
    }
}
Onde está o conteúdo do capítulo?
  • Construtor principal: Produto(int id, string nome, decimal preco, int estoque)
  • Sobrecarga de construtor: construtores com menos parâmetros chamando o principal com this(...)
  • ID automático: private static int _nextId + construtor sem ID
  • Sobrecarga de métodos: CalcularSubtotal com e sem desconto

Passo 2 — Ajustar o formulário para aceitar ID opcional (cadastro rápido)

Agora o usuário poderá cadastrar produtos com ID manual ou deixar o campo de ID vazio para o sistema gerar automaticamente. Assim, você vai praticar o uso de construtores diferentes.

  1. No designer do FrmProdutos, altere o label do ID para: ID (opcional).
  2. No arquivo FrmProdutos.cs, atualize o método btnAdicionar_Click conforme abaixo.
Arquivo: FrmProdutos.cs (trecho do botão Adicionar com construtores diferentes)
private void btnAdicionar_Click(object sender, EventArgs e)
{
    try
    {
        string nome = txtNome.Text.Trim();
        if (string.IsNullOrWhiteSpace(nome))
            throw new ArgumentException("Informe o nome do produto.");

        var cultura = new CultureInfo("pt-BR");
        if (!decimal.TryParse(txtPreco.Text, NumberStyles.Any, cultura, out decimal preco))
            throw new ArgumentException("Preço inválido. Ex.: 9,50");

        if (!int.TryParse(txtEstoque.Text, out int estoque))
            throw new ArgumentException("Estoque inválido.");

        Produto novo;

        // Se o ID estiver vazio, usa construtor com ID automático
        if (string.IsNullOrWhiteSpace(txtId.Text))
        {
            novo = new Produto(nome, preco, estoque);
        }
        else
        {
            if (!int.TryParse(txtId.Text, out int id))
                throw new ArgumentException("ID inválido.");

            // Regra: não permitir ID repetido
            if (_produtos.Any(p => p.Id == id))
                throw new InvalidOperationException("Já existe um produto com esse ID.");

            // Construtor com ID manual
            novo = new Produto(id, nome, preco, estoque);
        }

        _produtos.Add(novo);
        AtualizarGrid();

        txtId.Clear(); txtNome.Clear(); txtPreco.Clear(); txtEstoque.Clear();
        txtNome.Focus();
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
    }
}
O que você praticou aqui?
A mesma ideia de criar Produto agora tem duas formas: com ID manual (construtor completo) ou ID automático (construtor sobrecarregado).

Passo 3 — Usar a sobrecarga de métodos (subtotal) em um teste rápido

Ainda não temos a tela de Vendas, mas podemos testar a sobrecarga de métodos com um botão simples. Você vai criar um botão “Testar Subtotal” que calcula o subtotal do produto selecionado.

  1. No designer do FrmProdutos, adicione um botão: btnTestarSubtotal (Text: Testar Subtotal).
  2. Adicione também 2 campos (TextBox) para entrada:
  • txtQtdTeste (Label: Qtd.)
  • txtDescontoTeste (Label: Desconto (%) (opcional))
  1. Dê duplo clique no botão para criar o evento e use o código abaixo.
Arquivo: FrmProdutos.cs (evento para testar métodos sobrecarregados)
private void btnTestarSubtotal_Click(object sender, EventArgs e)
{
    try
    {
        Produto p = ProdutoSelecionado();

        if (!int.TryParse(txtQtdTeste.Text, out int qtd))
            throw new ArgumentException("Quantidade inválida.");

        decimal total;

        // Se desconto vazio, usa o método sem desconto
        if (string.IsNullOrWhiteSpace(txtDescontoTeste.Text))
        {
            total = p.CalcularSubtotal(qtd);
        }
        else
        {
            var cultura = new CultureInfo("pt-BR");
            if (!decimal.TryParse(txtDescontoTeste.Text, NumberStyles.Any, cultura, out decimal desconto))
                throw new ArgumentException("Desconto inválido.");

            total = p.CalcularSubtotal(qtd, desconto);
        }

        MessageBox.Show($"Subtotal: {total:C}", "Subtotal", MessageBoxButtons.OK, MessageBoxIcon.Information);
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
    }
}
Esse botão é apenas para treino. Na unidade de Vendas, esse cálculo será usado de verdade.

3) Atividades práticas (para concluir na semana seguinte)

Escolha 2 atividades (ou faça todas para bônus). O foco é praticar sobrecarga e construtores.

Atividade A — Construtor “Cadastro rápido” sem estoque
  • Crie uma nova sobrecarga: Produto(string nome, decimal preco) (sem estoque).
  • Ela deve chamar this(nome, preco, 0).
  • No form, permita cadastrar deixando o estoque vazio (assuma 0).
Atividade B — Sobrecarga de método para baixar com “motivo”
  • Crie uma sobrecarga: BaixarEstoque(int qtd, string motivo).
  • Ela deve chamar o método original e depois mostrar o motivo no MessageBox ou registrar em uma lista em memória.
  • Ex.: motivo = “Venda”, “Perda”, “Teste”.
Atividade C — Subtotal com desconto fixo por item
  • Crie outra sobrecarga: CalcularSubtotal(int qtd, decimal descontoReaisPorItem, bool descontoEmReais).
  • Ex.: desconto de R$ 1,00 por item (qtd 3 → desconto R$ 3,00).
  • Atualize o botão de teste para permitir esse modo (opcional).

Critérios de avaliação (simples)

  • Correto uso de sobrecarga: assinaturas diferentes, mesmo nome.
  • Reaproveitamento com this(...): evita duplicação.
  • Regras funcionando: validações continuam funcionando.
  • Demonstração: prints/vídeo com pelo menos 1 teste por atividade escolhida.
