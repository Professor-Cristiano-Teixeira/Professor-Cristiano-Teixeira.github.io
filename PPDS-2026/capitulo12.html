1) Parte teórica (fechando a arquitetura)

1.1 Integração: quando “arquitetura” vira produto

Até aqui você aprendeu conceitos e implementou partes. Nesta etapa, o foco é produto pronto: telas consistentes, navegação clara, regras centralizadas e relatórios úteis. A arquitetura (MVC) serve para diminuir o acoplamento: a View não faz regra de negócio e não sabe detalhes do repositório.

1.2 Relatórios e ViewModels

Um relatório é, na prática, uma transformação de dados do Model em informação para o usuário. Por isso, é perfeito para ViewModels. Você evita expor classes internas e cria colunas prontas para o grid.

1.3 Exportação e impressão (responsabilidades)

  • Controller prepara os dados (texto CSV, texto do cupom).
  • View escolhe onde salvar/como imprimir (diálogo e UI).
  • Service continua com regras e validações.
Checklist mental
Se você consegue trocar a UI (Form) sem mexer em regras e dados, você aplicou MVC de verdade.

Passo 2 — Criar RelatorioController

Vamos centralizar relatórios em um controller próprio. Ele usa o repositório e retorna ViewModels para a View.

Arquivo: Controllers/RelatorioController.cs
using System;
using System.Collections.Generic;
using System.Linq;
using LanchoneteApp.Data;
using LanchoneteApp.ViewModels;

namespace LanchoneteApp.Controllers
{
    public class RelatorioController
    {
        private readonly ProdutoRepository _repo;

        public RelatorioController(ProdutoRepository repo)
        {
            _repo = repo;
        }

        public List<EstoqueBaixoVM> EstoqueBaixo(int limite = 3)
        {
            return _repo.GetAll()
                .Where(p => p.Estoque <= limite)
                .Select(p => new EstoqueBaixoVM
                {
                    Id = p.Id,
                    Nome = p.Nome,
                    Tipo = p.Tipo,
                    Estoque = p.Estoque,
                    Detalhes = p.Detalhes
                })
                .OrderBy(p => p.Estoque)
                .ThenBy(p => p.Nome)
                .ToList();
        }

        public List<ResumoTipoVM> ResumoPorTipo()
        {
            return _repo.GetAll()
                .GroupBy(p => p.Tipo)
                .Select(g => new ResumoTipoVM
                {
                    Tipo = g.Key,
                    QuantidadeItens = g.Count(),
                    EstoqueTotal = g.Sum(x => x.Estoque),
                    ValorEstoque = g.Sum(x => x.Preco * x.Estoque)
                })
                .OrderBy(x => x.Tipo)
                .ToList();
        }

        public string ExportarCsvEstoqueBaixo(int limite = 3)
        {
            var lista = EstoqueBaixo(limite);
            var linhas = new List<string> { "Id;Nome;Tipo;Estoque;Detalhes" };
            linhas.AddRange(lista.Select(x => $"{x.Id};{x.Nome};{x.Tipo};{x.Estoque};{x.Detalhes}"));
            return string.Join(Environment.NewLine, linhas);
        }

        public string ExportarCsvResumoPorTipo()
        {
            var lista = ResumoPorTipo();
            var linhas = new List<string> { "Tipo;QuantidadeItens;EstoqueTotal;ValorEstoque" };
            linhas.AddRange(lista.Select(x => $"{x.Tipo};{x.QuantidadeItens};{x.EstoqueTotal};{x.ValorEstoque}"));
            return string.Join(Environment.NewLine, linhas);
        }
    }
}

Passo 3 — Criar a View de relatórios (FrmRelatorios)

Crie um Form FrmRelatorios com um TabControl interno com duas abas: Estoque Baixo e Resumo por Tipo. Em cada aba, coloque um DataGridView e botões Exportar.

Arquivo: Views/FrmRelatorios.cs (ideia base com controller + BindingSource)
using System;
using System.IO;
using System.Windows.Forms;
using LanchoneteApp.Controllers;
using LanchoneteApp.Data;

namespace LanchoneteApp.Views
{
    public partial class FrmRelatorios : Form
    {
        private readonly RelatorioController _controller;
        private readonly BindingSource _bsBaixo = new();
        private readonly BindingSource _bsResumo = new();

        public FrmRelatorios(ProdutoRepository repo)
        {
            InitializeComponent();
            _controller = new RelatorioController(repo);

            dgvBaixo.DataSource = _bsBaixo;
            dgvResumo.DataSource = _bsResumo;

            Atualizar();
        }

        private void Atualizar()
        {
            _bsBaixo.DataSource = _controller.EstoqueBaixo(3);
            _bsResumo.DataSource = _controller.ResumoPorTipo();
            _bsBaixo.ResetBindings(false);
            _bsResumo.ResetBindings(false);
        }

        private void btnExportarBaixo_Click(object sender, EventArgs e)
        {
            string csv = _controller.ExportarCsvEstoqueBaixo(3);
            SalvarCsv(csv, "estoque_baixo.csv");
        }

        private void btnExportarResumo_Click(object sender, EventArgs e)
        {
            string csv = _controller.ExportarCsvResumoPorTipo();
            SalvarCsv(csv, "resumo_por_tipo.csv");
        }

        private void SalvarCsv(string conteudo, string nomePadrao)
        {
            using var dlg = new SaveFileDialog();
            dlg.Filter = "CSV|*.csv";
            dlg.FileName = nomePadrao;
            if (dlg.ShowDialog() == DialogResult.OK)
            {
                File.WriteAllText(dlg.FileName, conteudo);
                MessageBox.Show("Arquivo salvo!", "Exportação", MessageBoxButtons.OK, MessageBoxIcon.Information);
            }
        }
    }
}
No Dashboard (Cap. 11), substitua a aba Relatórios para carregar FrmRelatorios no lugar de um relatório único.

Passo 5 — PrintPreview do cupom (Venda Simples)

Objetivo: permitir pré-visualizar o cupom e imprimir (opcional). Use PrintDocument + PrintPreviewDialog. A View gera o texto do cupom chamando o Controller (Cap. 08) e imprime.

  1. No FrmVendaSimples, adicione no Designer: PrintDocument (printDoc) e PrintPreviewDialog (dlgPreview).
  2. Crie um botão: btnImprimir (Text: "Pré-visualizar").
  3. Implemente o evento PrintPage.
Arquivo: Views/FrmVendaSimples.cs (texto do cupom + PrintPage)
using System.Drawing;
using System.Drawing.Printing;

private string _ultimoCupom = "";

private void btnImprimir_Click(object sender, EventArgs e)
{
    try
    {
        int id = IdSelecionado();
        string qtd = nudQtd.Value.ToString();
        _ultimoCupom = _vendaController.GerarCupom(id, qtd, txtDesconto.Text);

        dlgPreview.Document = printDoc;
        dlgPreview.Width = 900;
        dlgPreview.Height = 700;
        dlgPreview.ShowDialog();
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
    }
}

private void printDoc_PrintPage(object sender, PrintPageEventArgs e)
{
    using var fonte = new Font("Consolas", 11);
    e.Graphics.DrawString(_ultimoCupom, fonte, Brushes.Black, new RectangleF(40, 40, e.MarginBounds.Width, e.MarginBounds.Height));
}
Dica
Para cupom ficar alinhado, use fonte monoespaçada (Consolas/Courier New). Se a máquina não tiver, use uma fonte padrão.

Passo 6 — Qualidade: mensagens e feedback no Dashboard

Use o StatusStrip para orientar o usuário (ex.: “Produto cadastrado”, “CSV exportado”). Uma boa prática é o Dashboard expor um método SetStatus e as telas chamarem por evento. Como alternativa simples, mostre MessageBox e atualize status apenas por ações do menu.

3) Entrega 3 (Bimestre 3) — GUI + MVC + Relatórios

Avaliação

Esta entrega avalia integração e qualidade: arquitetura (MVC), UI profissional (Dashboard + abas + menus), controles bem configurados, relatórios e exportação/impressão.

Requisitos mínimos (rubrica do professor)

  • Dashboard único com MenuStrip, ToolStrip, StatusStrip e TabControl (Produtos/Venda/Relatórios).
  • Repositório compartilhado (um só) entre abas (consistência).
  • MVC respeitado: View chama Controller; regras no Service; sem regra pesada no Form.
  • Produtos: grid com colunas e destaque de estoque baixo; filtro por nome.
  • Venda: cálculo com polimorfismo + cupom (MessageBox) + (mínimo) botão de cupom.
  • Relatórios: estoque baixo e resumo por tipo em grids.
  • Exportação CSV (SaveFileDialog) para pelo menos 1 relatório.
  • Opcional/Bônus: PrintPreview do cupom (ou exportar cupom para TXT/CSV).

O que entregar

  1. .zip da solução.
  2. README.txt contendo:
    • Nome, turma, data.
    • Como executar (1 parágrafo).
    • Estrutura de pastas e fluxo MVC (2–4 linhas).
    • Lista de funcionalidades entregues + bônus.
  3. Evidências (prints ou vídeo curto) mostrando:
    • Dashboard com abas e menus
    • Produtos com destaque de estoque baixo e filtro
    • Venda com cupom
    • Relatórios (2 abas) + exportação CSV
    • Um erro tratado (ex.: desconto inválido) com mensagem amigável
Erros comuns
  • Dashboard criando múltiplos repositórios (cada aba com uma lista diferente).
  • Relatório fazendo cálculo no Form (deveria vir do Controller).
  • Exportação “hardcoded” sem SaveFileDialog.
  • Form com lógica de regra de negócio (validação complexa na View).

Bônus (vale pontos extras)

  • PrintPreview do cupom e/ou salvar cupom em TXT.
  • ContextMenuStrip no grid com copiar/etiqueta (Cap. 11).
  • Filtro no ToolStrip (barra de busca global) para produtos.
  • Relatório com gráfico simples (pode ser só barras em Panel desenhado manualmente — opcional).
