2º Bimestre • Capítulo 06 (100 min/semana)

Polimorfismo (aplicado ao projeto da lanchonete)

Você já criou Produto, Lanche e Bebida. Agora vamos usar polimorfismo para tratar todos como Produto, mas com comportamentos diferentes em tempo de execução. Na prática, vamos criar uma simulação de venda que calcula preço final de acordo com o tipo do produto.

Roteiro Passo a passo Atividades

Objetivos de aprendizagem

  • Explicar polimorfismo (mesma referência, comportamentos diferentes).
  • Usar coleções do tipo base (List<Produto>) com objetos de classes filhas.
  • Criar um método virtual na base e sobrescrever (override) nas filhas para regras de preço.
  • Aplicar pattern matching (is, switch) para casos específicos (sem exagero).
  • Construir uma tela de Simulação de Venda e um Resumo por tipo.

Pré-requisitos

  • Capítulo 05 finalizado (classes Lanche e Bebida com overrides)
  • FrmMenu e FrmProdutos funcionando (Cap. 04)
Ideia central
Uma lista de Produto pode conter Lanche e Bebida. Ao chamar um método virtual, cada tipo responde do seu jeito.

1) Parte teórica (conceitos essenciais)

1.1 O que é polimorfismo?

Polimorfismo significa “muitas formas”. Em POO, ele acontece quando você trata objetos diferentes através do mesmo tipo (geralmente o tipo base), mas cada objeto executa o comportamento de acordo com seu tipo real. Ou seja: a variável pode ser do tipo Produto, mas o objeto dentro dela pode ser um Lanche ou uma Bebida.

No nosso projeto, a lista do repositório é uma List<Produto>. Ela contém lanches e bebidas. Quando chamamos um método virtual (por exemplo, Etiqueta()), cada item responde do seu jeito porque as classes filhas usam override.

1.2 Polimorfismo na prática: despacho dinâmico (virtual/override)

Quando um método é virtual na classe base e override na filha, o C# decide em tempo de execução qual método executar. Isso permite criar regras diferentes por tipo sem precisar escrever vários if no formulário.

Exemplo: a regra de preço final pode variar: bebida alcoólica pode ter uma taxa extra; lanche grande pode ter um acréscimo. Em vez de fazer isso no Form, colocamos a regra no próprio objeto (classe filha), usando polimorfismo.

1.3 Pattern matching (uso moderado)

Às vezes precisamos de informações específicas do tipo (ex.: mostrar volume da bebida). Para isso, usamos pattern matching com is e switch. A regra é: use com moderação. Se você faz if (p is Bebida) toda hora, talvez você esteja perdendo o benefício do polimorfismo.

Dica de ouro
Preferir polimorfismo (virtual/override) para regras; usar pattern matching apenas para detalhes específicos (exibir algo extra).

2) Passo a passo (Simulação de venda com polimorfismo)

Vamos criar um método CalcularTotalVenda em Produto e sobrescrever em Bebida e Lanche. Depois, vamos criar a tela FrmVendaSimples para simular uma venda: escolher um produto, informar quantidade e desconto.

Antes de começar

  1. Abra a solução LanchoneteApp.
  2. Execute (F5) e confirme que a tela de produtos mostra lanches e bebidas (Cap. 05).

Passo 1 — Criar um método virtual de cálculo na classe base (Produto)

Vamos criar CalcularTotalVenda como virtual na classe base. Ele calcula: Preço * quantidade e aplica desconto percentual. As classes filhas poderão alterar isso.

  1. Abra Models/Produto.cs.
  2. Adicione este método dentro da classe (perto dos outros métodos):
Arquivo: Models/Produto.cs (novo método virtual)
public virtual decimal CalcularTotalVenda(int quantidade, decimal descontoPercentual = 0)
{
    if (quantidade <= 0)
        throw new ArgumentException("Quantidade deve ser maior que zero.");

    if (descontoPercentual < 0 || descontoPercentual > 100)
        throw new ArgumentException("Desconto deve estar entre 0 e 100.");

    decimal bruto = Preco * quantidade;
    decimal desconto = bruto * (descontoPercentual / 100m);
    return bruto - desconto;
}
Por que virtual?
Porque Bebida e Lanche vão sobrescrever o cálculo para regras específicas (taxa, acréscimo etc.).

Passo 2 — Sobrescrever o cálculo em Bebida (taxa para alcoólica)

Regra simples (didática): se a bebida for alcoólica, acrescenta 10% de taxa no valor final. Assim, o mesmo método se comporta de modo diferente dependendo do tipo.

  1. Abra Models/Bebida.cs.
  2. Adicione este override dentro da classe:
Arquivo: Models/Bebida.cs (override do cálculo)
public override decimal CalcularTotalVenda(int quantidade, decimal descontoPercentual = 0)
{
    decimal total = base.CalcularTotalVenda(quantidade, descontoPercentual);

    // Regra: bebida alcoólica tem taxa de 10%
    if (Alcoolica)
        total *= 1.10m;

    return total;
}

Passo 3 — Sobrescrever o cálculo em Lanche (acréscimo por tamanho)

Regra simples: se o tamanho for Grande, acrescenta 15%. Se for Média, acrescenta 5%. Se for Pequeno, não acrescenta.

  1. Abra Models/Lanche.cs.
  2. Adicione este override dentro da classe:
Arquivo: Models/Lanche.cs (override do cálculo)
public override decimal CalcularTotalVenda(int quantidade, decimal descontoPercentual = 0)
{
    decimal total = base.CalcularTotalVenda(quantidade, descontoPercentual);

    string t = (Tamanho ?? "").Trim().ToLower();
    if (t == "grande") total *= 1.15m;
    else if (t == "média" || t == "media") total *= 1.05m;

    return total;
}
Essa regra é só para aprendizado. Em sistemas reais, regras ficam mais sofisticadas e parametrizadas.

Passo 4 — Atualizar o Service para simular venda com polimorfismo

Agora o Service vai chamar CalcularTotalVenda do produto escolhido. Note: o service vai tratar como Produto, mas o método executado depende do tipo real.

  1. Abra Services/ProdutoService.cs.
  2. Adicione este método:
Arquivo: Services/ProdutoService.cs (novo método)
public decimal SimularVenda(int id, string qtdTexto, string? descontoTexto)
{
    if (!int.TryParse(qtdTexto, out int qtd))
        throw new ArgumentException("Quantidade inválida.");

    decimal desconto = 0;
    if (!string.IsNullOrWhiteSpace(descontoTexto))
    {
        var cultura = new CultureInfo("pt-BR");
        if (!decimal.TryParse(descontoTexto, NumberStyles.Any, cultura, out desconto))
            throw new ArgumentException("Desconto inválido.");
    }

    var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");

    // POLIMORFISMO: chama o método virtual (cada tipo calcula do seu jeito)
    return p.CalcularTotalVenda(qtd, desconto);
}

Passo 5 — Criar a tela FrmVendaSimples (Views)

Vamos criar uma tela de simulação de venda: o usuário escolhe um produto da lista, informa quantidade e desconto e clica em “Calcular”.

  1. Crie um novo Form em Views: FrmVendaSimples.cs.
  2. No Designer, crie os controles:
  • ComboBox cboProduto (DropDownStyle: DropDownList)
  • TextBox txtQtd (Label: Quantidade)
  • TextBox txtDesconto (Label: Desconto % (opcional))
  • Button btnCalcular (Text: Calcular Total)
  • Label lblResultado (Text inicial: “Total: R$ 0,00”)

Agora use este código do form (você pode adaptar nomes dos controles se necessário):

Arquivo: Views/FrmVendaSimples.cs (código completo sugerido)
using System;
using System.Linq;
using System.Windows.Forms;
using LanchoneteApp.Data;
using LanchoneteApp.Models;
using LanchoneteApp.Services;

namespace LanchoneteApp.Views
{
    public partial class FrmVendaSimples : Form
    {
        private readonly ProdutoRepository _repo;
        private readonly ProdutoService _service;

        public FrmVendaSimples(ProdutoRepository repo)
        {
            InitializeComponent();

            _repo = repo;
            _service = new ProdutoService(_repo);

            CarregarProdutos();
            lblResultado.Text = "Total: R$ 0,00";
        }

        private void CarregarProdutos()
        {
            var lista = _repo.GetAll().ToList();
            cboProduto.DataSource = lista;
            cboProduto.DisplayMember = "Nome"; // aparece no combo
            cboProduto.ValueMember = "Id";
        }

        private int IdSelecionado()
        {
            // ValueMember = Id
            if (cboProduto.SelectedValue is int id)
                return id;

            // fallback (caso SelectedValue não seja int)
            if (cboProduto.SelectedItem is Produto p)
                return p.Id;

            throw new InvalidOperationException("Selecione um produto.");
        }

        private void btnCalcular_Click(object sender, EventArgs e)
        {
            try
            {
                int id = IdSelecionado();
                decimal total = _service.SimularVenda(id, txtQtd.Text, txtDesconto.Text);

                // Exibir resultado
                lblResultado.Text = $"Total: {total:C}";

                // (Opcional) Mostrar detalhes do tipo usando pattern matching
                if (cboProduto.SelectedItem is Produto p)
                {
                    string extra = p switch
                    {
                        Bebida b => $"Tipo: Bebida ({b.VolumeMl}ml)",
                        Lanche l => $"Tipo: Lanche ({l.Tamanho})",
                        _ => $"Tipo: {p.Tipo}"
                    };
                    this.Text = $"Venda Simples • {extra}";
                }
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }
    }
}
Onde está o polimorfismo?
O Service chama p.CalcularTotalVenda. Se p for Bebida ou Lanche, o C# executa o override correto automaticamente.

Passo 7 — Testes obrigatórios

  • Simule venda de Bebida alcoólica e compare com uma não alcoólica (a alcoólica deve ficar ~10% mais cara).
  • Simule venda de Lanche Grande e compare com um lanche Médio (Grande deve ter acréscimo maior).
  • Teste desconto inválido (ex.: 150) e confirme a mensagem.
  • Teste quantidade inválida (ex.: 0 ou texto) e confirme a mensagem.
Resultado esperado

3) Atividades práticas (para consolidar)

Escolha 2 atividades (ou faça todas). Elas reforçam polimorfismo e boas decisões de design.

Atividade A — Regra de preço por volume (Bebida)
  • Se VolumeMl >= 600, aplicar 5% de desconto no total (além do desconto do usuário).
  • Faça isso no override de Bebida.
  • Teste com uma bebida 600ml no Seed.
Atividade B — Resumo por tipo (relatório)
  • Crie um form FrmResumoProdutos com 3 labels: Total de Lanches, Total de Bebidas, Total Geral.
  • Some usando Tipo (ou pattern matching) a partir de _repo.GetAll().
  • Mostre o resultado formatado em moeda.
Atividade C — “Cupom” com etiqueta final
  • Na venda simples, mostre um cupom com: Etiqueta() + quantidade + desconto + total.
  • Use Etiqueta() (polimórfico) para que o cupom mude conforme o tipo.
  • Exiba em MessageBox ou em um TextBox multilinha.

Critérios rápidos

  • Uso de virtual/override correto (polimorfismo de verdade).
  • Sem excesso de if (p is ...) para regras (usar override para regras).
  • Evidências: prints/vídeo comparando pelo menos 2 tipos com resultados diferentes.
