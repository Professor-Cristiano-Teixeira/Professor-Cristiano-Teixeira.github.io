3º Bimestre • Capítulo 09 (100 min/semana)

GUI: Formulários e Layout (Windows Forms)

Neste capítulo você vai elevar a qualidade visual do seu sistema: organizar telas, alinhar componentes, padronizar nomes, aplicar Dock/Anchor, usar TableLayoutPanel e FlowLayoutPanel, e melhorar a usabilidade com ErrorProvider e ToolTip. No final, seu FrmProdutos e FrmVendaSimples ficarão mais "profissionais".

Roteiro Passo a passo Atividades

Objetivos de aprendizagem

  • Aplicar boas práticas de design de formulários (consistência, alinhamento e navegação).
  • Usar Dock e Anchor para tornar telas responsivas.
  • Montar layouts com TableLayoutPanel e FlowLayoutPanel.
  • Padronizar nomes de controles e eventos (legibilidade e manutenção).
  • Adicionar ErrorProvider e ToolTip para feedback ao usuário.
  • Aplicar melhorias reais em FrmProdutos e FrmVendaSimples.

Pré-requisitos

  • Projeto LanchoneteApp com MVC (Cap. 08)
  • Forms FrmMenu, FrmProdutos, FrmVendaSimples
Resultado esperado
Telas mais organizadas, fáceis de usar, e com comportamento correto ao redimensionar.

1) Parte teórica (GUI para aplicações desktop)

1.1 Consistência e hierarquia

Uma boa tela responde a 3 perguntas rapidamente: (1) O que eu posso fazer aqui? (2) O que é obrigatório preencher? (3) Qual o próximo passo? Para isso, use agrupamentos (GroupBox/Painel), títulos claros e botões com nomes consistentes.

1.2 Dock e Anchor

  • Dock “encaixa” um controle em uma região (Top, Bottom, Left, Right, Fill). Ótimo para barras e grids.
  • Anchor mantém distância de bordas (Top/Right/Bottom/Left). Ótimo para inputs e botões que precisam acompanhar o resize.
Regra rápida
Use Dock para “regiões” (menu, rodapé, grid). Use Anchor para “posicionamento” (inputs e botões dentro de uma região).

1.3 TableLayoutPanel e FlowLayoutPanel

TableLayoutPanel organiza em linhas/colunas como uma tabela — perfeito para formulários. FlowLayoutPanel organiza em sequência (horizontal/vertical) — perfeito para botões.

1.4 Feedback ao usuário: ErrorProvider e ToolTip

ErrorProvider mostra um ícone de erro ao lado do controle com problema. ToolTip dá dicas ao passar o mouse (ex.: formato de preço). Isso reduz frustração e evita depender só de MessageBox.

Não exagere
Mensagem de erro em todo clique irrita. Prefira validação pontual (ex.: ao sair do campo) e resuma erros no final.

2) Passo a passo (melhorando as telas)

A seguir, um roteiro prático para deixar os Forms organizados e responsivos, mantendo MVC do Cap. 08.

Antes de começar

  1. Abra o projeto no Visual Studio.
  2. Execute (F5) e confira que Menu → Produtos e Menu → Venda simples abrem normalmente.
  3. Faça backup/commit.

Passo 1 — Padronizar nomes e propriedades básicas dos Forms

Em cada Form (Menu, Produtos, Venda), ajuste:

  • Text: título coerente (ex.: LanchoneteApp • Produtos)
  • StartPosition: CenterScreen (Menu) e CenterParent (demais)
  • MinimumSize: evita quebrar layout
  • AcceptButton e CancelButton quando fizer sentido (Enter/Esc)
Exemplo: FrmVendaSimples (no construtor, após InitializeComponent)
this.Text = "LanchoneteApp • Venda simples";
this.StartPosition = FormStartPosition.CenterParent;
this.MinimumSize = new Size(720, 460);
this.AcceptButton = btnCalcular;
this.CancelButton = btnFechar; // se você criar um botão Fechar

Passo 2 — Refatorar o layout do FrmProdutos com TableLayoutPanel

Objetivo: separar a tela em 2 áreas: (A) Formulário de cadastro/manutenção e (B) Lista (DataGridView).

  1. No Designer do FrmProdutos, arraste um SplitContainer (Dock = Fill).
  2. No painel esquerdo (Panel1), coloque um TableLayoutPanel (Dock = Fill) com 2 colunas (Label + Campo).
  3. No painel direito (Panel2), deixe o DataGridView com Dock = Fill.
  4. Crie um FlowLayoutPanel na parte inferior do Panel1 para botões (Dock = Bottom).
Configuração recomendada
  • SplitContainer.Orientation = Vertical
  • SplitContainer.SplitterDistance ~ 350
  • Grid com Dock = Fill
  • Botões agrupados em FlowLayoutPanel (RightToLeft = No)

Para o FlowLayoutPanel de botões, use esta ordem:

  • btnAdicionar, btnAlterarPreco, btnRepor, btnBaixar, btnEtiqueta
Você não precisa mudar o Controller. Apenas reorganize a View para ficar usável e responsiva.

Passo 3 — Aplicar Anchor e máscaras de entrada (sem complicar)

Ajuste os campos para expandirem com a tela: Anchor = Top, Left, Right (para inputs largos). Para números, você pode usar MaskedTextBox (opcional) ou manter TextBox com validação.

Dica: placeholders com ToolTip (ex.: preço no padrão pt-BR)
ToolTip tip = new ToolTip();

tip.SetToolTip(txtPreco, "Use vírgula: 9,50");
tip.SetToolTip(txtDesconto, "0 a 100 (opcional)");

Passo 4 — Adicionar ErrorProvider (validação visual)

  1. No Designer do FrmProdutos, arraste um ErrorProvider (chame de err).
  2. Crie eventos Validating nos campos principais: Nome, Preço, Tipo (e Volume/Tamanho conforme tipo).
Exemplo: validar Nome e Preço (evento Validating)
private void txtNome_Validating(object sender, CancelEventArgs e)
{
    if (string.IsNullOrWhiteSpace(txtNome.Text))
    {
        err.SetError(txtNome, "Nome é obrigatório.");
        e.Cancel = true;
    }
    else
    {
        err.SetError(txtNome, "");
    }
}

private void txtPreco_Validating(object sender, CancelEventArgs e)
{
    var cultura = new CultureInfo("pt-BR");
    if (!decimal.TryParse(txtPreco.Text, NumberStyles.Any, cultura, out var _))
    {
        err.SetError(txtPreco, "Preço inválido. Ex.: 9,50");
        e.Cancel = true;
    }
    else
    {
        err.SetError(txtPreco, "");
    }
}
Importante
Para que o Validating funcione, mantenha CausesValidation = true nos controles e evite desabilitar isso nos botões.

Passo 5 — Melhorar o FrmVendaSimples: layout em tabela + cupom

Objetivo: deixar a venda simples clara e rápida: escolher produto → quantidade → desconto → calcular → cupom.

  1. No FrmVendaSimples, use um TableLayoutPanel (Dock = Top) para as entradas.
  2. Coloque um FlowLayoutPanel (Dock = Top) para botões: btnCalcular, btnCupom, btnFechar.
  3. Coloque o lblResultado em destaque (fonte maior) e ancorado.
Sugestão de acessibilidade: atalhos de teclado (Text com &)
btnCalcular.Text = "&Calcular"; // Alt+C
btnCupom.Text = "&Cupom";       // Alt+U
btnFechar.Text = "&Fechar";     // Alt+F
Dica de UX
Deixe o combo de produto sempre visível e o botão Calcular como AcceptButton (Enter). Isso acelera o uso.

Passo 6 — Testes obrigatórios

  • Redimensione as telas: o grid deve expandir sem quebrar; inputs devem acompanhar.
  • Teste campos inválidos: ErrorProvider deve aparecer no campo correto.
  • Use Enter para calcular na venda simples e Esc/Fechar para sair.
  • Teste fluxo completo: cadastrar → vender → gerar cupom.
Resultado esperado
Telas mais profissionais: organizadas, responsivas e com feedback claro ao usuário.

3) Atividades práticas (para consolidar)

Faça 2 atividades (ou todas). O foco é UI e layout.

Atividade A — Tema visual e consistência
  • Padronize fontes e tamanhos (título, labels, botões).
  • Padronize textos dos botões (verbos no infinitivo).
  • Adicione um rodapé com versão do app (Label Dock Bottom).
Atividade B — Form “Sobre” completo
  • Crie FrmSobre com logo/ícone, versão e autores.
  • Abra pelo menu Ajuda → Sobre.
  • Use TableLayoutPanel para alinhar conteúdo.
Atividade C — Validação por tipo (UI)
  • Quando Tipo = Lanche, mostre somente Tamanho.
  • Quando Tipo = Bebida, mostre somente Volume + Alcoólica.
  • Use Visible e limpe erros do ErrorProvider ao trocar tipo.

Critérios rápidos

  • Layout responsivo (Dock/Anchor corretos).
  • Controles alinhados (TableLayoutPanel).
  • Feedback de erro (ErrorProvider) e dicas (ToolTip).
  • Fluxo rápido: teclado (Enter/Esc) e botões bem posicionados.
