1º Bimestre • Capítulo 02 (100 min/semana)

Atributos, Métodos e Encapsulamento (C#)

Agora que você já criou a classe Produto, vamos melhorar o modelo aplicando encapsulamento: controlar como os dados são acessados e alterados, criando regras dentro da classe. Você também vai criar métodos para alterar preço e estoque com segurança.

Roteiro Passo a passo Atividades

Objetivos de aprendizagem

  • Diferenciar atributos (campos) e propriedades em C#.
  • Explicar o que é encapsulamento e por que ele protege o sistema.
  • Criar métodos para aplicar regras (ex.: não deixar preço/estoque negativos).
  • Usar os métodos do Produto a partir do Windows Forms (alterar preço e ajustar estoque).

Pré-requisitos

  • Capítulo 01 concluído (projeto LanchoneteApp criado)
  • Noções de validação de entrada (TryParse)
Ideia principal
Em vez de alterar tudo direto (ex.: produto.Estoque = -10), vamos fazer o objeto se proteger.

1) Parte teórica (conceitos essenciais)

1.1 Atributos (campos) e Propriedades

Em POO, os atributos são os dados que descrevem um objeto. Em C#, esses dados podem existir como campos (variáveis dentro da classe) ou como propriedades (que parecem campos, mas podem conter regras no get/set). Propriedades são muito usadas porque permitem controlar o acesso aos dados sem mudar como o resto do programa usa.

Na prática: o produto tem atributos como Nome, Preco e Estoque. Se você deixar tudo público e editável, qualquer parte do sistema poderia colocar valores inválidos (ex.: estoque negativo). Por isso, vamos encapsular.

1.2 Métodos

Métodos são ações/funcionalidades de um objeto. Eles servem para fazer algo com os dados, e também para aplicar regras antes de alterar o estado do objeto. Um método pode, por exemplo, validar se o preço é maior que zero antes de aceitar.

No nosso projeto: vamos criar métodos como AlterarPreco e BaixarEstoque. Assim, quando a tela quiser mudar alguma coisa, ela chama o método, e o próprio objeto garante que a regra será respeitada.

1.3 Encapsulamento (por que é importante?)

Encapsulamento é o princípio de “proteger” os dados do objeto e controlar como eles podem ser alterados. Em vez de o programa inteiro mexer diretamente nos atributos, você define métodos e/ou propriedades com regras de acesso.

Pense na lanchonete: não faz sentido deixar alguém cadastrar um produto com preço negativo, nem reduzir o estoque abaixo de zero. Com encapsulamento, essas regras ficam no lugar certo: dentro da classe Produto. A tela só pede a alteração.

1.4 Modificadores de acesso: public e private

Em C#, public significa que qualquer parte do projeto pode acessar aquele membro. Já private significa que só o próprio objeto pode acessar (ou seja, apenas dentro da classe). Um padrão comum é: campos privados + propriedades públicas com regras.

Conexão com o passo a passo
A partir de agora, você vai evitar fazer produto.Preco = ... diretamente. Em vez disso, você chamará produto.AlterarPreco(...) e produto.BaixarEstoque(...). Isso é aplicar encapsulamento na prática.

Antes de começar — Abra o projeto do Capítulo 01

Passo 1 — Refatorar a classe Produto com encapsulamento

Agora vamos proteger o estado do objeto. A ideia é: (1) manter propriedades para o DataGridView exibir, (2) impedir alterações diretas indevidas, (3) criar métodos que aplicam regras.

  1. Abra Models/Produto.cs.
  2. Substitua pelo código abaixo.
Arquivo: Models/Produto.cs (versão com encapsulamento)
using System;

namespace LanchoneteApp.Models
{
    public class Produto
    {
        // Campos privados (não podem ser acessados diretamente fora da classe)
        private string _nome;
        private decimal _preco;
        private int _estoque;

        // Propriedades públicas (o grid consegue exibir)
        public int Id { get; }

        public string Nome
        {
            get => _nome;
            private set
            {
                if (string.IsNullOrWhiteSpace(value))
                    throw new ArgumentException("Nome não pode ser vazio.");

                _nome = value.Trim();
            }
        }

        public decimal Preco
        {
            get => _preco;
            private set
            {
                if (value < 0)
                    throw new ArgumentException("Preço não pode ser negativo.");

                _preco = value;
            }
        }

        public int Estoque
        {
            get => _estoque;
            private set
            {
                if (value < 0)
                    throw new ArgumentException("Estoque não pode ser negativo.");

                _estoque = value;
            }
        }

        // Construtor: garante que o objeto já nasce válido
        public Produto(int id, string nome, decimal preco, int estoque)
        {
            if (id <= 0)
                throw new ArgumentException("Id deve ser maior que zero.");

            Id = id;
            Nome = nome;
            Preco = preco;
            Estoque = estoque;
        }

        // Métodos (ações) para alterar o estado com regras
        public void AlterarPreco(decimal novoPreco)
        {
            if (novoPreco < 0)
                throw new ArgumentException("Preço não pode ser negativo.");

            Preco = novoPreco;
        }

        public void Renomear(string novoNome)
        {
            Nome = novoNome; // valida no setter
        }

        public void ReporEstoque(int quantidade)
        {
            if (quantidade <= 0)
                throw new ArgumentException("Quantidade para repor deve ser maior que zero.");

            Estoque = Estoque + quantidade;
        }

        public void BaixarEstoque(int quantidade)
        {
            if (quantidade <= 0)
                throw new ArgumentException("Quantidade para baixar deve ser maior que zero.");

            if (quantidade > Estoque)
                throw new InvalidOperationException("Não há estoque suficiente para baixar essa quantidade.");

            Estoque = Estoque - quantidade;
        }
    }
}
O que mudou?
Agora Nome, Preco e Estoque não podem ser alterados diretamente (setters privados). A tela deve usar os métodos AlterarPreco, ReporEstoque e BaixarEstoque.

Passo 3 — Atualizar o código do formulário para usar métodos (encapsulamento)

Agora vamos chamar os métodos do objeto em vez de alterar propriedades diretamente. Além disso, vamos tratar exceções (try/catch) para mostrar mensagens amigáveis.

  1. No FrmProdutos.cs, dê duplo clique nos botões novos para criar os eventos Click.
  2. Adicione/ajuste os métodos abaixo no seu formulário.
Arquivo: FrmProdutos.cs (trechos novos/importantes)
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;
using System.Windows.Forms;
using LanchoneteApp.Models;

namespace LanchoneteApp
{
    public partial class FrmProdutos : Form
    {
        private readonly List<Produto> _produtos = new();

        public FrmProdutos()
        {
            InitializeComponent();

            dgvProdutos.AutoGenerateColumns = true;
            dgvProdutos.ReadOnly = true;
            dgvProdutos.AllowUserToAddRows = false;

            // Produtos iniciais
            _produtos.Add(new Produto(1, "X-Burger", 18.50m, 5));
            _produtos.Add(new Produto(2, "Batata Frita", 12.00m, 10));
            _produtos.Add(new Produto(3, "Refrigerante Cola", 7.00m, 12));

            AtualizarGrid();
        }

        private void btnAdicionar_Click(object sender, EventArgs e)
        {
            try
            {
                if (!int.TryParse(txtId.Text, out int id))
                    throw new ArgumentException("ID inválido.");

                string nome = txtNome.Text.Trim();
                if (string.IsNullOrWhiteSpace(nome))
                    throw new ArgumentException("Informe o nome do produto.");

                var cultura = new CultureInfo("pt-BR");
                if (!decimal.TryParse(txtPreco.Text, NumberStyles.Any, cultura, out decimal preco))
                    throw new ArgumentException("Preço inválido. Ex.: 9,50");

                if (!int.TryParse(txtEstoque.Text, out int estoque))
                    throw new ArgumentException("Estoque inválido.");

                // Evitar IDs repetidos (regra simples)
                if (_produtos.Any(p => p.Id == id))
                    throw new InvalidOperationException("Já existe um produto com esse ID.");

                // O construtor já valida regras (objeto nasce válido)
                Produto novo = new Produto(id, nome, preco, estoque);
                _produtos.Add(novo);

                AtualizarGrid();

                txtId.Clear(); txtNome.Clear(); txtPreco.Clear(); txtEstoque.Clear();
                txtId.Focus();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private Produto ProdutoSelecionado()
        {
            // Se o DataSource é a lista, a linha selecionada é um Produto
            if (dgvProdutos.CurrentRow?.DataBoundItem is Produto p)
                return p;

            throw new InvalidOperationException("Selecione um produto no grid.");
        }

        private void btnAlterarPreco_Click(object sender, EventArgs e)
        {
            try
            {
                var cultura = new CultureInfo("pt-BR");
                if (!decimal.TryParse(txtNovoPreco.Text, NumberStyles.Any, cultura, out decimal novoPreco))
                    throw new ArgumentException("Novo preço inválido.");

                Produto p = ProdutoSelecionado();

                // Encapsulamento: a tela pede, o objeto valida
                p.AlterarPreco(novoPreco);

                AtualizarGrid();
                txtNovoPreco.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnRepor_Click(object sender, EventArgs e)
        {
            try
            {
                if (!int.TryParse(txtQtdEstoque.Text, out int qtd))
                    throw new ArgumentException("Quantidade inválida.");

                Produto p = ProdutoSelecionado();
                p.ReporEstoque(qtd);

                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnBaixar_Click(object sender, EventArgs e)
        {
            try
            {
                if (!int.TryParse(txtQtdEstoque.Text, out int qtd))
                    throw new ArgumentException("Quantidade inválida.");

                Produto p = ProdutoSelecionado();
                p.BaixarEstoque(qtd);

                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void AtualizarGrid()
        {
            dgvProdutos.DataSource = null;
            dgvProdutos.DataSource = _produtos;
        }
    }
}
Onde estão atributos, métodos e encapsulamento aqui?
  • Atributos/campos: _nome, _preco, _estoque (privados).
  • Propriedades: Nome, Preco, Estoque com validações no set.
  • Métodos: AlterarPreco, ReporEstoque, BaixarEstoque.
  • Encapsulamento: a tela não altera diretamente; ela chama métodos e o objeto garante as regras.

Critérios simples de avaliação (rubrica)

  • Organização: classe em Models, nomes claros, código legível.
  • Encapsulamento: sem set público para dados sensíveis (preço/estoque/nome).
  • Regras funcionando: bloqueia inválidos e mostra mensagens.
  • Demonstração: prints ou vídeo curto mostrando pelo menos 2 cenários de erro e 1 de sucesso.
