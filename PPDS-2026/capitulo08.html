MVC (adaptado ao Windows Forms) + Entrega 2

Neste capítulo, você vai organizar o projeto com um padrão MVC adaptado ao Windows Forms. A ideia é separar responsabilidades: Model (regras/dados), View (telas) e Controller (orquestração). Ao final, você fará a Entrega 2, integrando Produtos + Venda Simples + Relatórios, usando o padrão.

Roteiro Passo a passo Entrega 2

Objetivos de aprendizagem

  • Explicar o papel de Model, View e Controller.
  • Aplicar MVC em WinForms (sem frameworks): o Controller recebe entradas da View e chama Services/Models.
  • Criar controllers reais: ProdutoController e VendaController.
  • Criar ViewModels simples para o DataGridView e para ComboBox (evitar vazamento de detalhes).
  • Concluir a Entrega 2 com critérios claros e evidências.

Pré-requisitos

  • Capítulos 05–07 concluídos (herança, polimorfismo, abstratas/interfaces)
  • Projeto organizado por pastas: Models/Data/Services/Views/Utils
  • FrmMenu, FrmProdutos e FrmVendaSimples funcionando
Importante
MVC aqui é “adaptado”: WinForms não é MVC nativo. Vamos aplicar o princípio de separação de responsabilidades.

1) Parte teórica (MVC em poucas palavras)

1.1 O que é MVC?

MVC é um padrão de organização de software que separa responsabilidades: Model (dados + regras), View (interface) e Controller (coordena ações).

Em WinForms, a tela (Form) normalmente mistura tudo. O objetivo do MVC aqui é reduzir essa mistura: a View deve só capturar entradas e exibir saídas; o Controller decide o que fazer; e o Model/Service concentra regras.

1.2 Como fica no nosso projeto?

  • Models: Produto (abstrato), Lanche, Bebida, interfaces.
  • Data: ProdutoRepository (memória) — no futuro vira DAO.
  • Services: ProdutoService (regras e validações).
  • Controllers: camada nova, orquestra o que a View pede e prepara dados para a View.
  • ViewModels: objetos simples para exibição (grid/combobox), evitando “vazar” classe completa na tela.
  • Views: Forms (Menu, Produtos, Venda, Relatórios) — apenas UI.
Sinal de que você está aplicando MVC corretamente
Se a View ficou menor e sem regra de negócio (sem validações complexas), e a lógica migrou para Controller/Service.

Passo 3 — Criar ProdutoController

O controller vai expor métodos que a View precisa: listar para grid, listar para combo, criar por tipo, alterar preço, ajustar estoque e gerar etiqueta.

Arquivo: Controllers/ProdutoController.cs
using System;
using System.Collections.Generic;
using System.Linq;
using LanchoneteApp.Data;
using LanchoneteApp.Models;
using LanchoneteApp.Services;
using LanchoneteApp.ViewModels;

namespace LanchoneteApp.Controllers
{
    public class ProdutoController
    {
        private readonly ProdutoRepository _repo;
        private readonly ProdutoService _service;

        public ProdutoController(ProdutoRepository repo)
        {
            _repo = repo;
            _service = new ProdutoService(_repo);
        }

        public List<ProdutoListItemVM> ListarParaGrid()
        {
            return _repo.GetAll().Select(p => new ProdutoListItemVM
            {
                Id = p.Id,
                Nome = p.Nome,
                Preco = p.Preco,
                Estoque = p.Estoque,
                Tipo = p.Tipo,
                Detalhes = p.Detalhes
            }).ToList();
        }

        public List<ProdutoComboItemVM> ListarParaCombo()
        {
            return _repo.GetAll().Select(p => new ProdutoComboItemVM
            {
                Id = p.Id,
                Texto = $"{p.Nome} ({p.Tipo})"
            }).ToList();
        }

        public void CadastrarPorTipo(string tipo, string? id, string nome, string preco, string estoque, string? tamanho, string? volume, bool alcoolica)
        {
            _service.CriarProdutoPorTipo(tipo, id, nome, preco, estoque, tamanho, volume, alcoolica);
        }

        public void AlterarPreco(int id, string novoPreco) => _service.AlterarPreco(id, novoPreco);
        public void ReporEstoque(int id, string qtd) => _service.ReporEstoque(id, qtd);
        public void BaixarEstoque(int id, string qtd) => _service.BaixarEstoque(id, qtd);

        public string Etiqueta(int id)
        {
            var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");
            return p.Etiqueta();
        }

        public object EstoqueBaixo(int limite = 3) => _service.EstoqueBaixo(limite);
    }
}
Observe
A View chama o Controller. O Controller chama o Service/Repo e devolve ViewModels prontos para exibir.

Passo 4 — Criar VendaController (simulação + cupom)

Vamos encapsular a lógica da venda simples no controller. Ele vai calcular total e também gerar um “cupom” com etiqueta + quantidade + desconto.

Arquivo: Controllers/VendaController.cs
using System;
using System.Globalization;
using LanchoneteApp.Data;
using LanchoneteApp.Services;

namespace LanchoneteApp.Controllers
{
    public class VendaController
    {
        private readonly ProdutoRepository _repo;
        private readonly ProdutoService _service;

        public VendaController(ProdutoRepository repo)
        {
            _repo = repo;
            _service = new ProdutoService(_repo);
        }

        public decimal CalcularTotal(int produtoId, string qtdTexto, string? descontoTexto)
        {
            return _service.SimularVenda(produtoId, qtdTexto, descontoTexto);
        }

        public string GerarCupom(int produtoId, string qtdTexto, string? descontoTexto)
        {
            // reaproveita o cálculo
            decimal total = CalcularTotal(produtoId, qtdTexto, descontoTexto);

            int qtd = int.TryParse(qtdTexto, out var q) ? q : 0;

            decimal desconto = 0;
            if (!string.IsNullOrWhiteSpace(descontoTexto))
            {
                var cultura = new CultureInfo("pt-BR");
                decimal.TryParse(descontoTexto, NumberStyles.Any, cultura, out desconto);
            }

            var p = _repo.FindById(produtoId) ?? throw new InvalidOperationException("Produto não encontrado.");

            return $"CUPOM\n" +
                   $"--------------------------\n" +
                   $"{p.Etiqueta()}\n" +
                   $"Qtd: {qtd}\n" +
                   $"Desconto: {desconto}%\n" +
                   $"TOTAL: {total:C}\n" +
                   $"--------------------------";
        }
    }
}

Passo 5 — Refatorar FrmProdutos para usar o Controller

Agora a View não deve usar Service diretamente. Ela recebe um repository compartilhado (como antes), cria o Controller e usa apenas métodos do Controller.

Arquivo: Views/FrmProdutos.cs (estrutura-base com controller)
using System;
using System.Windows.Forms;
using LanchoneteApp.Controllers;
using LanchoneteApp.Data;

namespace LanchoneteApp.Views
{
    public partial class FrmProdutos : Form
    {
        private readonly ProdutoController _controller;

        public FrmProdutos(ProdutoRepository repo)
        {
            InitializeComponent();
            _controller = new ProdutoController(repo);

            dgvProdutos.AutoGenerateColumns = true;
            dgvProdutos.ReadOnly = true;
            dgvProdutos.AllowUserToAddRows = false;

            cboTipo.Items.Clear();
            cboTipo.Items.AddRange(new object[] { "Lanche", "Bebida" });
            cboTipo.SelectedIndex = 0;

            AtualizarGrid();
        }

        private int IdSelecionado()
        {
            if (dgvProdutos.CurrentRow?.DataBoundItem is dynamic row)
                return (int)row.Id;
            throw new InvalidOperationException("Selecione um item no grid.");
        }

        private void AtualizarGrid()
        {
            dgvProdutos.DataSource = null;
            dgvProdutos.DataSource = _controller.ListarParaGrid();
        }

        private void btnAdicionar_Click(object sender, EventArgs e)
        {
            try
            {
                _controller.CadastrarPorTipo(
                    cboTipo.SelectedItem?.ToString() ?? "",
                    txtId.Text,
                    txtNome.Text,
                    txtPreco.Text,
                    txtEstoque.Text,
                    txtTamanho.Text,
                    txtVolume.Text,
                    chkAlcoolica.Checked
                );

                AtualizarGrid();
                txtId.Clear(); txtNome.Clear(); txtPreco.Clear(); txtEstoque.Clear();
                txtTamanho.Clear(); txtVolume.Clear(); chkAlcoolica.Checked = false;
                txtNome.Focus();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnAlterarPreco_Click(object sender, EventArgs e)
        {
            try
            {
                _controller.AlterarPreco(IdSelecionado(), txtNovoPreco.Text);
                AtualizarGrid();
                txtNovoPreco.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnRepor_Click(object sender, EventArgs e)
        {
            try
            {
                _controller.ReporEstoque(IdSelecionado(), txtQtdEstoque.Text);
                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnBaixar_Click(object sender, EventArgs e)
        {
            try
            {
                _controller.BaixarEstoque(IdSelecionado(), txtQtdEstoque.Text);
                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnEtiqueta_Click(object sender, EventArgs e)
        {
            try
            {
                MessageBox.Show(_controller.Etiqueta(IdSelecionado()), "Etiqueta", MessageBoxButtons.OK, MessageBoxIcon.Information);
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }
    }
}
Nota
Como o grid agora recebe ViewModel, o DataBoundItem não é mais Produto. Por isso pegamos o Id e pedimos tudo ao controller.

Passo 6 — Refatorar FrmVendaSimples para usar Controller + ViewModel no Combo

A tela de venda não deve acessar o repositório diretamente. Ela usa ProdutoController para carregar o combo e VendaController para calcular/cupom.

Arquivo: Views/FrmVendaSimples.cs (ideia base)
using System;
using System.Linq;
using System.Windows.Forms;
using LanchoneteApp.Controllers;
using LanchoneteApp.Data;
using LanchoneteApp.ViewModels;

namespace LanchoneteApp.Views
{
    public partial class FrmVendaSimples : Form
    {
        private readonly ProdutoController _produtoController;
        private readonly VendaController _vendaController;

        public FrmVendaSimples(ProdutoRepository repo)
        {
            InitializeComponent();
            _produtoController = new ProdutoController(repo);
            _vendaController = new VendaController(repo);

            CarregarProdutos();
            lblResultado.Text = "Total: R$ 0,00";
        }

        private void CarregarProdutos()
        {
            var lista = _produtoController.ListarParaCombo();
            cboProduto.DataSource = lista;
            cboProduto.DisplayMember = "Texto";
            cboProduto.ValueMember = "Id";
        }

        private int IdSelecionado() => (int)(cboProduto.SelectedValue ?? 0);

        private void btnCalcular_Click(object sender, EventArgs e)
        {
            try
            {
                int id = IdSelecionado();
                decimal total = _vendaController.CalcularTotal(id, txtQtd.Text, txtDesconto.Text);
                lblResultado.Text = $"Total: {total:C}";
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnCupom_Click(object sender, EventArgs e)
        {
            try
            {
                int id = IdSelecionado();
                string cupom = _vendaController.GerarCupom(id, txtQtd.Text, txtDesconto.Text);
                MessageBox.Show(cupom, "Cupom", MessageBoxButtons.OK, MessageBoxIcon.Information);
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }
    }
}
Crie o botão btnCupom no Designer (Text: “Gerar Cupom”).

3) Entrega 2 (Bimestre 2) — MVC + Produtos + Vendas

Avaliação

Esta entrega integra: herança, polimorfismo, abstratas/interfaces e MVC (adaptado ao WinForms). O foco é organização + funcionalidade.

Requisitos mínimos (checklist do professor)

  • Estrutura: pastas Models, Data, Services, Controllers, ViewModels, Views, Utils.
  • Model robusto: Produto abstrato, com Lanche e Bebida, interfaces IEtiquetavel e IPrecificavel.
  • Controllers funcionando: ProdutoController e VendaController.
  • Views refatoradas: FrmProdutos e FrmVendaSimples usam Controllers (não usam Service diretamente).
  • Venda simples: calcular total + gerar cupom.
  • Relatório: estoque baixo (ou resumo por tipo) acessível via menu.
  • Repositório compartilhado entre telas via FrmMenu.

O que entregar

  1. .zip da solução completa.
  2. README.txt com:
    • Nome, turma, data
    • Arquitetura (pastas) e fluxo MVC (1 parágrafo)
    • Prints/vídeo: produtos, venda, cupom e relatório
  3. Evidências (prints ou vídeo curto):
    • Cadastro de Lanche e Bebida
    • Venda simples com cálculo diferente por tipo
    • Botão Cupom
    • Relatório (estoque baixo)
    • Uma validação de erro (ex.: desconto inválido, volume vazio)
Erros comuns
  • Form com validação complexa (deveria estar no Service/Controller)
  • Controller acessando UI diretamente (controller não deve conhecer controles)
  • Mais de uma lista de produtos (quebra consistência)

Bônus (opcional)

  • Implementar Combo (Cap. 07) e incluir no cadastro por tipo.
  • Adicionar um relatório “Resumo por tipo” (total de lanches/bebidas em estoque).
  • Adicionar filtro por nome no grid (controller retorna lista filtrada).

4) Atividades práticas (opcionais)

Atividade A — Controller de relatório

Atividade B — ViewModel de cupom
  • Crie CupomVM (texto + total + data/hora).
  • VendaController retorna o VM e a View só exibe.
Atividade C — Testes manuais (roteiro)
