Namespaces, Organização do Projeto e Mini-Entrega (B1)

Neste capítulo você vai aprender a organizar seu projeto: usar namespaces para evitar conflitos, separar arquivos em pastas coerentes e criar uma estrutura simples em camadas (Models, Data, Services, Views). Ao final, você fará a Entrega 1 integrando tudo que foi visto no 1º bimestre.

Roteiro Passo a passo Entrega 1

Objetivos de aprendizagem

  • Relacionar pastas e namespaces (organização do código).
  • Aplicar uma estrutura simples por camadas: Models, Data, Services, Views, Utils.
  • Refatorar o projeto para usar um repositório em memória e um serviço (preparação para DAO no futuro).

Projeto organizado = manutenção mais fácil, menos bugs e base pronta para MVC/DAO/BD depois.

1) Parte teórica (conceitos essenciais)

1.1 O que é namespace?

Um namespace é um “sobrenome” do código. Ele agrupa classes relacionadas e evita conflito quando existem duas classes com o mesmo nome. Exemplo: você pode ter LanchoneteApp.Models.Produto e, em outro contexto, OutraBiblioteca.Models.Produto. O namespace deixa claro qual Produto você quer usar.

1.2 using: como você “importa” um namespace

O using permite usar classes de um namespace sem escrever o nome completo toda hora. Ex.: com using LanchoneteApp.Models; você pode escrever Produto em vez de LanchoneteApp.Models.Produto. Se houver conflito de nomes, você pode usar o nome completo para resolver.

1.3 Pastas x Namespaces (o que tem a ver?)

Pastas organizam arquivos no seu projeto (visual). Namespaces organizam nomes no código (lógico). O Visual Studio normalmente sugere um namespace baseado no nome do projeto e na pasta, mas isso pode ser ajustado. Uma boa prática é manter pastas e namespaces alinhados.

1.4 Organização por camadas (simples e realista)

Para deixar o projeto mais claro, vamos separar responsabilidades: Models (entidades como Produto), Data (armazenamento: lista em memória agora, DAO depois), Services (regras de negócio), Views (forms/telas) e Utils (ajudas como parse). Isso prepara o terreno para MVC e DAO no futuro.

Resumo em 1 frase
Pastas + namespaces organizados = menos confusão, código mais limpo e evolução mais fácil (especialmente quando o projeto cresce).

2) Passo a passo (refatoração de organização)

Vamos reorganizar o projeto criando as pastas e classes necessárias e refatorando o formulário para usar um serviço. Sem banco ainda: o repositório será em memória, mas estruturado como se fosse o “Data Access” futuro.

Passo 1 — Criar pastas (camadas) e ajustar namespaces

  1. No projeto LanchoneteApp, crie as pastas: Models, Data, Services, Views, Utils.
  2. Mova FrmProdutos.cs para a pasta Views (arraste no Solution Explorer).

Passo 2 — Criar o repositório em memória (Data)

O repositório será responsável por guardar e fornecer produtos. Ele encapsula a lista interna. No futuro, você poderá substituir o conteúdo por um DAO com MySQL sem mudar tanto o resto do sistema.

  1. Crie uma classe em Data chamada ProdutoRepository.cs.
  2. Use o código abaixo.
Arquivo: Data/ProdutoRepository.cs
using System;
using System.Collections.Generic;
using System.Linq;
using LanchoneteApp.Models;

namespace LanchoneteApp.Data
{
    public class ProdutoRepository
    {
        private readonly List<Produto> _dados = new();

        public IReadOnlyList<Produto> GetAll() => _dados;

        public Produto? FindById(int id) => _dados.FirstOrDefault(p => p.Id == id);

        public void Add(Produto produto)
        {
            if (FindById(produto.Id) != null)
                throw new InvalidOperationException("Já existe um produto com esse ID.");

            _dados.Add(produto);
        }

        public bool Remove(int id)
        {
            var p = FindById(id);
            if (p == null) return false;
            _dados.Remove(p);
            return true;
        }

        public List<Produto> GetEstoqueBaixo(int limite = 3)
        {
            return _dados.Where(p => p.Estoque <= limite).ToList();
        }

        // Para testes iniciais
        public void SeedBasico()
        {
            if (_dados.Count > 0) return;
            _dados.Add(new Produto(1, "X-Burger", 18.50m, 5));
            _dados.Add(new Produto(2, "Batata Frita", 12.00m, 2));
            _dados.Add(new Produto(3, "Refrigerante Cola", 7.00m, 12));
        }
    }
}
Onde entra namespace aqui?
Perceba o namespace LanchoneteApp.Data. Agora você tem uma área do projeto dedicada a dados.

Passo 3 — Criar o serviço (Services) para regras e ações

O serviço coordena regras e usa o repositório. Ele vira o “lugar certo” para decisões de negócio. Ex.: como cadastrar produto, quando bloquear, como ajustar estoque etc.

  1. Crie uma classe em Services chamada ProdutoService.cs.
  2. Use o código abaixo.
Arquivo: Services/ProdutoService.cs
using System;
using System.Globalization;
using System.Linq;
using LanchoneteApp.Data;
using LanchoneteApp.Models;

namespace LanchoneteApp.Services
{
    public class ProdutoService
    {
        private readonly ProdutoRepository _repo;

        public ProdutoService(ProdutoRepository repo)
        {
            _repo = repo;
        }

        public Produto CriarProduto(string? idTexto, string nome, string precoTexto, string estoqueTexto)
        {
            nome = (nome ?? "").Trim();
            if (string.IsNullOrWhiteSpace(nome))
                throw new ArgumentException("Informe o nome do produto.");

            var cultura = new CultureInfo("pt-BR");
            if (!decimal.TryParse(precoTexto, NumberStyles.Any, cultura, out decimal preco))
                throw new ArgumentException("Preço inválido. Ex.: 9,50");

            int estoque = 0;
            if (!string.IsNullOrWhiteSpace(estoqueTexto))
            {
                if (!int.TryParse(estoqueTexto, out estoque))
                    throw new ArgumentException("Estoque inválido.");
            }

            Produto novo;

            // ID opcional: se vazio, usa construtor com ID automático
            if (string.IsNullOrWhiteSpace(idTexto))
            {
                novo = new Produto(nome, preco, estoque);
            }
            else
            {
                if (!int.TryParse(idTexto, out int id))
                    throw new ArgumentException("ID inválido.");

                if (_repo.FindById(id) != null)
                    throw new InvalidOperationException("Já existe um produto com esse ID.");

                novo = new Produto(id, nome, preco, estoque);
            }

            _repo.Add(novo);
            return novo;
        }

        public void AlterarPreco(int id, string novoPrecoTexto)
        {
            var cultura = new CultureInfo("pt-BR");
            if (!decimal.TryParse(novoPrecoTexto, NumberStyles.Any, cultura, out decimal novoPreco))
                throw new ArgumentException("Novo preço inválido.");

            var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");
            p.AlterarPreco(novoPreco);
        }

        public void ReporEstoque(int id, string qtdTexto)
        {
            if (!int.TryParse(qtdTexto, out int qtd))
                throw new ArgumentException("Quantidade inválida.");

            var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");
            p.ReporEstoque(qtd);
        }

        public void BaixarEstoque(int id, string qtdTexto)
        {
            if (!int.TryParse(qtdTexto, out int qtd))
                throw new ArgumentException("Quantidade inválida.");

            var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");
            p.BaixarEstoque(qtd);
        }

        public decimal TestarSubtotal(int id, string qtdTexto, string? descontoTexto)
        {
            if (!int.TryParse(qtdTexto, out int qtd))
                throw new ArgumentException("Quantidade inválida.");

            var p = _repo.FindById(id) ?? throw new InvalidOperationException("Produto não encontrado.");

            if (string.IsNullOrWhiteSpace(descontoTexto))
                return p.CalcularSubtotal(qtd);

            var cultura = new CultureInfo("pt-BR");
            if (!decimal.TryParse(descontoTexto, NumberStyles.Any, cultura, out decimal desc))
                throw new ArgumentException("Desconto inválido.");

            return p.CalcularSubtotal(qtd, desc);
        }

        public object ListarParaGrid() => _repo.GetAll().ToList();
        public object EstoqueBaixo(int limite = 3) => _repo.GetEstoqueBaixo(limite);
    }
}
Benefício real
O Form fica mais simples. As regras ficam no serviço/modelo. Isso é um passo importante para MVC e DAO no futuro.

Passo 4 — Atualizar o formulário (Views) para usar o serviço

  1. Abra Views/FrmProdutos.cs.
  2. No topo, ajuste os using para apontar para os novos namespaces.
  3. Substitua o uso da lista _produtos por ProdutoRepository + ProdutoService.
Arquivo: Views/FrmProdutos.cs (estrutura-base após refatoração)
using System;
using System.Windows.Forms;
using LanchoneteApp.Data;
using LanchoneteApp.Models;
using LanchoneteApp.Services;

namespace LanchoneteApp.Views
{
    public partial class FrmProdutos : Form
    {
        private readonly ProdutoRepository _repo;
        private readonly ProdutoService _service;

        public FrmProdutos(ProdutoRepository repo)
        {
            InitializeComponent();

            _repo = repo;
            _service = new ProdutoService(_repo);

            dgvProdutos.AutoGenerateColumns = true;
            dgvProdutos.ReadOnly = true;
            dgvProdutos.AllowUserToAddRows = false;

            _repo.SeedBasico();
            AtualizarGrid();
        }

        private int IdSelecionado()
        {
            if (dgvProdutos.CurrentRow?.DataBoundItem is Produto p)
                return p.Id;
            throw new InvalidOperationException("Selecione um produto no grid.");
        }

        private void btnAdicionar_Click(object sender, EventArgs e)
        {
            try
            {
                _service.CriarProduto(txtId.Text, txtNome.Text, txtPreco.Text, txtEstoque.Text);
                AtualizarGrid();

                txtId.Clear(); txtNome.Clear(); txtPreco.Clear(); txtEstoque.Clear();
                txtNome.Focus();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnAlterarPreco_Click(object sender, EventArgs e)
        {
            try
            {
                _service.AlterarPreco(IdSelecionado(), txtNovoPreco.Text);
                AtualizarGrid();
                txtNovoPreco.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnRepor_Click(object sender, EventArgs e)
        {
            try
            {
                _service.ReporEstoque(IdSelecionado(), txtQtdEstoque.Text);
                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnBaixar_Click(object sender, EventArgs e)
        {
            try
            {
                _service.BaixarEstoque(IdSelecionado(), txtQtdEstoque.Text);
                AtualizarGrid();
                txtQtdEstoque.Clear();
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void btnTestarSubtotal_Click(object sender, EventArgs e)
        {
            try
            {
                decimal total = _service.TestarSubtotal(IdSelecionado(), txtQtdTeste.Text, txtDescontoTeste.Text);
                MessageBox.Show($"Subtotal: {total:C}", "Subtotal", MessageBoxButtons.OK, MessageBoxIcon.Information);
            }
            catch (Exception ex)
            {
                MessageBox.Show(ex.Message, "Atenção", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }

        private void AtualizarGrid()
        {
            dgvProdutos.DataSource = null;
            dgvProdutos.DataSource = _service.ListarParaGrid();
        }
    }
}
Importante
Perceba que o construtor do Form agora recebe o ProdutoRepository. Isso evita “listas soltas” e centraliza os dados.

Passo 5 — Criar uma tela inicial (Menu Principal) e um relatório simples

Para fechar o bimestre com algo integrado, vamos criar: (1) um FrmMenu como tela inicial e (2) um FrmEstoqueBaixo que mostra produtos com estoque <= 3.

  1. Crie um novo Form em Views: FrmMenu.cs.
  2. No Designer, adicione um MenuStrip com itens:
  • Cadastros → Produtos
  • Relatórios → Estoque baixo
  • Ajuda → Sobre

Agora crie o Form do relatório:

  1. Crie um Form em Views: FrmEstoqueBaixo.cs.
  2. Adicione um DataGridView chamado dgvEstoqueBaixo e um TextBox txtLimite (valor padrão 3) + botão btnAtualizar.
Arquivo: Views/FrmEstoqueBaixo.cs (carregar relatório)
using System;
using System.Windows.Forms;
using LanchoneteApp.Data;
using LanchoneteApp.Services;

namespace LanchoneteApp.Views
{
    public partial class FrmEstoqueBaixo : Form
    {
        private readonly ProdutoService _service;

        public FrmEstoqueBaixo(ProdutoRepository repo)
        {
            InitializeComponent();
            _service = new ProdutoService(repo);
            dgvEstoqueBaixo.AutoGenerateColumns = true;
            dgvEstoqueBaixo.ReadOnly = true;
            dgvEstoqueBaixo.AllowUserToAddRows = false;

            txtLimite.Text = "3";
            Atualizar();
        }

        private void btnAtualizar_Click(object sender, EventArgs e)
        {
            Atualizar();
        }

        private void Atualizar()
        {
            int limite = 3;
            int.TryParse(txtLimite.Text, out limite);
            dgvEstoqueBaixo.DataSource = null;
            dgvEstoqueBaixo.DataSource = _service.EstoqueBaixo(limite);
        }
    }
}
Arquivo: Views/FrmMenu.cs (abrir telas com o mesmo repositório)

3) Entrega 1 (Bimestre 1) — Módulo Produtos v1

Avaliação

Esta entrega integra: POO (classe/objeto), encapsulamento, construtores/sobrecargas e organização com namespaces. O objetivo é entregar um projeto funcional e bem organizado.

Requisitos mínimos (checklist do professor)

  • Estrutura: pastas e namespaces alinhados: Models, Data, Services, Views.
  • Produto encapsulado: setters privados + validações + métodos de ajuste (preço/estoque).
  • Construtores: permitir criação com ID manual e ID automático (cadastro rápido).
  • Form Menu como tela inicial com MenuStrip abrindo:
    • FrmProdutos (cadastro/manutenção + teste de subtotal)
    • FrmEstoqueBaixo (relatório por limite)
  • Repositório único compartilhado entre as telas (mesmos dados em todas as telas).

O que entregar

  1. Arquivo .zip da solução (LanchoneteApp).
  2. Prints (ou vídeo curto) mostrando:
    • Menu inicial
    • Cadastro rápido (ID vazio) funcionando
    • Relatório de estoque baixo
    • Um caso de erro tratado (ex.: desconto inválido, baixar mais que estoque)
  3. Um arquivo README.txt (ou comentário no envio) com:
    • Seu nome e turma
    • O que foi feito
    • Onde aparecem os 4 pilares deste bimestre (classe/objeto, encapsulamento, construtores, namespaces)
Dica de ouro
Se você organizar bem agora, o resto do ano (MVC, GUI avançada e MySQL/DAO) fica muito mais fácil.

Sugestões de extensão (opcional/bônus)

  • Adicionar botão Remover produto (usando repository).
