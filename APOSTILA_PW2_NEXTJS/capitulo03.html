Capítulo 3 — Listas, Condicionais e Grid do Bootstrap (Catálogo com Filtro por Categoria)

Carga: 2 aulas × 140 min

Projeto-base: Sistema da Lanchonete (Admin) iniciado nos Cap. 1–2

Stack fixa: Next.js (App Router) + React, Bootstrap 5 + Bootstrap Icons, Git

Resultados de aprendizagem deste capítulo:

  • Renderizar listas em React com map e chaves (keys) estáveis.
  • Aplicar renderização condicional (&&, ternário, early return).
  • Construir um catálogo responsivo com Grid do Bootstrap (container/row/col).
  • Implementar filtros de categoria (todas, bebidas, lanches, sobremesas) e exibir/ocultar esgotados.
  • Melhorar a experiência com badges, estados vazios e acessibilidade básica.

🧠 Parte Teórica (explicação do conteúdo)

1) Renderização de listas e keys

Em React, quase toda interface real envolve listas: produtos, categorias, pedidos, mensagens, etc. Para transformar um array em elementos na tela, usamos map. O map percorre cada item do array e devolve um novo array com JSX. É por isso que você vê o padrão: lista.map(item => <Componente />).

Porém, quando renderizamos listas, o React precisa de um jeito de identificar cada item entre renderizações. Imagine que você aplicou um filtro e a lista mudou de ordem, ou que um item foi ocultado por estar esgotado. Se o React não souber qual “card” corresponde a qual item, ele pode reaproveitar o DOM errado e causar efeitos estranhos (por exemplo, um badge ou foco “pular” para outro item).

É exatamente para isso que existe a key. A key deve ser:

  • Única dentro daquela lista (nenhum item pode repetir a mesma key).
  • Estável (não deve mudar quando você filtra, ordena ou altera a lista).
  • Semântica (idealmente, um id do produto, e não o índice do array).

Por que evitar o índice do array? Porque o índice muda quando a lista muda. Se você ordena por “destaque” ou esconde itens indisponíveis, os índices mudam e o React pode confundir itens, reaproveitando elementos errados.

Exemplo aplicado no Passo a Passo

No passo a passo, ao renderizar os cards em /cardapio você faz listaFiltrada.map((item) => ... key={item.id} ...). Essa key baseada em id é o que garante que, ao trocar filtros ou ordenar por destaque/nome, o React atualize cada card corretamente (Etapa 4).

2) Renderização condicional em JSX

A interface não é estática: ela muda conforme dados e interações. Em React, você controla o que aparece na tela usando renderização condicional. Existem três formas muito comuns, cada uma com um propósito:

  • Curto-circuito (&&): quando você quer mostrar algo apenas se a condição for verdadeira. Ex.: mostrar um badge “destaque” somente se destaque === true.
  • Ternário: quando há dois caminhos (A ou B). Ex.: se a lista estiver vazia, mostrar “Nenhum item encontrado”; se não, renderizar o grid de cards.
  • Early return: quando faz sentido encerrar o componente cedo para simplificar a leitura. Ex.: se estiver carregando, retornar um spinner; se houver erro, retornar um alerta. (Neste capítulo usamos mais o ternário para o “estado vazio”, mas o conceito é o mesmo.)

Um detalhe importante neste capítulo: como agora o catálogo tem itens de categorias diferentes, alguns campos são opcionais (por exemplo, bebida tem volume, lanche/sobremesa têm descricao). Isso exige condicional para não renderizar “buracos” na UI: se não existe descrição, não mostramos o parágrafo de descrição.

Além disso, renderização condicional é fundamental para uma boa UX: quando um filtro não encontra nada, você não deve deixar a tela em branco. Você deve mostrar um empty state (mensagem + ação para resolver, como “Limpar filtros”).

Exemplo aplicado no Passo a Passo

Você aplica renderização condicional em dois pontos principais: (1) no ProductCard, ao exibir volume e descricao somente quando existirem (Etapa 2); e (2) na página /cardapio, usando ternário para renderizar o estado vazio quando listaFiltrada.length === 0 e, caso contrário, renderizar o grid (Etapa 4).

3) Grid do Bootstrap (responsividade)

Uma lista pode estar correta do ponto de vista lógico, mas se ela não estiver bem organizada visualmente, a experiência do usuário fica ruim. O Grid do Bootstrap resolve isso com uma estrutura simples: .container (limita largura e dá alinhamento) → .row (linha) → .col-* (colunas).

O ponto-chave são os breakpoints: você define quantas colunas aparecem dependendo da largura da tela. Assim, o mesmo catálogo pode virar uma coluna no celular, duas colunas em tablet e três colunas no desktop, sem precisar escrever CSS manual.

Exemplo clássico do capítulo: col-12 col-sm-6 col-lg-4 significa:

  • col-12: no mobile, o card ocupa a linha inteira (1 coluna).
  • col-sm-6: a partir de “sm”, dois cards por linha (2 colunas).
  • col-lg-4: a partir de “lg”, três cards por linha (3 colunas).

Para espaçamento entre cards, usamos gutters como g-4. Isso evita que os cards fiquem “colados” e melhora a leitura.

Exemplo aplicado no Passo a Passo

Na Etapa 4, ao renderizar a lista filtrada, cada item vai dentro de <div className="col-12 col-sm-6 col-lg-4"> e todos ficam dentro de uma row g-4. Isso garante que o catálogo fique responsivo automaticamente.

4) Componentização, reuso e “fonte de verdade”

Conforme a aplicação cresce, o risco é duplicar código: um card para bebidas, outro para lanches, outro para sobremesas. Isso torna a manutenção difícil (se mudar o layout, você precisa alterar em vários lugares). A solução é componentizar e criar peças reutilizáveis.

Neste capítulo, dois componentes são essenciais:

  • ProductCard: representa um item do catálogo e concentra o layout do card.
  • CategoryFilters: concentra a UI e acessibilidade do filtro (grupo de botões + switch).

Outro conceito importante aqui é não duplicar a “fonte de verdade”. A lista filtrada e ordenada é um exemplo de estado derivado: ela depende do dataset (itens) e de estados como categoria e mostrarEsgotados. Em vez de salvar a lista em useState (o que pode gerar inconsistências), você calcula a lista no render usando filter e sort. O código usa useMemo para evitar recalcular desnecessariamente quando nada mudou.

A regra prática para o aluno: se um valor pode ser calculado a partir de outros valores, prefira calcular (em vez de criar um estado separado). Isso reduz bugs.

Exemplo aplicado no Passo a Passo

Na Etapa 4, você mantém apenas os estados “de controle” (categoria e mostrarEsgotados) e calcula listaFiltrada com useMemo a partir desses estados e do dataset itens. Isso é aplicar a ideia de “estado derivado sem duplicação”.

5) Acessibilidade mínima (a11y) e UX do catálogo

Acessibilidade não é “extra”: ela melhora a experiência para todos, inclusive em situações comuns como uso por teclado, telas pequenas e leitores de tela. Neste capítulo, a acessibilidade aparece principalmente nos controles de filtro e no feedback quando não há resultados.

Boas práticas aplicáveis aqui:

  • Use botão de verdade: para ações (filtrar, alternar), use <button> e não <a href="#">. Isso garante comportamento correto para teclado e leitores.
  • Estado visível e anunciado: em botões “toggle”, use aria-pressed para indicar ativo/inativo. Isso ajuda leitores de tela a entender o estado atual.
  • Feedback quando não há itens: o empty state evita confusão (“sumiu tudo?”) e oferece uma ação para recuperar (limpar filtros).
  • Rótulos corretos: no switch “Mostrar esgotados”, use label ligado ao id para permitir clique no texto e leitura correta.

UX (experiência do usuário) também inclui microdetalhes úteis: badges de contagem nos filtros orientam escolhas; ordenar por destaque melhora descoberta; e manter o layout consistente em todas as categorias dá sensação de produto final.

Exemplo aplicado no Passo a Passo

Na Etapa 3, o filtro usa role="group" e aria-pressed em cada botão para indicar qual categoria está ativa, e o switch “Mostrar esgotados” usa label htmlFor. Na Etapa 4, o empty state mostra uma mensagem e um botão “Limpar filtros”, evitando uma tela vazia sem explicação.

const categoriaBadgeClass = (categoria) => {

'use client';

const labels = {
todas: 'Todas',

};

export default function CategoryFilters({
categorias = ['todas', 'bebida', 'lanche', 'sobremesa'],
selecionada = 'todas',
onSelecionar,
contagem = {}, // ex.: { bebida: 3, lanche: 3, sobremesa: 3, todas: 9 }
mostrarEsgotados = false,
onToggleEsgotados,
}) {
return (

<div className="btn-group" role="group" aria-label="Filtro por categoria">

const count = contagem?.[cat] ?? null;
return (
<button
key={cat}
type="button"
className={`btn btn-outline-primary ${active ? 'active' : ''}`}
aria-pressed={active}
onClick={() => onSelecionar?.(cat)}
title={`Filtrar por ${labels[cat] ?? cat}`}
>
{labels[cat] ?? cat}
{typeof count === 'number' && (
<span className="badge text-bg-light ms-2">{count}</span>

</button>
);
})}
</div>

<div className="form-check form-switch ms-md-3">
<input
className="form-check-input"
type="checkbox"
id="mostrarEsgotados"
checked={mostrarEsgotados}
onChange={(e) => onToggleEsgotados?.(e.target.checked)}
/>
<label className="form-check-label" htmlFor="mostrarEsgotados">
Mostrar esgotados
</label>
</div>
</div>
);

4) Refatorar a página /cardapio para usar filtros

Edite app/cardapio/page.jsx:

JSX

// app/cardapio/page.jsx
'use client';

import { useEffect, useMemo, useState } from 'react';
import { itens } from '@/data/itens';
import ProductCard from '@/components/ProductCard';
import FloatingCartButton from '@/components/FloatingCartButton';
import CategoryFilters from '@/components/CategoryFilters';

export default function CardapioPage() {
const [cartCount, setCartCount] = useState(0);
const [alerta, setAlerta] = useState(null); // { tipo: 'success' | 'info' | 'danger', texto: string }
const [categoria, setCategoria] = useState('todas');
const [mostrarEsgotados, setMostrarEsgotados] = useState(false);

// Contagem por categoria (para badges nos filtros)
const contagem = useMemo(() => {
const base = { todas: itens.length, bebida: 0, lanche: 0, sobremesa: 0 };
for (const it of itens) base[it.categoria] = (base[it.categoria] || 0) + 1;
return base;
}, []);

// Lista filtrada e ordenada (derived state calculado no render)
const listaFiltrada = useMemo(() => {
let lista = itens.filter((it) => categoria === 'todas' || it.categoria === categoria);
if (!mostrarEsgotados) {
lista = lista.filter((it) => it.disponivel);
}
// Ordena destaque primeiro e depois por nome
return lista.sort((a, b) => {
if (a.destaque !== b.destaque) return a.destaque ? -1 : 1;
return a.nome.localeCompare(b.nome, 'pt-BR');
});
}, [categoria, mostrarEsgotados]);

function handleAdd(item) {
setCartCount((prev) => prev + 1);
setAlerta({ tipo: 'success', texto: `${item.nome} adicionado ao carrinho!` });
}

useEffect(() => {
if (!alerta) return;
const id = setTimeout(() => setAlerta(null), 1800);
return () => clearTimeout(id);
}, [alerta]);

return (
<>
<header className="mb-3">
<h1 className="h3 mb-1">Cardápio</h1>
<p className="text-muted">Filtre por categoria e gerencie seu pedido.</p>
</header>

{alerta && (
<div className={`alert alert-${alerta.tipo} alert-dismissible fade show`} role="alert">
<i className="bi bi-check-circle me-2"></i>
{alerta.texto}
<button
type="button"
className="btn-close"
onClick={() => setAlerta(null)}
aria-label="Fechar"
></button>
</div>
)}

<CategoryFilters
selecionada={categoria}
onSelecionar={setCategoria}
contagem={contagem}
mostrarEsgotados={mostrarEsgotados}
onToggleEsgotados={setMostrarEsgotados}
/>

{/* Estado vazio */}
{listaFiltrada.length === 0 ? (
<div className="text-center text-muted my-5">
<i className="bi bi-search mb-3" style={{ fontSize: '2rem', display: 'block' }}></i>
<p className="mb-2">Nenhum item encontrado com os filtros atuais.</p>
<button
className="btn btn-outline-secondary btn-sm"
onClick={() => {
setCategoria('todas');
setMostrarEsgotados(false);
}}
>
Limpar filtros
</button>
</div>
) : (
<div className="row g-4">
{listaFiltrada.map((item) => (
<div className="col-12 col-sm-6 col-lg-4" key={item.id}>
<ProductCard item={item} onAdd={handleAdd} />
</div>
))}
</div>
)}

<FloatingCartButton
count={cartCount}
onClick={() =>
setAlerta({ tipo: 'info', texto: 'Carrinho: recurso em desenvolvimento.' })
}
/>
</>
);
}
