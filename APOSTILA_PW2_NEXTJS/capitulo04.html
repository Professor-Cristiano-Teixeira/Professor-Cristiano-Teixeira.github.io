🧠 Parte Teórica (explicação do conteúdo)

1) App Router (roteamento por arquivos/pastas)

O Next.js com App Router (pasta app/) usa um modelo chamado file-based routing: a URL do site nasce diretamente da estrutura de pastas e arquivos. Isso reduz configurações manuais e deixa o projeto mais fácil de entender, porque você “enxerga” as rotas olhando para as pastas.

A regra principal é: dentro de app/, uma pasta representa um segmento da rota, e o arquivo page.jsx define o conteúdo daquela rota. Por exemplo, app/cardapio/page.jsx vira /cardapio. Esse padrão é importante porque, conforme o sistema cresce, você adiciona páginas apenas criando arquivos no lugar certo.

Além do page.jsx, o App Router introduz arquivos especiais que ajudam a organizar comportamento por rota:

  • layout.jsx: estrutura compartilhada por um conjunto de páginas (ex.: sidebar do admin).
  • loading.jsx: fallback enquanto uma rota carrega (melhora UX).
  • not-found.jsx: página 404 contextual (por escopo).
  • error.jsx: error boundary da rota (captura erros naquele segmento).

Outro recurso do App Router é a possibilidade de definir metadados (título/descrição) no layout ou na página com export const metadata. Isso melhora organização e SEO, além de deixar cada área (como /admin) com identidade própria.

Exemplo aplicado no Passo a Passo

No passo a passo, você cria app/favoritos/page.jsx para ter a rota /favoritos (Etapa 2) e cria app/admin/layout.jsx para que todas as páginas dentro de /admin herdem a sidebar (Etapa 5). Isso é file-based routing + layout aninhado funcionando na prática.

2) Navegação SPA com Link e usePathname

Em aplicações modernas, queremos navegação rápida e sem recarregar a página inteira. O Next.js oferece isso com o componente Link. Ele faz navegação no estilo SPA: quando você clica, o Next troca a rota e carrega somente o necessário, preservando parte do estado e evitando o “reload completo” que acontece com um <a> tradicional.

Para menus, um detalhe de UX importante é mostrar qual página está ativa. No App Router, você consegue ler a rota atual com usePathname() (hook do Next). Como hooks rodam no cliente, isso exige que o componente seja um Client Component. Depois, você compara o pathname com o href do link e aplica uma classe como active. O aluno aprende aqui um padrão muito usado em sistemas: estado visual baseado na rota atual.

Um cuidado comum em menus: quando você tem rotas “filhas” (ex.: /cardapio e /cardapio/[id]), faz sentido marcar o menu como ativo também nas páginas internas. Por isso, o exemplo usa uma regra de “começa com” (pathname.startsWith) para garantir que o link “Cardápio” continue ativo no detalhe do item.

Exemplo aplicado no Passo a Passo

Na Etapa 1, você altera o Header para usar usePathname() e aplica active no link correto. Depois, ao navegar para /cardapio/xburger, o link “Cardápio” continua marcado como ativo porque o helper isActive considera subrotas.

3) Rotas dinâmicas ([id])

Rotas dinâmicas existem quando parte da URL varia. Em um catálogo, isso é natural: cada item tem um id, então a URL pode ser /cardapio/xburger, /cardapio/petit-gateau, etc. No App Router, você cria isso colocando o segmento entre colchetes: [id]. Assim, app/cardapio/[id]/page.jsx vira qualquer URL do tipo /cardapio/<alguma-coisa>.

O valor do parâmetro chega no componente da página via params. Como o arquivo de detalhe, por padrão, é um Server Component, você pode buscar dados ali de forma direta (neste capítulo, no dataset). A lógica típica é:

  1. Ler params.id.
  2. Buscar o item no dataset.
  3. Se não existir, chamar notFound().
  4. Se existir, renderizar o detalhe.

Isso ensina um raciocínio essencial para APIs e banco de dados mais tarde: todo acesso por ID pode falhar, então sua UI precisa estar preparada para o caso “não encontrado”.

Exemplo aplicado no Passo a Passo

Na Etapa 4, você cria app/cardapio/[id]/page.jsx e usa const item = itens.find(...). Se o item não existir, chama notFound() e o Next renderiza o not-found.jsx do cardápio. Isso conecta diretamente “rota dinâmica” com “tratamento de recurso inexistente”.

4) Estados de carregamento e erro (loading/not-found/error)

Em aplicações reais, nem tudo é instantâneo: páginas podem depender de dados e demorar. Para evitar uma tela “travada”, o App Router permite criar um loading por rota. Quando a rota está carregando, o Next renderiza loading.jsx automaticamente como fallback. Isso melhora UX porque o usuário vê feedback imediato.

Para o caso em que a rota ou recurso não existe, existe o not-found. Você pode ter um not-found.jsx global (em app/) ou específico (por exemplo, dentro de app/cardapio). O Next escolhe o mais específico disponível para aquele “escopo” de rota.

Já error.jsx funciona como um error boundary da rota: se ocorrer um erro durante a renderização daquele segmento, o Next mostra o error.jsx em vez de quebrar tudo. Isso é útil quando você vai integrar APIs (Cap. 7) e quer uma tela amigável caso o fetch falhe.

Exemplo aplicado no Passo a Passo

Na Etapa 4, você cria app/cardapio/[id]/loading.jsx com placeholders (o usuário vê “carregando” sem tela vazia) e cria app/cardapio/not-found.jsx para o 404 contextual. Opcionalmente, você pode criar app/cardapio/error.jsx como atividade extra para capturar erros naquela área.

5) Layouts aninhados (ex.: /admin)

Um sistema costuma ter áreas com aparência diferente: o público vê o cardápio; o administrador vê dashboards e menus de gestão. Se você repetir sidebar e estrutura em todas as páginas do admin, o código fica duplicado. A solução do App Router são os layouts aninhados.

Quando você cria app/admin/layout.jsx, esse layout passa a envolver todas as páginas dentro de /admin. Isso garante consistência: a sidebar aparece em /admin, /admin/itens e /admin/config sem duplicação. Além disso, se um dia você quiser mudar o menu lateral, muda uma vez só.

Importante: o layout aninhado não substitui o layout raiz; ele se soma. Ou seja, você continua com o Header/Footer globais (do app/layout.jsx) e, dentro do conteúdo, o admin ganha uma estrutura própria.

Exemplo aplicado no Passo a Passo

Na Etapa 5, você cria app/admin/layout.jsx com aside (sidebar) e renderiza {children} à direita. Em seguida, cria páginas como app/admin/itens/page.jsx. Ao abrir essas páginas, a sidebar aparece automaticamente, provando como layouts aninhados evitam repetição.

JSX

// components/Header.jsx
'use client';

import Link from 'next/link';
import { usePathname } from 'next/navigation';

const isActive = (pathname, href) => {
if (href === '/') return pathname === '/';
// marca como ativo se começa com a rota (ex.: /cardapio e /cardapio/[id])
return pathname === href || pathname.startsWith(href + '/');
};

export default function Header() {
const pathname = usePathname();

const navItem = (href, label) => (
<li className="nav-item">
<Link
className={`nav-link ${isActive(pathname, href) ? 'active' : ''}`}
href={href}
aria-current={isActive(pathname, href) ? 'page' : undefined}
>
{label}
</Link>
</li>
);

return (
<header>
<nav className="navbar navbar-expand-lg navbar-dark bg-dark">
<div className="container">
/
<i className="bi bi-cup-straw"></i>
<span>Lanchonete Admin</span>
</Link>

<button
className="navbar-toggler"
type="button"
data-bs-toggle="collapse"
data-bs-target="#mainNavbar"
aria-controls="mainNavbar"
aria-expanded="false"
aria-label="Alternar navegação"
>
<span className="navbar-toggler-icon"></span>
</button>

<div className="collapse navbar-collapse" id="mainNavbar">
<ul className="navbar-nav ms-auto mb-2 mb-lg-0">
{navItem('/', 'Início')}
{navItem('/cardapio', 'Cardápio')}
{navItem('/favoritos', 'Favoritos')}
{navItem('/admin', 'Administração')}

</header>

2) Favoritos (página + leitura do localStorage)

Vamos criar uma página simples que lê favoritos do localStorage e exibe.

Nota: Se você já tiver implementado o “favoritar” do Cap. 3 (atividade), esta página vai listar os itens salvos. Caso não, você pode simular alguns IDs no localStorage para testar.

Crie app/favoritos/page.jsx:

JSX

// app/favoritos/page.jsx
'use client';

import { useEffect, useMemo, useState } from 'react';
import { itens } from '@/data/itens';
import ProductCard from '@/components/ProductCard';

const STORAGE_KEY = 'favIds';

export default function FavoritosPage() {
const [favIds, setFavIds] = useState([]);

useEffect(() => {
try {
const raw = localStorage.getItem(STORAGE_KEY);
setFavIds(raw ? JSON.parse(raw) : []);
} catch (e) {
console.error('Erro ao ler favoritos:', e);
}
}, []);

const favoritos = useMemo(() => itens.filter((it) => favIds.includes(it.id)), [favIds]);

return (
<>
<header className="mb-3">
<h1 className="h3 mb-1">Favoritos</h1>
<p className="text-muted">Itens marcados como favoritos.</p>
</header>

{favoritos.length === 0 ? (
<div className="text-center text-muted my-5">
<i className="bi bi-heart mb-3" style={{ fontSize: '2rem', display: 'block' }}></i>
<p>Nenhum favorito no momento.</p>
/cardapio
Ver cardápio
</a>
</div>
) : (
<div className="row g-4">
{favoritos.map((item) => (
<div className="col-12 col-sm-6 col-lg-4" key={item.id}>
<ProductCard item={item} />
</div>
))}
</div>
)}
</>
);
}
