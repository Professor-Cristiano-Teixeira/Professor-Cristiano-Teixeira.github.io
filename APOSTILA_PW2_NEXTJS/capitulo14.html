Capítulo 14 — Builds e Releases (Next.js)
Build de produção, .env, otimizações de bundle, fontes/imagens, cache headers e checklist de performance

Carga: 2 aulas × 140 min

Projeto-base: Lanchonete (Cap. 1–13)

Stack fixa: Next.js (App Router) + React, Bootstrap 5 + Bootstrap Icons, Git

Resultados de aprendizagem deste capítulo:

  • Entender o pipeline de build do Next.js e executar a app em modo produção (next build / next start).
  • Configurar variáveis de ambiente com .env.local; entender o que é exposto no cliente (NEXT_PUBLIC_*) e o que fica no servidor.
  • Otimizar bundles com code splitting, dynamic import, next/font e next/image.
  • Configurar cabeçalhos de cache para assets estáticos e revisar checklist de performance (Lighthouse/DevTools).
  • Medir e reduzir o tamanho do bundle usando @next/bundle-analyzer.

🎯 Competências e Habilidades

  • Competências: (2) Aplicar práticas de desenvolvimento de sistemas.
  • Habilidades: 4 (builds, releases, variáveis de ambiente, otimização e versionamento).

📆 Plano de Aula

Aula 1 (140 min) — Teoria + Build/Start + .env

Teoria (35–45 min):

  • Diferenças entre desenvolvimento x produção no Next.js.
  • next build (compilação, minificação, análise estática), next start (servidor).
  • .env.local, .env.development, .env.production; prefixo NEXT_PUBLIC_.
  • Server Components x Client Components e impacto na build.

Prática (85–95 min):

  • Criar .env.local, ler variável no cliente e no servidor (API Route).
  • Rodar build e subir produção local (next start).
  • Conferir logs e respostas HTML no DevTools (Network → Response/TTFB).

Aula 2 (140 min) — Teoria + Otimizações + Analyzer

Teoria (20–30 min):

  • Code splitting e dynamic(); evitar enviar JS desnecessário.
  • Imagens (next/image) e fontes (next/font).
  • Cache headers para assets; prefetch de links; Lighthouse.

Prática (100–110 min):

  • Adicionar @next/bundle-analyzer e medir bundles.
  • Aplicar dynamic import em componentes pesados (Modal/Offcanvas).
  • Trocar fontes externas por next/font e exemplos com next/image.
  • Adicionar headers de cache para estáticos.
  • Rodar Lighthouse e anotar melhorias.

Entrega rápida (10 min): Print do bundle-analyzer e do Lighthouse com 2–3 ações corretivas.

🧠 Parte Teórica (explicação do conteúdo)

1) Dev × Prod no Next.js

  • Dev (next dev): HMR, verificações extras e não minifica tudo.
  • Prod (next build + next start): tree-shaking, minificação, divisão de pacotes e pré-renderização (SSG/SSR conforme o código). O resultado fica em .next/.

2) Variáveis de ambiente

  • .env.local (prioridade, não versionar), .env.development e .env.production (opcionais).
  • Exposição ao cliente: só variáveis com NEXT_PUBLIC_*.
  • Variáveis sem prefixo ficam no servidor (Route Handlers/Server Components).
  • Boas práticas: não colocar segredos em NEXT_PUBLIC_*.

3) Tamanho do bundle e code splitting

  • Menos JS = melhor.
  • Use dynamic(() => import('...')) para carregar sob demanda (Modal/Offcanvas).
  • Evite libs grandes no nível global.

4) Imagens e fontes

  • next/image otimiza, redimensiona e ativa lazy loading.
  • next/font incorpora fontes com subset e reduz CLS.

5) Cache e cabeçalhos

  • Assets estáticos podem ter cache longo (1 ano, immutable).
  • Páginas dinâmicas (SSR) não devem ter cache agressivo; use no-store ou revalidação conforme o caso.

6) Medições

  • DevTools (Network): TTFB, Transfer, Content-Encoding (gzip/br).
  • Lighthouse: Performance / Best Practices / Accessibility / SEO.

🛠️ Passo a Passo — Build de Produção + Otimizações

0) Checagem de scripts

No package.json, confirme (ou adicione):

{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start -p 3000",
    "lint": "next lint"
  }
}

1) Criar .env.local (cliente + servidor)

  1. Crie .env.local (não versionar):

    # Variáveis do cliente (sem segredos)
NEXT_PUBLIC_APP_NAME=Lanchonete Admin
NEXT_PUBLIC_API_BASE=http://localhost:3000

# Variáveis apenas do servidor (simuladas)
ADMIN_SECRETO=nao-colocar-isto-no-cliente

  2. Usar no cliente (ex.: no Header):

    // components/Header.jsx (trecho)
const appName = process.env.NEXT_PUBLIC_APP_NAME || 'Lanchonete Admin';
// usar appName no branding

  3. Usar no servidor (ex.: API Route):

    // app/api/segredo/route.js
import { NextResponse } from 'next/server';

export async function GET() {
  const secreto = process.env.ADMIN_SECRETO ? 'OK' : 'MISSING';
  return NextResponse.json({ status: secreto });
}

    Teste: acesse /api/segredo e confirme { "status": "OK" }.

2) Configurar next.config.mjs (imagens, headers, análise)

Crie/edite next.config.mjs:

/** @type {import('next').NextConfig} */
const nextConfig = {
  reactStrictMode: true,

  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 'images.unsplash.com' },
      { protocol: 'https', hostname: 'picsum.photos' }
    ],
    formats: ['image/avif', 'image/webp']
  },

  async headers() {
    return [
      {
        // cache longo para assets públicos dentro de /public/_static
        source: '/_static/:path*',
        headers: [
          { key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }
        ]
      }
    ];
  }
};

export default nextConfig;

Dica

Crie a pasta public/_static para imagens que não mudam (logos/ícones). Rotas dinâmicas/SSG/SSR mantêm o comportamento padrão.

3) Otimizar Fonte com next/font

No layout, troque fonte externa por next/font/google:

// app/layout.jsx
import { Poppins } from 'next/font/google';

const poppins = Poppins({
  subsets: ['latin'],
  weight: ['400', '600'],
  display: 'swap'
});

export default function RootLayout({ children }) {
  return (
    <html lang="pt-BR">
      <body className={poppins.className}>
        {/* ...Header */}
        {/* ...CartProvider + main */}
        {/* ...Footer, BootstrapClient */}
      </body>
    </html>
  );
}

Benefício: menos requisições externas e menor CLS (melhor Lighthouse).

4) Usar next/image (exemplo simples)

Crie um banner leve na Home:

// app/page.jsx (trecho)
import Image from 'next/image';

<section className="py-4 text-center bg-light rounded-3 border">
  <div className="container">
    {/* /_static/hero.jpg */}
    <Image
      src="/_static/hero.jpg"
      alt="Banner da Lanchonete"
      width={1200}
      height={400}
      priority
      className="img-fluid rounded"
    />
    {/* ...restante do hero */}
  </div>
</section>

Notas: use priority acima da dobra; width/height evitam layout shift.

5) Code Splitting com dynamic import (componentes pesados)

Carregue Modal/Offcanvas sob demanda:

// app/cardapio/page.jsx (trecho)
import dynamic from 'next/dynamic';

const ItemModal = dynamic(() => import('@/components/ItemModal'), {
  ssr: false // modal depende de DOM/Bootstrap JS
});

const CartOffcanvas = dynamic(() => import('@/components/cart/CartOffcanvas'), {
  ssr: false
});

// ...use <ItemModal /> e <CartOffcanvas /> como antes

Resultado: bundle inicial menor; modal/offcanvas carregam quando necessário.

6) Instalar e rodar o bundle analyzer

  1. Instale:

    npm i -D @next/bundle-analyzer

  2. Ajuste next.config.mjs:

    import bundleAnalyzer from '@next/bundle-analyzer';

const withBundleAnalyzer = bundleAnalyzer({ enabled: process.env.ANALYZE === 'true' });

export default withBundleAnalyzer(nextConfig);

  3. Adicione script:

    {
  "scripts": {
    "analyze": "ANALYZE=true next build"
  }
}

  4. Rode:

    npm run analyze

    Relatórios em http://localhost:8888 (client/server bundles).

Ações comuns após medir
  • Remover imports não usados.
  • Converter imports globais em dinâmicos (quando fizer sentido).
  • Checar libs grandes entrando por engano.

7) Build e produção local

npm run build
npm run start
# Abra http://localhost:3000

Verificações (DevTools → Network):

  • Response da Home (SSG): HTML pré-renderizado com “Destaques”.
  • TTFB — compare com /admin (SSR).
  • Content-Encoding (gzip/br) pode depender do servidor/proxy final.
  • Tamanho transferido vs descompactado.

8) Lighthouse (Chrome → Lighthouse → Analyze page load)

  • Faça no / (Home) e /cardapio.
  • Registre Performance e Best Practices.
  • Aplique ao menos 2 melhorias (reduzir JS com dynamic(), otimizar imagens, next/font).

🧪 Atividades Práticas (para você desenvolver)

  1. Limpeza de JS inicial no Cardápio
    • Marque ProductCard para usar onDetails só quando necessário com dynamic.
    • Compare o bundle antes/depois no analyzer.
  2. Ícones otimizados
    • Troque um ícone para SVG inline em componentes mais acessados e meça o impacto.
  3. Cache de estáticos e imagens
    • Mova imagens de marca para public/_static.
    • Garanta que o header Cache-Control está ativo (Network → headers).
  4. Ambientes
    • Crie .env.production simulando NEXT_PUBLIC_API_BASE apontando para URL fictícia.
    • Na build prod, logue no server para entender precedence, sem expor segredos.
  5. Pré-carregamento de rotas
    • Adicione prefetch={false} em alguns <Link> não prioritários e compare (didático).
