🧠 Parte Teórica (explicação do conteúdo)

1) Server vs Client Components e Hidratação

No App Router, o Next.js separa componentes em dois mundos: Server Components (servidor) e Client Components (navegador). Entender essa divisão é essencial para construir aplicações híbridas (SSG/SSR + interatividade) sem bugs de hidratação.

Server Components (SC) são o padrão: se um arquivo não começa com 'use client', ele é tratado como componente de servidor. Isso significa que ele roda em ambiente Node/Edge e pode:

  • Importar módulos do servidor (ex.: acesso a banco, libs server-only, variáveis de ambiente).
  • Gerar HTML pronto (SSG ou SSR) com baixo custo de JavaScript no cliente.
  • Evitar hidratação para aquela parte (menos JS baixado e menos trabalho no navegador).

Client Components (CC) são usados quando você precisa de interatividade: useState, useEffect, handlers de clique, leitura de localStorage, acesso a window, etc. Eles exigem a diretiva 'use client' e precisam ser hidratados.

Hidratação é o processo em que o React pega o HTML já enviado (SSG/SSR) e “liga” esse HTML ao JavaScript no navegador: eventos passam a funcionar, estados passam a atualizar e a UI se torna interativa. A consequência prática é: o HTML inicial pode vir pronto, mas o estado do cliente só existe depois que o bundle foi carregado e a hidratação aconteceu.

Para o aluno, a regra mental mais útil é: SC = estrutura e dados iniciais; CC = interação e estado do navegador. Esse capítulo usa exatamente esse padrão para o carrinho: a página pode ser SSG/SSR, mas o carrinho é uma “ilha” client.

Exemplo aplicado no Passo a Passo

No passo a passo, o CartProvider é um Client Component (tem 'use client', usa useState/useEffect e lê/grava localStorage). Ele é injetado dentro de app/layout.jsx, que é Server Component. O resultado: páginas SSG/SSR continuam server, mas ganham uma ilha client para o carrinho (Etapas 1 e 2).

2) Cuidados para evitar mismatch (diferenças SSR × cliente)

Um dos erros mais comuns ao misturar SSR/SSG com interatividade é o mismatch de hidratação. Isso acontece quando o HTML gerado no servidor (ou no build) não bate com o que o React tenta renderizar no primeiro render do cliente. Quando isso ocorre, o React avisa no console e pode “reconstruir” a árvore, causando piscadas, comportamento estranho ou perda de performance.

A causa mais frequente é simples: o servidor não tem acesso a APIs do browser. Então, se você tenta ler localStorage durante o render inicial, o servidor não consegue e o resultado difere do cliente. Por isso, a regra prática é:

  • Nunca leia localStorage no render inicial. Leia em useEffect (após montar).
  • Comece com um estado inicial neutro (ex.: carrinho vazio/contador 0) e atualize depois da montagem.
  • Quando um trecho depende muito do browser (ex.: contador, UI que muda bastante), use um flag de montagem (como hasMounted) para evitar renderizar valores “incertos” antes do cliente.

Esse padrão é o que você já viu em capítulos anteriores com tema e favoritos: primeiro render é “safe”, depois o efeito sincroniza com o armazenamento local.

Exemplo aplicado no Passo a Passo

No CartProvider, o capítulo usa hasMounted e carrega o carrinho do localStorage dentro de useEffect, só depois persistindo alterações. No botão do Header, o contador exibido usa shown = hasMounted ? count : 0 para evitar mismatch de hidratação (Etapas 1 e 3).

3) “Client islands” em páginas SSG/SSR (Provider global)

O termo client islands (ilhas client) descreve um padrão moderno: a maior parte da página é renderizada no servidor (rápida, com HTML pronto), e apenas pequenos pedaços são hidratados para interatividade. Isso é o oposto de um SPA 100% client. No App Router, esse padrão é natural.

O carrinho é um exemplo perfeito de ilha client:

  • O catálogo e detalhes podem ser SSG (Cap. 9–10) ou SSR (Cap. 11) para performance/atualização.
  • O carrinho depende de estado do navegador e interação, então precisa ser client.
  • Como ele é “global”, faz sentido colocar no layout como Provider e UI do Offcanvas.

Ao injetar um Provider no layout, você garante que qualquer página (Home SSG, Categoria SSG, Admin SSR) compartilhe o mesmo carrinho. Isso evita duplicação de estados locais (como um cartCount em cada página) e torna a UX consistente.

Outro ponto importante: quando um Server Component “inclui” um Client Component, o Next cria uma fronteira. A parte server renderiza e a parte client hidrata depois. Você deve manter as props que atravessam essa fronteira serializáveis (JSON simples), algo reforçado no questionário do capítulo.

Exemplo aplicado no Passo a Passo

Na Etapa 2, app/layout.jsx envolve o <main> com <CartProvider>. Na Etapa 3, você adiciona o CartOffcanvas dentro do Provider para que ele exista em todas as páginas. Assim, qualquer rota pode abrir o carrinho via evento open-cart.

4) Padrões de UX com Bootstrap (JS): Offcanvas para carrinho

Para UX, carrinhos costumam seguir dois padrões: modal central (bloqueia a tela) ou painel lateral. O painel lateral (Offcanvas) é uma metáfora muito usada porque:

  • Permite revisar itens sem “sair” da página principal.
  • É rápido de abrir/fechar e mantém o contexto do usuário.
  • Combina bem com mobile (arrasta/fecha) e desktop (lateral).

O Bootstrap oferece Offcanvas como componente com JavaScript. No projeto, como o bundle do Bootstrap já está carregado, você consegue controlar o Offcanvas via API: Offcanvas.getOrCreateInstance(el).show(). Em React, o padrão correto é usar ref para apontar para o elemento e abrir/fechar a instância.

Um detalhe de arquitetura do capítulo: em vez de acoplar o botão diretamente ao Offcanvas, você dispara um evento custom (open-cart) e o Offcanvas escuta esse evento para abrir. Isso desacopla componentes e permite abrir o carrinho de qualquer lugar (Header, botão em card, etc.).

Além da abertura, a UX do carrinho precisa de ações básicas: aumentar/diminuir quantidade, remover item e limpar. O capítulo organiza isso no Context, evitando lógica duplicada no UI.

Exemplo aplicado no Passo a Passo

Na Etapa 3, você cria CartOffcanvas com um ref e, ao receber o evento open-cart, chama a API do Bootstrap para abrir o painel. O corpo do Offcanvas renderiza a lista do contexto e oferece botões de aumentar/diminuir/remover/limpar, todos chamando funções do Provider.

1) CartProvider (Context + localStorage)

Crie components/cart/CartProvider.jsx:

// components/cart/CartProvider.jsx
'use client';

import { createContext, useContext, useEffect, useMemo, useState } from 'react';

const CartContext = createContext(null);
const CART_KEY = 'cartItems';

export function useCart() {
  return useContext(CartContext);
}

export default function CartProvider({ children }) {
  const [items, setItems] = useState([]); // [{id, nome, preco, icone, qty}]
  const [hasMounted, setHasMounted] = useState(false);

  // Carrega do localStorage após montar (evita mismatch)
  useEffect(() => {
    try {
      const raw = localStorage.getItem(CART_KEY);
      if (raw) setItems(JSON.parse(raw));
    } catch {}
    setHasMounted(true);
  }, []);

  // Persiste no localStorage quando items muda
  useEffect(() => {
    if (!hasMounted) return;
    try {
      localStorage.setItem(CART_KEY, JSON.stringify(items));
    } catch {}
  }, [items, hasMounted]);

  function addItem(prod, delta = 1) {
    setItems((curr) => {
      const i = curr.findIndex((x) => x.id === prod.id);
      if (i >= 0) {
        const next = [...curr];
        next[i] = { ...next[i], qty: next[i].qty + delta };
        return next;
      }
      return [...curr, { id: prod.id, nome: prod.nome, preco: prod.preco, icone: prod.icone, qty: delta }];
    });
  }

  function decrementItem(id, delta = 1) {
    setItems((curr) => {
      const i = curr.findIndex((x) => x.id === id);
      if (i < 0) return curr;
      const next = [...curr];
      const newQty = next[i].qty - delta;
      if (newQty <= 0) next.splice(i, 1);
      else next[i] = { ...next[i], qty: newQty };
      return next;
    });
  }

  function removeItem(id) {
    setItems((curr) => curr.filter((x) => x.id !== id));
  }

  function clearCart() {
    setItems([]);
  }

  const count = useMemo(() => items.reduce((s, it) => s + it.qty, 0), [items]);
  const total = useMemo(() => items.reduce((s, it) => s + it.preco * it.qty, 0), [items]);

  const value = useMemo(
    () => ({ items, count, total, addItem, decrementItem, removeItem, clearCart, hasMounted }),
    [items, count, total]
  );

  return <CartContext.Provider value={value}>{children}</CartContext.Provider>;
}

3) Botão do carrinho + Offcanvas (UI global)

Crie components/cart/CartOffcanvas.jsx:

// components/cart/CartOffcanvas.jsx
'use client';

import { useEffect, useRef } from 'react';
import { useCart } from './CartProvider';

export default function CartOffcanvas() {
  const { items, total, addItem, decrementItem, removeItem, clearCart } = useCart();
  const offRef = useRef(null);

  // Expor open() para outros componentes abrirem o carrinho via evento custom
  useEffect(() => {
    function onOpen() {
      import('bootstrap/dist/js/bootstrap.bundle.min.js').then(({ Offcanvas }) => {
        const oc = Offcanvas.getOrCreateInstance(offRef.current);
        oc.show();
      });
    }
    window.addEventListener('open-cart', onOpen);
    return () => window.removeEventListener('open-cart', onOpen);
  }, []);

  const formatBRL = (n) => n.toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' });

  return (
    <div
      ref={offRef}
      className="offcanvas offcanvas-end"
      tabIndex="-1"
      id="cartOffcanvas"
      aria-labelledby="cartOffcanvasLabel"
    >
      <div className="offcanvas-header">
        <h5 id="cartOffcanvasLabel" className="offcanvas-title d-flex align-items-center gap-2">
          <i className="bi bi-cart3"></i> Seu carrinho
        </h5>
        <button type="button" className="btn-close" data-bs-dismiss="offcanvas" aria-label="Fechar"></button>
      </div>

      <div className="offcanvas-body d-flex flex-column">
        {items.length === 0 ? (
          <div className="text-center text-muted my-4">
            <i className="bi bi-emoji-neutral d-block mb-2" style={{ fontSize: '2rem' }}></i>
            Carrinho vazio.
          </div>
        ) : (
          <ul className="list-group mb-3">
            {items.map((it) => (
              <li key={it.id} className="list-group-item d-flex justify-content-between align-items-center">
                <div className="me-2">
                  <div className="fw-semibold d-flex align-items-center gap-2">
                    <i className={`bi ${it.icone}`}></i> {it.nome}
                  </div>
                  <small className="text-muted">{formatBRL(it.preco)} • qtd: {it.qty}</small>
                </div>

                <div className="btn-group">
                  <button className="btn btn-outline-secondary btn-sm" onClick={() => decrementItem(it.id)} aria-label="Diminuir">−</button>
                  <button className="btn btn-outline-secondary btn-sm" onClick={() => addItem(it, 1)} aria-label="Aumentar">+</button>
                  <button className="btn btn-outline-danger btn-sm" onClick={() => removeItem(it.id)} aria-label="Remover">
                    <i className="bi bi-trash"></i>
                  </button>
                </div>
              </li>
            ))}
          </ul>
        )}

        <div className="mt-auto">
          <div className="d-flex justify-content-between align-items-center mb-3">
            <span className="fw-semibold">Total</span>
            <span className="fw-bold">{formatBRL(total)}</span>
          </div>
          <div className="d-grid gap-2">
            <button className="btn btn-success" disabled={items.length === 0}>
              <i className="bi bi-bag-check me-1"></i> Finalizar (demo)
            </button>
            <button className="btn btn-outline-secondary" onClick={clearCart} disabled={items.length === 0}>
              Limpar carrinho
            </button>
          </div>
        </div>
      </div>
    </div>
  );
}
