Parte Teórica (explicação do conteúdo)

1) SPA e Next.js (visão geral)

Antes de escrever qualquer código, é importante entender o tipo de aplicação que estamos construindo. Uma SPA (Single Page Application) é um modelo no qual o navegador carrega um HTML “base” apenas uma vez e, a partir daí, a navegação e as atualizações de tela acontecem com JavaScript, trocando componentes e dados sem recarregar a página inteira. Isso deixa a experiência mais fluida (menos “pisca”), permite manter estados (como filtros e carrinho) enquanto o usuário navega e reduz a quantidade de requisições de páginas completas.

O React é uma biblioteca para criar interfaces compondo pequenas partes (componentes). Já o Next.js é um framework que “organiza a casa”: ele define uma estrutura de pastas, oferece roteamento pronto, otimiza build e entrega, e possibilita uma renderização híbrida. Híbrida significa que, dependendo do que você escrever, a página pode ser:

  • CSR (Client-Side Rendering): a tela é montada no navegador; ótimo para interações e estado local.
  • SSG (Static Site Generation): gera HTML no build; ideal para conteúdo estável e rápido.
  • SSR (Server-Side Rendering): gera HTML em cada requisição; ideal para dados “ao vivo”.

No App Router (pasta /app), o Next.js transforma pastas em rotas. Isso diminui o “trabalho manual” de configurar rotas e ajuda a manter o projeto consistente. Dois arquivos são fundamentais:

  • app/layout.jsx: define o layout compartilhado (estrutura comum em todas as páginas).
  • app/page.jsx: define o conteúdo da rota raiz / (a Home).
Exemplo aplicado no Passo a Passo

No passo a passo, quando você cria app/layout.jsx e coloca Header e Footer ali, você está aplicando a ideia de “layout compartilhado”. Em seguida, ao criar app/page.jsx, você define o conteúdo específico da Home. Isso já te dá uma navegação de SPA com estrutura organizada.

2) Framework CSS: por que Bootstrap 5

Em projetos reais, a maior parte do tempo não está em “inventar” um layout do zero, e sim em entregar uma interface que funcione bem em telas diferentes, seja consistente e seja fácil de manter. Um framework CSS como o Bootstrap acelera isso porque ele já traz um conjunto de padrões prontos.

O Bootstrap 5 entrega três pilares importantes:

  • Grid responsivo: você monta layouts com container, row e col-*, e o conteúdo se adapta automaticamente entre celular, tablet e desktop.
  • Utilitários: classes rápidas para espaçamento, alinhamento e display (por exemplo, p-3 para padding, m-2 para margin, d-flex, gap-2 etc.). Isso reduz CSS “manual” e aumenta produtividade.
  • Componentes: Navbar, Cards, Buttons, Alerts, Modals, Offcanvas… todos com estilos consistentes. Em muitos casos você só monta a estrutura HTML/JSX e aplica as classes.

Além disso, os Bootstrap Icons fornecem ícones vetoriais fáceis de usar com classes bi bi-*. Em um projeto educacional, isso ajuda a reforçar semântica visual (um ícone de carrinho, de lista, de contato) sem depender de imagens externas.

Exemplo aplicado no Passo a Passo

No passo a passo, quando você instala bootstrap e bootstrap-icons e depois cria uma Home com container, row, col-md-4 e card, você aplica diretamente o grid e os componentes. A Navbar responsiva com navbar-expand-lg e collapse também é um exemplo clássico de componente Bootstrap.

3) Git (início)

Git é uma ferramenta de controle de versão. Pense nele como uma “linha do tempo” do seu projeto. Em vez de salvar arquivos com nomes como projeto-final-versao3, você registra mudanças em etapas chamadas commits. Cada commit guarda o estado do código naquele momento e uma mensagem descrevendo o que foi feito.

Isso traz benefícios práticos para estudar e trabalhar:

  • Segurança: se algo quebrar, você consegue voltar para um ponto que estava funcionando.
  • Organização: dá para ver o histórico do que foi feito e por quê.
  • Trabalho em etapas: você implementa pequenas partes, testa e “salva” com commit.

Uma branch é uma “linha paralela” de desenvolvimento. Em projetos maiores, você pode criar uma branch para uma funcionalidade (ex.: cap1 ou final/cap16), trabalhar sem afetar a principal, e depois juntar. Aqui, já no começo, a disciplina de commits pequenos ajuda a evitar retrabalho.

Exemplo aplicado no Passo a Passo

No passo a passo, quando você executa git init, faz git add . e registra um commit como “chore: bootstrap projeto Next.js + Bootstrap para Lanchonete”, você cria o primeiro marco do projeto. Depois, ao criar Header/Footer e fazer novos commits, você pratica a ideia de “pequenas entregas versionadas”.

4) ESLint & Prettier (padrões de código)

Quando muitas pessoas (ou você mesmo ao longo do tempo) mexem no mesmo projeto, o código pode ficar inconsistente: aspas diferentes, tamanhos de linha, indentação irregular, nomes confusos. Isso dificulta ler e revisar. Para resolver, usamos duas ferramentas complementares:

  • ESLint: procura problemas de qualidade e possíveis bugs (por exemplo, variáveis não usadas, padrões perigosos, regras recomendadas do React/Next).
  • Prettier: padroniza a formatação automaticamente (espaços, quebras de linha, aspas, ponto e vírgula). Ele reduz discussões sobre “estilo” e deixa o foco na lógica.

O ganho real é que você passa a estudar o código com menos distrações. Quando o arquivo está bem formatado e sem avisos críticos, fica mais fácil identificar conceitos como componentes, props, estado e rotas nos capítulos seguintes.

Exemplo aplicado no Passo a Passo

No passo a passo, ao criar o arquivo .prettierrc e rodar npm run lint, você valida que o projeto está seguindo padrões mínimos. Isso evita que pequenos erros (como imports errados ou variáveis não usadas) virem problemas maiores quando você começar a criar páginas e componentes mais complexos.

2) Instalar Bootstrap 5 e Bootstrap Icons

Shell

3) Configurar imports globais no app/layout.jsx

Crie/edite app/layout.jsx:

// app/layout.jsx
import 'bootstrap/dist/css/bootstrap.min.css';
import 'bootstrap-icons/font/bootstrap-icons.css';
import './globals.css';
import BootstrapClient from '@/components/BootstrapClient';
import Header from '@/components/Header';
import Footer from '@/components/Footer';
export const metadata = {
  title: 'Lanchonete — Admin',
  description: 'Sistema de lanchonete (Admin) — Projeto didático',
};
export default function RootLayout({ children }) {
  return (
    <html lang="pt-BR">
      <body>
        <Header />
        <main className="container my-4">{children}</main>
        <Footer />
        {/* Carrega JS do Bootstrap no client */}
        <BootstrapClient />
      </body>
    </html>
  );
}

Crie o componente que carrega o JS do Bootstrap:

// components/BootstrapClient.jsx
'use client';

import { useEffect } from 'react';

export default function BootstrapClient() {
  useEffect(() => {
    // Importa o bundle que inclui Popper.js (necessário para alguns componentes)
    import('bootstrap/dist/js/bootstrap.bundle.min.js');
  }, []);

  return null;
}

Shell

git init

Sugestão de convenção simples de mensagens:

  • feat: (nova funcionalidade)
  • fix: (correção)
  • style: (formatação/estilo, sem mudança lógica)
  • chore: (tarefas de manutenção)
  • docs: (documentação)
  • refactor: (refatoração)

Ex.:

  • feat: criar Header com Navbar responsiva
  • style: aplicar Prettier e ajustar imports
