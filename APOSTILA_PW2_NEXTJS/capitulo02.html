Parte Teórica (explicação do conteúdo)

1) JSX e Componentes

O JSX é a forma mais comum de escrever interfaces em React. Ele parece HTML, mas na verdade é JavaScript com uma sintaxe especial. Quando você escreve JSX, o React transforma esse “quase HTML” em estruturas que o navegador consegue renderizar. Isso deixa o código mais legível, porque você descreve a tela diretamente no lugar onde define a lógica.

Um componente funcional é uma função que retorna JSX. Você pode imaginar um componente como um “bloco de UI” reutilizável: um título, um card de produto, uma lista, um botão. Ao dividir a interface em componentes, você ganha: reuso (usar o mesmo componente em várias páginas), organização (cada peça em um arquivo) e manutenção (alterar um componente e refletir em todos os lugares).

Veja um exemplo simples: o componente recebe um texto e retorna um <h1> com esse valor. Note que, no JSX, usamos { } (chaves) para “injetar” JavaScript dentro da marcação.

JSX

function Titulo({ texto }) {
    return (
    <h1>{texto}</h1>
    );
}

Esse padrão (função → retorna JSX) é a base do capítulo. Quando você entender isso, vai conseguir criar componentes como ProductCard e montar páginas completas combinando vários blocos.

Exemplo aplicado no Passo a Passo

No passo a passo, você cria o componente ProductCard (Etapa 2) e usa esse componente dentro da página /cardapio (Etapa 4). Isso é exatamente “componentização”: uma peça de UI reutilizável sendo usada para renderizar vários itens da lista.

2) Props (Propriedades)

Props são informações que um componente recebe “de fora”. Pense nelas como parâmetros da função: o componente pai passa dados para o componente filho. Por padrão, props são somente leitura para o componente que recebe (o filho não deve tentar alterar). Isso ajuda a manter o fluxo de dados previsível: o pai controla os dados e o filho apenas exibe e dispara eventos.

Além de dados (como um objeto item), props podem carregar funções. Esse é um padrão importante em React: o filho não precisa saber como atualizar o carrinho; ele só precisa chamar uma função que o pai forneceu.

Veja o exemplo abaixo: o pai envia o item e uma função onAdd. Quando o botão for clicado, o filho chama essa função. Perceba como isso separa responsabilidades: o card é responsável por UI; a página é responsável por estado e regras.

JSX

<ProductCard item={bebida} onAdd={() => handleAdd(bebida)} />

Uma dica de leitura de código: para reduzir repetição, usamos desestruturação em parâmetros. Em vez de acessar props.item e props.onAdd, fazemos function ProductCard({ item, onAdd }). Isso deixa o componente mais claro e menor.

Exemplo aplicado no Passo a Passo

Na Etapa 4, a página CardapioPage define handleAdd e passa essa função para <ProductCard onAdd={handleAdd} />. Assim, o card chama onAdd(item) e quem atualiza o contador/alerta é a página (que é onde o estado está).

3) Estado (useState)

Se props são dados que vêm de fora, o estado é o dado que o componente guarda por conta própria e que pode mudar com o tempo. Quando o estado muda, o React re-renderiza o componente, ou seja, ele “desenha” a tela novamente com os novos valores.

No React moderno, o estado em componentes funcionais é criado com o hook useState. Ele devolve um par: [valor, setValor]. O valor é o estado atual; setValor é a função que atualiza o estado. Uma regra importante: não altere o estado diretamente (por exemplo, não faça cartCount++), sempre use o setter.

Quando o novo estado depende do valor anterior (como um contador), use a forma funcional: assim o React calcula corretamente mesmo com múltiplas atualizações rápidas.

JSX

setContador((anterior) => anterior + 1);

Esse cuidado evita bugs clássicos em interfaces: dois cliques muito rápidos podem acontecer antes do React aplicar uma atualização, e o resultado pode ficar errado se você não usar o valor anterior.

Exemplo aplicado no Passo a Passo

Na Etapa 4, você cria cartCount com useState(0) e atualiza com setCartCount(prev => prev + 1) ao clicar em “Adicionar”. O botão flutuante recebe count={cartCount} e exibe o número automaticamente.

4) Eventos

Interfaces existem para reagir ao usuário. Em React, essa reação acontece por eventos. Eventos são funções executadas quando algo ocorre na tela: clique, digitação, envio de formulário, mudança de opção, foco, entre outros. No JSX, os eventos seguem um padrão de nome: onClick, onChange, onSubmit, etc.

Um ponto crítico: no JSX você normalmente passa uma referência de função. Se você escrever handleClick() direto, a função executa na hora de renderizar, e não quando o usuário clicar. Quando você precisa enviar um parâmetro (por exemplo, um item), use uma função anônima: () => ....

JSX

<button onClick={handleClick}>Adicionar</button>
Exemplo aplicado no Passo a Passo

Na Etapa 2 (ProductCard), o botão “Adicionar” usa onClick={() => onAdd(item)}. Isso é um evento com parâmetro: o clique dispara a função passando o item selecionado para a página.

5) Elevação de Estado (visão geral)

Conforme o projeto cresce, surge uma pergunta: onde o estado deve ficar? Se só um componente precisa do estado, ele pode ficar ali mesmo. Mas se vários componentes precisam do mesmo estado, colocamos esse estado em um componente “mais acima” (um ancestral comum) e repassamos via props. Esse processo é chamado de elevação de estado.

Um exemplo típico é o carrinho: em capítulos futuros, o contador do carrinho será exibido no Header e em outras telas, então o estado não pode ficar preso a uma página só. Por isso, mais adiante você vai usar Context API.

Exemplo aplicado no Passo a Passo

Aqui, o contador não fica no botão flutuante. Ele fica na página CardapioPage e é passado para o botão via props. Isso já mostra a ideia de separar “quem manda” (estado) de “quem exibe” (componente de UI).

6) Client Components no Next.js

No Next.js com App Router, componentes são Server Components por padrão. Para usar useState, useEffect e eventos, você precisa que o componente rode no navegador. Para isso, marcamos o arquivo com a diretiva 'use client'; na primeira linha.

JSX

'use client';

Neste capítulo, essa diretiva é essencial porque o card tem clique e a página tem estado e timer do alerta. Sem ela, o Next.js impediria o uso de hooks e a interatividade não funcionaria.

Exemplo aplicado no Passo a Passo

Na Etapa 2, ProductCard começa com 'use client' para habilitar interações. Na Etapa 4, CardapioPage também é client porque usa useState e useEffect (fechar o alerta após 2s).

2) Criar o componente ProductCard

Crie components/ProductCard.jsx:

JSX

// components/ProductCard.jsx
'use client';

export default function ProductCard({ item, onAdd }) {
const { nome, preco, volume, disponivel, destaque, icone } = item;

return (
<div className="card h-100 shadow-sm">
<div className="card-body d-flex flex-column">
<div className="d-flex justify-content-between align-items-start mb-2">
<h5 className="card-title mb-0">
<i className={`bi ${icone} me-2`}></i>
{nome}
</h5>
{destaque && <span className="badge bg-warning text-dark">Destaque</span>}
</div>

<p className="card-text text-muted mb-1">{volume}</p>
<p className="card-text fw-semibold mb-3">R$ {preco.toFixed(2)}</p>

{!disponivel && (
<div className="alert alert-secondary py-1 mb-3" role="alert">
Indisponível no momento
</div>
)}

<div className="mt-auto d-grid">
<button
className="btn btn-primary"
disabled={!disponivel}
onClick={() => onAdd(item)}
aria-label={`Adicionar ${nome} ao carrinho`}
>
<i className="bi bi-cart-plus me-2"></i>
Adicionar
</button>
</div>
</div>
</div>
);
}

4) Implementar a página /cardapio com estado e alerta

Edite/crie app/cardapio/page.jsx:

JSX

// app/cardapio/page.jsx
'use client';

import { useEffect, useState } from 'react';
import { bebidas } from '@/data/bebidas';
import ProductCard from '@/components/ProductCard';
import FloatingCartButton from '@/components/FloatingCartButton';

export default function CardapioPage() {
const [cartCount, setCartCount] = useState(0);
const [alerta, setAlerta] = useState(null); // { tipo: 'success' | 'danger', texto: string }

function handleAdd(item) {
setCartCount((prev) => prev + 1);
setAlerta({ tipo: 'success', texto: `${item.nome} adicionado ao carrinho!` });
}

// Fecha o alerta automaticamente após 2s
useEffect(() => {
if (!alerta) return;
const id = setTimeout(() => setAlerta(null), 2000);
return () => clearTimeout(id);
}, [alerta]);

return (
<>
<header className="mb-4">
<h1 className="h3 mb-1">Cardápio — Bebidas</h1>
<p className="text-muted">Escolha sua bebida e adicione ao carrinho.</p>
</header>

{alerta && (
<div
className={`alert alert-${alerta.tipo} alert-dismissible fade show`}
role="alert"
>
<i className="bi bi-check-circle me-2"></i>
{alerta.texto}
<button
type="button"
className="btn-close"
onClick={() => setAlerta(null)}
aria-label="Fechar"
></button>
</div>
)}

<div className="row g-4">
{bebidas.map((item) => (
<div className="col-12 col-sm-6 col-lg-4" key={item.id}>
<ProductCard item={item} onAdd={handleAdd} />
</div>
))}
</div>

<FloatingCartButton
count={cartCount}
onClick={() => {
setAlerta({ tipo: 'info', texto: 'Carrinho: recurso em desenvolvimento.' });
}}
/>
</>
);
}

Acessibilidade: usamos aria-label nos botões e permitimos fechar o alerta com btn-close.
