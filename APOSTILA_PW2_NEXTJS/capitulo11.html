Capítulo 11 — SSR (Server Side Rendering) para dados “ao vivo”
Dashboard do Administrador — Pedidos do dia / Estoque simulado

Carga: 2 aulas × 140 min

Projeto-base: Sistema da Lanchonete (Admin) (Cap. 1–10)

Stack fixa: Next.js (App Router) + React, Bootstrap 5 + Bootstrap Icons, Git, Postman

Resultados de aprendizagem deste capítulo:

  • Entender quando e por que usar SSR em vez de SSG/CSR.
  • Implementar páginas SSR que buscam dados “ao vivo” em cada requisição.
  • Controlar cache e revalidação com fetch server: { cache: 'no-store' }, revalidate: 0 e dynamic.
  • Criar uma API /api/pedidos-dia e consumir no servidor e no cliente.
  • Usar botão de atualizar com router.refresh() e medir diferenças de TTFB/FP.

🎯 Competências e Habilidades trabalhadas

  • Competências: (1) Elaborar interfaces web; (2) Aplicar práticas de desenvolvimento de sistemas.
  • Habilidades: 1.3 (Renderização híbrida — SSR), 4 (práticas de desenvolvimento: inspeção, testes com Postman).

🧠 Parte Teórica (explicação do conteúdo)

1) Quando usar SSR?

  • SSR renderiza o HTML a cada requisição. Bom para dados que mudam rápido (ex.: pedidos do dia, estoque atual, fila de atendimento).
  • Vantagens: HTML pronto (melhor SEO e conteúdo mutável), segurança (acesso a segredos no servidor), coerência por requisição.
  • Custo: Maior TTFB e CPU no servidor do que SSG.

2) Cache e controle no App Router

  • Forçar SSR com fetch no servidor: { cache: 'no-store' }.
  • Ou na página: export const dynamic = 'force-dynamic'.
  • revalidate = 0 (sem ISR) reforça “sempre novo”.

3) Server x Client Components

  • Server Components (sem 'use client') não precisam hidratação e são ideais para SSR/SSG com HTML pronto.
  • Client Components para interação (ex.: botão “Atualizar”, gráficos), acionando router.refresh() ou APIs.

4) Medindo na prática

  • TTFB costuma ser maior em SSR que em SSG; compare Home (SSG) com /admin (SSR) no DevTools → Network.
  • Use “Disable cache” e observe a guia Response com HTML completo já contendo os dados “do dia”.

🛠️ Passo a Passo — Dashboard SSR de Pedidos do Dia

Objetivo: Criar uma experiência SSR para o painel do administrador: KPIs (Total, Faturamento, Ticket médio), tabela de pedidos recentes e um botão de atualizar que dispara router.refresh().

0) Preparação

  • Projeto até o Cap. 10 (com /admin já existente).
  • Teremos dados simulados “ao vivo” para efeito de aprendizado.

1) Gerador de dados “do dia” (server safe)

Crie lib/pedidos.js:

// lib/pedidos.js
// Simulação simples de "pedidos do dia" variando a cada chamada.

const ITENS = [
  { id: 'xburger', nome: 'X-Burger', preco: 18.0 },
  { id: 'xsalada', nome: 'X-Salada', preco: 19.5 },
  { id: 'refri-cola-350', nome: 'Refrigerante Cola 350ml', preco: 7.0 },
  { id: 'suco-laranja-300', nome: 'Suco de Laranja 300ml', preco: 9.5 },
  { id: 'petit-gateau', nome: 'Petit Gâteau', preco: 16.0 },
];

const STATUS = ['recebido', 'em preparo', 'pronto', 'entregue', 'cancelado'];

function rand(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

function pick(arr) {
  return arr[rand(0, arr.length - 1)];
}

export function gerarPedidosDoDia(qtde = 8) {
  const agora = Date.now();
  const pedidos = Array.from({ length: qtde }).map((_, i) => {
    const itensCount = rand(1, 3);
    const itens = Array.from({ length: itensCount }).map(() => {
      const base = pick(ITENS);
      const qtd = rand(1, 3);
      return { id: base.id, nome: base.nome, qtd, preco: base.preco };
    });
    const total = itens.reduce((s, it) => s + it.preco * it.qtd, 0);
    const status = pick(STATUS);
    const criadoEm = new Date(agora - rand(1, 60) * 60 * 1000); // até 60 min atrás
    return {
      id: `PD-${agora.toString(36)}-${i}-${rand(100, 999)}`,
      itens,
      total: Number(total.toFixed(2)),
      status,
      criadoEm: criadoEm.toISOString(),
    };
  });
  // Ordena do mais recente para o mais antigo
  pedidos.sort((a, b) => new Date(b.criadoEm) - new Date(a.criadoEm));
  return pedidos;
}

export function calcularKPIs(pedidos) {
  const totalPedidos = pedidos.length;
  const faturamento = pedidos.reduce((s, p) => s + p.total, 0);
  const ticketMedio = totalPedidos ? faturamento / totalPedidos : 0;
  const emAndamento = pedidos.filter((p) => p.status === 'recebido' || p.status === 'em preparo').length;
  return {
    totalPedidos,
    faturamento: Number(faturamento.toFixed(2)),
    ticketMedio: Number(ticketMedio.toFixed(2)),
    emAndamento,
  };
}

2) API “Pedidos do Dia” (GET)

Crie app/api/pedidos-dia/route.js:

// app/api/pedidos-dia/route.js
import { NextResponse } from 'next/server';
import { gerarPedidosDoDia, calcularKPIs } from '@/lib/pedidos';

export const dynamic = 'force-dynamic'; // sempre dinâmico
export const revalidate = 0;

export async function GET() {
  // simula "dados do momento"
  const pedidos = gerarPedidosDoDia(10);
  const kpis = calcularKPIs(pedidos);
  return NextResponse.json({ kpis, pedidos }, { status: 200 });
}
Teste no Postman
  • URL: http://localhost:3000/api/pedidos-dia
  • Method: GET
  • Esperado: 200 com { kpis: {...}, pedidos: [ ... ] }.

3) Transformar /admin em Dashboard SSR

Substitua o conteúdo de app/admin/page.jsx pelo dashboard que roda no servidor em cada requisição.

// app/admin/page.jsx
import Link from 'next/link';
import { gerarPedidosDoDia, calcularKPIs } from '@/lib/pedidos';
import RefreshButton from './refresh-button';

export const dynamic = 'force-dynamic'; // força SSR
export const revalidate = 0;

function formatBRL(n) {
  return n.toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' });
}

export default async function AdminHome() {
  // Gera no servidor a cada request (simulação "ao vivo")
  const pedidos = gerarPedidosDoDia(10);
  const kpis = calcularKPIs(pedidos);

  return (
    <>
      <div className="d-flex justify-content-between align-items-center mb-3">
        <h1 className="h4 mb-0">Admin — Dashboard (SSR)</h1>
        <div className="d-flex gap-2">
          <RefreshButton /> {/* Client component que chama router.refresh() */}
          /admin/itens
            <i className="bi bi-list-ul me-1"></i> Itens
          </Link>
        </div>
      </div>
      <p className="text-muted">Dados simulados a cada requisição (pedidos do dia).</p>

      {/* KPIs */}
      <div className="row g-3 mb-4">
        <div className="col-12 col-md-3">
          <div className="card text-bg-light h-100">
            <div className="card-body">
              <h5 className="card-title">Pedidos Hoje</h5>
              <p className="display-6 mb-0">{kpis.totalPedidos}</p>
            </div>
          </div>
        </div>
        <div className="col-12 col-md-3">
          <div className="card text-bg-light h-100">
            <div className="card-body">
              <h5 className="card-title">Em andamento</h5>
              <p className="display-6 mb-0">{kpis.emAndamento}</p>
            </div>
          </div>
        </div>
        <div className="col-12 col-md-3">
          <div className="card text-bg-light h-100">
            <div className="card-body">
              <h5 className="card-title">Faturamento</h5>
              <p className="display-6 mb-0">{formatBRL(kpis.faturamento)}</p>
            </div>
          </div>
        </div>
        <div className="col-12 col-md-3">
          <div className="card text-bg-light h-100">
            <div className="card-body">
              <h5 className="card-title">Ticket Médio</h5>
              <p className="display-6 mb-0">{formatBRL(kpis.ticketMedio)}</p>
            </div>
          </div>
        </div>
      </div>

      {/* Tabela de pedidos recentes */}
      <div className="card">
        <div className="card-body">
          <h5 className="card-title d-flex justify-content-between align-items-center">
            Pedidos recentes
            <span className="badge text-bg-secondary">{pedidos.length}</span>
          </h5>

          <div className="table-responsive">
            <table className="table align-middle">
              <thead>
                <tr>
                  <th>Pedido</th>
                  <th>Itens</th>
                  <th>Total</th>
                  <th>Status</th>
                  <th>Criado em</th>
                </tr>
              </thead>
              <tbody>
                {pedidos.map((p) => (
                  <tr key={p.id}>
                    <td className="text-nowrap"><code>{p.id}</code></td>
                    <td>
                      <ul className="list-unstyled mb-0">
                        {p.itens.map((it, idx) => (
                          <li key={idx}>{it.qtd}× {it.nome}</li>
                        ))}
                      </ul>
                    </td>
                    <td className="fw-semibold">{formatBRL(p.total)}</td>
                    <td>
                      <span
                        className={
                          'badge ' + (
                            p.status === 'cancelado' ? 'text-bg-danger' :
                            p.status === 'entregue' ? 'text-bg-success' :
                            'text-bg-warning text-dark'
                          )
                        }
                      >
                        {p.status}
                      </span>
                    </td>
                    <td className="text-nowrap">
                      {new Date(p.criadoEm).toLocaleTimeString('pt-BR', { hour: '2-digit', minute: '2-digit' })}
                    </td>
                  </tr>
                ))}
              </tbody>
            </table>
          </div>

          <div className="mt-3 small text-muted">
            * Dados simulados a cada carregamento (ensino de SSR).
          </div>
        </div>
      </div>
    </>
  );
}

Crie o botão de atualizar como Client Component:

// app/admin/refresh-button.jsx
'use client';

import { useTransition } from 'react';
import { useRouter } from 'next/navigation';

export default function RefreshButton() {
  const router = useRouter();
  const [pending, startTransition] = useTransition();

  return (
    <button
      className="btn btn-primary btn-sm d-flex align-items-center gap-2"
      onClick={() => startTransition(() => router.refresh())}
      disabled={pending}
      aria-busy={pending}
      title="Atualizar dados do dashboard"
    >
      <i className="bi bi-arrow-clockwise"></i>
      {pending ? 'Atualizando…' : 'Atualizar'}
    </button>
  );
}
Por que SSR aqui?

A página /admin é um Server Component que gera HTML com dados atuais a cada requisição. O RefreshButton provoca revalidação sem recarregar a aplicação inteira.

4) (Opcional) Consumir a API na página SSR com fetch(no-store)

Se preferir separar o provedor de dados via API, troque o gerador local por fetch:

// trecho dentro de AdminHome (substitua geração local)
const res = await fetch(`${process.env.NEXT_PUBLIC_BASE_URL ?? ''}/api/pedidos-dia`, {
  cache: 'no-store',
});
if (!res.ok) throw new Error('Falha ao buscar pedidos');
const { kpis, pedidos } = await res.json();

Nota: em desenvolvimento local, usar uma URL absoluta confiável simplifica (ex.: variável NEXT_PUBLIC_BASE_URL=http://localhost:3000). Manter a versão “importando do lib” evita depender dessa configuração e continua SSR.
