Capítulo 5 — Bootstrap Avançado e Customização (Tema, Modal e Toast)

Carga: 2 aulas × 140 min

Projeto-base: Sistema da Lanchonete (Admin) (Cap. 1–4)

Stack fixa: Next.js (App Router) + React, Bootstrap 5 + Bootstrap Icons, Git

Resultados de aprendizagem deste capítulo:

  • Usar Grid avançado e utilitários do Bootstrap (flex, spacing, display, cores, visibilidade).
  • Aplicar componentes do Bootstrap (Modal e Toast) controlados por React (JS API do Bootstrap).
  • Customizar tema do Bootstrap com CSS Variables (cores de marca, radius, bordas, etc.) e modo claro/escuro (atributo data-bs-theme).
  • Melhorar UX do projeto substituindo Alert por Toast e criando Modal de detalhes.

  • Habilidades: 1.2 (Framework CSS: leiaute, componentes, ícones, customização), 1.1 (interação), 4 (práticas de versionamento e organização).

🧠 Parte Teórica (explicação do conteúdo)

1) Grid do Bootstrap (avançado)

No capítulo anterior você já usou o Grid do Bootstrap para montar cards responsivos. Agora vamos consolidar o Grid como uma “linguagem de layout” completa. O objetivo do Grid não é apenas colocar colunas na tela, mas permitir que a interface se adapte a diferentes tamanhos de tela com o mínimo de CSS manual.

Os breakpoints são pontos de mudança de layout (xs, sm, md, lg, xl). Quando você usa classes como col-sm-6 ou col-lg-4, está dizendo: “a partir desta largura, o elemento ocupa este tanto de colunas”. O Bootstrap segue a lógica mobile-first: você define o comportamento para telas pequenas primeiro e vai melhorando para telas maiores.

Os gutters (classes g-1 até g-5, ou separadas em gx-* e gy-*) controlam o espaçamento entre colunas e linhas. Isso é importante para legibilidade: cards muito juntos parecem “amontoados”.

Em layouts mais complexos, aparecem dois recursos valiosos:

  • Order (order-*): muda a ordem de blocos sem alterar o HTML (ex.: imagem primeiro no mobile, texto primeiro no desktop).
  • Offset (offset-*): cria “margem” em colunas, útil para centralizar ou criar respiros em telas grandes.
Exemplo aplicado no Passo a Passo

No passo a passo (Etapa 2), você revisa a Home com um banner e botões usando utilitários, e na prática do Cap. 3/4 você já usa col-12 col-sm-6 col-lg-4 para o catálogo. Aqui, você aplica o “Grid avançado” ao ajustar espaçamento com g-4 e, se quiser refinar o layout do banner, pode usar order-md-* para reorganizar elementos em telas maiores.

2) Utilitários essenciais

Os utilitários do Bootstrap são classes pequenas que resolvem problemas comuns de layout sem você escrever CSS. Eles são especialmente úteis em projetos didáticos porque ajudam a manter consistência e acelerar entrega. A ideia é: usar utilitários para 80% dos ajustes e recorrer a CSS customizado apenas quando fizer sentido.

Os grupos de utilitários mais usados neste capítulo são:

  • Espaçamento: p-*, px-*, py-*, m-*, my-* e gap-* (este é excelente em flex/grid).
  • Display/visibilidade: d-none, d-md-block, d-flex, d-grid para adaptar UI por tamanho.
  • Alinhamento com flex: justify-content-between, align-items-center para distribuir e alinhar itens.
  • Cores: bg-*, text-*, text-bg-* para planos, textos e badges consistentes.

Um “atalho mental”: se você quer alinhar elementos em uma linha com espaçamento entre eles, use d-flex com justify-content-between (extremos) ou gap-2 (distância constante). Se quer botões ocupando toda a largura, use d-grid (ou w-100 em casos simples).

Exemplo aplicado no Passo a Passo

Na Etapa 2, ao refatorar o hero da Home, você aplica utilitários como py-5, text-center, d-flex, justify-content-center e gap-2 para alinhar os botões. Isso demonstra como montar uma UI agradável sem escrever CSS extra.

3) Customização por CSS Variables e data-bs-theme

A partir do Bootstrap 5, boa parte do tema é controlada por variáveis CSS (os “tokens” do design). Isso significa que você consegue alterar cores, bordas e outros detalhes sem precisar usar SASS. Em vez de recompilar o framework, você sobrescreve variáveis como --bs-primary e --bs-border-radius no seu CSS.

O benefício educacional é enorme: os alunos enxergam que a identidade visual pode ser centralizada em poucos pontos e aplicada em toda a UI. Ao mudar --bs-primary, por exemplo, botões, links, badges e componentes que usam “primary” herdam a nova cor.

Já o atributo data-bs-theme é um mecanismo simples para alternar entre modo claro e escuro. Quando você define data-bs-theme="dark" no <html> (ou em um container), o Bootstrap ativa tokens de cor compatíveis com dark mode. Você pode complementar isso sobrescrevendo variáveis específicas em :root[data-bs-theme='dark'].

Um ponto importante: tema não é só “ficar bonito”. Ele também pode melhorar legibilidade (contraste), reduzir cansaço visual e criar consistência de marca.

Exemplo aplicado no Passo a Passo

Na Etapa 1, você sobrescreve variáveis como --bs-primary e --bs-border-radius em app/globals.css, e cria um botão ThemeToggle que alterna data-bs-theme no elemento document.documentElement. O resultado é que toda a aplicação muda para o tema escuro/claro sem trocar arquivos CSS.

4) Componentes com JS API (Modal e Toast)

Alguns componentes do Bootstrap são apenas CSS (ex.: badges, cards), mas outros precisam de JavaScript porque têm comportamento: abrir/fechar, animar, controlar foco. É o caso de Modal e Toast. Como o projeto já carrega o bootstrap.bundle.min.js no cliente (via BootstrapClient), a API JavaScript do Bootstrap fica disponível.

Quando usamos React, o padrão mais seguro é: o React controla quando o componente deve abrir/fechar (por estado), e o Bootstrap executa a UI/animação (por instância). Por isso, usamos ref para acessar o elemento DOM e chamamos Modal.getOrCreateInstance(...) ou Toast.getOrCreateInstance(...). Esse padrão evita bugs de “duas fontes de verdade”: React controla intenção; Bootstrap controla o comportamento visual.

Também é uma boa prática usar import dinâmico do bundle do Bootstrap dentro do effect, garantindo que esse código rode só no cliente.

Exemplo aplicado no Passo a Passo

Na Etapa 3, você cria ToastContainer que, ao receber show=true, chama a API do Bootstrap para exibir o toast automaticamente. Na Etapa 4, você cria ItemModal e usa a API do Bootstrap para abrir/fechar o modal de acordo com o estado open. Assim, o clique em “Detalhes” vira uma ação React que dispara um comportamento Bootstrap.

5) Acessibilidade (foco, ARIA e feedback não intrusivo)

Quando adicionamos componentes “por cima” (Modal e Toast), a acessibilidade vira prioridade. Um modal, por definição, deve prender o foco enquanto estiver aberto, para que o usuário de teclado não navegue “por trás” sem perceber. O Bootstrap já ajuda nisso, mas você precisa garantir atributos corretos e botões com rótulos.

Para o Modal, boas práticas incluem:

  • aria-labelledby apontando para o título do modal.
  • Botão de fechar com aria-label.
  • Evitar conteúdos que não possam ser alcançados pelo teclado.

Para o Toast, o objetivo é informar sem interromper. Por isso, usamos uma região com aria-live="polite" e role="status". Assim, leitores de tela anunciam a mensagem de forma apropriada. E como o toast some sozinho, ele reduz “poluição visual” em relação ao Alert.

Por fim, para botões de alternância (como o tema), o atributo aria-pressed comunica “ligado/desligado” para tecnologias assistivas.

Exemplo aplicado no Passo a Passo

Na Etapa 1, o ThemeToggle usa aria-pressed para indicar quando o modo escuro está ativo. Na Etapa 3, o container do toast define aria-live e o toast usa role="status". Na Etapa 4, o modal define aria-labelledby e o botão de fechar tem aria-label. Esses detalhes tornam a interface mais inclusiva e profissional.

1.2) Alternar claro/escuro pelo data-bs-theme

Crie components/ThemeToggle.jsx:

JSX

// components/ThemeToggle.jsx
'use client';

import { useEffect, useState } from 'react';

const STORAGE_KEY = 'theme'; // 'light' | 'dark'

export default function ThemeToggle() {
const [theme, setTheme] = useState('light');

useEffect(() => {
try {
const saved = localStorage.getItem(STORAGE_KEY);
if (saved === 'dark' || saved === 'light') {
setTheme(saved);
document.documentElement.setAttribute('data-bs-theme', saved);
}
} catch {}
}, []);

function toggle() {
const next = theme === 'light' ? 'dark' : 'light';
setTheme(next);
document.documentElement.setAttribute('data-bs-theme', next);
try {
localStorage.setItem(STORAGE_KEY, next);
} catch {}
}

return (
<button
className="btn btn-outline-light btn-sm d-flex align-items-center gap-2"
onClick={toggle}
aria-pressed={theme === 'dark'}
title="Alternar tema claro/escuro"
>
<i className={`bi ${theme === 'dark' ? 'bi-sun' : 'bi-moon'}`}></i>
<span className="d-none d-sm-inline">{theme === 'dark' ? 'Claro' : 'Escuro'}</span>
</button>
);
}

3) Criar Toast global “Adicionado ao carrinho”

3.1) Componente ToastContainer

Crie components/ToastContainer.jsx:

JSX

// components/ToastContainer.jsx
'use client';

import { useEffect, useRef } from 'react';

export default function ToastContainer({ message, show, onHide }) {
const toastRef = useRef(null);

useEffect(() => {
let instance;
if (show && toastRef.current) {
// lazy import para garantir bootstrap no cliente
import('bootstrap/dist/js/bootstrap.bundle.min.js').then(({ Toast }) => {
instance = Toast.getOrCreateInstance(toastRef.current, { delay: 1800 });
instance.show();
toastRef.current.addEventListener('hidden.bs.toast', () => onHide?.(), { once: true });
});
}
return () => {
if (instance) {
try { instance.dispose(); } catch {}
}
};
}, [show, onHide]);

return (
<div
className="toast-container position-fixed bottom-0 end-0 p-3"
style={{ zIndex: 1080 }}
aria-live="polite"
aria-atomic="true"
>
<div
ref={toastRef}
className={`toast text-bg-success ${show ? 'show' : 'hide'}`}
role="status"
>
<div className="d-flex">
<div className="toast-body d-flex align-items-center gap-2">
<i className="bi bi-check-circle"></i>
{message || 'Ação realizada com sucesso!'}
</div>
<button
type="button"
className="btn-close btn-close-white me-2 m-auto"
aria-label="Fechar"
onClick={onHide}
></button>
</div>
</div>
</div>
);
}

4) Modal de Detalhes do item (controlado por React)

4.1) Componente ItemModal

Crie components/ItemModal.jsx:

JSX

// components/ItemModal.jsx
'use client';

import { useEffect, useRef } from 'react';

export default function ItemModal({ item, open, onClose, onAdd }) {
const modalRef = useRef(null);

useEffect(() => {
let instance;
async function ensure() {
if (!modalRef.current) return;
const { Modal } = await import('bootstrap/dist/js/bootstrap.bundle.min.js');
instance = Modal.getOrCreateInstance(modalRef.current, { backdrop: 'static' });
if (open) {
instance.show();
modalRef.current.addEventListener('hidden.bs.modal', () => onClose?.(), { once: true });
} else {
instance.hide();
}
}
ensure();
return () => {
if (instance) {
try { instance.dispose(); } catch {}
}
};
}, [open, onClose]);

const nome = item?.nome ?? 'Item';
const preco = item?.preco?.toFixed ? item.preco.toFixed(2) : '';
const icon = item?.icone ? `bi ${item.icone}` : 'bi bi-info-circle';

return (
<div
ref={modalRef}
className="modal fade"
tabIndex="-1"
aria-labelledby="itemModalLabel"
aria-hidden="true"
>
<div className="modal-dialog modal-dialog-centered">
<div className="modal-content">
<div className="modal-header">
<h5 id="itemModalLabel" className="modal-title d-flex align-items-center gap-2">
<i className={icon}></i> {nome}
</h5>
<button type="button" className="btn-close" aria-label="Fechar" onClick={onClose}></button>
</div>
<div className="modal-body">
{item?.descricao && <p className="mb-2">{item.descricao}</p>}
{item?.volume && <p className="mb-2"><strong>Volume:</strong> {item.volume}</p>}
{item && (
<p className="mb-0">
<strong>Preço:</strong> R$ {preco}
</p>
)}
{!item?.disponivel && (
<div className="alert alert-secondary mt-3" role="alert">
Indisponível no momento
</div>
)}
</div>
<div className="modal-footer">
<button className="btn btn-outline-secondary" onClick={onClose}>
Fechar
</button>
<button
className="btn btn-primary"
disabled={!item?.disponivel}
onClick={() => onAdd?.(item)}
>
<i className="bi bi-cart-plus me-1"></i> Adicionar
</button>
</div>
</div>
</div>
</div>
);
}
