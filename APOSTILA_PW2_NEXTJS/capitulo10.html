Capítulo 10 — Rotas Dinâmicas com SSG (detalhe do produto e páginas de categoria)

Carga: 2 aulas × 140 min

Projeto-base: Sistema da Lanchonete (Admin) (Cap. 1–9)

Stack fixa: Next.js (App Router) + React, Bootstrap 5 + Bootstrap Icons, Git

Resultados de aprendizagem deste capítulo:

  • Gerar páginas estáticas dinâmicas (SSG) com generateStaticParams (detalhe do produto e categorias).
  • Produzir metadados dinâmicos para SEO com generateMetadata.
  • Escolher políticas de fallback via dynamicParams (404 vs fallback dinâmico) e revalidate por rota.
  • Manter UX e acessibilidade: breadcrumb, estado indisponível, navegação SPA.

  • Habilidades: 1.1 (SPAs com framework frontend), 1.3 (renderização híbrida: SSG), 1.2 (uso consistente de componentes do framework CSS).

🧠 Parte Teórica (explicação do conteúdo)

1) generateStaticParams (App Router) — SSG para rotas dinâmicas

No Cap. 9 você aprendeu que SSG gera HTML estático no build. O desafio agora é: como fazer SSG quando a rota tem parâmetro (por exemplo, /cardapio/[id])? No App Router, a resposta é generateStaticParams().

A ideia é simples: o Next precisa saber quais valores de parâmetro existem para conseguir gerar as páginas antes. Então você retorna uma lista de objetos com os params. Para produtos, isso costuma ser uma lista de id. Para categorias, uma lista de strings como bebida, lanche e sobremesa.

Quando o Next executa o build, ele chama generateStaticParams(), percorre essa lista e cria um HTML estático para cada combinação. O resultado é um “SSG dinâmico”: as páginas são dinâmicas na URL, mas estáticas no conteúdo gerado.

Um ponto importante: a fonte dos parâmetros precisa ser determinística e server-safe para o build. No capítulo, usamos o dataset local data/itens.js, que é perfeito para isso. Em projetos reais, isso pode vir de um banco ou CMS durante o build (ou via ISR).

Exemplo aplicado no Passo a Passo

Na Etapa 1, você transforma app/cardapio/[id]/page.jsx em SSG ao implementar generateStaticParams() retornando itens.map(it => ({ id: it.id })). Assim, cada item do dataset gera um HTML próprio no build.

2) dynamicParams: política de fallback (404 vs render dinâmico)

Quando você gera páginas estáticas para uma rota dinâmica, surge uma pergunta: “e se alguém acessar um parâmetro que não estava na lista do build?”. É aqui que entra dynamicParams.

Pense nisso como uma política de “fallback”:

  • dynamicParams = true (padrão): parâmetros não listados podem ser tratados dinamicamente (dependendo da configuração e do tipo de dado). Em alguns cenários, isso permite que uma página “nova” apareça sem rebuild total.
  • dynamicParams = false: qualquer parâmetro fora de generateStaticParams vira 404. Isso é excelente para catálogos fechados, onde você quer URLs previsíveis e evitar páginas “fantasmas”.

No contexto didático da lanchonete, usar dynamicParams = false é ótimo para aprender: você consegue testar rapidamente se o Next está respeitando a lista pré-gerada. Se acessar /cardapio/xyz sem existir, a UI deve cair no 404 contextual.

Exemplo aplicado no Passo a Passo

Na Etapa 1 (detalhe) e na Etapa 2 (categoria), você define export const dynamicParams = false. Com isso, /cardapio/categoria/pizza e /cardapio/id-inexistente viram 404 imediatamente, reforçando a ideia de “catálogo fechado” com SSG.

3) generateMetadata (SEO dinâmico) e por que importa em SSG

SEO não é só “aparecer no Google”: é também como um link fica quando é compartilhado. Metadados (title, description e Open Graph) definem o título da aba, a descrição e a forma como redes sociais criam um card do link.

No App Router, você pode gerar metadados de duas formas:

  • Estático: export const metadata = {...} quando o conteúdo é fixo.
  • Dinâmico: export function generateMetadata({ params }) quando depende do parâmetro.

No detalhe do produto, isso é perfeito: o título deve ser o nome do item. Em páginas de categoria, o título deve refletir a categoria. E como as páginas são SSG, esses metadados já saem prontos no HTML gerado — o que melhora indexação e compartilhamento.

Um cuidado: se o item não existir, você deve gerar metadados coerentes (“Item não encontrado”) e também aplicar a lógica de 404 (via notFound() e/ou dynamicParams=false).

Exemplo aplicado no Passo a Passo

Na Etapa 1, você implementa generateMetadata no detalhe usando params.id para achar o item no dataset e montar title, description e openGraph. Na Etapa 2, faz o mesmo para categorias, criando títulos como “Cardápio — Lanches”.

4) revalidate por segmento: ISR “por rota”

No Cap. 9 você viu que revalidate ativa ISR. A novidade aqui é pensar em ISR por rota dinâmica: o Next permite que cada segmento tenha sua própria política.

Por exemplo:

  • Detalhe do produto pode revalidar a cada 12 horas (60*60*12), porque preço e descrição mudam pouco.
  • Página de categoria pode revalidar diariamente (60*60*24), pois o catálogo muda por campanhas.

O resultado é uma aplicação com custo baixo (continua estática) e com atualização automática sem “rebuild manual”. Em projetos reais, essa decisão afeta custo e experiência: revalidar muito rápido pode gerar mais regenerações; revalidar muito lento pode deixar conteúdo desatualizado.

Exemplo aplicado no Passo a Passo

Na Etapa 1, você define revalidate = 60 * 60 * 12 no detalhe. Na Etapa 2, define revalidate = 60 * 60 * 24 nas categorias. Assim, ambos são SSG, mas com atualização automática em ritmos diferentes.

5) App Router x Pages Router (visão rápida e migração mental)

Muitos materiais antigos sobre Next.js usam o Pages Router (pages/), com funções como getStaticPaths e getStaticProps. No App Router (app/), a mentalidade muda:

  • generateStaticParams é o equivalente moderno de getStaticPaths.
  • O “getStaticProps” deixa de existir como função separada porque, em Server Components, você pode buscar dados diretamente (import local, fetch com cache, etc.).
  • Estratégias de renderização (SSG/SSR) dependem de cache, dynamic e revalidate.
  • Server Components não hidratam; Client Components hidratam. Isso permite páginas muito rápidas com JS reduzido.

A prática deste capítulo reforça exatamente essa “migração mental”: você cria rotas dinâmicas SSG sem precisar escrever funções de props, apenas dizendo ao Next quais params gerar e como montar a página.

Exemplo aplicado no Passo a Passo

No passo a passo, você não usa getStaticPaths. Em vez disso, usa generateStaticParams tanto para itens quanto para categorias. Também usa generateMetadata para SEO. Esse é o padrão do App Router e prepara você para projetos modernos.

1. Transformar /cardapio/[id] em SSG; 2) Criar /cardapio/categoria/[categoria] (lista SSG) com ISR diário e 404 para categorias inexistentes.

Pré-requisitos: Projeto até o Cap. 9 (Home SSG) com data/itens.js e páginas do cardápio funcionando.

1) SSG no detalhe: app/cardapio/[id]/page.jsx

1.1) Gerar params (ids) no build

// app/cardapio/[id]/page.jsx (Server Component)
import { notFound } from 'next/navigation';
import { itens } from '@/data/itens';

export function generateStaticParams() {
  // lista todos os ids conhecidos para pré-renderização
  return itens.map((it) => ({ id: it.id }));
}

// opcional: revalidate para ISR no detalhe (ex.: 12 horas)
export const revalidate = 60 * 60 * 12;

// [Didático] se quiser forçar 404 em ids não listados:
export const dynamicParams = false;

// Metadados dinâmicos (SEO)
export function generateMetadata({ params }) {
  const item = itens.find((it) => it.id === params.id);
  if (!item) return { title: 'Item não encontrado — Cardápio' };
  const titulo = `${item.nome} — Cardápio`;
  const descricao = item.descricao || item.volume || 'Detalhe do item do cardápio';
  return {
    title: titulo,
    description: descricao,
    openGraph: {
      title: titulo,
      description: descricao,
      type: 'article',
    },
  };
}

export default function ItemDetalhePage({ params }) {
  const { id } = params;
  const item = itens.find((it) => it.id === id);
  if (!item) return notFound();

  return (
    <section>
      <nav aria-label="breadcrumb" className="mb-3">
        <ol className="breadcrumb">
          <li className="breadcrumb-item">/Início</a></li>
          <li className="breadcrumb-item">/cardapioCardápio</a></li>
          <li className="breadcrumb-item active" aria-current="page">{item.nome}</li>
        </ol>
      </nav>

      <header className="mb-3">
        <h1 className="h4 d-flex align-items-center gap-2">
          <i className={`bi ${item.icone}`}></i> {item.nome}
        </h1>
        <p className="text-muted mb-2">
          {item.categoria.toUpperCase()} • R$ {item.preco.toFixed(2)}
        </p>
        {!item.disponivel && <span className="badge text-bg-secondary">Indisponível</span>}
        {item.destaque && <span className="badge text-bg-warning text-dark ms-2">Destaque</span>}
      </header>

      {item.volume && <p className="mb-2"><strong>Volume:</strong> {item.volume}</p>}
      {item.descricao && <p className="mb-3">{item.descricao}</p>}

      <div className="d-flex gap-2">
        /cardapio
          <i className="bi bi-arrow-left me-1"></i> Voltar ao cardápio
        </a>
        /cardapio
          <i className="bi bi-cart-plus me-1"></i> Adicionar (via card)
        </a>
      </div>
    </section>
  );
}

2.2) Implementação com generateStaticParams + revalidate

// app/cardapio/categoria/[categoria]/page.jsx
import Link from 'next/link';
import { notFound } from 'next/navigation';
import { itens } from '@/data/itens';

// categorias válidas no dataset
const CATS = ['bebida', 'lanche', 'sobremesa'];

export function generateStaticParams() {
  // gera SSG para cada categoria conhecida
  return CATS.map((c) => ({ categoria: c }));
}

// Revalidate diário (catálogo muda pouco)
export const revalidate = 60 * 60 * 24;

// Garante 404 para categorias fora da lista
export const dynamicParams = false;

export function generateMetadata({ params }) {
  const cat = params.categoria;
  if (!CATS.includes(cat)) return { title: 'Categoria inválida — Cardápio' };
  const titulo = `Cardápio — ${cat[0].toUpperCase()}${cat.slice(1)}s`;
  const descricao = `Lista de ${cat}s da Lanchonete`;
  return {
    title: titulo,
    description: descricao,
    openGraph: { title: titulo, description: descricao, type: 'website' },
  };
}

export default function CategoriaPage({ params }) {
  const cat = params.categoria;
  if (!CATS.includes(cat)) return notFound();

  const lista = itens
    .filter((it) => it.categoria === cat)
    .sort((a, b) => {
      if (a.destaque !== b.destaque) return a.destaque ? -1 : 1;
      return a.nome.localeCompare(b.nome, 'pt-BR');
    });

  return (
    <section>
      <nav aria-label="breadcrumb" className="mb-3">
        <ol className="breadcrumb">
          <li className="breadcrumb-item">/Início</Link></li>
          <li className="breadcrumb-item">/cardapioCardápio</Link></li>
          <li className="breadcrumb-item active" aria-current="page">
            {cat[0].toUpperCase()}{cat.slice(1)}s
          </li>
        </ol>
      </nav>

      <header className="mb-3">
        <h1 className="h4">Cardápio — {cat[0].toUpperCase()}{cat.slice(1)}s</h1>
        <p className="text-muted">Páginas estáticas com ISR diário.</p>
      </header>

      {lista.length === 0 ? (
        <div className="alert alert-secondary">Nenhum item nesta categoria.</div>
      ) : (
        <div className="row g-4">
          {lista.map((item) => (
            <div className="col-12 col-sm-6 col-lg-4" key={item.id}>
              <div className="card h-100 shadow-sm">
                <div className="card-body d-flex flex-column">
                  <div className="d-flex justify-content-between align-items-start mb-2">
                    <h5 className="card-title mb-0 d-flex align-items-center gap-2">
                      <i className={`bi ${item.icone}`}></i> {item.nome}
                    </h5>
                    {item.destaque && <span className="badge text-bg-warning text-dark">Destaque</span>}
                  </div>
                  {item.volume && <p className="text-muted mb-1">{item.volume}</p>}
                  {item.descricao && <p className="text-muted mb-1">{item.descricao}</p>}
                  <p className="fw-semibold mb-3">R$ {item.preco.toFixed(2)}</p>
                  <div className="mt-auto d-flex gap-2">
                    <Link className="btn btn-outline-secondary btn-sm" href={`/cardapio/${item.id}`}>
                      <i className="bi bi-info-circle me-1"></i> Detalhes
                    </Link>
                    /cardapio
                      <i className="bi bi-cart-plus me-1"></i> Adicionar
                    </Link>
                  </div>
                  {!item.disponivel && (
                    <div className="alert alert-secondary py-1 mt-3 mb-0" role="alert">
                      Indisponível no momento
                    </div>
                  )}
                </div>
              </div>
            </div>
          ))}
        </div>
      )}
    </section>
  );
}
