Capítulo 10 — Integração com bancos de dados e formatação de dados

Carga: 4h (teoria e laboratório)

Projeto-base: Serviço receptor de telemetria que valida JSON e persiste no MySQL ou MongoDB

Stack fixa: ESP8266/ESP32 (simulado ou real) + HTTP/MQTT → Python (Flask) → MySQL/MongoDB

Resultados de aprendizagem deste capítulo:

  • Modelar dados de telemetria com campos mínimos: timestamp, deviceId, métrica e valor.
  • Criar tabela MySQL e coleção MongoDB com índices adequados para consultas por dispositivo e tempo.
  • Implementar um endpoint (HTTP) que recebe JSON, valida e insere dados no banco.
  • Realizar consultas básicas (SELECT no MySQL e find no MongoDB) para validação.
  • Aplicar boas práticas de sanitização, validação e tratamento de erros.

Competências e Habilidades

  • Projetar esquema simples para séries temporais de IoT.
  • Operar CRUD básico em MySQL e MongoDB.
  • Serializar/deserializar JSON de forma robusta e segura.
  • Documentar endpoints e estrutura de dados.
  • Testar integração ponta a ponta e analisar logs/erros.

Plano de Aula (Capítulo 10)

  1. Contextualização (20 min): Revisão do fluxo IoT e requisitos de persistência. Comparação SQL x NoSQL.
  2. Teoria guiada (40 min): Modelagem mínima de telemetria; chaves/índices; JSON, sanitização e validação.
  3. Laboratório 1 (40 min): MySQL: criação de banco/tabela, INSERT/SELECT, índice composto.
  4. Laboratório 2 (40 min): MongoDB: criação de coleção e índices, inserções e consultas.
  5. Laboratório 3 (40 min): Serviço receptor em Python (Flask) que valida e persiste conforme configuração.
  6. Validação e troubleshooting (20 min): Testes com cURL/Postman/MQTT-HTTP bridge, análise de logs, correções.
  7. Fechamento (10 min): Checklist, atividades propostas e entregáveis.

Parte Teórica (explicação do conteúdo)

1) Modelagem simples para telemetria

A telemetria em IoT costuma ser uma série temporal. Um registro mínimo inclui: timestamp (quando a medição ocorreu), deviceId (qual dispositivo enviou), metric (o que está sendo medido, ex.: temperature) e value (o valor numérico/textual). Campos opcionais úteis: unit (°C, %), status (ok/fault), meta (JSON com detalhes), e source (mqtt/http).

Em bancos relacionais (MySQL), representamos isso em uma tabela com tipos adequados (DATETIME/TIMESTAMP, VARCHAR, DOUBLE). Em documentos (MongoDB), cada medição é um documento JSON com os mesmos campos. Em ambos, índices por deviceId e por tempo melhoram filtros e gráficos.

Onde vou aplicar: no Passo 1 e Passo 2, ao criar tabela/coleção e definir índices. No Passo 3, ao mapear o JSON recebido para o esquema.

2) SQL básico (INSERT/SELECT) e índices no MySQL

Para validar o fluxo, você executará INSERT (inserção de novas leituras) e SELECT (consultas por período e dispositivo). Índices aceleram essas consultas; um índice composto em (deviceId, ts) é comum para séries temporais.

Boas práticas incluem: usar tipos corretos (DOUBLE/DECIMAL para valores), normalizar deviceId, e evitar campos redundantes. Para confiabilidade, ative NOT NULL e limites sensatos de tamanho.

Onde vou aplicar: no Passo 1, criando a tabela e índices; no Passo 3, ao inserir via aplicação; no teste com SELECT.

3) NoSQL no MongoDB (coleções e índices)

No MongoDB, a flexibilidade do documento ajuda quando métricas diferentes possuem metadados variados. Ainda assim, convém padronizar campos base (ts, deviceId, metric, value, unit). Índices em deviceId, metric e ts melhoram o desempenho.

Escolha Time-Series Collections quando disponível (MongoDB 5+) para otimizar séries temporais (opcional). Caso contrário, uma coleção normal com índices já atende bem a projetos didáticos.

Onde vou aplicar: no Passo 2, criando a coleção, definindo índices e testando inserções/consultas.

4) JSON: serialização, sanitização e validação

O dispositivo envia JSON; o servidor valida tipos e valores antes de persistir. Sanitização remove campos inesperados e normaliza unidades. Validação rejeita payloads com campos ausentes ou fora do intervalo aceitável.

Regras mínimas: obrigatórios (deviceId, metric, value, ts); tipos corretos; limites (ex.: temperatura entre -50 e 150 °C para sensores comuns); strings com tamanho máximo; datas no padrão ISO 8601 (UTC) quando possível.

Onde vou aplicar: no Passo 3, ao implementar o endpoint Flask que valida e retorna erros claros em caso de falhas.

5) Boas práticas de integração

Use variáveis de ambiente para credenciais e URIs. Separe lógica de banco do endpoint. Registre erros e retornos no log. Escreva consultas de validação para conferir se os dados inseridos estão corretos.

Onde vou aplicar: no Passo 0 (preparo do ambiente) e no Passo 3 (estrutura do serviço e testes).

Passo a Passo — Persistência de Telemetria em MySQL e MongoDB

Objetivo desta etapa:

Construir um fluxo completo: receber JSON de telemetria por HTTP, validar e armazenar em MySQL ou MongoDB, e consultar para conferir a persistência.


Passo 0 — Preparar o ambiente

Instale as ferramentas necessárias. Você pode usar contêineres locais (Docker) ou serviços instalados nativamente.

Terminal (bash)

# Python + venv
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install flask pymysql mysqlclient pymongo python-dotenv

# MySQL (exemplo com Docker)
docker run --name mysql-iot -e MYSQL_ROOT_PASSWORD=senha -e MYSQL_DATABASE=iotdb -p 3306:3306 -d mysql:8

# MongoDB (exemplo com Docker)
docker run --name mongo-iot -p 27017:27017 -d mongo:6

# Opcional: Postman ou cURL para testar endpoints
Dica: para Windows sem Docker, use MySQL Community Installer e MongoDB Community + Compass.

Passo 1 — MySQL: criar tabela e índices

Conecte ao MySQL, selecione o banco e crie a tabela de telemetria com índice composto em (deviceId, ts).

-- usar banco criado
CREATE DATABASE IF NOT EXISTS iotdb;
USE iotdb;

-- tabela de telemetria
CREATE TABLE IF NOT EXISTS telemetry (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  deviceId VARCHAR(64) NOT NULL,
  metric   VARCHAR(64) NOT NULL,
  value    DOUBLE NOT NULL,
  unit     VARCHAR(16) NULL,
  ts       DATETIME NOT NULL,
  source   VARCHAR(16) NOT NULL DEFAULT 'http',
  meta     JSON NULL,
  INDEX idx_device_ts (deviceId, ts),
  INDEX idx_metric_ts (metric, ts)
);

-- teste de inserção
INSERT INTO telemetry (deviceId, metric, value, unit, ts)
VALUES ('esp32-01', 'temperature', 23.5, 'C', NOW());

-- consulta por dispositivo e último período
SELECT deviceId, metric, value, unit, ts
FROM telemetry
WHERE deviceId = 'esp32-01'
  AND ts >= NOW() - INTERVAL 1 DAY
ORDER BY ts DESC
LIMIT 10;
Onde aplicar: usaremos esta tabela no Passo 3 para inserções via API.

Passo 2 — MongoDB: criar coleção e índices

Conecte ao Mongo e crie a coleção telemetry com índices em deviceId e ts. Você pode usar o shell mongosh:

// no mongosh
use iotdb;

db.createCollection('telemetry');
db.telemetry.createIndex({ deviceId: 1, ts: -1 });
db.telemetry.createIndex({ metric: 1, ts: -1 });

// teste de inserção
db.telemetry.insertOne({
  deviceId: "esp32-02",
  metric: "humidity",
  value: 45.2,
  unit: "%",
  ts: new Date(),
  source: "http"
});

// consulta por dispositivo e último período
db.telemetry.find({
  deviceId: "esp32-02",
  ts: { $gte: new Date(Date.now() - 24*60*60*1000) }
}).sort({ ts: -1 }).limit(10);
Onde aplicar: usaremos esta coleção no Passo 3 para inserções via API.

Passo 3 — Serviço receptor HTTP (Flask) com validação

Implemente um endpoint POST /ingest que recebe JSON no formato:

{
  "deviceId": "esp32-01",
  "metric": "temperature",
  "value": 23.5,
  "unit": "C",
  "ts": "2024-05-01T12:00:00Z",
  "backend": "mysql"  // ou "mongo"
}

Estruture o projeto com variáveis de ambiente para credenciais.

# .env (exemplo - NÃO versionar credenciais reais)
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DB=iotdb
MYSQL_USER=root
MYSQL_PASSWORD=senha

MONGO_URI=mongodb://localhost:27017
MONGO_DB=iotdb

app.py (Flask)

import os, json, datetime
from flask import Flask, request, jsonify
from dotenv import load_dotenv
import pymysql
from pymongo import MongoClient

load_dotenv()

app = Flask(__name__)

# MySQL connection factory
def get_mysql_conn():
    return pymysql.connect(
        host=os.getenv("MYSQL_HOST","127.0.0.1"),
        port=int(os.getenv("MYSQL_PORT","3306")),
        user=os.getenv("MYSQL_USER","root"),
        password=os.getenv("MYSQL_PASSWORD",""),
        database=os.getenv("MYSQL_DB","iotdb"),
        cursorclass=pymysql.cursors.DictCursor,
        autocommit=True
    )

# MongoDB client (reutilizável)
mongo_client = MongoClient(os.getenv("MONGO_URI","mongodb://localhost:27017"))
mongo_db = mongo_client[os.getenv("MONGO_DB","iotdb")]

def parse_ts(value):
    # aceita ISO 8601 ou epoch (segundos)
    if value is None:
        return None
    if isinstance(value, (int, float)):
        return datetime.datetime.utcfromtimestamp(value)
    try:
        return datetime.datetime.fromisoformat(value.replace("Z","+00:00")).replace(tzinfo=None)
    except Exception:
        return None

def validate_payload(p):
    errors = []
    # campos obrigatórios
    for f in ["deviceId","metric","value","ts"]:
        if f not in p:
            errors.append(f"Campo obrigatório ausente: {f}")
    # tipos e tamanhos
    if "deviceId" in p and (not isinstance(p["deviceId"], str) or len(p["deviceId"]) > 64):
        errors.append("deviceId inválido (string até 64).")
    if "metric" in p and (not isinstance(p["metric"], str) or len(p["metric"]) > 64):
        errors.append("metric inválido (string até 64).")
    if "unit" in p and (p["unit"] is not None) and (not isinstance(p["unit"], str) or len(p["unit"]) > 16):
        errors.append("unit inválido (string até 16).")
    if "value" in p and not isinstance(p["value"], (int, float)):
        errors.append("value inválido (numérico).")
    ts_parsed = parse_ts(p.get("ts"))
    if not ts_parsed:
        errors.append("ts inválido (ISO 8601 ou epoch).")
    # exemplo de regra de faixa (temperatura comum)
    if p.get("metric") == "temperature":
        v = p.get("value")
        if isinstance(v, (int,float)) and not (-50 <= v <= 150):
            errors.append("value fora da faixa esperada para temperatura (-50..150).")
    return errors, ts_parsed

@app.post("/ingest")
def ingest():
    try:
        data = request.get_json(force=True, silent=False)
    except Exception:
        return jsonify(ok=False, error="JSON inválido"), 400

    if not isinstance(data, dict):
        return jsonify(ok=False, error="Payload deve ser um objeto JSON"), 400

    errors, ts_parsed = validate_payload(data)
    if errors:
        return jsonify(ok=False, error="; ".join(errors)), 422

    deviceId = data["deviceId"].strip()
    metric   = data["metric"].strip()
    value    = float(data["value"])
    unit     = (data.get("unit") or "").strip() or None
    source   = (data.get("source") or "http").strip()[:16]
    backend  = (data.get("backend") or "mysql").lower().strip()

    # meta opcional: sanitiza para objeto JSON simples
    meta = data.get("meta")
    if meta is not None and not isinstance(meta, (dict, list, str, int, float, bool)):
        meta = None

    try:
        if backend == "mysql":
            with get_mysql_conn() as conn:
                with conn.cursor() as cur:
                    sql = ("INSERT INTO telemetry (deviceId, metric, value, unit, ts, source, meta) "
                           "VALUES (%s,%s,%s,%s,%s,%s,%s)")
                    cur.execute(sql, (deviceId, metric, value, unit, ts_parsed, source, json.dumps(meta) if meta is not None else None))
            return jsonify(ok=True, backend="mysql"), 201

        elif backend == "mongo":
            doc = {
                "deviceId": deviceId,
                "metric": metric,
                "value": value,
                "unit": unit,
                "ts": ts_parsed,
                "source": source
            }
            if meta is not None:
                doc["meta"] = meta
            mongo_db.telemetry.insert_one(doc)
            return jsonify(ok=True, backend="mongo"), 201

        else:
            return jsonify(ok=False, error="backend deve ser 'mysql' ou 'mongo'"), 400

    except Exception as e:
        # log simplificado (para aula)
        return jsonify(ok=False, error=f"Falha ao persistir: {str(e)}"), 500

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Passo 4 — Consultas de validação

Após os envios, confira se os dados chegaram corretamente.

MySQL

SELECT COUNT(*) AS total, MIN(ts) AS primeiro, MAX(ts) AS ultimo
FROM telemetry
WHERE deviceId = 'esp32-01'
  AND ts >= NOW() - INTERVAL 1 DAY;

MongoDB

db.telemetry.aggregate([
  { $match: { deviceId: "esp32-02", ts: { $gte: new Date(Date.now()-24*60*60*1000) } } },
  { $group: { _id: "$deviceId", total: { $sum: 1 }, primeiro: { $min: "$ts" }, ultimo: { $max: "$ts" } } }
]);

Passo 5 — Integração com o dispositivo (opcional)

Se já possui o dispositivo do Cap. 9, aponte o endpoint HTTP para o /ingest e envie medições reais. Caso use MQTT, crie uma ponte simples publicando em um serviço que converte mensagens (bridge) para HTTP, ou adapte seu firmware para enviar diretamente via POST.

# Exemplo MicroPython (esboço) para POST (ajuste para seu ambiente)
import urequests, ujson, time

payload = {
  "deviceId": "esp8266-lab",
  "metric": "temperature",
  "value": 25.1,

  "ts": "2024-05-01T13:10:00Z",
  "backend": "mysql"

r = urequests.post(URL, json=payload)

r.close()

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar a persistência de telemetria com validação, realizar consultas e documentar a API.

  1. Extensão de esquema: Adicione campo status (ok/fault) e ajuste o serviço para aceitar somente strings válidas. Crie índice em (status, ts) no MySQL e MongoDB.
  2. Validador de limites: Para a métrica humidity, rejeite valores fora de 0..100. Retorne HTTP 422 e mensage clara. Mostre 3 exemplos de payloads rejeitados e aceitos.
  3. Documentação: Crie um README com especificação do endpoint, exemplos de request/response e scripts de testes (cURL). Inclua comandos SQL/mongosh de verificação.

Critérios de Avaliação

  • Funcionamento end‑to‑end (envio, validação, persistência, consulta).
  • Qualidade do código (organização, tratamento de erros, mensagens claras).
  • Banco de dados (esquema correto, índices, consultas de validação).
  • Segurança básica (sem credenciais no código, uso de .env).
  • Documentação mínima e reprodutibilidade (comandos e exemplos).

Pesquisas complementares (sugestões)

  • Time-Series em MongoDB e alternativas (InfluxDB, TimescaleDB) — quando usar e prós/contras.
  • Migração de dados: como exportar/importar de MySQL para MongoDB (e vice-versa) em protótipos IoT.
  • Estratégias de retenção e arquivamento de telemetria (particionamento, TTL, agregações).
  • Boas práticas de nomenclatura de métricas e padronização de unidades (SI).

Entregáveis ao final do Capítulo 10

  • Serviço Flask funcional com endpoint /ingest validando e persistindo dados.
