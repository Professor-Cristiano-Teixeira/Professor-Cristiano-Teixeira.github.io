Capítulo 08 — MQTT: publicação, assinatura, tópicos e QoS

Carga: 4–6 horas

Projeto-base: Telemetria MQTT end‑to‑end com ESP8266/ESP32, publicação de sensor e assinatura de comandos para relé

Stack fixa: ESP8266/ESP32; MicroPython ou Arduino C++; Broker HiveMQ (público/cloud); MQTT Explorer/Studio

Resultados de aprendizagem deste capítulo:

  • Configurar cliente MQTT em dispositivo ESP e conectar‑se a um broker público de testes.
  • Publicar telemetria em tópicos hierárquicos com payload em JSON e boas práticas de nomenclatura.
  • Assinar tópicos de comando e acionar atuadores (relé/LED) de forma segura e com validação.
  • Ajustar QoS (0/1/2), usar retain e configurar LWT (Last Will and Testament).
  • Diagnosticar falhas de conexão e simular perda de link aplicando reconexão robusta.
  • Utilizar ferramentas (MQTT Explorer/Studio) para inspecionar tópicos, mensagens e retaineds.

Competências e Habilidades

  • Aplicar o padrão pub/sub com MQTT em cenários de IoT.
  • Estruturar tópicos e payloads com consistência e segurança básica.
  • Implementar lógica de reconexão e QoS adequado ao requisito.
  • Operar ferramentas de teste e interpretar logs do cliente/broker.

Parte Teórica (explicação do conteúdo)

MQTT e o padrão Pub/Sub

MQTT é um protocolo leve de mensagens baseado em publicação/assinatura (pub/sub). Em vez de clientes se comunicarem diretamente, todos falam com um broker central: dispositivos publicam mensagens em tópicos e outros dispositivos/serviços assinam tópicos de interesse. Isso desacopla produtores e consumidores, reduzindo complexidade e consumo de banda.

Onde vou aplicar isso: ao enviar telemetria do sensor para a nuvem e receber comandos de um painel de controle para acionar um relé/LED no Passo a passo.

Tópicos hierárquicos e convenções

Tópicos são strings hierárquicas separadas por “/”, como casa/sala/temperatura. Recomenda‑se padronizar: usar minúsculas, evitar espaços, definir prefixos por ambiente e deviceId. Ex.: iot/escola/lab01/deviceA/telemetry e iot/escola/lab01/deviceA/cmd.

Onde vou aplicar isso: você criará tópicos de telemetria e comando para o seu dispositivo, garantindo organização e filtragem fácil no broker.

Wildcards: + e #

Na assinatura, + substitui um único nível da hierarquia; # substitui níveis múltiplos no final. Ex.: iot/+/+/+/telemetry assina quatro níveis fixos e variações; iot/# pega tudo após iot/. Use com cuidado para não consumir mensagens demais.

Onde vou aplicar isso: no MQTT Explorer para monitorar um conjunto de dispositivos e no firmware para assinar o comando específico do seu deviceId.

QoS 0, 1 e 2

QoS 0 (no máximo uma vez): menor overhead, sem confirmação. QoS 1 (pelo menos uma vez): garante entrega com possível duplicação. QoS 2 (exatamente uma vez): mais confiável e custoso. Em IoT, geralmente telemetria usa QoS 0/1; comandos críticos podem usar QoS 1/2 conforme necessidade.

Onde vou aplicar isso: você alternará QoS para telemetria e para o tópico de comando e observará impactos no teste.

Retained messages

Uma mensagem marcada como retain fica armazenada no broker e é entregue imediatamente ao próximo assinante do tópico, útil para “último estado conhecido” (ex.: ON/OFF). Use com parcimônia e limpe retained quando necessário.

Onde vou aplicar isso: publicar o estado atual do relé como retained para que novos assinantes vejam o último estado.

LWT (Last Will and Testament)

O LWT é uma mensagem configurada na conexão MQTT para ser publicada pelo broker caso o cliente desconecte de forma inesperada. Ajuda a detectar dispositivos “offline” e acionar rotinas de alerta.

Onde vou aplicar isso: configurar um tópico de status com LWT para sinalizar offline/online do dispositivo.

Segurança básica

Evite credenciais embutidas no código público. Prefira usuários/senhas específicos, TLS quando disponível (porta 8883) e tópicos com privilégios mínimos. Em produção, use certificados e segregação por tenant.

Onde vou aplicar isso: separar credenciais em arquivo/constante isolada e, quando possível, testar broker com TLS.

Passo a Passo — Telemetria e comandos MQTT com ESP e broker público

Objetivo desta etapa:

Configurar um cliente MQTT no ESP8266/ESP32 que: (1) conecta ao Wi‑Fi e ao broker, (2) publica telemetria em JSON, (3) assina comandos para acionar um relé/LED, (4) usa QoS apropriado, retained para estado e LWT para status, (5) reconecta automaticamente em falhas.


1) Preparar ambiente e variáveis

Instale/abra o Thonny (MicroPython) ou Arduino IDE. Tenha um cliente MQTT (MQTT Explorer/Studio) e um broker de testes (ex.: broker.hivemq.com ou instância gratuita na HiveMQ Cloud). Ajuste SSID/senha do Wi‑Fi e parâmetros do broker.

Exemplo de configuração (JSON) para reutilizar:

{
  "wifi": { "ssid": "SEU_WIFI", "senha": "SUA_SENHA" },
  "mqtt": {
    "host": "broker.hivemq.com",
    "port": 1883,
    "clientId": "psic-dev-{{timestamp}}",
    "user": "",
    "pass": "",
    "baseTopic": "iot/escola/lab01/deviceA",
    "qosTelemetry": 0,
    "qosCmd": 1,
    "retainState": true,
    "useTLS": false
  }
}
Dica: Em produção, use porta 8883 e TLS habilitado. Em brokers públicos sem TLS, use somente para testes e nunca publique dados sensíveis.

2) MicroPython: cliente MQTT com telemetria, comando e LWT

O código abaixo demonstra conexão Wi‑Fi, MQTT com LWT, publicação periódica de telemetria simulada e assinatura de comando para acionar um pino (LED/relé).

# main.py (MicroPython para ESP8266/ESP32)
import network, time, json, machine
from umqtt.simple import MQTTClient

WIFI_SSID = "SEU_WIFI"
WIFI_PASS = "SUA_SENHA"

MQTT_HOST = "broker.hivemq.com"
MQTT_PORT = 1883
CLIENT_ID  = b"psic-dev-esp32"
BASE       = b"iot/escola/lab01/deviceA"
TOP_TELE   = BASE + b"/telemetry"
TOP_CMD    = BASE + b"/cmd"
TOP_STATE  = BASE + b"/state"
TOP_STATUS = BASE + b"/status"

LED_PIN = 2  # embarcado no ESP32/ESP8266 (ajuste se necessário)
led = machine.Pin(LED_PIN, machine.Pin.OUT)

def wifi_connect():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        wlan.connect(WIFI_SSID, WIFI_PASS)
        backoff = 1
        while not wlan.isconnected():
            print("Conectando Wi-Fi...", backoff)
            time.sleep(backoff)
            backoff = min(backoff * 2, 10)
    print("Wi-Fi OK:", wlan.ifconfig())
    return wlan

def on_msg(topic, msg):
    print("Msg recebida:", topic, msg)
    try:
        data = json.loads(msg)
        if "relay" in data:
            estado = 1 if str(data["relay"]).upper() in ("ON","1","TRUE") else 0
            led.value(estado)
            # publicar estado como retained
            payload = json.dumps({"relay": "ON" if estado else "OFF"})
            client.publish(TOP_STATE, payload, retain=True, qos=1)
    except Exception as e:
        print("Erro no handler:", e)

wifi_connect()

# Configura LWT: se desconectar abruptamente, broker publica "offline"
lwt_payload = json.dumps({"status":"offline"})
client = MQTTClient(client_id=CLIENT_ID,
                    server=MQTT_HOST,
                    port=MQTT_PORT,
                    user=None, password=None,
                    keepalive=30)
client.set_last_will(TOP_STATUS, lwt_payload, retain=True, qos=1)
client.set_callback(on_msg)

def ensure_mqtt():
    while True:
        try:
            client.connect(clean_session=True)
            client.subscribe(TOP_CMD, qos=1)
            # publica status online
            client.publish(TOP_STATUS, json.dumps({"status":"online"}), retain=True, qos=1)
            # publica estado atual
            client.publish(TOP_STATE, json.dumps({"relay":"ON" if led.value() else "OFF"}), retain=True, qos=1)
            print("MQTT conectado e inscrito em", TOP_CMD)
            return
        except Exception as e:
            print("Falha MQTT, tentando reconectar:", e)
            time.sleep(3)

ensure_mqtt()

# Loop principal: publica telemetria simulada
import random
while True:
    try:
        # processa mensagens recebidas
        client.check_msg()
        # telemetria (ex.: temperatura simulada)
        temp = 20 + random.uniform(-1.0, 1.5)
        payload = json.dumps({"t": round(temp,2), "ts": time.time()})
        client.publish(TOP_TELE, payload, qos=0)
        print("Pub:", payload)
        time.sleep(5)
    except Exception as e:
        print("Erro no loop, reconectando:", e)
        try:
            client.disconnect()
        except:
            pass
        time.sleep(2)
        ensure_mqtt()
Onde aplicar: este firmware será carregado no ESP; use o MQTT Explorer para enviar {"relay":"ON"} ao tópico /cmd e observar o estado em /state.

3) Alternativa em Arduino C++ (PubSubClient)

Se preferir Arduino IDE, utilize a biblioteca PubSubClient. Ajuste SSID/senha e tópicos. O exemplo abaixo faz o equivalente ao código MicroPython.

// Arduino C++ para ESP8266/ESP32 com PubSubClient
#include <WiFi.h>
#include <PubSubClient.h>

const char* WIFI_SSID = "SEU_WIFI";
const char* WIFI_PASS = "SUA_SENHA";
const char* MQTT_HOST = "broker.hivemq.com";
const int   MQTT_PORT = 1883;

const char* BASE      = "iot/escola/lab01/deviceA";
String TOP_TELE  = String(BASE) + "/telemetry";
String TOP_CMD   = String(BASE) + "/cmd";
String TOP_STATE = String(BASE) + "/state";
String TOP_STATUS= String(BASE) + "/status";

WiFiClient espClient;
PubSubClient client(espClient);
const int LED_PIN = 2;

void wifiConnect(){
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  int backoff = 500;
  while(WiFi.status() != WL_CONNECTED){
    delay(backoff);
    backoff = min(backoff*2, 4000);
  }
}

void publishState(){
  String payload = String("{\"relay\":\"") + (digitalRead(LED_PIN) ? "ON" : "OFF") + "\"}";
  client.publish(TOP_STATE.c_str(), payload.c_str(), true);
}

void callback(char* topic, byte* payload, unsigned int length){
  String msg;
  for(unsigned int i=0;i<length;i++) msg += (char)payload[i];
  if(String(topic) == TOP_CMD){
    if(msg.indexOf("ON") >= 0) digitalWrite(LED_PIN, HIGH);
    else digitalWrite(LED_PIN, LOW);
    publishState();
  }
}

void mqttConnect(){
  // LWT
  String lwt = "{\"status\":\"offline\"}";
  client.setServer(MQTT_HOST, MQTT_PORT);
  client.setCallback(callback);
  while(!client.connected()){
    if(client.connect("psic-dev-arduino", NULL, NULL, TOP_STATUS.c_str(), 1, true, lwt.c_str())){
      client.subscribe(TOP_CMD.c_str(), 1);
      client.publish(TOP_STATUS.c_str(), "{\"status\":\"online\"}", true);
      publishState();
    }else{
      delay(2000);
    }
  }
}

void setup(){
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);
  wifiConnect();
  mqttConnect();
}

void loop(){
  if(!client.connected()) mqttConnect();
  client.loop();
  // Telemetria simulada
  static unsigned long last = 0;
  if(millis() - last > 5000){
    last = millis();
    float temp = 20.0 + (random(-100,150)/100.0);
    String payload = String("{\"t\":") + String(temp,2) + ",\"ts\":" + String(millis()/1000) + "}";
    client.publish(TOP_TELE.c_str(), payload.c_str(), false);
  }
}

4) Testando com MQTT Explorer/Studio

Abra o cliente MQTT e conecte ao broker. Assine iot/# para visualizar tudo, depois filtre por iot/escola/lab01/deviceA/#. Envie comandos JSON para TOP_CMD e observe state/telemetry.

# Exemplo de publish via mosquitto_pub (opcional)
mosquitto_pub -h broker.hivemq.com -t iot/escola/lab01/deviceA/cmd -m '{"relay":"ON"}'
mosquitto_sub -h broker.hivemq.com -t 'iot/escola/lab01/deviceA/#' -v
Cheque retained: ao publicar com retain=true em /state, desconecte e reconecte o cliente de monitoramento; o último estado deve chegar imediatamente.

5) Simulando perda de conexão e reconexão

Desligue o Wi‑Fi do roteador por 1–2 minutos e religue. Verifique se o dispositivo reconecta ao Wi‑Fi e ao broker, republica status online e reenvia telemetria. Veja se o LWT foi publicado como offline durante a queda.

Boas práticas: exponha tempos de backoff progressivo, evite loops bloqueantes longos e use QoS coerente com o tipo de dado.
