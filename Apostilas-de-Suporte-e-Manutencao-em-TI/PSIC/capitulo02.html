Capítulo 02 — Revisão de programação para IoT (Python e C/C++)

Carga: 4h (teoria) + 2h (prática guiada)

Projeto-base: Telemetria de temperatura/umidade com máquina de estados e parser JSON

Stack fixa: Python 3.11+, Arduino IDE (C/C++), ESP8266/ESP32 (Wokwi opcional), ArduinoJson, logging, JSON

Parte Teórica (explicação do conteúdo)

Condicionais e laços

Condicionais (if/elif/else) e laços (for/while) controlam o fluxo do programa. Em IoT, são usados para verificar limites, temporizações e decidir quando ler sensores ou acionar atuadores. Em C/C++ e Python, a lógica é similar, mudando a sintaxe.

Laços não bloqueantes são preferíveis: usar contadores e checar tempo decorrido ao invés de delays longos melhora a responsividade do firmware.

Onde vou aplicar isso: no passo a passo, usaremos condicionais para validar leituras e laços para varrer o loop principal do firmware e do script.

Funções e módulos

Funções encapsulam tarefas recorrentes (ex.: ler_sensor, publicar_json). Módulos separam responsabilidades e melhoram manutenção. Em Python, criamos arquivos .py; em C/C++, dividimos em .h/.cpp.

Separar “camada de hardware” (GPIO) da “lógica de negócio” (regras do sensor) e da “rede” (MQTT/HTTP) facilita testes e evolução.

Onde vou aplicar isso: criaremos funções utilitárias para parsing de JSON e leitura de sensor; no Arduino, isolaremos a máquina de estados em funções.

Exceções e logs

Exceções indicam erros em tempo de execução. Em Python, use try/except e logging para registrar mensagens com níveis (DEBUG, INFO, WARNING, ERROR). Em embedded C/C++, não há exceções por padrão; use códigos de retorno e mensagens seriais/LEDs para diagnóstico.

Logs facilitam o troubleshooting, principalmente em IoT distribuída.

Onde vou aplicar isso: o script Python fará logging estruturado; no firmware, exibiremos estados e erros via Serial.

Arquivos e JSON

JSON é o formato de dados mais comum na telemetria IoT. Em Python, o módulo json lê/escreve dicionários; em Arduino, bibliotecas como ArduinoJson ajudam a compor e interpretar payloads com baixo custo.

Salvaremos leituras em um arquivo local (simulando um log) e construiremos/parciaremos JSON de telemetria.

Onde vou aplicar isso: persistiremos dados em arquivo no Python e receberemos/enviaremos JSON no firmware.

Dependências e bibliotecas

Bibliotecas aceleram o desenvolvimento. Em Python, use pip/venv; no Arduino IDE, use o Library Manager. Mantenha registro de versões no README para reprodutibilidade.

Onde vou aplicar isso: instalaremos ArduinoJson no Arduino IDE e estruturaremos requirements no Python.

Boas práticas de legibilidade

Nomeie variáveis claramente, comente intenções, use docstrings em Python e cabeçalhos em C. Evite “números mágicos”, prefira constantes. Mantenha funções curtas e coesas.

Onde vou aplicar isso: todo o código do passo a passo seguirá padrão de nomes, comentários e docstrings.

Máquina de estados finita (FSM) em IoT

FSM organiza a lógica como estados e transições: IDLE, READ, PROCESS, ALERT, etc. É fácil de debugar e escala melhor que “ifs” espalhados.

Onde vou aplicar isso: implementaremos uma FSM para um sensor de temperatura com alarme por limiar e histerese.

Estruturas de dados úteis

Em Python, dicionários e listas bastam para muitos fluxos de telemetria. Em C/C++, structs representam pacotes e buffers fixos são importantes para economia de RAM.

Onde vou aplicar isso: usaremos dict em Python para o payload e uma struct no Arduino para leituras.

Python — Parser de telemetria JSON com logs e arquivo

Crie o arquivo parser.py. O script simula recebimento de JSON de telemetria, valida campos, grava em arquivo e emite logs.

"""
parser.py — Parser de telemetria IoT com logs e persistência local
Conteúdo aplicado:
- condicionais, laços, funções, módulos
- exceções e logging
- leitura/escrita de arquivos e JSON
"""

import json
import logging
from datetime import datetime
from typing import Dict, Any, Optional

# Configuração de logs
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    datefmt="%H:%M:%S"
)
logger = logging.getLogger("telemetry")

def validar_payload(payload: Dict[str, Any]) -> bool:
    """Valida campos mínimos de uma telemetria."""
    campos = ["deviceId", "ts", "type", "value"]
    for c in campos:
        if c not in payload:
            logger.warning("Campo ausente: %s", c)
            return False
    if not isinstance(payload["value"], (int, float)):
        logger.warning("value deve ser numérico")
        return False
    return True

def processar_json(linha: str) -> Optional[Dict[str, Any]]:
    """Recebe uma string JSON, valida e retorna dict normalizado."""
    try:
        data = json.loads(linha)
        if not validar_payload(data):
            return None
        # Normaliza timestamp (ts) para ISO se vier numérico
        if isinstance(data["ts"], (int, float)):
            data["ts_iso"] = datetime.fromtimestamp(data["ts"]).isoformat()
        else:
            data["ts_iso"] = str(data["ts"])
        return data
    except json.JSONDecodeError as e:
        logger.error("JSON inválido: %s", e)
    except Exception as e:
        logger.error("Falha inesperada: %s", e)
    return None

def salvar_em_arquivo(reg: Dict[str, Any], caminho: str = "telemetria.log") -> None:
    """Acrescenta o registro JSON normalizado em um arquivo local (uma linha por JSON)."""
    try:
        with open(caminho, "a", encoding="utf-8") as f:
            f.write(json.dumps(reg, ensure_ascii=False) + "\n")
    except OSError as e:
        logger.error("Erro ao gravar arquivo: %s", e)

def main():
    exemplo = [
        '{"deviceId":"sensor-01","ts": 1700000000,"type":"temperature","value": 26.7}',
        '{"deviceId":"sensor-01","ts": "2024-01-01T10:00:00","type":"humidity","value": 55}',
        '{"deviceId":"sensor-01","ts": 1700000300,"type":"temperature","value": "alto"}'  # inválido
    ]
    for linha in exemplo:
        logger.info("Recebido: %s", linha)
        reg = processar_json(linha)
        if reg:
            logger.info("OK: %s %.2f @ %s", reg["type"], reg["value"], reg["ts_iso"])
            salvar_em_arquivo(reg)
        else:
            logger.warning("Registro descartado")

if __name__ == "__main__":
    main()

  "deviceId": "sensor-01",
  "ts": 1700000000,
  "type": "temperature",
  "value": 25.2
}

Arduino (C/C++) — Máquina de estados com histerese e JSON

Crie um sketch (ex.: cap02_fsm.ino). Simularemos a leitura do sensor com ruído, aplicaremos histerese e publicaremos JSON via Serial.

// cap02_fsm.ino — FSM simples para temperatura com histerese e JSON
// Conceitos: laços não bloqueantes, funções, struct, estados, logs seriais
#include <Arduino.h>
#include <ArduinoJson.h>

enum State { IDLE, READ, PROCESS, ALERT };
State state = IDLE;

struct Telemetry {
  const char* deviceId;
  float value;
  unsigned long ts;
};

const char* DEVICE_ID = "sensor-01";
const float LIMIAR = 28.0;
const float HISTER = 0.8;   // para evitar liga/desliga frequente
bool alertaAtivo = false;

unsigned long lastRead = 0;
const unsigned long READ_INTERVAL = 1000; // ms

float lerTemperaturaSimulada() {
  // Simulação: valor base + pequena variação
  static float base = 26.0;
  base += (random(-5, 6)) / 10.0; // -0.5 a +0.5
  return base;
}

void enviarJSON(const Telemetry &t) {
  StaticJsonDocument<200> doc;
  doc["deviceId"] = t.deviceId;
  doc["ts"] = t.ts / 1000;   // timestamp em segundos
  doc["type"] = "temperature";
  doc["value"] = t.value;
  String out;
  serializeJson(doc, out);
  Serial.println(out);
}

void setup() {
  Serial.begin(115200);
  delay(500);
  randomSeed(analogRead(A0));
  Serial.println(F("# Iniciando FSM de temperatura"));
}

void loop() {
  unsigned long now = millis();

  switch (state) {
    case IDLE:
      if (now - lastRead >= READ_INTERVAL) {
        state = READ;
      }
      break;

    case READ: {
      float temp = lerTemperaturaSimulada();
      Telemetry t{DEVICE_ID, temp, now};
      enviarJSON(t);
      lastRead = now;
      state = PROCESS;
      break;
    }

    case PROCESS: {
      // checa limiar com histerese
      // Entrar em ALERT se valor >= LIMIAR; sair apenas se valor <= (LIMIAR - HISTER)
      // Para obter o último valor lido, poderíamos guardar em variável global;
      // como exemplo didático, vamos recalcular nesta etapa:
      float temp = lerTemperaturaSimulada(); // (em projeto real, use o valor da leitura)
      if (!alertaAtivo && temp >= LIMIAR) {
        alertaAtivo = true;
        Serial.println(F("# ALERTA ATIVADO"));
        state = ALERT;
      } else if (alertaAtivo && temp <= (LIMIAR - HISTER)) {
        alertaAtivo = false;
        Serial.println(F("# ALERTA DESATIVADO"));
        state = IDLE;
      } else {
        state = IDLE;
      }
      break;
    }

    case ALERT:
      // Poderia acionar buzzer/LED ou publicar mensagem específica
      // Aqui, apenas loga a condição e retorna ao IDLE
      Serial.println(F("# Estado ALERT (ação: led/buzzer)"));
      state = IDLE;
      break;
  }
}
Dica: em produção, não relia o sensor no PROCESS. Armazene a última leitura para consistência entre estados.

Arduino — Parsing de JSON recebido (comandos)

Suponha que o dispositivo receba comandos JSON pela Serial (ex.: alterar limiar). Use ArduinoJson para parse.

// Trecho adicional: leitura de comando JSON pela Serial
void processarComandoSerial() {
  if (!Serial.available()) return;
  String linha = Serial.readStringUntil('\n');
  StaticJsonDocument<200> doc;
  DeserializationError err = deserializeJson(doc, linha);
  if (err) {
    Serial.println(F("# JSON inválido"));
    return;
  }
  const char* cmd = doc["cmd"];
  if (cmd && String(cmd) == "setThreshold") {
    float novo = doc["value"] | LIMIAR; // fallback no valor atual
    // Validação simples
    if (novo >= 10.0 && novo <= 80.0) {
      // cast away const for didática (em produção use variável não-const)
      *(float*)&LIMIAR = novo; // apenas para demo; prefira variável mutável
      Serial.print(F("# Limiar atualizado para: "));
      Serial.println(novo);
    } else {
      Serial.println(F("# Valor fora da faixa permitida"));
    }
  }
}

void loop() {
  unsigned long now = millis();
  processarComandoSerial();
  // ... restante do switch(state) mostrado antes ...
}
Importante: evite alterar variáveis const em projetos reais. Aqui foi ilustrativo. Use uma variável global mutável (ex.: float g_threshold).
