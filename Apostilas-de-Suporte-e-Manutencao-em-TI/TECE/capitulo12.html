Capítulo 12 — Ferramentas de IA para Automação de Suporte

Carga: 6–8 horas (2 encontros + prática orientada)

Projeto-base: Protótipo de triagem automática de chamados com IA (FAQ + classificação)

Stack fixa: Python 3, pandas, scikit-learn; alternativa sem código com plataforma de IA/NLP gratuita

Resultados de aprendizagem deste capítulo:

  • Identificar serviços e ferramentas de IA aplicáveis à automação de suporte (NLP, classificação, FAQ).
  • Configurar um classificador simples para triagem automática de tickets por categoria.
  • Calcular e interpretar métricas básicas de eficácia (precisão, recall, F1, acurácia, CSAT).
  • Planejar integrações comuns entre IA e sistemas de suporte (e-mail, help desk, webhooks).
  • Aplicar noções de segurança, privacidade e responsabilidade no uso de dados de tickets.

Competências e Habilidades

  • Mapear problemas de suporte que podem ser automatizados com IA.
  • Preparar dados etiquetados para treinar e avaliar um classificador de textos.
  • Operar uma pipeline básica de NLP e exportar um modelo.
  • Definir e monitorar métricas de qualidade do serviço automatizado.
  • Registrar decisões técnicas e cuidados de segurança/privacidade no diário de bordo.

Plano de Aula (Capítulo 12)

Objetivo do capítulo: Explorar serviços prontos de IA para automação de suporte e construir um classificador simples para triagem de chamados, medindo sua eficácia e discutindo boas práticas.

Pré-requisitos: Noções de redes, VMs e contas em nuvem (cap. 2–8), monitoramento (cap. 9), fundamentos de IA (cap. 11) e leitura técnica básica. Caso necessário, realizar nivelamento com microtarefas.

Estrutura sugerida:

  1. Exposição dialogada (30–40 min): panorama de ferramentas de IA para suporte, integrações e métricas.
  2. Demo guiada (30–40 min): pipeline curta de classificação de tickets (com e sem código).
  3. Laboratório prático (90–120 min): preparar dataset, treinar, avaliar e exportar o modelo.
  4. Reflexão e registro (20 min): riscos, privacidade, viés e próximos passos de integração com ITSM.

Critérios de avaliação formativa: corretude técnica, documentação do processo, análise das métricas, segurança/privacidade e clareza do diário de bordo.

Projeto Integrador — Entrega incremental (2º bimestre): incorporar um classificador de triagem ao protótipo de chatbot/FAQ e registrar como as categorias serão roteadas no ITSM simulado.

Parte Teórica (explicação do conteúdo)

1) Serviços de NLP, Classificação e FAQ

Ferramentas de IA para suporte geralmente oferecem três capacidades principais: processamento de linguagem natural (NLP) para entender textos, classificação para atribuir rótulos a tickets (como “Acesso”, “Senha”, “Impressora”) e mecanismos de FAQ/knowledge base para respostas rápidas. Plataformas variam entre soluções sem código, APIs prontas e bibliotecas para desenvolvimento.

Para suporte técnico, a classificação automatizada agiliza triagem, priorização e encaminhamento. O FAQ reduz carga do time ao responder dúvidas recorrentes. Em muitos cenários, uma combinação de FAQ + classificador + regras de roteamento traz ganhos imediatos.

Onde vou aplicar isso: no passo a passo você vai criar um classificador de tickets e, se quiser, acoplar a uma FAQ simples para respostas automáticas.

2) Integrações Comuns

Integrações ligam a IA às ferramentas de suporte: e-mail (para ler a fila de chamados), formulários web, chat/portal interno e sistemas ITSM (GLPI/OTRS/ServiceNow em ambientes de teste). Muitas integrações usam webhooks ou APIs REST para criar/atualizar tickets e anexar classificações ao fluxo.

Boas práticas incluem logs detalhados, versionamento do modelo e um modo “somente sugestão” antes de automatizar decisões. Sempre registre a origem do dado e mantenha trilhas de auditoria.

Onde vou aplicar isso: no passo a passo você verá como exportar previsões do classificador e um exemplo de payload JSON que poderia ser enviado a um ITSM.

3) Preparação de Dados de Tickets

Dados de tickets podem conter ruídos: abreviações, erros de digitação e informações sensíveis. A preparação inclui limpeza de texto, remoção de PII quando necessário, normalização (minúsculas, remoção de pontuação) e divisão treino/teste. Etiquetas claras e balanceadas elevam a qualidade do modelo.

Onde vou aplicar isso: você criará um CSV simples de tickets rotulados e usará uma pipeline de vetorização + classificador.

4) Métricas: Precisão, Recall, F1, Acurácia e CSAT

A acurácia informa o percentual total de acertos, mas pode enganar quando há classes desbalanceadas. Precisão mede o quão “confiável” é um acerto para uma classe; recall mede a cobertura dos itens daquela classe. F1 é a média harmônica entre precisão e recall. Fora do modelo, o CSAT (satisfação do cliente) avalia percepção do usuário.

Onde vou aplicar isso: você calculará métricas do classificador e registrará decisões de melhoria com base nos resultados.

5) Segurança, Privacidade e Responsabilidade

Ao usar tickets reais, proteja dados pessoais e sensíveis. Aplique o princípio do menor privilégio, anonimização quando possível e evite treinar modelos com dados que exponham credenciais, telefones ou outros PII. Documente o uso pretendido e mantenha revisão humana para casos ambíguos.

Onde vou aplicar isso: você adicionará uma etapa de anonimização simples no pré-processamento e registrará um checklist de conformidade no final.

Passo a Passo — Triagem automática de chamados com classificador NLP

Objetivo desta etapa:

Construir um classificador de textos para categorizar tickets de suporte (ex.: Senha, E-mail, Impressora, Rede), avaliar métricas e preparar a saída para integração com um fluxo ITSM.


Visão geral das trilhas

Você pode seguir uma das duas trilhas abaixo (ou ambas, se preferir):

  • Trilha A — Sem código: usar uma plataforma de IA/NLP gratuita para importar CSV, treinar classificador e exportar previsões.
  • Trilha B — Com código: usar Python, pandas e scikit-learn para treinar e avaliar um modelo localmente.

Passo 1 — Preparar o dataset rotulado (com anonimização)

Crie um arquivo CSV chamado tickets.csv com duas colunas: texto,classe. Mantenha frases curtas que representem o problema do usuário. Substitua nomes/telefones por placeholders.

texto,classe
"Não consigo entrar no e-mail corporativo","Email"
"Esqueci minha senha do Windows","Senha"
"Impressora do andar 2 não imprime","Impressora"
"Internet caiu no laboratório 1","Rede"
"Erro ao enviar anexos no Outlook","Email"
"Conta bloqueada após tentativas","Senha"
"Fila da impressora travada","Impressora"
"Queda de conexão Wi-Fi","Rede"

Dica: para bases maiores, garanta distribuição equilibrada entre as classes.

Passo 2 — Trilha A (sem código)

  1. Acesse uma plataforma de IA/NLP gratuita que permita treinamento de classificadores de texto.
  2. Crie um novo projeto/modelo de classificação e importe o arquivo tickets.csv.
  3. Configure a coluna de texto e a coluna de rótulo (classe). Execute o treinamento.
  4. Use a área de teste para digitar novos tickets e verificar a classe prevista.
  5. Exporte as previsões em CSV/JSON para integração futura.

Exemplo de payload de integração (fictício) para um ITSM via webhook:

{
  "ticket_id": "TCK-2024-0001",
  "titulo": "Problema de acesso ao e-mail",
  "descricao": "Usuário relata erro de login no e-mail.",
  "classificacao_prevista": "Email",
  "confianca": 0.92,
  "acao_sugerida": "Roteamento para fila: Suporte-Email"
}

Passo 3 — Trilha B (com código, Python + scikit-learn)

Instale dependências em um ambiente virtual local.

python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -U pip
pip install pandas scikit-learn

Crie o script train_classifier.py:

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, accuracy_score

# 1) Carregar dataset
df = pd.read_csv("tickets.csv")

# 2) Dividir treino/teste
X_train, X_test, y_train, y_test = train_test_split(
    df["texto"], df["classe"], test_size=0.25, random_state=42, stratify=df["classe"]
)

# 3) Pipeline: TF-IDF + Regressão Logística
pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(lowercase=True, stop_words=None)),
    ("clf", LogisticRegression(max_iter=1000))
])

# 4) Treinar
pipeline.fit(X_train, y_train)

# 5) Avaliar
y_pred = pipeline.predict(X_test)
print("Acurácia:", round(accuracy_score(y_test, y_pred), 3))
print(classification_report(y_test, y_pred))

# 6) Teste rápido
exemplos = [
    "Não consigo acessar meu email",
    "Minha senha expirou",
    "Impressora sem responder",
    "Wi-Fi instável no bloco B"
]
print("Exemplos de previsão:")
for t in exemplos:
    print(t, "=>", pipeline.predict([t])[0])

# 7) Salvar modelo (opcional)
import joblib
joblib.dump(pipeline, "modelo_ticket_clf.joblib")

Execute o treinamento:

python train_classifier.py

Crie um script para inferência em lote (gera JSON de saída):

import sys, json
import pandas as pd
import joblib

modelo = joblib.load("modelo_ticket_clf.joblib")
df = pd.read_csv("tickets_novos.csv")  # colunas: ticket_id,titulo,descricao
saidas = []
for _, row in df.iterrows():
    texto = f"{row['titulo']} {row['descricao']}"
    classe = modelo.predict([texto])[0]
    saidas.append({
        "ticket_id": row["ticket_id"],
        "classificacao_prevista": classe
    })

print(json.dumps(saidas, ensure_ascii=False, indent=2))

Passo 4 — Métricas e melhoria

Analise a acurácia e o relatório de classificação. Se alguma classe tiver recall baixo, colete mais exemplos e reequilibre a base. Experimente n-grams (TfidfVectorizer com ngram_range=(1,2)) e ajuste hiperparâmetros.

# Exemplo de ajuste simples
from sklearn.model_selection import GridSearchCV

params = {
    "tfidf__ngram_range": [(1,1), (1,2)],
    "clf__C": [0.5, 1.0, 2.0]
}

grid = GridSearchCV(pipeline, params, cv=3, n_jobs=-1)
grid.fit(X_train, y_train)
print("Melhor combinação:", grid.best_params_)
print("Score de validação:", grid.best_score_)

Passo 5 — Cuidados de segurança e privacidade

Remova PII dos textos antes de treinar. Exemplo simples de anonimização:

import re

def anonimizar(texto: str) -> str:
    # telefones
    t = re.sub(r"\b\d{2,3}[-.\s]?\d{4,5}[-.\s]?\d{4}\b", "[TELEFONE]", texto)
    # e-mails
    t = re.sub(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}", "[EMAIL]", t)
    # nomes próprios (heurística simples, ajustar conforme contexto)
    t = re.sub(r"\b([A-ZÁÉÍÓÚÂÊÔÃÕ][a-záéíóúâêôãõç]{2,})\b", "[NOME]", t)
    return t

Inclua no seu diário de bordo: quais dados foram coletados, como foram tratados e quem tem acesso ao repositório.
