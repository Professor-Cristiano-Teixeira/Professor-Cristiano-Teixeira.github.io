Capítulo 13 — Design de Chatbots e Fluxos de Conversa

Carga: 4h (2h teoria + 2h prática)

Projeto-base: Protótipo de chatbot de suporte orientado a metas (reset de senha e troubleshooting básico)

Stack fixa: Node.js 18+, JSON/Markdown para intents/FAQ, Bot Framework Emulator (local), Diagramação com draw.io/diagrams.net

Resultados de aprendizagem deste capítulo:

  • Planejar fluxos conversacionais eficazes com intenções, entidades e contexto.
  • Definir mensagens, confirmações, rotas de sucesso e estratégias de fallback.
  • Especificar requisitos de acessibilidade e linguagem clara para chatbots.
  • Modelar um fluxograma de conversa para reset de senha e troubleshooting.
  • Criar um artefato de design (JSON/YAML) representando intents e passos do diálogo.

Competências e Habilidades

  • Organizar o pensamento em fluxos e estados conversacionais.
  • Coletar e rotular dados de entrada (frases de exemplo, entidades).
  • Aplicar boas práticas de UX conversacional e linguagem inclusiva.
  • Projetar estratégias de recuperação de erros e confirmação com o usuário.
  • Documentar decisões de design e critérios de aceitação.
  • Preparar entregáveis reutilizáveis para implementação no capítulo 14.

Parte Teórica (explicação do conteúdo)

1) Intenções (intents), Entidades e Contexto

Intenções representam o objetivo do usuário ao falar com o chatbot, como “resetar senha” ou “ver status do chamado”. Cada intenção é treinada com frases de exemplo (utterances) para ajudar o modelo a reconhecer variações naturais de linguagem. Uma mesma frase pode acionar diferentes intenções dependendo do contexto e das palavras-chave.

Entidades são pedaços de informação que precisamos extrair da fala do usuário, como “usuário: joao.silva”, “sistema: e-mail corporativo” ou “número do ticket: 52341”. Entidades podem ser simples (um valor único) ou compostas (múltiplas partes), e podem ter sinônimos ou padrões (regex) para facilitar a extração.

O contexto é o “estado da conversa”. Ele guarda informações já coletadas (ex.: usuário autenticado, canal de atendimento) e direciona os próximos passos do fluxo. Sem contexto, a conversa vira uma sequência solta de perguntas e respostas. Com contexto, conseguimos confirmar dados, pular etapas e lidar com ambiguidades de forma inteligente.

Onde vou aplicar isso no passo a passo: você definirá intents e entidades em um JSON de design e usará o contexto para controlar o fluxo de reset de senha e troubleshooting.

2) Mensagens, Confirmações e Desambiguação

Mensagens devem ser claras, curtas e orientadas a ação. Prefira linguagem simples e direta, evite jargões desnecessários e ofereça sempre a próxima etapa. Em fluxos críticos (como reset de senha), mensagens de confirmação são essenciais para validar dados e reduzir erros.

A desambiguação ocorre quando o chatbot encontra múltiplas interpretações possíveis. Em vez de “adivinhar”, ele deve perguntar de forma objetiva: “Você quer resetar a senha do e-mail ou do sistema de RH?”. Essa prática aumenta a precisão e a satisfação do usuário.

Confirmações podem ser explícitas (“Confirmar e prosseguir?”) ou implícitas (repetir o dado antes do próximo passo). Em casos sensíveis, prefira confirmações explícitas e registre as decisões no contexto para auditoria.

Onde vou aplicar isso no passo a passo: você projetará mensagens modelo, confirmações e perguntas de desambiguação no fluxograma e nos artefatos JSON.

3) Fallback, Erros e Contenção

Fallback é a estratégia quando o chatbot não entende a intenção ou falha ao executar uma ação. Um bom fallback reconhece a limitação, oferece opções alternativas ou encaminha para um canal humano, mantendo a experiência positiva.

Trate erros de forma informativa e empática: explique o que deu errado em linguagem simples e sugira o que o usuário pode tentar a seguir. Sempre registre o motivo do erro para futura melhoria do fluxo.

Contenção significa resolver solicitações sem precisar escalar para humanos. O objetivo é alto, mas não absoluto: o foco é qualidade e segurança. Defina critérios claros de quando escalar (ex.: múltiplas tentativas falhas, dado sensível incompleto).

Onde vou aplicar isso no passo a passo: você criará respostas de fallback e regras de escalonamento em pontos críticos do fluxo.

4) Acessibilidade e Linguagem Clara

Chatbots precisam ser inclusivos. Utilize linguagem clara, frases curtas, evite ambiguidade e ofereça alternativas quando usar siglas. Garanta contraste adequado na interface, suporte a leitores de tela e tempo suficiente para resposta do usuário.

Considere boas práticas como: feedback imediato, evitar blocos longos de texto, oferecer opções numeradas e permitir correções (“digite 1 para alterar o e-mail informado”). Respeite normas de privacidade e evite solicitar dados sensíveis sem necessidade.

Onde vou aplicar isso no passo a passo: você revisará cada mensagem do fluxo com critérios de acessibilidade e linguagem clara antes da validação em pares.

5) Métricas de Qualidade Conversacional

Para avaliar o design, acompanhe métricas como taxa de compreensão de intenção, passos por resolução, taxa de contenção, reinterpretações (reprompts) e satisfação do usuário (CSAT). No design, antecipe pontos que podem gerar confusão e planeje medições.

Durante testes, colete transcrições e classifique tipos de erro (intenção errada, entidade ausente, mensagem confusa). Use esse feedback para refinar exemplos de treino e mensagens.

Onde vou aplicar isso no passo a passo: você incluirá critérios de aceitação e indicadores no artefato do fluxo para avaliação no capítulo 14.

Passo a Passo — Design de fluxos para reset de senha e troubleshooting

Objetivo desta etapa:

Modelar intenções, entidades, mensagens e estados de conversa; criar um fluxograma e um artefato JSON base para implementação posterior.


Passo 1 — Definir intenções e entidades

Liste as intenções principais e as entidades necessárias. Inclua frases de exemplo variadas (sinônimos, ordem das palavras, erros comuns). Comece com um escopo enxuto e claro.

{
  "intents": [
    {
      "name": "resetar_senha",
      "examples": [
        "Esqueci minha senha",
        "Preciso resetar a senha do e-mail",
        "Como troco minha senha?",
        "reset de senha email corporativo"
      ],
      "entities": ["sistema", "usuario"]
    },
    {
      "name": "troubleshooting_basico",
      "examples": [
        "Meu computador está lento",
        "Navegador travando",
        "Erro ao abrir o sistema de RH",
        "problema no login"
      ],
      "entities": ["sistema", "erro", "prioridade"]
    },
    {
      "name": "status_chamado",
      "examples": [
        "Ver status do chamado 52341",
        "Qual é o andamento do ticket 1002?"
      ],
      "entities": ["ticket_id"]
    }
  ],
  "entities": {
    "sistema": {
      "type": "list",
      "values": [
        {"value":"email","synonyms":["e-mail", "email corporativo", "correio"]},
        {"value":"rh","synonyms":["sistema de rh","folha","recursos humanos"]}
      ]
    },
    "usuario": { "type": "pattern", "pattern": "^[a-z0-9_.-]+$" },
    "ticket_id": { "type": "pattern", "pattern": "^[0-9]{3,6}$" },
    "erro": { "type": "free_text" },
    "prioridade": {
      "type":"list",
      "values":[
        {"value":"alta","synonyms":["urgente","critico"]},
        {"value":"media","synonyms":["normal"]},
        {"value":"baixa","synonyms":["pode esperar"]}
      ]
    }
  }
}
Dica: Use exemplos reais de tickets da sua organização (anonimizados) para enriquecer as frases e sinônimos.

Passo 2 — Esboçar o fluxograma

Desenhe o fluxo no diagrams.net. Inclua estados: Início, Coleta de dados, Confirmação, Ação, Sucesso, Fallback, Escalonamento. Indique condições (ex.: “sistema não informado?”) e mensagens correspondentes.

# Fluxograma (resumo textual)
[Início] -> Detectar intenção
  - resetar_senha?
    - coletar(usuario)
    - coletar(sistema)
    - confirmar dados
    - acao: gerar link de reset (mock)
    - sucesso ou fallback/escala
  - troubleshooting_basico?
    - coletar(sistema, erro, prioridade)
    - sugerir passos (checklist)
    - confirmar resolução
    - sucesso ou escalar
  - caso contrário: fallback genérico + opções
Critérios: cada seta deve ter condição clara; cada estado deve ter 1) mensagem de saída, 2) dados necessários, 3) próxima ação.

Passo 3 — Especificar mensagens, confirmações e desambiguação

Escreva mensagens curtas e numeradas quando houver opções. Planeje confirmações explícitas para dados sensíveis e perguntas de desambiguação quando faltar precisão.

{
  "messages": {
    "greeting": "Olá! Sou o assistente de suporte. Como posso ajudar?",
    "ask_usuario": "Informe seu usuário de rede (ex.: nome.sobrenome).",
    "ask_sistema": "Para qual sistema? 1) E-mail corporativo  2) RH",
    "confirm_reset": "Você confirma resetar a senha de {sistema} para o usuário {usuario}? (sim/não)",
    "reset_sucesso": "Tudo certo! Enviamos as instruções de reset para o seu e-mail alternativo cadastrado.",
    "trbl_collect": "Descreva brevemente o problema e, se possível, informe o sistema e a prioridade.",
    "trbl_checklist": "Tente: 1) Reiniciar o app  2) Limpar cache  3) Verificar conexão. Funcionou? (sim/não)",
    "fallback": "Desculpe, não entendi. Você gostaria de: 1) Resetar senha  2) Resolver problema  3) Ver status de chamado?",
    "handover": "Vou encaminhar para um atendente humano. Anote o protocolo: {protocolo}.",
    "clarify_sistema": "Você se refere ao e-mail corporativo ou ao sistema de RH?"
  }
}

Passo 4 — Modelar estados e transições com contexto

Crie uma máquina de estados simples em JSON. Cada estado define a mensagem, os dados esperados, validações e as transições conforme a entrada do usuário.

{
  "states": {
    "inicio": {
      "onEnter": "greeting",
      "routes": [
        {"ifIntent":"resetar_senha","to":"coletar_usuario"},
        {"ifIntent":"troubleshooting_basico","to":"trbl_coletar"},
        {"else":"fallback_menu"}
      ]
    },
    "coletar_usuario": {
      "onEnter": "ask_usuario",
      "expect": {"entity":"usuario","saveAs":"ctx.usuario"},
      "next": "coletar_sistema"
    },
    "coletar_sistema": {
      "onEnter": "ask_sistema",
      "expect": {"entity":"sistema","saveAs":"ctx.sistema"},
      "ifAmbiguous": "perguntar_sistema",
      "next": "confirmar_reset"
    },
    "perguntar_sistema": {
      "onEnter":"clarify_sistema",
      "expect": {"entity":"sistema","saveAs":"ctx.sistema"},
      "next":"confirmar_reset"
    },
    "confirmar_reset": {
      "onEnter": "confirm_reset",
      "expect": {"type":"yesno","saveAs":"ctx.confirm"},
      "routes": [
        {"ifEquals":{"var":"ctx.confirm","value":"sim"},"to":"acao_reset"},
        {"else":"fallback_menu"}
      ]
    },
    "acao_reset": {
      "action": "mock_reset_password",
      "onSuccess": "reset_sucesso",
      "next": "fim"
    },
    "trbl_coletar": {
      "onEnter": "trbl_collect",
      "expect": {"entities":["sistema","erro","prioridade"],"saveAs":"ctx.trbl"},
      "next": "trbl_sugerir"
    },
    "trbl_sugerir": {
      "onEnter": "trbl_checklist",
      "expect": {"type":"yesno","saveAs":"ctx.trbl_ok"},
      "routes": [
        {"ifEquals":{"var":"ctx.trbl_ok","value":"sim"},"to":"fim"},
        {"else":"handover"}
      ]
    },
    "fallback_menu": {
      "onEnter":"fallback",
      "expect":{"type":"option","values":["1","2","3"]},
      "routes":[
        {"ifEquals":{"var":"input","value":"1"},"to":"coletar_usuario"},
        {"ifEquals":{"var":"input","value":"2"},"to":"trbl_coletar"},
        {"ifEquals":{"var":"input","value":"3"},"to":"fim"}
      ]
    },
    "handover": {
      "onEnter":"handover",
      "next":"fim"
    },
    "fim": {}
  }
}

Passo 5 — Prototipar diálogo local (simulação)

Use um script simples em Node.js para simular a máquina de estados no terminal. Isso ajuda a validar mensagens e lógica antes da implementação na plataforma do capítulo 14.

// simflow.js - Simulador simples de fluxo (Node.js)
const readline = require('readline');

const ctx = { usuario: null, sistema: null, trbl: {}, trbl_ok: null };
const messages = {
  greeting: "Olá! Sou o assistente de suporte. Como posso ajudar?",
  ask_usuario: "Informe seu usuário de rede (ex.: nome.sobrenome).",
  ask_sistema: "Para qual sistema? 1) E-mail corporativo  2) RH",
  confirm_reset: (c) => `Você confirma resetar a senha de ${c.sistema} para o usuário ${c.usuario}? (sim/não)`,
  reset_sucesso: "Tudo certo! Enviamos as instruções de reset para o seu e-mail alternativo cadastrado.",
  trbl_collect: "Descreva o problema, informe sistema (email/rh) e prioridade (alta/media/baixa).",
  trbl_checklist: "Tente: 1) Reiniciar o app  2) Limpar cache  3) Verificar conexão. Funcionou? (sim/não)",
  fallback: "Desculpe, não entendi. 1) Resetar senha  2) Resolver problema  3) Ver status de chamado"
};

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
let state = 'inicio';

function ask(text){
  return new Promise(res => rl.question(text + '\n> ', res));
}

function intentFrom(text){
  text = text.toLowerCase();
  if (text.includes('senha') || text.includes('reset')) return 'resetar_senha';
  if (text.includes('problema') || text.includes('erro') || text.includes('trava')) return 'troubleshooting_basico';
  if (text.includes('status') || text.includes('ticket')) return 'status_chamado';
  return null;
}

function parseSistema(text){
  if (/1|email|e-mail/.test(text.toLowerCase())) return 'email';
  if (/2|rh/.test(text.toLowerCase())) return 'rh';
  return null;
}

async function loop(){
  while(true){
    if(state === 'inicio'){
      const input = await ask(messages.greeting);
      const it = intentFrom(input);
      state = it === 'resetar_senha' ? 'coletar_usuario' :
              it === 'troubleshooting_basico' ? 'trbl_coletar' : 'fallback_menu';
    }
    else if(state === 'coletar_usuario'){
      ctx.usuario = await ask(messages.ask_usuario);
      state = 'coletar_sistema';
    }
    else if(state === 'coletar_sistema'){
      const s = await ask(messages.ask_sistema);
      ctx.sistema = parseSistema(s) || await ask("Digite 'email' ou 'rh':\n> ");
      state = 'confirmar_reset';
    }
    else if(state === 'confirmar_reset'){
      const c = await ask(typeof messages.confirm_reset === 'function' ? messages.confirm_reset(ctx) : messages.confirm_reset);
      state = (c.toLowerCase().startsWith('s')) ? 'acao_reset' : 'fallback_menu';
    }
    else if(state === 'acao_reset'){
      console.log(messages.reset_sucesso);
      state = 'fim';
    }
    else if(state === 'trbl_coletar'){
      const d = await ask(messages.trbl_collect);
      ctx.trbl = { descricao: d };
      state = 'trbl_sugerir';
    }
    else if(state === 'trbl_sugerir'){
      const ok = await ask(messages.trbl_checklist);
      state = ok.toLowerCase().startsWith('s') ? 'fim' : 'handover';
    }
    else if(state === 'handover'){
      console.log("Encaminhando para humano. Protocolo: 2024-0001");
      state = 'fim';
    }
    else if(state === 'fallback_menu'){
      const opt = await ask(messages.fallback);
      state = (/^1/.test(opt)) ? 'coletar_usuario' : (/^2/.test(opt)) ? 'trbl_coletar' : 'fim';
    }
    else if(state === 'fim'){
      console.log("Sessão finalizada. Obrigado!");
      break;
    }
  }
  rl.close();
}
loop();
Como executar: salve como simflow.js, rode com node simflow.js e interaja no terminal.

Passo 6 — Revisar com critérios de acessibilidade e qualidade

Valide cada mensagem: é clara? curta? inclusiva? Há opções numeradas quando adequado? Existem confirmações em pontos críticos? O fluxo trata ambiguidades e erros? Documente ajustes e prepare os artefatos para o capítulo 14.

Checklist de revisão
- [ ] Mensagens curtas, sem jargões
- [ ] Opções numeradas quando há menu
- [ ] Confirmação explícita para ações sensíveis
- [ ] Fallback com caminhos úteis
- [ ] Registros de contexto suficientes
- [ ] Desambiguação quando necessário
- [ ] Preparado para testes e métricas
