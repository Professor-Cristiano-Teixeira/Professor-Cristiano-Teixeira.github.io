Capítulo 15 — Integração com ITSM e Canais de Atendimento

Carga: 6h

Projeto-base: Chatbot de Suporte integrado a ITSM (ambiente de teste)

Stack fixa: Chatbot (plataforma gratuita) + GLPI/OTRS de teste + Webhooks + API REST + Node.js/Python

Resultados de aprendizagem deste capítulo:

  • Explicar conceitos de ITSM, catálogo de serviços e ciclo de vida de tickets.
  • Configurar integração via API/webhook entre chatbot e ferramenta ITSM (GLPI/OTRS ou similar).
  • Implementar abertura e atualização de tickets a partir de canais (web, e-mail, chat).
  • Aplicar roteamento e priorização com base em regras de negócio (SLA, categoria, impacto/urgência).
  • Adotar práticas básicas de segurança: autenticação, tokens e sanitização de dados.

Competências e Habilidades

  • Instalar/configurar integrações com APIs REST e webhooks.
  • Modelar payloads de criação/atualização de tickets.
  • Aplicar roteamento por filas, categorias e SLAs.
  • Monitorar logs e lidar com erros/transientes de rede.
  • Documentar integrações e fluxos de suporte.

Plano de Aula (Capítulo 15)

Título: Integração com ITSM e Canais de Atendimento

Pré-requisitos recomendados: noções de redes (HTTP/HTTPS), uso de terminal/PowerShell, JSON, autenticação por token, conceitos de chatbot (intenções/entidades) e capítulo 14 concluído (protótipo de FAQ).

Estrutura:

  1. Revisão breve de ITSM e catálogo de serviços (20 min).
  2. Como funcionam APIs e webhooks em ITSM (30 min).
  3. Segurança: tokens, mínimos privilégios, sanitização (20 min).
  4. Laboratório guiado: criar ticket via API (60–90 min).
  5. Extensão: atualização de ticket e roteamento (40 min).
  6. Teste de ponta a ponta e logs (30 min).

Materiais: GLPI/OTRS em ambiente de teste, conta em plataforma de chatbot gratuita, Node.js ou Python instalado, editor de texto, ferramentas de teste de API (curl, Postman/Insomnia).

Avaliação formativa: funcionamento do fluxo (abrir ticket), qualidade do payload, tratamento de erros e documentação do passo a passo.

Parte Teórica (explicação do conteúdo)

1) ITSM e Catálogo de Serviços — o que é e por que importa?

ITSM (IT Service Management) organiza como a TI entrega serviços aos usuários. Ferramentas como GLPI e OTRS ajudam a registrar, priorizar e resolver incidentes e requisições, com base em SLAs. O catálogo de serviços descreve o que a TI oferece (ex.: reset de senha, acesso a sistemas, solicitação de equipamento) e define campos mínimos, fluxo e responsáveis.

Aplicação no passo a passo: você usará o catálogo para mapear quais tipos de tickets o chatbot pode abrir e quais campos preencher (categoria, urgência, descrição, contato).

2) Integração via API e Webhooks — visão geral

APIs REST permitem criar, ler e atualizar dados na ferramenta ITSM por meio de endpoints HTTP. Já webhooks são callbacks que a própria plataforma de chatbot dispara quando certos eventos ocorrem (ex.: intenção "abrir_chamado" reconhecida). A integração conecta ambos: o chatbot recebe a intenção, constrói um payload JSON e chama a API do ITSM; quando o status do ticket muda, o ITSM pode chamar um endpoint seu para notificar o chatbot.

Aplicação no passo a passo: você vai configurar um webhook de saída no chatbot e um endpoint do ITSM para criação de tickets usando token de acesso.

3) Roteamento e Priorização

Roteamento decide para qual fila, grupo ou técnico um ticket vai. Priorização combina impacto e urgência para determinar o SLA e a ordem de atendimento. Regras comuns: categoria "Acesso" vai para a fila de Identidade; impacto "Alto" com urgência "Alta" resulta em prioridade "Crítica".

Aplicação no passo a passo: você implementará regras simples com base em categoria e canal de origem (chat = prioridade normal; chat + impacto alto = alta).

4) Segurança na Integração

Use HTTPS, tokens de API rotacionáveis, princípio do menor privilégio (token só pode criar/ler tickets necessários), validação/sanitização de entradas do usuário para evitar injeção e logs sem expor dados sensíveis. Separe ambientes (teste x produção) e registre auditoria.

Aplicação no passo a passo: você armazenará tokens em variáveis de ambiente, validará campos obrigatórios e tratará erros de rede/time-out.

5) Monitoramento e Observabilidade

Registre métricas como número de tickets abertos via chatbot, taxa de erro da API, tempo médio de resposta e CSAT. Logs estruturados em JSON facilitam análises e alertas. Integrações estáveis exigem testes periódicos e alarmes para falhas.

Aplicação no passo a passo: você adicionará logs claros para requisições e respostas do ITSM, e validará códigos HTTP.

Passo a Passo — Integração do Chatbot com ITSM (GLPI/OTRS)

Objetivo desta etapa:

Configurar um fluxo no qual o chatbot cria e atualiza tickets no ITSM via API REST, com roteamento básico e segurança mínima (tokens e validação).


Etapa 0 — Preparação do ambiente

  1. Provisionar um GLPI/OTRS de teste (pode ser local em VM ou instância de demonstração) e ativar a API REST.
  2. Criar um usuário de integração com perfil mínimo necessário para criar e ler tickets.
  3. Gerar um token de API e guardar em variável de ambiente.
  4. Ter um projeto simples em Node.js ou Python para os testes de chamada.

Exemplo de variáveis de ambiente (.env)

# arquivo: .env (não versionar)
ITSM_BASE_URL=https://seu-glpi-ou-otrs.local/api
ITSM_TOKEN=seu_token_secreto_aqui
ITSM_TOOL=glpi # ou otrs
DEFAULT_QUEUE=ServiceDesk

Etapa 1 — Criar ticket via API (teste isolado)

Antes de integrar ao chatbot, teste a criação de ticket diretamente na API para confirmar credenciais, payload e permissões.

cURL (modelo genérico)

curl -X POST "$ITSM_BASE_URL/tickets" \
  -H "Authorization: Bearer $ITSM_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Problema de acesso ao e-mail",
    "description": "Usuário relata erro 401 ao acessar webmail",
    "requester": {"email": "usuario@exemplo.com"},
    "category": "Acesso",
    "impact": "Alto",
    "urgency": "Média",
    "source": "Chatbot",
    "queue": "ServiceDesk"
  }'

Node.js (fetch)

import 'dotenv/config';

const base = process.env.ITSM_BASE_URL;
const token = process.env.ITSM_TOKEN;

async function criarTicket(dados){
  const res = await fetch(`${base}/tickets`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify(dados)
  });
  if(!res.ok){
    const body = await res.text();
    throw new Error(`Falha API (${res.status}): ${body}`);
  }
  return res.json();
}

(async () => {
  try {
    const resp = await criarTicket({
      title: 'Problema de acesso ao e-mail',
      description: 'Usuário relata erro 401 ao acessar webmail',
      requester: { email: 'usuario@exemplo.com' },
      category: 'Acesso',
      impact: 'Alto',
      urgency: 'Média',
      source: 'Chatbot',
      queue: 'ServiceDesk'
    });
    console.log('Ticket criado:', resp);
  } catch (e) {
    console.error('Erro:', e.message);
  }
})();

Python (requests)

import os, json, requests
BASE = os.getenv("ITSM_BASE_URL")
TOKEN = os.getenv("ITSM_TOKEN")

def criar_ticket(payload):
    r = requests.post(
        f"{BASE}/tickets",
        headers={"Authorization": f"Bearer {TOKEN}", "Content-Type": "application/json"},
        data=json.dumps(payload),
        timeout=15
    )
    if not r.ok:
        raise RuntimeError(f"Falha API ({r.status_code}): {r.text}")
    return r.json()

if __name__ == "__main__":
    try:
        resp = criar_ticket({
            "title": "Problema de acesso ao e-mail",
            "description": "Usuário relata erro 401 ao acessar webmail",
            "requester": {"email": "usuario@exemplo.com"},
            "category": "Acesso",
            "impact": "Alto",
            "urgency": "Média",
            "source": "Chatbot",
            "queue": "ServiceDesk"
        })
        print("Ticket criado:", resp)
    except Exception as e:
        print("Erro:", e)
Onde vou aplicar isso: este payload e tratamento de resposta serão usados diretamente no webhook do chatbot que abrirá o ticket.

Etapa 2 — Regras de roteamento e priorização

Implemente uma função que, a partir de categoria, impacto e urgência, defina fila e prioridade. Isso padroniza o ticket vindo do chatbot.

// roteamento.js
export function decidirRoteamento({ category, impact, urgency }) {
  const filaPorCategoria = {
    'Acesso': 'Identidade',
    'Hardware': 'Suporte_Hardware',
    'Software': 'Aplicacoes',
    'Rede': 'Infra_Network',
  };
  const queue = filaPorCategoria[category] || 'ServiceDesk';

  // matriz simples de prioridade
  const matriz = {
    'Alto|Alta': 'Crítica',
    'Alto|Média': 'Alta',
    'Médio|Alta': 'Alta',
    'Médio|Média': 'Média',
  };
  const chave = `${impact}|${urgency}`;
  const priority = matriz[chave] || 'Normal';

  return { queue, priority };
}
Onde vou aplicar isso: antes de enviar o payload ao ITSM, você calculará a fila e prioridade com base nos campos do usuário.

Etapa 3 — Webhook do Chatbot (saída)

Configure na plataforma do chatbot um webhook para a intenção "abrir_chamado". O provedor enviará um POST com os dados extraídos da conversa (nome, e-mail, categoria, descrição).

Exemplo de payload recebido no seu endpoint

{
  "intent": "abrir_chamado",
  "user": {
    "name": "João Silva",
    "email": "joao.silva@exemplo.com",
    "channel": "webchat"
  },
  "entities": {
    "categoria": "Acesso",
    "impacto": "Alto",
    "urgencia": "Média"
  },
  "text": "Não consigo entrar no e-mail corporativo"
}

Servidor Node.js para receber o webhook e chamar o ITSM

import 'dotenv/config';
import express from 'express';
import { decidirRoteamento } from './roteamento.js';

const app = express();
app.use(express.json());

const base = process.env.ITSM_BASE_URL;
const token = process.env.ITSM_TOKEN;

app.post('/webhook/abrir-chamado', async (req, res) => {
  try {
    const { intent, user, entities, text } = req.body || {};
    if (intent !== 'abrir_chamado') return res.status(400).json({ error: 'Intent inválida' });
    if (!user?.email || !text) return res.status(400).json({ error: 'Campos obrigatórios ausentes' });

    const category = entities?.categoria || 'Outros';
    const impact = entities?.impacto || 'Médio';
    const urgency = entities?.urgencia || 'Média';
    const { queue, priority } = decidirRoteamento({ category, impact, urgency });

    const payload = {
      title: `[${category}] Solicitação via ${user.channel || 'Chatbot'}`,
      description: text,
      requester: { email: user.email, name: user.name || '' },
      category, impact, urgency,
      source: 'Chatbot',
      queue, priority
    };

    const itsmResp = await fetch(`${base}/tickets`, {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' },
      body: JSON.stringify(payload)
    });

    const bodyText = await itsmResp.text();
    if (!itsmResp.ok) {
      console.error('Falha ITSM:', itsmResp.status, bodyText);
      return res.status(502).json({ error: 'Falha ao criar ticket', details: bodyText });
    }

    const data = JSON.parse(bodyText);
    // Retorne informações essenciais para o chatbot confirmar ao usuário
    return res.json({ message: 'Ticket criado', ticketId: data.id, priority });
  } catch (e) {
    console.error('Erro webhook:', e);
    return res.status(500).json({ error: 'Erro interno' });
  }
});

app.listen(3000, () => console.log('Webhook ouvindo em http://localhost:3000'));
Onde vou aplicar isso: este endpoint será cadastrado no provedor do chatbot como destino do webhook da intenção "abrir_chamado".

Etapa 4 — Atualização de ticket (status/comentário)

Implemente a capacidade de adicionar um comentário ao ticket ou mudar seu status quando o usuário enviar novas informações.

# adicionar comentário (modelo)
curl -X POST "$ITSM_BASE_URL/tickets/12345/comments" \
  -H "Authorization: Bearer $ITSM_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"Complemento: erro ocorre somente no Wi-Fi da empresa."}'

async function comentarTicket(id, texto){
  const res = await fetch(`${base}/tickets/${id}/comments`, {
    method: 'POST',
    headers: {'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json'},
    body: JSON.stringify({ text: texto })
  });
  if(!res.ok) throw new Error(`Falha comentário (${res.status})`);
  return res.json();
}
Onde vou aplicar isso: crie uma intenção "atualizar_chamado" no chatbot para coletar ID do ticket e o comentário, disparando este endpoint.

Etapa 5 — Segurança e validação

  • Valide e normalize entradas do usuário: tamanho máximo, caracteres inesperados, e-mails válidos.
  • Armazene tokens somente em variáveis de ambiente e nunca faça log de credenciais.
  • Trate timeouts e retentativas exponenciais, e implemente circuit breaker em produção.
function validarEmail(email){
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
}

function sanitizeTexto(t){
  return String(t).slice(0, 2000); // limita o tamanho
}

// uso no webhook:
if(!validarEmail(user?.email)) return res.status(400).json({ error: 'E-mail inválido' });
payload.description = sanitizeTexto(payload.description);
Onde vou aplicar isso: antes de enviar ao ITSM, aplique as funções de validação/sanitização no texto e nos campos críticos.

  1. No chatbot, execute a conversa de “abrir chamado” e confirme a criação do ticket.
  2. No ITSM, verifique se o ticket chegou na fila correta e com prioridade adequada.
  3. Teste erro de credencial (token inválido) e falta de campos obrigatórios para validar mensagens de erro.
  4. Inclua logs estruturados (JSON) para facilitar depuração.

  console.log(JSON.stringify({ ts: new Date().toISOString(), evt, ...extra }));
