Parte Teórica (explicação do conteúdo)

1) APT e dpkg: visão geral, repositórios, cache e chaves

O Linux Mint utiliza a pilha APT/dpkg herdada do Debian/Ubuntu. O dpkg é o gerenciador de pacotes de baixo nível que instala arquivos .deb. O APT (Advanced Package Tool) é a camada de alto nível que resolve dependências, consulta repositórios e oferece comandos amigáveis como apt update, apt install e apt upgrade.

Repositórios são fontes de pacotes assinados digitalmente, definidos em /etc/apt/sources.list e em arquivos .list em /etc/apt/sources.list.d/. O APT mantém um cache local de metadados em /var/lib/apt/lists/ e um cache de pacotes em /var/cache/apt/archives/.

Chaves GPG garantem a integridade/autenticidade dos pacotes. O Mint/Ubuntu mantém chaves em /etc/apt/trusted.gpg.d/. Ao adicionar um repositório, é comum importar sua chave pública para que o APT valide as assinaturas dos índices e dos pacotes.

Onde vou aplicar isso: no passo a passo, você atualiza índices (apt update), consulta repositórios e verifica políticas de versão e chaves.

2) Operações comuns: pesquisar, instalar, atualizar e remover

A rotina básica é: atualizar índices (apt update), inspecionar pacotes atualizáveis (apt list --upgradable), aplicar atualizações (apt upgrade) e, quando necessário, remover pacotes (apt remove ou apt purge para também remover arquivos de configuração).

Para pesquisar pacotes, use apt search e, para obter detalhes, apt show. Para verificar de qual repositório e com que prioridade uma versão vem, use apt-cache policy nome_do_pacote.

Onde vou aplicar isso: você realizará uma atualização segura e registrará no relatório as versões instaladas e atualizadas.

3) Pinning básico (prioridade de versões)

O pinning permite preferir versões de determinadas origens, definindo prioridades em /etc/apt/preferences.d/*. Cada entrada define Package, Pin (origem, release, versão) e Pin-Priority. Valores mais altos favorecem determinadas versões.

No Mint (base Ubuntu), o pinning é útil para controlar pacotes específicos que você não quer atualizar automaticamente, ou para manter compatibilidade em ambientes controlados.

Onde vou aplicar isso: no passo a passo, você verá como “congelar” temporariamente um pacote com apt-mark hold (uma forma simples) e como inspecionar políticas com apt-cache policy.

4) Snap e Flatpak: visão geral no Mint

Snap e Flatpak são formatos de empacotamento “sandboxed” e autocontidos. Eles permitem instalar versões recentes com dependências isoladas. O Linux Mint prioriza o Flatpak por padrão e, em versões recentes, o Snapd pode estar desativado ou opcional.

Use flatpak search/install para Flatpak e snap find/install para Snap (quando habilitado). Lembre-se: objetivos deste capítulo focam APT/dpkg; Snap/Flatpak são apresentados como alternativas.

Onde vou aplicar isso: você fará uma verificação rápida da presença do Flatpak e listará remotes, entendendo a diferença em relação ao APT.

5) Integridade e rollback simples

O APT valida assinaturas dos índices via chaves confiáveis. Você também pode verificar versões instaladas com dpkg -l e dpkg-query, comparar com políticas e, em alguns casos, reverter para uma versão específica: apt install pacote=versão. O “rollback” simples depende de a versão anterior estar disponível no repositório/cache.

Para evitar atualizações indesejadas, apt-mark hold congela um pacote. Para liberar, apt-mark unhold. Para limpeza e economia de espaço, use apt autoclean, apt clean e apt autoremove.

Onde vou aplicar isso: no roteiro prático, você fará freeze/unfreeze de um pacote e testará a instalação por versão, além de gerar relatório de versões para auditoria.

Passo a Passo — Automação segura de updates e relatório com APT

Objetivo desta etapa:

Aplicar atualização segura do sistema no Linux Mint via APT, realizar limpeza de cache, experimentar pinning simples (hold/unhold) e construir um script que gera relatório detalhado de versões instaladas para o portfólio.


Pré-validações

  1. Abra o Terminal (Ctrl+Alt+T) na VM Linux Mint Cinnamon.
  2. Confirme conectividade com a Internet: 
    ping -c 2 linuxmint.com || nmcli general status
  3. Atualize o índice de pacotes: 
    sudo apt update
  4. Verifique se há atualizações disponíveis: 
    apt list --upgradable

Atualização segura e inspeção

  1. Atualize os pacotes (interativamente): 
    sudo apt upgrade
    Dica: para atualizar kernel/componentes críticos, considere snapshot (ver Cap. 16) antes, em ambientes de produção.
  2. Inspecione detalhes de um pacote específico (ex.: nano): 
    apt show nano
apt-cache policy nano
  3. Listar pacotes instalados rapidamente: 
    dpkg -l | less
Relação com a teoria: você aplicou APT/dpkg, consultou repositórios e políticas de versão (tópicos 1 e 2).

Limpeza de cache e dependências órfãs

Após atualizar, limpe arquivos obsoletos e dependências que não são mais necessárias.

sudo apt autoremove -y
sudo apt autoclean
sudo apt clean
Relação com a teoria: manutenção preventiva com limpeza de cache (tópico 5).

Pinning simples: congelar um pacote (hold/unhold)

  1. Escolha um pacote comum (ex.: nano) e congele a versão: 
    sudo apt-mark hold nano
apt-mark showhold
  2. Descongele quando terminar o teste: 
    sudo apt-mark unhold nano
apt-mark showhold

Para pinning avançado, use arquivos em /etc/apt/preferences.d/ com prioridades (ver pesquisas complementares).

Rollback simples (instalar versão específica)

  1. Liste versões disponíveis para um pacote (ex.: nano): 
    apt-cache policy nano
  2. Se houver versões alternativas disponíveis, instale uma versão específica: 
    sudo apt install nano=VERSAO_EXATA
    Substitua VERSAO_EXATA pelo valor listado. Caso a versão não esteja mais no repositório, o rollback não será possível desta forma.

Flatpak/Snap: verificação rápida

# Flatpak (Mint costuma vir com suporte)
flatpak --version
flatpak remotes
# Snap (se instalado)
snap version || echo "Snap não habilitado"

Observe a diferença conceitual em relação ao APT (pacotes isolados, remotes/lojas distintas).

Script: atualização, limpeza e relatório de versões

Crie um diretório para scripts e um para relatórios.

mkdir -p ~/scripts ~/relatorios
nano ~/scripts/atualiza_mint.sh

Insira o conteúdo abaixo no arquivo:

#!/usr/bin/env bash
# atualiza_mint.sh — Atualiza APT, aplica upgrades, limpa e gera relatório
# Uso: sudo ./atualiza_mint.sh

set -euo pipefail

DATA="$(date +'%Y-%m-%d_%H-%M-%S')"
REL_DIR="${HOME}/relatorios"
REL_ARQ="${REL_DIR}/relatorio_pacotes_${DATA}.txt"
LOG_ARQ="${REL_DIR}/atualiza_${DATA}.log"

mkdir -p "${REL_DIR}"

{
  echo "==== INÍCIO: ${DATA} ===="
  echo "# Etapa 1: Atualizando índices"
  apt update

  echo "# Etapa 2: Listando atualizáveis"
  apt list --upgradable || true

  echo "# Etapa 3: Aplicando upgrades"
  apt upgrade -y

  echo "# Etapa 4: Limpezas"
  apt autoremove -y
  apt autoclean
  apt clean

  echo "# Etapa 5: Gerando relatório de versões instaladas"
  # Formato: pacote versão arquitetura descrição curta
  dpkg-query -W -f='${Package}\t${Version}\t${Architecture}\t${binary:Summary}\n' | sort -f > "${REL_ARQ}"

  echo "Relatório gerado em: ${REL_ARQ}"
  echo "==== FIM: $(date +'%Y-%m-%d_%H-%M-%S') ===="
} | tee "${LOG_ARQ}"

echo "Log salvo em: ${LOG_ARQ}"
echo "Concluído com sucesso."

Salve e feche (Ctrl+O, Enter, Ctrl+X). Torne executável e rode com privilégios:

chmod +x ~/scripts/atualiza_mint.sh
sudo ~/scripts/atualiza_mint.sh

Abra o relatório para conferir:

less ~/relatorios/relatorio_pacotes_*.txt
