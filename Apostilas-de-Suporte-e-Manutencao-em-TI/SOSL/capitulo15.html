Capítulo 15 — Introdução ao Shell Script e Automação

Carga: 4h (teórico-prática)

Projeto-base: VM Linux Mint Cinnamon no VirtualBox com automações administrativas

Stack fixa: Linux Mint Cinnamon, Bash, cron, systemd, tar, rsync, grep/sed/awk, journalctl, apt

Resultados de aprendizagem deste capítulo:

  • Escrever scripts bash seguros com shebang, permissões e variáveis de ambiente.
  • Usar parâmetros, condicionais e laços para automatizar rotinas administrativas.
  • Implementar logs, tratamento básico de erros e códigos de saída.
  • Criar um backup rotativo diário com verificação de espaço e registro em log.
  • Agendar a execução via cron e validar a automação com evidências (logs e saídas).

Competências e Habilidades

  • Aplicar automação com shell script em ambiente Linux.
  • Documentar scripts com comentários e mensagens de log.
  • Realizar troubleshooting de scripts e tarefas agendadas.
  • Adotar boas práticas de segurança e manutenção em automações.

Plano de Aula (Capítulo 15)

  1. Introdução (15 min): Contexto de automação no Linux, exemplos práticos do suporte técnico (backup, limpeza, verificação de serviços).
  2. Teoria (45 min): Estrutura de scripts bash, variáveis, parâmetros, condicionais, laços, funções; boas práticas (shebang, execução, logs, tratamento de erros, segurança); cron.
  3. Demonstração guiada (30 min): Construir um script incremental: iniciar simples, adicionar validações, logs e rotação.
  4. Laboratório (60–70 min): Estudantes desenvolvem o script de backup rotativo com checagem de espaço e agendam via cron. Validam logs e executam teste de restauração parcial.
  5. Fechamento (10 min): Revisão dos conceitos, checklist e direcionamento de atividades práticas e leituras.

Parte Teórica (explicação do conteúdo)

1) O que é um shell script? Estrutura básica

Shell script é um arquivo de texto com comandos do shell (bash, no Mint) executados em sequência. Ele permite automatizar tarefas repetitivas, padronizar rotinas e reduzir erros humanos. A estrutura básica inclui o shebang, comentários, variáveis e comandos.

O shebang indica qual interpretador executar. Em sistemas Linux, o bash costuma estar em /bin/bash. Comentários começam com # e servem para documentar.

Onde vou aplicar isso: no início do seu script de backup rotativo, definindo o interpretador correto e documentando o objetivo e uso.

#!/usr/bin/env bash
# backup_rotativo.sh - Realiza backup rotativo diário com log
# Uso: ./backup_rotativo.sh /origem /destino

echo "Início do backup..."

2) Permissões e execução

Para executar, o arquivo precisa ter permissão de execução. Use chmod +x para tornar o script executável. Você pode executar com ./script.sh ou explicitamente pelo interpretador bash script.sh.

Manter scripts em um diretório próprio (por exemplo, ~/bin) ajuda na organização. É possível incluir esse diretório no PATH para executar de qualquer lugar.

Onde vou aplicar isso: após criar o arquivo do script, definir execução e organizar no diretório adequado.

chmod +x backup_rotativo.sh
mkdir -p "$HOME/bin"
mv backup_rotativo.sh "$HOME/bin/"
# opcional: adicionar ~/bin ao PATH no ~/.bashrc

3) Variáveis, parâmetros e saída

Variáveis guardam valores temporários e são referenciadas com $NOME. Parâmetros posicionais ($1, $2, ...) recebem argumentos na linha de comando. Use echo para imprimir mensagens e exit N para informar sucesso (0) ou erro (não zero).

Valide entradas: verifique se diretórios existem e se parâmetros foram fornecidos. Exiba uma mensagem de uso em caso de erro.

Onde vou aplicar isso: receber caminhos de origem/destino e validar antes de executar o backup.

ORIGEM="$1"
DESTINO="$2"

if [[ -z "$ORIGEM" || -z "$DESTINO" ]]; then
  echo "Uso: $0 <origem> <destino>" >&2
  exit 2
fi

if [[ ! -d "$ORIGEM" ]]; then
  echo "Erro: origem não encontrada: $ORIGEM" >&2
  exit 3
fi

4) Condicionais e laços

Condicionais if/elif/else permitem executar blocos conforme condições. Laços for/while iteram sobre listas ou saídas de comandos. Combine com testes de arquivos (-d, -f, -s) e comparações de strings/números.

Onde vou aplicar isso: checar espaço disponível antes do backup, iterar por arquivos de log para rotação e limpeza.

# if com teste de espaço livre
LIVRE_KB=$(df -Pk "$DESTINO" | awk 'NR==2{print $4}')
NECESSARIO_KB=1048576  # ~1GB

if (( LIVRE_KB < NECESSARIO_KB )); then
  echo "Erro: espaço insuficiente em $DESTINO" >&2
  exit 4
fi

# for simples
for f in *.log; do
  [[ -e "$f" ]] || continue
  echo "Encontrado log: $f"
done

5) Funções, logs e tratamento de erros

Funções encapsulam trechos reutilizáveis e facilitam a leitura. Registre eventos com timestamps em arquivo de log e também no stdout. Trate erros com set -euo pipefail para tornar o script mais seguro e use trap para ações de limpeza.

Onde vou aplicar isso: criar função log(), validar comandos críticos e capturar falhas inesperadas.

set -o errexit
set -o nounset
set -o pipefail

LOGDIR="/var/log/backup_rotativo"
LOGFILE="$LOGDIR/backup-$(date +%F).log"

log() {
  local msg="$1"
  local ts
  ts="$(date '+%F %T')"
  echo "[$ts] $msg" | tee -a "$LOGFILE"
}

trap 'log "Falha inesperada. Código $?"; exit 99' ERR

6) Ferramentas de backup: tar e rsync

tar cria arquivos compactados e preserva permissões e estrutura. rsync sincroniza diretórios e permite cópias incrementais com eficiência. A escolha depende do objetivo: arquivo único versionado (tar) ou espelho com histórico (rsync + snapshots).

Onde vou aplicar isso: gerar um pacote tar.gz diário com sufixo de data e manter uma política de rotação.

# Exemplo com tar
ARQ="backup-$(date +%F).tar.gz"
tar -C "$ORIGEM" -czpf "$DESTINO/$ARQ" . 2>&1 | tee -a "$LOGFILE"

# Exemplo com rsync
# rsync -a --delete "$ORIGEM"/ "$DESTINO/espelho"/ 2>&1 | tee -a "$LOGFILE"

7) Agendamento com cron

cron executa comandos periodicamente com base em crontabs. Use crontab -e para editar tarefas do usuário e verifique a execução consultando logs e produzindo arquivos de saída com timestamps.

Onde vou aplicar isso: agendar a execução diária do backup à noite e redirecionar saídas para log.

# Editar crontab do usuário atual
crontab -e

# Agendar todo dia às 02:15 (exemplo)
15 2 * * * /home/aluno/bin/backup_rotativo.sh /home/aluno/Documentos /home/aluno/Backups >> /home/aluno/Backups/cron.log 2>&1

8) Boas práticas de segurança e organização

Evite caminhos relativos em cron, valide entradas, use aspas em variáveis para lidar com espaços, limite permissões em diretórios e logs sensíveis, e documente o uso no topo do script. Em ambiente de produção, considere systemd timers e armazenamento de logs no journal.

Onde vou aplicar isso: uso de aspas, validação de diretórios, permissão 700 no diretório de backups e 600 para logs.

install -d -m 700 "/home/aluno/Backups"
sudo install -d -m 750 "/var/log/backup_rotativo"
sudo chown "$USER":"$USER" "/var/log/backup_rotativo"
chmod 600 "/var/log/backup_rotativo"/*.log 2>/dev/null || true

Passo a Passo — Automação de backup rotativo diário com validações e cron

Objetivo desta etapa:

Criar, testar e agendar um shell script confiável que gera backup rotativo diário da pasta de trabalho, checa espaço em disco, registra logs e valida a execução automática via cron.


Passo 1 — Preparar diretórios e arquivo do script

Crie uma estrutura mínima para manter seus scripts e backups organizados. Defina permissões adequadas desde o início.

mkdir -p "$HOME/bin" "$HOME/Backups"
install -d -m 750 "$HOME/Backups"
cat >"$HOME/bin/backup_rotativo.sh" <<'EOF'
#!/usr/bin/env bash
# backup_rotativo.sh - Realiza backup rotativo diário com log
# Uso: ./backup_rotativo.sh <origem> <destino>
set -o errexit
set -o nounset
set -o pipefail

ORIGEM="${1:-}"
DESTINO="${2:-}"
LOGDIR="/var/log/backup_rotativo"
install -d -m 750 "$LOGDIR"
LOGFILE="$LOGDIR/backup-$(date +%F).log"

log() {
  local ts; ts="$(date '+%F %T')"
  echo "[$ts] $*" | tee -a "$LOGFILE"
}

erro() {
  log "ERRO: $*"
  exit 1
}

[[ -n "$ORIGEM" && -n "$DESTINO" ]] || erro "Uso: $0 <origem> <destino>"
[[ -d "$ORIGEM" ]] || erro "Origem inexistente: $ORIGEM"
install -d -m 750 "$DESTINO"

# Checar espaço livre (~1GB necessário)
LIVRE_KB=$(df -Pk "$DESTINO" | awk 'NR==2{print $4}')
NECESSARIO_KB=1048576
(( LIVRE_KB >= NECESSARIO_KB )) || erro "Espaço insuficiente em $DESTINO"

ARQUIVO="backup-$(hostname)-$(date +%F).tar.gz"
log "Iniciando backup de $ORIGEM para $DESTINO/$ARQUIVO"

# Gerar pacote
tar -C "$ORIGEM" -czpf "$DESTINO/$ARQUIVO" . 2>&1 | tee -a "$LOGFILE"
log "Pacote gerado: $DESTINO/$ARQUIVO"

# Rotação: manter últimos 7 arquivos
TOTAL=$(ls -1t "$DESTINO"/backup-*.tar.gz 2>/dev/null | wc -l | tr -d ' ')
if (( TOTAL > 7 )); then
  log "Aplicando rotação (manter 7). Atual: $TOTAL"
  ls -1t "$DESTINO"/backup-*.tar.gz | tail -n +8 | while read -r antigo; do
    log "Removendo: $antigo"
    rm -f -- "$antigo"
  done
fi

log "Backup concluído com sucesso."
exit 0
EOF

chmod +x "$HOME/bin/backup_rotativo.sh"
echo "Script criado em: $HOME/bin/backup_rotativo.sh"
Dica: Se o diretório /var/log/backup_rotativo exigir permissões elevadas, execute o script via cron do usuário atual e mantenha logs no seu $HOME como alternativa (ver Passo 5).

Passo 2 — Teste local com uma pasta de exemplo

Crie conteúdo de teste e execute o script manualmente para verificar mensagens, geração do tar.gz e rotação.

mkdir -p "$HOME/Documentos/lab_script"
echo "arquivo A" > "$HOME/Documentos/lab_script/a.txt"
echo "arquivo B" > "$HOME/Documentos/lab_script/b.txt"

"$HOME/bin/backup_rotativo.sh" "$HOME/Documentos/lab_script" "$HOME/Backups"

ls -lh "$HOME/Backups"
sudo tail -n 20 /var/log/backup_rotativo/backup-$(date +%F).log
Validação: verifique se o arquivo backup-host-AAAA-MM-DD.tar.gz foi criado e se o log contém “Backup concluído com sucesso.”

Passo 3 — Simular rotação (mais de 7 backups)

Execute o script várias vezes alterando a data no nome do arquivo para simular dias diferentes. Para testes rápidos, use um sufixo de hora adicional temporariamente.

# Crie uma cópia de teste que adiciona hora (apenas para simulação)
cp "$HOME/bin/backup_rotativo.sh" /tmp/backup_teste.sh
sed -i 's/\.tar\.gz/-$(date +%H%M%S).tar.gz/' /tmp/backup_teste.sh

for i in {1..10}; do
  /tmp/backup_teste.sh "$HOME/Documentos/lab_script" "$HOME/Backups"
  sleep 1
done

echo "Total após simulação:"; ls -1 "$HOME/Backups"/backup-*.tar.gz | wc -l
echo "Listagem:"; ls -1t "$HOME/Backups"/backup-*.tar.gz
Espera-se que restem apenas os 7 mais recentes no destino.

Passo 4 — Melhorias: verificação de integridade e tamanho

Após gerar o tar.gz, confira se o arquivo existe, tem tamanho maior que zero e pode ser listado com tar -tzf.

# Inserir após a criação do pacote no script principal
if [[ ! -s "$DESTINO/$ARQUIVO" ]]; then
  erro "Arquivo de backup ausente ou vazio: $DESTINO/$ARQUIVO"
fi

if ! tar -tzf "$DESTINO/$ARQUIVO" >/dev/null; then
  erro "Falha ao validar integridade do tar.gz"
fi

log "Integridade verificada: $ARQUIVO"

Passo 5 — Agendar execução diária com cron

Agende o script para rodar diariamente às 02:15. Redirecione saída padrão e erros para um log de cron no seu diretório pessoal, caso não use /var/log.

crontab -l 2>/dev/null > /tmp/mycron || true
echo '15 2 * * * /home/aluno/bin/backup_rotativo.sh /home/aluno/Documentos/lab_script /home/aluno/Backups >> /home/aluno/Backups/cron.log 2>&1' >> /tmp/mycron
crontab /tmp/mycron
rm -f /tmp/mycron

# Validar cron ativo
crontab -l
# Após a primeira execução programada, conferir:
tail -n 100 "$HOME/Backups/cron.log"
Observação: garanta caminhos absolutos no cron. Variáveis de ambiente são mínimas; se necessário, exporte PATH explicitamente no comando do cron.

Passo 6 — Evidências e restauração parcial de teste

Para comprovar a efetividade do backup, liste o conteúdo do tar.gz e restaure uma cópia de teste para uma pasta temporária.

# Listar conteúdo do último backup
ARQ_ULT=$(ls -1t "$HOME/Backups"/backup-*.tar.gz | head -n 1)
tar -tzf "$ARQ_ULT" | head

# Restaurar em pasta de teste
mkdir -p "$HOME/RestauradoTest"
tar -xzf "$ARQ_ULT" -C "$HOME/RestauradoTest"
ls -l "$HOME/RestauradoTest"
Entregue no portfólio: comando usado, saída do ls do destino e trecho do log confirmando sucesso.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar o uso de shell script, logs e agendamento para automações úteis no suporte.

  1. Limpeza controlada de cache: Escreva um script que liste diretórios temporários do usuário e ofereça a opção de limpeza segura (somente arquivos mais antigos que 14 dias). Gere log e simule via modo “dry-run”.
  2. Verificação de serviços essenciais: Crie um script que cheque se serviços como cups, ssh e NetworkManager estão ativos (systemctl is-active). Se algum estiver inativo, registre log, colete journalctl -u serviço --since "1 hour" e sinalize com código de saída diferente de zero.
  3. Relatório diário do sistema: Geração de relatório com uptime, uso de CPU/memória (top -b -n1 | head -n 5), espaço em disco (df -h) e pacotes atualizáveis (apt list --upgradable 2>/dev/null | wc -l). Agende com cron e arquive relatórios por data.

Critérios de avaliação

  • Corretude técnica (funciona conforme especificado, sem erros).
  • Boas práticas (shebang, validação de entradas, uso de aspas, códigos de saída, comentários).
  • Registro e evidências (logs claros, outputs e prints de execução/agendamento).
  • Organização do código (funções, legibilidade e padronização).
