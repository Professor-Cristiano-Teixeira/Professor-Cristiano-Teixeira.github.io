Capítulo 12 — Gerenciamento de Arquivos: navegação, cópia e backup

Carga: 6h

Projeto-base: Laboratório em VM no VirtualBox com Linux Mint Cinnamon

Stack fixa: Linux Mint Cinnamon, Terminal Bash, Nemo (gerenciador de arquivos), tar e rsync

Resultados de aprendizagem deste capítulo:

  • Executar operações de criação, listagem, cópia, movimentação e remoção de arquivos e diretórios via CLI e GUI.
  • Criar e gerenciar links simbólicos e hard links, entendendo impactos em armazenamento e organização.
  • Localizar arquivos usando find, inspecionar uso de disco com du/df e planejar limpeza segura.
  • Compactar/arquivar com tar e sincronizar pastas com rsync para uma rotina de backup simples.
  • Validar a integridade de um backup e documentar todos os passos com comandos e evidências.

Competências e Habilidades

  • Operar o sistema de arquivos com segurança e eficiência.
  • Aplicar boas práticas de organização conforme FHS em ambientes de usuário.
  • Planejar e executar rotinas de backup local com validação.
  • Produzir documentação técnica do procedimento realizado.

Plano de Aula (Capítulo 12)

  • Abertura (10 min): retomada rápida de FHS (Cap. 08) e CLI básica (Cap. 09).
  • Exposição guiada (35 min): comandos mkdir, touch, ls, cp, mv, rm, ln; boas práticas e segurança (lixeira/GUI vs terminal).
  • Exploração prática (40 min): exercícios progressivos de organização de pastas e arquivos em ~/trabalho.
  • Ferramentas de localização e espaço (25 min): find, du, df; diagnóstico de espaço, limpeza consciente.
  • Arquivamento e sincronização (40 min): tar (criar, listar, extrair) e rsync (parâmetros úteis) para backup local.
  • Validação e registro (20 min): verificação de integridade do backup, geração de logs e checklist.
  • Fechamento (10 min): dúvidas, orientações para atividades autônomas e portfólio.

Parte Teórica (explicação do conteúdo)

Navegação e criação de estrutura: mkdir, touch e ls

Para trabalhar com arquivos no Linux, você navegará pela árvore de diretórios e criará uma estrutura organizada. O comando mkdir cria diretórios (pastas). O touch cria arquivos vazios (ou atualiza a data de modificação se o arquivo já existir). O ls lista conteúdos e, com opções, mostra detalhes e arquivos ocultos.

Boas práticas incluem usar nomes descritivos e evitar espaços (ou usar aspas). Combine opções como ls -lha para ver permissões, tamanhos e datas em formato legível.

Onde vou aplicar isso: No passo a passo, você criará a pasta de trabalho, subpastas temáticas e arquivos de teste para simular documentos reais.

# criar estrutura
mkdir -p ~/trabalho/{documentos,imagens,projetos}
# criar arquivos vazios
touch ~/trabalho/documentos/relatorio.txt
# listar com detalhes e ocultos
ls -lha ~/trabalho

Cópia, movimentação e remoção: cp, mv, rm

O cp copia arquivos e diretórios. Use -r para copiar diretórios recursivamente e -i para confirmar sobregravação. O mv move ou renomeia arquivos. O rm remove arquivos e diretórios; por segurança, utilize -i para confirmação e -r para diretórios. Evite usar rm -rf sem total certeza do caminho.

Na interface gráfica (Nemo), a remoção vai para a Lixeira, o que é mais seguro para iniciantes. No terminal, a remoção é imediata.

Onde vou aplicar isso: Você copiará modelos para novas pastas, moverá arquivos para reestruturar e removerá itens temporários com confirmação.

# copiar diretório recursivamente (com confirmação)
cp -ir ~/trabalho/documentos ~/trabalho/backup_temp
# mover/renomear
mv ~/trabalho/relatorio.txt ~/trabalho/documentos/relatorio_v1.txt
# remover com confirmação
rm -i ~/trabalho/documentos/relatorio_v1.txt

Links no Linux: hard links e links simbólicos (ln)

Links permitem referenciar o mesmo conteúdo por múltiplos nomes. Hard links apontam para o mesmo inode (mesmo conteúdo) e só funcionam no mesmo sistema de arquivos. Links simbólicos (symlinks) são atalhos que apontam para um caminho e podem cruzar sistemas de arquivos, mas quebram se o alvo é movido.

Use ln arquivo link para hard links e ln -s alvo link para symlinks. Verifique com ls -li para ver inodes.

Onde vou aplicar isso: Você criará symlinks para atalhos de pastas usadas com frequência e testará um hard link para entender a relação com o arquivo original.

# hard link (mesmo inode)
ln ~/trabalho/documentos/notas.txt ~/trabalho/documentos/notas_hard.txt
# link simbólico (atalho)
ln -s ~/trabalho/projetos ~/trabalho/meus_projetos
# inspecionar inodes
ls -li ~/trabalho/documentos

Localização e espaço em disco: find, du e df

O find busca arquivos por nome, tipo, tamanho, data e executa ações (como deletar com confirmação). O du resume uso de disco por diretório, útil para achar pastas grandes. O df mostra o espaço livre e usado em sistemas de arquivos montados.

Combinados, eles ajudam na manutenção e limpeza consciente, evitando apagar dados importantes.

Onde vou aplicar isso: Você localizará arquivos específicos, identificará o que ocupa mais espaço e planejará seu backup com base nesses dados.

# localizar por nome (case-insensitive)
find ~/trabalho -iname "*relatorio*"
# uso de disco (tamanho legível, resumo por diretório de topo)
du -h --max-depth=1 ~/trabalho | sort -h
# espaço livre em todos os sistemas de arquivos
df -hT

Arquivamento e compactação: tar

O tar cria arquivos de arquivo (.tar) que reúnem múltiplos arquivos/diretórios. Com parâmetros, pode comprimir (por exemplo, .tar.gz com -z). Principais opções: -c (criar), -t (listar), -x (extrair), -v (verbose), -f (arquivo), -z (gzip), -J (xz).

Arquivar é útil para transportar e versionar snapshots de pastas, inclusive para backups simples.

Onde vou aplicar isso: Você criará um arquivo tar comprimido da sua pasta de trabalho e validará seu conteúdo antes de armazenar.

# criar arquivo tar.gz
tar -czvf ~/backup/trabalho_$(date +%F).tar.gz -C ~/ trabalho
# listar conteúdo do tar
tar -tzf ~/backup/trabalho_$(date +%F).tar.gz | head
# extrair para pasta de teste
mkdir -p ~/restores/teste
tar -xzvf ~/backup/trabalho_$(date +%F).tar.gz -C ~/restores/teste

Sincronização eficiente: rsync

O rsync sincroniza diretórios de forma incremental, transferindo apenas diferenças. Opções comuns: -a (arquivar, preserva permissões e recursivo), -v (verbose), -h (tamanhos legíveis), --delete (remove no destino o que não existe na origem), --progress (barra de progresso). Use barra final para controlar a semântica de origem/destino.

É excelente para backups locais e remotos. Em ambiente inicial, use sem --delete até ter confiança.

Onde vou aplicar isso: Você fará um backup incremental da pasta de trabalho para outra unidade/pasta e verificará diferenças.

# sincronizar origem em destino
rsync -avh --progress ~/trabalho/ /media/usuario/DADOS/backup_trabalho/
# simular (dry-run) sem alterar nada
rsync -avhn ~/trabalho/ /media/usuario/DADOS/backup_trabalho/
# comparar rapidamente com checksums (mais lento, porém rigoroso)
rsync -avhc --dry-run ~/trabalho/ /media/usuario/DADOS/backup_trabalho/

Gerenciador de Arquivos (Nemo) no Cinnamon

O Nemo é o gerenciador de arquivos do Cinnamon. Permite criar, copiar, mover, renomear e excluir arquivos com interface gráfica, incluindo envio para Lixeira e recuperação. Possui recursos de abas, pesquisa rápida, visão de detalhes e atalhos de teclado.

Útil para operações seguras do dia a dia; combine com o terminal para tarefas avançadas e automação.

Onde vou aplicar isso: Você repetirá as operações essenciais no Nemo, ativará exibição de arquivos ocultos e utilizará a Lixeira como segurança adicional.

Passo a Passo — Organização e Backup da pasta de trabalho

Objetivo desta etapa:

Criar uma estrutura de trabalho organizada em ~/trabalho, praticar operações de arquivo via CLI e GUI e implementar um backup local validado com tar e rsync.


1) Preparar o ambiente

  1. Abra o Terminal no Linux Mint (Ctrl+Alt+T) e garanta que sua VM está atualizada (você já viu no Cap. 10).
  2. Crie as pastas base do laboratório em sua Home.
# criar estrutura de trabalho
mkdir -p ~/trabalho/{documentos,imagens,projetos,temp}
# criar exemplos de arquivos
touch ~/trabalho/documentos/{relatorio.txt,notas.txt}
touch ~/trabalho/imagens/{banner.png,logo.svg}
echo "Projeto A" > ~/trabalho/projetos/README.txt

2) Navegar e listar conteúdos com detalhes

Observe permissões, tamanhos e datas; identifique arquivos ocultos se necessário.

# navegação e listagem
cd ~/trabalho
pwd
ls -lha
# criar arquivo oculto (config de exemplo)
echo "modo=teste" > ~/.config/minhaapp.conf
ls -lha ~/.config | head

3) Copiar, mover, renomear e remover com segurança

  1. Copie documentos para backup_temp com confirmação de sobregravação (-i).
  2. Renomeie relatorio.txt para relatorio_v1.txt e mova para projetos.
  3. Remova um arquivo temporário usando -i para confirmar.
cp -ir ~/trabalho/documentos ~/trabalho/backup_temp
mv ~/trabalho/documentos/relatorio.txt ~/trabalho/projetos/relatorio_v1.txt
rm -i ~/trabalho/temp/* 2>/dev/null || true
Dica: No Nemo, use Delete para enviar à Lixeira. Para restaurar, abra a Lixeira e use “Restaurar”.

4) Trabalhar com links: atalhos úteis

  1. Crie um link simbólico para a pasta projetos na raiz de ~/trabalho.
  2. Crie um hard link do arquivo notas.txt.
  3. Compare inodes para entender a diferença.
ln -s ~/trabalho/projetos ~/trabalho/meus_projetos
ln ~/trabalho/documentos/notas.txt ~/trabalho/documentos/notas_hard.txt
ls -li ~/trabalho/documentos

5) Localizar arquivos e avaliar uso de disco

  1. Encontre qualquer arquivo cujo nome contenha “relatorio”.
  2. Veja quais subpastas em ~/trabalho mais ocupam espaço.
  3. Cheque o espaço disponível no sistema de arquivos.
find ~/trabalho -iname "*relatorio*"
du -h --max-depth=1 ~/trabalho | sort -h
df -hT

6) Criar backup com tar (snapshot compactado)

  1. Crie a pasta de destino de backups.
  2. Gere um arquivo tar.gz da pasta trabalho usando -C para evitar caminhos longos.
  3. Liste o conteúdo do tar para validar.
mkdir -p ~/backup
ARQ=~/backup/trabalho_$(date +%F_%H%M).tar.gz
tar -czvf "$ARQ" -C ~/ trabalho
# validar: listar e contar itens
tar -tzf "$ARQ" | wc -l
tar -tzf "$ARQ" | head
Validação rápida: Se a contagem bate com a expectativa e a listagem não falha, o arquivo foi gerado corretamente.

7) Sincronizar com rsync para outra unidade/pasta

Se você possui uma segunda unidade (ex.: /media/usuario/DADOS), sincronize a pasta de trabalho. Caso não tenha, use um diretório de teste em sua Home.

# ajuste DESTINO conforme seu ambiente
DESTINO="/media/$USER/DADOS/backup_trabalho"
# fallback se não existir a unidade DADOS
[ -d "$DESTINO" ] || DESTINO="$HOME/backup_destino"
mkdir -p "$DESTINO"

# simular sincronização (dry-run)
rsync -avhn ~/trabalho/ "$DESTINO"/

# executar sincronização real
rsync -avh --progress ~/trabalho/ "$DESTINO"/
Observação: A barra no fim de ~/trabalho/ copia o conteúdo. Sem barra, poderia criar um subdiretório trabalho dentro do destino.

8) Verificar integridade do backup

Verifique o tar e confira consistência do rsync. Para maior rigor, compare checksums de alguns arquivos amostrados.

# verificar se o tar está íntegro (listar sem erros)
tar -tzf "$ARQ" > /dev/null

# verificar diferenças com rsync em modo checksum
rsync -avhc --dry-run ~/trabalho/ "$DESTINO"/

# amostrar um arquivo e comparar checksum
ARQ_TESTE=~/trabalho/documentos/notas.txt
[ -f "$ARQ_TESTE" ] && md5sum "$ARQ_TESTE" "$DESTINO/documentos/notas.txt"

9) Repetir operações no Nemo (GUI)

  1. Abra o Nemo e habilite Exibir arquivos ocultos (Ctrl+H).
  2. Crie uma nova pasta “entregas” em ~/trabalho e mova um arquivo para ela.
  3. Exclua um arquivo via GUI e restaure-o da Lixeira.

10) Registrar evidências no portfólio

Capture telas do Nemo e salve saídas de comandos em um arquivo de log.

# exemplo de registro de saídas
{
  echo "===== Estrutura ====="
  tree -L 2 ~/trabalho 2>/dev/null || ls -R ~/trabalho
  echo "===== Tamanho ====="
  du -h --max-depth=1 ~/trabalho
  echo "===== Backup TAR ====="
  ls -lh ~/backup
  echo "===== Sincronização ====="
  ls -lh "$DESTINO"
} | tee ~/trabalho/documentos/relatorio_cap12.log

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar o domínio de operações de arquivos e rotinas de backup local com validação e registro técnico.

Atividade 1 — Organização temática e links úteis

Crie uma estrutura em ~/trabalho/cursos/{sosl,redes,hardware}. Mova documentos relacionados para cada pasta e crie um symlink “atalhos” em ~/trabalho apontando para ~/trabalho/cursos/sosl. Liste inodes de um arquivo e crie um hard link para ele dentro de sosl.

Atividade 2 — Diagnóstico de espaço e limpeza consciente

Use du e df para identificar as 3 pastas que mais ocupam espaço em ~/trabalho. Apague conteúdo temporário em ~/trabalho/temp com confirmação e registre antes/depois no seu relatório.

Atividade 3 — Backup híbrido (tar + rsync)

Gere um tar.gz de ~/trabalho e armazene em ~/backup. Em seguida, sincronize com rsync para um diretório externo (ou substituto em sua Home). Valide com tar -tzf, rsync em modo checksum e md5sum de 3 arquivos aleatórios. Inclua todas as evidências no portfólio.

Critérios de Avaliação

  • Correta execução dos comandos e segurança nas operações (confirmações, caminhos).
  • Organização clara da estrutura de pastas e uso apropriado de links.
  • Backup criado e validado com registros de verificação.
  • Documentação: clareza, evidências (prints, logs) e conclusões técnicas.

Pesquisas complementares (sugestões)

  • Documentação do GNU tar: opções avançadas e boas práticas de exclusões (–exclude).
  • Manual do rsync: estratégias de versionamento e parâmetros de performance.
  • Guia Foca Linux: capítulos sobre sistema de arquivos e comandos básicos.
  • Arch Wiki: “General recommendations” e “rsync” para conceitos gerais.
