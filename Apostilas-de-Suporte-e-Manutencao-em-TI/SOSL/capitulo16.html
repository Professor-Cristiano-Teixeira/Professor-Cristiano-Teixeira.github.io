Capítulo 16 — Manutenção Preventiva, Backup e Implantação

Carga: 6h

Projeto-base: VM Linux Mint Cinnamon no VirtualBox com automações de backup e verificação

Stack fixa: VirtualBox, Linux Mint Cinnamon, Bash, rsync/tar, Timeshift, VBoxManage

Resultados de aprendizagem deste capítulo:

  • Planejar e executar manutenção preventiva periódica em um sistema Linux.
  • Aplicar estratégias de backup completas e diferenciais, e realizar restauração validando integridade.
  • Utilizar snapshots, exportação e importação de VMs no VirtualBox para clonagem/implantação.
  • Documentar procedimentos, registrar evidências e validar com checklists.
  • Consolidar a entrega final do Projeto Integrador do bimestre (automação + backup + implantação).

Competências e Habilidades

  • MSI: Instalação e manutenção de sistemas operacionais.
  • MSI: Gestão de segurança de dados (backup/restauração).
  • MSI: Administração de virtualização e imagens.
  • MSI: Automação e documentação técnica.

Parte Teórica (explicação do conteúdo)

1) Manutenção preventiva: conceito, ciclos e checklist

A manutenção preventiva reúne ações planejadas para manter o sistema estável, rápido e seguro. Envolve limpeza lógica (cache, kernels antigos, pacotes órfãos), atualizações controladas e verificação de espaço em disco e logs. O objetivo é reduzir falhas e paradas não planejadas.

Definir um ciclo (por exemplo, semanal/mensal) com um checklist ajuda a garantir padronização e rastreabilidade. Cada ação deve possuir evidência (saída de comando, print, log).

Onde vou aplicar isso? No passo a passo, você executará um checklist real, registrará saídas e consolidará evidências no portfólio.

2) Atualizações e drivers: estratégias seguras

Atualizações devem ser feitas com repositórios confiáveis, verificando lista do que será alterado e atentando a pacotes essenciais. Em ambientes produtivos, recomenda-se testar em uma VM clone antes de aplicar em produção. Em desktops Linux Mint, drivers de hardware podem ser gerenciados via “Driver Manager” e atualizações via apt.

Boas práticas: criar snapshot antes de grandes atualizações, revisar changelogs e manter backups atualizados.

Onde vou aplicar isso? Você realizará atualização completa com apt, validará integridade e reverterá usando snapshot em caso de problema.

3) Estratégias de backup: completo, incremental/diferencial e verificação

Backups completos copiam todo o conjunto; diferenciais copiam mudanças desde o último completo; incrementais copiam apenas mudanças desde o último backup (de qualquer tipo). Em ambientes educacionais, uma rotina completa semanal + diferencial diário é um bom equilíbrio.

Verificação é crítica: checar códigos de saída, comparar hashes, fazer restauração de teste. Sem restauração testada, o backup não é confiável.

Onde vou aplicar isso? Você fará um backup completo da pasta /home, validará com checksums e executará uma restauração parcial e total simulando incidente controlado.

4) Ferramentas: tar, rsync e Timeshift

O tar é útil para empacotar e, opcionalmente, comprimir; o rsync copia sincronizando alterações de forma eficiente, preservando permissões. O Timeshift cria snapshots do sistema (especialmente / e configurações), facilitando rollback.

Escolha a ferramenta conforme objetivo: tar para arquivos versionados e portáveis (com compressão); rsync para espelhamento/rotinas frequentes; Timeshift para snapshots sistêmicos.

Onde vou aplicar isso? Você criará um backup com tar/rsync e um snapshot com Timeshift, validando recuperação.

5) VirtualBox: snapshots, exportação (OVA/OVF) e implantação

Snapshots registram o estado da VM em um momento. A exportação OVA/OVF cria um pacote portável para importar em outro host. Implantação é o processo de restaurar/clonar a VM em outro ambiente, garantindo reprodutibilidade.

Boas práticas: nomear snapshots com data e motivo, limpar estados desnecessários e verificar integridade do OVA após exportação.

Onde vou aplicar isso? Você criará snapshots, exportará a VM para OVA e testará a importação, simulando implantação.

Passo a Passo — Rotina de manutenção, backup e implantação

Objetivo desta etapa:

Executar uma rotina completa de manutenção preventiva, realizar backup e restauração de dados, e consolidar clonagem/implantação da VM via snapshots e exportação OVA no VirtualBox, com registro de evidências.


Preparação e registro

  1. Abra sua VM Linux Mint Cinnamon no VirtualBox.
  2. Crie uma pasta local para evidências: comandos utilizados, saídas e capturas.
  3. Confirme espaço em disco livre para snapshots e OVA (recomendado: 10–20 GB livres).
# criar diretório de trabalho para evidências
mkdir -p ~/portfolio/cap16/evidencias
date | tee -a ~/portfolio/cap16/evidencias/session.log
df -h | tee -a ~/portfolio/cap16/evidencias/session.log

1) Manutenção preventiva (limpeza e atualizações)

Onde aplica a teoria: conceitos 1 e 2 (ciclos, atualização segura).

  1. Listar pacotes atualizáveis e avaliar alterações.
  2. Criar um snapshot do sistema antes de atualizar (Timeshift).
  3. Executar atualização segura e limpeza de cache/kernels antigos.
# 1. listar atualizações
sudo apt update | tee -a ~/portfolio/cap16/evidencias/apt.log
apt list --upgradable | tee -a ~/portfolio/cap16/evidencias/apt.log

# 2. criar snapshot com timeshift (GUI ou CLI)
# Instalar timeshift se necessário
sudo apt install -y timeshift
# criar snapshot (modo RSYNC)
sudo timeshift --create --comments "pre-update-$(date +%F)" --tags D

# 3. aplicar atualizações
sudo apt full-upgrade -y | tee -a ~/portfolio/cap16/evidencias/apt-upgrade.log

# limpeza de pacotes e kernels antigos
sudo apt autoremove --purge -y | tee -a ~/portfolio/cap16/evidencias/apt-clean.log
sudo apt autoclean -y | tee -a ~/portfolio/cap16/evidencias/apt-clean.log

# validar estado do sistema
uname -a | tee -a ~/portfolio/cap16/evidencias/pos-upgrade.log
journalctl -p 3 -xb | tee -a ~/portfolio/cap16/evidencias/pos-upgrade.log
Dica: Se algo crítico falhar após a atualização, você poderá reverter usando o Timeshift para o snapshot anterior.

2) Backup completo da /home com tar e verificação

Onde aplica a teoria: conceitos 3 e 4 (estratégias e ferramentas).

  1. Definir diretório de destino do backup (pode ser uma pasta em disco diferente ou dispositivo externo montado).
  2. Gerar um arquivo TAR comprimido com preservação de permissões.
  3. Gerar e validar checksums (sha256) do arquivo de backup.
# definir destino de backup
DEST="/mnt/backup"
mkdir -p "$DEST"

# criar backup completo da /home (excluindo lixos temporários comuns)
EXCLUDES="--exclude='.cache' --exclude='Downloads/*.iso' --exclude='*.ova'"
sudo tar -cvpaf "$DEST/home-backup-$(date +%F).tar.xz" $EXCLUDES /home \
  2>&1 | tee -a ~/portfolio/cap16/evidencias/backup-tar.log

# gerar checksum
cd "$DEST"
sha256sum home-backup-*.tar.xz | tee -a ~/portfolio/cap16/evidencias/backup-tar.sha256
Observação: Use nomes de arquivos com data para facilitar rotação e identificação. Armazene checksums junto ao backup.

3) Backup/sincronização com rsync (diferencial)

Onde aplica a teoria: conceitos 3 e 4 (incremental/diferencial; rsync).

  1. Criar um espelho da sua pasta de trabalho (ex.: ~/Documentos) para o destino de backup.
  2. Habilitar preservação de permissões, dono e grupos.
# sincronizar uma pasta de trabalho com rsync (diferencial)
SRC="$HOME/Documentos"
DEST_RSYNC="/mnt/backup/espelho-documentos"
rsync -avh --delete "$SRC/" "$DEST_RSYNC/" | tee -a ~/portfolio/cap16/evidencias/rsync.log

# verificar diferenças (opcional)
rsync -avhn --delete "$SRC/" "$DEST_RSYNC/" | tee -a ~/portfolio/cap16/evidencias/rsync-dry-run.log

4) Restauração de teste (contingência simulada)

Onde aplica a teoria: conceito 3 (teste de recuperação).

  1. Simular falha controlada movendo uma pasta de teste para quarentena.
  2. Restaurar a pasta a partir do backup TAR.
  3. Validar integridade por comparação de hashes ou diff.
# criar diretório de quarentena
mkdir -p ~/quarentena
# mover pasta de teste (ex.: uma subpasta em Documentos)
mv ~/Documentos/ProjetoDemo ~/quarentena/

# restaurar apenas a pasta removida a partir do TAR
cd /  # importante: restaurar com caminhos absolutos quando necessário
sudo tar -xvpaf /mnt/backup/home-backup-*.tar.xz home/$(whoami)/Documentos/ProjetoDemo \
  --overwrite \
  2>&1 | tee -a ~/portfolio/cap16/evidencias/restore.log

# validar conteúdo
diff -qr ~/quarentena/ProjetoDemo ~/Documentos/ProjetoDemo | tee -a ~/portfolio/cap16/evidencias/restore-compare.log
Se a restauração for bem-sucedida e a comparação não indicar divergências, você validou a efetividade do backup.

5) Snapshots com Timeshift (rollback do sistema)

Onde aplica a teoria: conceito 4 (Timeshift) e 2 (rollback pós-update).

  1. Listar snapshots existentes e criar um novo pós-atualização.
  2. Testar restauração de um snapshot (simulação; não execute se estiver em prova prática sem autorização).
# listar snapshots
sudo timeshift --list | tee -a ~/portfolio/cap16/evidencias/timeshift.log

# criar snapshot pós-update
sudo timeshift --create --comments "post-update-$(date +%F)" --tags D

# restauração (apenas se solicitado/permitido)
# sudo timeshift --restore  # segue prompts interativos

6) VirtualBox: criar snapshot, exportar OVA e importar

Onde aplica a teoria: conceito 5 (snapshots, exportação/implantação).

  1. Criar snapshot da VM pelo VBoxManage.
  2. Exportar a VM para OVA com identificação clara.
  3. Importar o OVA em outra máquina/host (ou na mesma, com novo nome) para teste de implantação.
# substituir "Mint-Cinnamon" pelo nome exato da sua VM
VM="Mint-Cinnamon"

# 1) snapshot no VirtualBox
VBoxManage snapshot "$VM" take "pre-export-$(date +%F)" --description "Snapshot antes da exportação"

# 2) exportar OVA
mkdir -p ~/portfolio/cap16/export
VBoxManage export "$VM" -o ~/portfolio/cap16/export/MintCinnamon-$(date +%F).ova

# (opcional) verificar integridade do arquivo
cd ~/portfolio/cap16/export
sha256sum MintCinnamon-*.ova | tee ../evidencias/ova.sha256

# 3) importar OVA (exemplo; cuidado com nomes duplicados)
# VBoxManage import MintCinnamon-*.ova --vsys 0 --vmname "Mint-Cinnamon-Clone"
A importação pode ser feita pela interface gráfica do VirtualBox: Arquivo → Importar Appliance. Verifique se a VM importada inicia corretamente.

7) Consolidação e documentação

  1. Reunir logs, checksums, capturas de tela e anotações no portfólio.
  2. Escrever um resumo técnico: o que foi feito, por que, ferramentas, resultados e próximos passos.
  3. Atualizar o script de automação do capítulo 15 para incluir verificação de espaço antes dos backups e logs dedicados.
# exemplo de trecho adicional no script (verificação de espaço)
MIN_GB=5
FREE_GB=$(df -BG /mnt/backup | awk 'NR==2{gsub("G","",$4); print $4}')
if [ "$FREE_GB" -lt "$MIN_GB" ]; then
  echo "[ERRO] Espaço insuficiente em /mnt/backup (${FREE_GB}GB < ${MIN_GB}GB)" | tee -a ~/portfolio/cap16/evidencias/automacao.log
  exit 1
fi
echo "[OK] Espaço suficiente: ${FREE_GB}GB" | tee -a ~/portfolio/cap16/evidencias/automacao.log
