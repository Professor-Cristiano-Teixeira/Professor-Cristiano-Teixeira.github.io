Capítulo 13 — Automação com PowerShell

Carga: 6h

Projeto-base: Laboratório de administração do Windows 11 em VM com automações de rotina

Stack fixa: Windows 11, PowerShell 5.1/7, VirtualBox, Editor de código (VS Code)

Resultados de aprendizagem deste capítulo:

  • Dominar variáveis, estruturas de controle e funções no PowerShell para compor scripts reutilizáveis.
  • Manipular serviços, processos, arquivos e logs com cmdlets e tratamento de erros.
  • Criar e agendar tarefas automatizadas com o Agendador de Tarefas (Task Scheduler).
  • Desenvolver um script que cria usuários em lote, aplica grupos e configura pastas com permissões NTFS.

Competências e Habilidades

  • Escrever scripts claros, comentados e idempotentes para tarefas administrativas.
  • Interpretar mensagens de erro e aplicar try/catch/finally para robustez.
  • Operar cmdlets de gestão de usuários, serviços, processos e arquivos.
  • Planejar, testar e agendar automações com segurança e logs.
Ir para Passo a Passo Voltar: CLI e PowerShell: fundamentos Próximo: Segurança e BitLocker

Plano de Aula (Capítulo 13)

- Abertura (15 min): retomada do Cap. 12 (cmdlets, pipeline, help). Apresentação dos objetivos de automação.
- Teoria 1 (30 min): variáveis, tipos, arrays/hashtables, estruturas de controle (if/elseif/else, switch) e loops (for/foreach/while). Onde aplicar no script final.
- Teoria 2 (30 min): funções e parâmetros, escopo, módulos e tratamento de erros (try/catch/finally; ErrorAction). Boas práticas (comentários, naming, idempotência).
- Teoria 3 (30 min): cmdlets para serviços, processos, arquivos, logs e permissões NTFS; conceitos de ACL e herança.
- Demonstração guiada (30 min): montar bloco por bloco do script de criação de usuários em lote, grupos e pastas com ACLs; execução parcial e testes.
- Prática 1 (40 min): estudantes implementam e testam o script na VM com contas e pastas de um cenário fictício.
- Teoria/Demo (20 min): agendamento de tarefa com o Task Scheduler (Register-ScheduledTask e schtasks).
- Prática 2 (25 min): agendar execução do script e gerar log de auditoria.
- Encerramento (20 min): revisão, discussão de erros comuns, checklist e registro no diário de bordo.

Parte Teórica (explicação do conteúdo)

1) Variáveis, tipos e coleções

No PowerShell, variáveis começam com $. Elas são fracamente tipadas por padrão, mas você pode tipar quando necessário. Tipos comuns: [string], [int], [bool], [datetime]. Coleções importantes: arrays e hashtables.

# Variáveis e tipos
$name = "Aluno"
[int]$idade = 17
$data = [datetime]::Now

# Arrays
$notas = 7, 8.5, 9

# Hashtable (dicionário)
$usuario = @{
  Nome = "maria.souza"
  Grupo = "Vendas"
  Ativo = $true
}

Onde vou aplicar isso: declarar listas de usuários a serem criados, tabelas com grupos por departamento e parâmetros do script.

2) Estruturas de controle e loops

Use if/elseif/else para decisões, switch para múltiplos casos e loops para repetição. Foreach é ideal para percorrer arrays e coleções de objetos retornados por cmdlets.

# Decisão
if ($idade -ge 18) {
  "Maior de idade"
} elseif ($idade -eq 17) {
  "Quase lá"
} else {
  "Menor de idade"
}

# Switch
$setor = "TI"
switch ($setor) {
  "Vendas" { $grupo = "GRP_Vendas" }
  "TI"     { $grupo = "GRP_TI" }
  default  { $grupo = "GRP_Geral" }
}

# Loop
$usuarios = @("joao", "maria", "ana")
foreach ($u in $usuarios) {
  "Criando conta para $u"
}

Onde vou aplicar isso: percorrer a lista de usuários, decidir grupos por departamento e validar pré-condições antes de alterar o sistema.

3) Funções, parâmetros e modularização

Funções organizam o código, aceitam parâmetros e permitem reuso. Use o bloco param e valide entradas. Separe responsabilidades: criação de usuário, associação a grupos e configuração de ACL.

function New-DeptUser {
  [CmdletBinding()]
  param(
    [Parameter(Mandatory)]
    [string]$UserName,
    [string]$FullName,
    [Parameter(Mandatory)]
    [string]$Department,
    [SecureString]$Password
  )
  # Corpo: criar usuário, definir nome completo e senha se fornecida
}

Onde vou aplicar isso: construir um módulo simples para a empresa fictícia com funções específicas para cada etapa do provisionamento.

4) Tratamento de erros e robustez

Cmdlets podem falhar por permissões, inexistência de objetos ou conflitos. Use try/catch/finally e preferencialmente cmdlets com -ErrorAction Stop. Registre eventos em log para auditoria.

try {
  New-LocalUser -Name "ana" -NoPassword -ErrorAction Stop
} catch {
  Write-Warning "Falha ao criar usuário 'ana': $($_.Exception.Message)"
} finally {
  # Sempre executado
}

Onde vou aplicar isso: garantir que, se a criação de um usuário falhar, o script registre e siga para o próximo sem interromper toda a execução.

5) Serviços, processos, arquivos e logs

Automação costuma envolver verificar serviços (Start/Stop/Restart-Service), processos (Get/Stop-Process), arquivos (Get/Copy/Move-Item) e logs (Get-WinEvent). Manipular esses recursos de forma segura é essencial.

# Serviços
Get-Service -Name Spooler | Restart-Service

# Processos
Get-Process | Where-Object CPU -gt 50

# Arquivos
Copy-Item "C:\Modelos\Padrao.txt" "D:\Departamentos\Vendas" -Force

# Logs (últimos 20 eventos do Sistema, nível erro)
Get-WinEvent -LogName System -ErrorAction SilentlyContinue |
  Where-Object LevelDisplayName -eq "Error" |
  Select-Object -First 20

Onde vou aplicar isso: criar pastas padrão, copiar modelos e registrar em log as ações do script e erros encontrados.

6) Permissões NTFS (ACL) com PowerShell

NTFS usa ACLs para controlar acesso. No PowerShell, você pode usar Get-Acl e Set-Acl, criando regras FileSystemAccessRule. É importante desabilitar herança quando necessário e aplicar apenas o mínimo de privilégios.

$pasta = "D:\Departamentos\Vendas\maria.souza"
New-Item -ItemType Directory -Path $pasta -Force | Out-Null

$acl = Get-Acl $pasta
$rule = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "maria.souza",
  "Modify",
  "ContainerInherit,ObjectInherit",
  "None",
  "Allow"
)
$acl.SetAccessRuleProtection($true, $false)  # Desabilita herança
$acl.SetAccessRule($rule)
Set-Acl -Path $pasta -AclObject $acl

Onde vou aplicar isso: ao criar as pastas pessoais e de departamento, garantindo que apenas os usuários/grupos corretos tenham acesso.

7) Agendamento com o Task Scheduler

Automatize a execução periódica dos scripts com o Agendador de Tarefas. Você pode usar Register-ScheduledTask (PowerShell) ou schtasks (compatível com versões antigas). Use contas de serviço limitadas.

# Exemplo com Register-ScheduledTask
$acao = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -File C:\Scripts\Provisionar.ps1"
$gatilho = New-ScheduledTaskTrigger -Daily -At 08:00
Register-ScheduledTask -TaskName "ProvisionamentoDiario" -Action $acao -Trigger $gatilho -Description "Cria/ajusta usuários e pastas" -User "NT AUTHORITY\SYSTEM" -RunLevel Highest

Onde vou aplicar isso: rodar revisões diárias para garantir conformidade de pastas e permissões, além de processamento de novos usuários.

Passo a Passo — Script de automação com PowerShell (criação de usuários, grupos, pastas e ACLs)

Objetivo desta etapa:

Construir e validar um script completo que recebe uma lista de usuários e departamentos, cria contas locais, adiciona aos grupos, cria pastas pessoais e de departamento com permissões NTFS adequadas e registra logs. Em seguida, agendar sua execução.


1) Preparação do ambiente

  1. Abra sua VM Windows 11 e crie um snapshot chamado “Cap13-Base”.
  2. Crie a pasta C:\Scripts e D:\Departamentos (use um segundo disco virtual, se possível).
  3. Abra o VS Code ou o PowerShell ISE e habilite a execução de scripts em escopo de usuário, se necessário.
# Executar em console elevado somente se necessário
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force

New-Item -ItemType Directory -Path "C:\Scripts","D:\Departamentos" -Force | Out-Null

2) Fonte de dados: CSV de usuários

Crie um arquivo CSV com colunas UserName,FullName,Department. Salve como C:\Scripts\usuarios.csv.

# Exemplo de CSV (salve como texto)
@"
UserName,FullName,Department
joao.silva,João da Silva,Vendas
maria.souza,Maria Souza,Vendas
ana.costa,Ana Costa,TI
"@ | Set-Content -Path "C:\Scripts\usuarios.csv" -Encoding UTF8

Conceitos aplicados: variáveis e coleções (Teoria 1), loops (Teoria 2).

3) Estrutura do script e logging

Crie C:\Scripts\Provisionar.ps1. Ele irá carregar o CSV, criar estrutura de pastas por departamento e registrar logs tanto na tela quanto em arquivo.

# C:\Scripts\Provisionar.ps1
[CmdletBinding()]
param(
  [Parameter(Mandatory)]
  [string]$CsvPath = "C:\Scripts\usuarios.csv",
  [string]$RootDept = "D:\Departamentos",
  [string]$LogPath = "C:\Scripts\provisionamento.log"
)

function Write-Log {
  param([string]$Message, [string]$Level = "INFO")
  $line = "{0} [{1}] {2}" -f (Get-Date -Format "yyyy-MM-dd HH:mm:ss"), $Level, $Message
  $line | Tee-Object -FilePath $LogPath -Append
}

try {
  Write-Log "Início do provisionamento"
  $usuarios = Import-Csv -Path $CsvPath -ErrorAction Stop
} catch {
  Write-Log "Erro ao carregar CSV: $($_.Exception.Message)" "ERROR"
  throw
}

Conceitos aplicados: funções (Teoria 3) e tratamento de erros (Teoria 4).

4) Funções de criação de usuários e grupos

Usaremos contas locais para fins didáticos. Em ambientes corporativos com AD, adapte para New-ADUser e Add-ADGroupMember.

function Ensure-LocalGroup {
  param([Parameter(Mandatory)][string]$GroupName)
  if (-not (Get-LocalGroup -Name $GroupName -ErrorAction SilentlyContinue)) {
    try {
      New-LocalGroup -Name $GroupName -ErrorAction Stop | Out-Null
      Write-Log "Grupo criado: $GroupName"
    } catch {
      Write-Log "Erro criando grupo $GroupName: $($_.Exception.Message)" "ERROR"
    }
  } else {
    Write-Log "Grupo já existe: $GroupName"
  }
}

function Ensure-LocalUser {
  param(
    [Parameter(Mandatory)][string]$UserName,
    [string]$FullName
  )
  if (-not (Get-LocalUser -Name $UserName -ErrorAction SilentlyContinue)) {
    try {
      New-LocalUser -Name $UserName -NoPassword -FullName $FullName -ErrorAction Stop | Out-Null
      Write-Log "Usuário criado: $UserName"
    } catch {
      Write-Log "Erro criando usuário $UserName: $($_.Exception.Message)" "ERROR"
    }
  } else {
    Write-Log "Usuário já existe: $UserName"
  }
}

function Ensure-GroupMembership {
  param([string]$UserName, [string]$GroupName)
  try {
    Add-LocalGroupMember -Group $GroupName -Member $UserName -ErrorAction Stop
    Write-Log "Usuário $UserName adicionado ao grupo $GroupName"
  } catch {
    if ($_.Exception.Message -match "is already a member") {
      Write-Log "Usuário $UserName já é membro de $GroupName"
    } else {
      Write-Log "Erro adicionando $UserName em $GroupName: $($_.Exception.Message)" "ERROR"
    }
  }
}

Conceitos aplicados: funções e idempotência (checar antes de criar ou adicionar).

5) Pastas e permissões NTFS

Criaremos pastas por departamento e pasta pessoal para cada usuário, aplicando ACL adequada.

function Ensure-Folder {
  param([Parameter(Mandatory)][string]$Path)
  if (-not (Test-Path $Path)) {
    New-Item -ItemType Directory -Path $Path -Force | Out-Null
    Write-Log "Pasta criada: $Path"
  } else {
    Write-Log "Pasta já existe: $Path"
  }
}

function Set-ExclusiveAcl {
  param(
    [Parameter(Mandatory)][string]$Path,
    [Parameter(Mandatory)][string[]]$AllowIdentities, # ex: "BUILTIN\Administrators","maria.souza"
    [string]$Rights = "Modify"
  )
  try {
    $acl = Get-Acl $Path
    $acl.SetAccessRuleProtection($true, $false) # sem herança
    # limpa regras existentes
    $acl.Access | ForEach-Object { $acl.RemoveAccessRule($_) | Out-Null }

    foreach ($id in $AllowIdentities) {
      $rule = New-Object System.Security.AccessControl.FileSystemAccessRule(
        $id, $Rights, "ContainerInherit,ObjectInherit", "None", "Allow"
      )
      $acl.AddAccessRule($rule) | Out-Null
    }
    Set-Acl -Path $Path -AclObject $acl
    Write-Log "ACL definida em: $Path"
  } catch {
    Write-Log "Erro definindo ACL em $Path: $($_.Exception.Message)" "ERROR"
  }
}

Conceitos aplicados: ACLs NTFS (Teoria 6) com proteção de herança e privilégio mínimo.

6) Fluxo principal do script

Integre leitura do CSV, criação de grupos por departamento, usuários, associação e criação de pastas.

# Mapear grupos por departamento
$DeptToGroup = @{}

# Garante pasta raiz
Ensure-Folder -Path $RootDept

foreach ($u in $usuarios) {
  $dept = $u.Department.Trim()
  $grp  = "GRP_{0}" -f ($dept -replace '\s','')
  if (-not $DeptToGroup.ContainsKey($dept)) {
    Ensure-LocalGroup -GroupName $grp
    $DeptToGroup[$dept] = $grp
    # Pasta do departamento
    $deptPath = Join-Path $RootDept $dept
    Ensure-Folder -Path $deptPath
    Set-ExclusiveAcl -Path $deptPath -AllowIdentities @("BUILTIN\Administrators",$grp) -Rights "Modify"
  }

  Ensure-LocalUser -UserName $u.UserName -FullName $u.FullName
  Ensure-GroupMembership -UserName $u.UserName -GroupName $DeptToGroup[$dept]

  # Pasta pessoal
  $home = Join-Path (Join-Path $RootDept $dept) $u.UserName
  Ensure-Folder -Path $home
  Set-ExclusiveAcl -Path $home -AllowIdentities @("BUILTIN\Administrators",$u.UserName) -Rights "Modify"
}

Write-Log "Fim do provisionamento"

Conceitos aplicados: controle de fluxo, coleções e funções reutilizáveis.

7) Testes e validação

  1. Execute o script e verifique o log.
  2. Confira usuários criados em painéis gráficos (lusrmgr.msc) e grupos.
  3. Valide pastas e ACLs com Get-Acl.
powershell.exe -ExecutionPolicy Bypass -NoProfile -File "C:\Scripts\Provisionar.ps1" -CsvPath "C:\Scripts\usuarios.csv"

# Verificar ACL
Get-Acl "D:\Departamentos\Vendas\maria.souza" | Format-List

8) Agendamento da tarefa

Agende a execução diária às 08:00 usando conta do Sistema. Em produção, prefira uma conta de serviço com privilégios mínimos.

$acao = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Provisionar.ps1"
$gatilho = New-ScheduledTaskTrigger -Daily -At 08:00
Register-ScheduledTask -TaskName "ProvisionamentoDiario" -Action $acao -Trigger $gatilho -Description "Provisiona usuários e pastas" -User "NT AUTHORITY\SYSTEM" -RunLevel Highest

# Testar a tarefa manualmente
Start-ScheduledTask -TaskName "ProvisionamentoDiario"

9) Melhorias e boas práticas

  • Validar cabeçalhos do CSV e campos obrigatórios.
  • Adicionar parâmetro -WhatIf e -Confirm para operações sensíveis.
  • Separar o script em módulo (.psm1) para reutilização.
  • Gerar relatório final em CSV com status por usuário.
# Exemplo de export de relatório
$relatorio = foreach ($u in $usuarios) {
  [pscustomobject]@{
    UserName   = $u.UserName
    Department = $u.Department
    Criado     = (Get-LocalUser -Name $u.UserName -ErrorAction SilentlyContinue) -ne $null
    PastaOk    = Test-Path (Join-Path (Join-Path $RootDept $u.Department) $u.UserName)
  }
}
$relatorio | Export-Csv -Path "C:\Scripts\resultado.csv" -NoTypeInformation -Encoding UTF8
