Capítulo 11 — Gerenciamento de usuários, grupos e perfis

Carga: 4h (estimada)

Projeto-base: Administração local segura de contas e pastas em Windows 11 (VM VirtualBox)

Stack fixa: Windows 11 • MMC (lusrmgr.msc, secpol.msc) • PowerShell • NTFS

Resultados de aprendizagem deste capítulo:

  • Criar, configurar e remover contas de usuários locais com segurança.
  • Organizar permissões por grupos, aplicando privilégio mínimo.
  • Definir políticas de senha e bloqueio de conta adequadas ao laboratório.
  • Configurar e migrar perfis de usuário (pastas de perfil, diretório base e dados).
  • Validar acesso a recursos protegidos e registrar evidências.

Competências e Habilidades

  • Administrar identidades e privilégios no Windows com boas práticas.
  • Diagnosticar e corrigir problemas comuns de acesso e perfil.
  • Automatizar tarefas básicas com PowerShell para padronização.

Parte Teórica (explicação do conteúdo)

Contas locais, grupos e privilégio mínimo

Uma conta local representa uma identidade que autentica no computador. Em ambientes sem domínio/AD, usamos contas locais para controlar acesso. Grupos são coleções lógicas de contas; permissões são atribuídas a grupos para simplificar a administração e aplicar o princípio do privilégio mínimo (dar apenas o necessário para a tarefa).

No Windows 11, você pode gerenciar contas e grupos via lusrmgr.msc (Edições Pro/Enterprise/Education), Configurações, PowerShell ou comandos clássicos. Grupos integrados como Administrators, Users e Remote Desktop Users já possuem direitos pré-definidos.

Onde vou aplicar isso no passo a passo: criação de dois usuários (um padrão e um auxiliar), criação de grupos departamentais e delegação de acesso a pastas protegidas apenas via grupos.

Políticas de senha e bloqueio de conta

Políticas de senha definem complexidade, tamanho mínimo e validade. Políticas de bloqueio controlam quantas tentativas falhas são permitidas e por quanto tempo. Em máquina local, podem ser configuradas via secpol.msc (Políticas de Conta) ou por linha de comando.

Boas práticas incluem: comprimento mínimo ≥ 8, complexidade habilitada, histórico para evitar reutilização e bloqueio após tentativas falhas (com janela de observação). Ajuste conforme o risco do laboratório.

Onde vou aplicar isso no passo a passo: configurar requisitos mínimos de senha e ativar bloqueio após 5 falhas, usando secpol.msc ou PowerShell/CMD.

Perfis de usuário, diretório base e dados

O perfil de usuário é um conjunto de pastas e configurações pessoais (AppData, Desktop, Documents, etc.) armazenado em C:\Users\. O diretório base (Home directory) pode ser usado para apontar um caminho onde o usuário mantém seus dados. Em ambiente local, geralmente o perfil é local.

Ao criar usuários, é importante planejar a localização de dados, permissões NTFS e estratégias de migração/backup do perfil. Para migração simples entre contas locais, é possível copiar dados do perfil (com atenção a AppData e permissões) e ajustar propriedade de pastas.

Onde vou aplicar isso no passo a passo: criar estrutura C:\Dados\Departamentos, apontar pastas e garantir que cada usuário/grupo tenha acesso adequado. Opcionalmente demonstrar cópia de dados de um perfil antigo para um novo.

Permissões NTFS e testes de acesso

NTFS permite configurar permissões detalhadas em pastas/arquivos. Conceder permissão a grupos, nunca diretamente ao usuário, facilita manutenção. A herança deve ser administrada para evitar permissões excessivas. Testes de acesso confirmam se a política está funcionando.

Para diagnóstico, use a aba Segurança (Propriedades), o efetivo de acesso e utilitários como icacls e Get-Acl/Set-Acl no PowerShell.

Onde vou aplicar isso no passo a passo: aplicar permissões somente-leitura a um grupo e leitura/gravação a outro; validar com login de teste e com o comando whoami /groups.

Ferramentas: GUI, CLI e PowerShell

GUI: lusrmgr.msc para contas/grupos, secpol.msc para políticas de senha/bloqueio, Propriedades de pasta para NTFS. CLI: net user, net localgroup, net accounts. PowerShell: New-LocalUser, Set-LocalUser, Add-LocalGroupMember, Get-LocalGroup, bem como cmdlets para ACLs.

Escolha a ferramenta conforme a tarefa: GUI para visualização rápida; CLI/PowerShell para automação e repetibilidade (essencial para documentação e reexecução).

Onde vou aplicar isso no passo a passo: criar usuários/grupos e aplicar permissões com PowerShell, registrar os comandos no diário de bordo.

Passo a Passo — Administração local segura de identidades e perfis

Objetivo desta etapa:

Criar usuários e grupos locais no Windows 11 (VM), definir políticas de senha/bloqueio, organizar dados por pastas com NTFS e validar o acesso de forma controlada, registrando evidências.


1) Preparação do ambiente (VM e snapshot)

  1. Abra sua VM Windows 11 no VirtualBox e aplique updates básicos (se necessário).
  2. Crie um snapshot chamado “C11-Início” para poder retornar a este ponto.
  3. Abra um PowerShell como Administrador (clique direito no botão Iniciar > Windows Terminal (Admin)).

2) Criar grupos locais departamentais

PowerShell

Crie grupos para organizar permissões por função (privilégio mínimo).

# Listar grupos existentes
Get-LocalGroup | Select-Object Name, SID

# Criar grupos departamentais
New-LocalGroup -Name "GRP_Vendas" -Description "Acesso aos dados do departamento de Vendas"
New-LocalGroup -Name "GRP_RH" -Description "Acesso aos dados do departamento de RH"

# Conferir
Get-LocalGroup | Where-Object Name -match "GRP_"

3) Criar usuários locais padrão

PowerShell

Crie contas sem privilégios administrativos para uso diário e testes.

# Criar senhas seguras (substitua por senhas definidas no laboratório)
$pwdVendas = Read-Host "Defina a senha do usuario vendas01" -AsSecureString
$pwdRH     = Read-Host "Defina a senha do usuario rh01" -AsSecureString

# Criar usuários
New-LocalUser -Name "vendas01" -FullName "Vendas 01" -Description "Usuário do depto de Vendas" -Password $pwdVendas
New-LocalUser -Name "rh01"     -FullName "RH 01"     -Description "Usuário do depto de RH"     -Password $pwdRH

# Adicionar aos grupos
Add-LocalGroupMember -Group "GRP_Vendas" -Member "vendas01"
Add-LocalGroupMember -Group "GRP_RH"     -Member "rh01"

# Verificar associação
Get-LocalGroupMember -Group "GRP_Vendas"
Get-LocalGroupMember -Group "GRP_RH"
Dica: mantenha sua conta administrativa separada da conta padrão usada no dia a dia.

4) Definir políticas de senha e bloqueio

CMD/PowerShell

Use net accounts para um ajuste rápido em ambiente local.

:: Executar em Prompt (Admin) ou dentro do Windows Terminal (Admin) com cmd
net accounts /minpwlen:8 /maxpwage:60 /minpwage:1 /uniquepw:5
net accounts /lockoutthreshold:5 /lockoutduration:30 /lockoutwindow:30

:: Exibir configurações atuais
net accounts

Alternativa GUI: secpol.msc → Políticas de Conta → Política de Senha e Bloqueio de Conta.

5) Estruturar pastas e aplicar NTFS por grupo

Crie pastas departamentais e aplique permissões NTFS apenas aos grupos correspondentes.

# Estrutura de dados
New-Item -Path "C:\Dados\Departamentos" -ItemType Directory -Force | Out-Null
New-Item -Path "C:\Dados\Departamentos\Vendas" -ItemType Directory -Force | Out-Null
New-Item -Path "C:\Dados\Departamentos\RH"     -ItemType Directory -Force | Out-Null

# Remover herança e limpar permissões herdadas
icacls "C:\Dados\Departamentos\Vendas" /inheritance:r
icacls "C:\Dados\Departamentos\RH"     /inheritance:r

# Garantir Administrators com controle total e Users sem acesso
icacls "C:\Dados\Departamentos\Vendas" /grant:r "Administrators:(OI)(CI)(F)"
icacls "C:\Dados\Departamentos\RH"     /grant:r "Administrators:(OI)(CI)(F)"

# Conceder ao grupo departamental
icacls "C:\Dados\Departamentos\Vendas" /grant "GRP_Vendas:(OI)(CI)(M)"
icacls "C:\Dados\Departamentos\RH"     /grant "GRP_RH:(OI)(CI)(M)"

# Verificar ACL
icacls "C:\Dados\Departamentos\Vendas"
icacls "C:\Dados\Departamentos\RH"
Conceitos: (F) Full Control; (M) Modify; (OI)(CI) aplicam a arquivos e subpastas. Use grupos sempre que possível.

6) Validar o acesso com contas de teste

Crie um arquivo de teste em cada pasta e valide acesso com as novas contas.

# Criar arquivos de teste
"Relatório de Vendas" | Out-File -FilePath "C:\Dados\Departamentos\Vendas\leia-me.txt" -Encoding UTF8
"Dados de RH"         | Out-File -FilePath "C:\Dados\Departamentos\RH\leia-me.txt"     -Encoding UTF8
:: Alternar contexto com runas (GUI) ou efetuar logoff e abrir sessão
whoami
whoami /groups

:: Testar como vendas01: deve acessar somente Vendas
:: Testar como rh01: deve acessar somente RH

Registre capturas de tela: tentativa de leitura em pasta permitida e negada, além do whoami /groups.

7) Diretório base e dados do usuário

Opcionalmente, padronize uma pasta base por usuário para armazenar documentos de trabalho.

# Criar pastas pessoais e conceder acesso exclusivo
New-Item -Path "C:\Dados\Usuarios" -ItemType Directory -Force | Out-Null
New-Item -Path "C:\Dados\Usuarios\vendas01" -ItemType Directory -Force | Out-Null
New-Item -Path "C:\Dados\Usuarios\rh01"     -ItemType Directory -Force | Out-Null

# Permissão exclusiva ao usuário + Administrators
icacls "C:\Dados\Usuarios\vendas01" /inheritance:r
icacls "C:\Dados\Usuarios\rh01"     /inheritance:r

icacls "C:\Dados\Usuarios\vendas01" /grant:r "Administrators:(OI)(CI)(F)" "vendas01:(OI)(CI)(M)"
icacls "C:\Dados\Usuarios\rh01"     /grant:r "Administrators:(OI)(CI)(F)" "rh01:(OI)(CI)(M)"

Documente a localização dos dados e o padrão de nomenclatura adotado.

8) Migração simples de dados de perfil (opcional)

Para migrar dados entre contas locais, copie pastas de usuário com cuidado (evite AppData a menos que necessário).

# Exemplo: mover Documentos antigos para a nova pasta de dados
$origem = "C:\Users\antigo\Documents"
$dest   = "C:\Dados\Usuarios\vendas01\DocumentosMigrados"
Copy-Item -Path $origem -Destination $dest -Recurse -Force

# Ajustar propriedade para o usuário
$acl = Get-Acl $dest
$rule = New-Object System.Security.AccessControl.FileSystemAccessRule("vendas01","Modify","ContainerInherit,ObjectInherit","None","Allow")
$acl.SetAccessRule($rule)
Set-Acl -Path $dest -AclObject $acl
Atenção: fechar aplicativos antes de copiar. Evite copiar AppData a menos que tenha um motivo e saiba o impacto.

9) Auditoria rápida e registro

# Relatório rápido de usuários e grupos criados
Get-LocalUser | Select-Object Name, Enabled, LastLogon
Get-LocalGroup | Where-Object Name -match "GRP_" | Select-Object Name
Get-LocalGroupMember -Group "GRP_Vendas"
Get-LocalGroupMember -Group "GRP_RH"

# Exportar para CSV (evidência)
Get-LocalUser | Select Name,Enabled | Export-Csv -Path "C:\Dados\relatorio-usuarios.csv" -NoTypeInformation -Encoding UTF8

Inclua no diário de bordo: comandos usados, prints de verificação de acesso e análise de eventuais erros.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar o gerenciamento de usuários/grupos e o controle de acesso por NTFS, com documentação clara.

  1. Crie um terceiro grupo “GRP_Treinamento” e dois usuários (treina01 e treina02). Conceda acesso Modificar a C:\Dados\Departamentos\Treinamento (crie a pasta). Valide acesso e registre evidências.
  2. Implemente política de bloqueio mais restritiva (3 tentativas, 15 min) e documente o comportamento realizando tentativas falhas controladas.
  3. Automatize com PowerShell: um script que cria grupos/usuários de um CSV e aplica permissões NTFS em pastas correspondentes.

Critérios de avaliação

  • Correção técnica (estrutura de grupos, políticas e NTFS adequadas).
  • Privilégio mínimo aplicado e validado com testes de acesso.
  • Documentação clara com comandos, prints e justificativas.
  • Uso de snapshots/backup e boas práticas de laboratório.

Pesquisas complementares (sugestões)

  • Documentação Microsoft: Gerenciamento de contas locais e grupos no Windows 11.
  • Cmdlets de PowerShell para LocalAccounts: Get-LocalUser, New-LocalUser, Add-LocalGroupMember.
  • Guia de melhores práticas de permissões NTFS e herança.
  • Estratégias de políticas de senha e bloqueio (NIST, OWASP — visão geral).

Entregáveis ao final do Capítulo 11

  • Capturas de tela de testes de acesso (permitido/negado) e whoami /groups.
  • Script PowerShell utilizado (se houver) e anotações do diário de bordo.
