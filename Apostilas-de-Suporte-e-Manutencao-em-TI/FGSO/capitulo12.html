Capítulo 12 — Linha de comando e PowerShell: fundamentos

Carga: Não especificada

Projeto-base: Inventário básico do sistema via PowerShell com exportação em CSV

Stack fixa: Windows 11, PowerShell 5.1/7.x, Console do Windows/Terminal, VirtualBox

Resultados de aprendizagem deste capítulo:

  • Comparar CMD e PowerShell, reconhecendo suas diferenças de arquitetura e uso.
  • Navegar pelo sistema de arquivos e outros providers do PowerShell usando cmdlets apropriados.
  • Utilizar o pipeline e cmdlets de consulta/filtragem/seleção para compor comandos reutilizáveis.
  • Usar o sistema de ajuda integrado (Get-Help, Get-Command) para autoaprendizagem.
  • Aplicar políticas de execução de scripts de forma segura (ExecutionPolicy) em ambiente de laboratório.
  • Gerar um inventário básico do sistema e exportar resultados em CSV.

Competências e Habilidades

  • Operar ferramentas de linha de comando com segurança e precisão.
  • Interpretar mensagens de erro e documentação oficial.
  • Compor comandos com pipeline para automatizar consultas administrativas.
  • Gerar relatórios práticos (CSV) a partir de cmdlets.
  • Aplicar boas práticas de laboratório com VMs e snapshots.

Parte Teórica (explicação do conteúdo)

1) CMD vs. PowerShell: conceitos e diferenças

O CMD (Prompt de Comando) é um interpretador tradicional de comandos no Windows que trabalha essencialmente com texto. Já o PowerShell é uma plataforma de automação baseada em .NET que trabalha com objetos. Isso significa que, no PowerShell, os resultados dos comandos são objetos ricos com propriedades e métodos, facilitando filtragem, seleção e exportação sem “quebrar” texto.

Cmdlets são comandos do PowerShell padronizados no formato Verbo-Substantivo (ex.: Get-Process). Eles retornam objetos que podem ser encadeados via pipeline (|), permitindo composições poderosas e reutilizáveis. Apesar de o PowerShell executar muitos comandos legados do CMD, seu uso ideal é com cmdlets.

Onde vou aplicar isso: você usará cmdlets nativos em vez de comandos de texto para coletar dados de sistema e gerar relatórios com confiabilidade.

2) Navegação e Providers

O PowerShell utiliza “providers”, que expõem diferentes repositórios como se fossem sistemas de arquivos. O provider FileSystem permite navegar em diretórios e arquivos com cd, dir (alias de Get-ChildItem), etc. Outros providers comuns: Registry (HKLM:, HKCU:), Environment (Env:), Cert:, entre outros.

Isso viabiliza navegar e operar de forma consistente: listar chaves de registro ou variáveis de ambiente torna-se similar a listar arquivos.

Onde vou aplicar isso: você navegará no FileSystem e consultará informações em providers como Env: para enriquecer o relatório.

3) Pipeline e composição de cmdlets

O pipeline (|) conecta a saída de um cmdlet à entrada de outro. Como os dados são objetos, operações como Where-Object (filtrar), Select-Object (selecionar colunas), Sort-Object (ordenar) e Export-Csv (exportar) funcionam de forma previsível.

Exemplo: Get-Process | Where-Object CPU -gt 1 | Select-Object Name, CPU | Sort-Object CPU -Descending exporta facilmente processos que usam CPU acima de um limiar.

Onde vou aplicar isso: você usará pipeline para compor um inventário e refinar exatamente os campos que irão para o CSV.

4) Sistema de ajuda: Get-Help e Get-Command

O PowerShell tem ajuda integrada. Get-Help mostra documentação de cmdlets, inclusive exemplos. Get-Command ajuda a descobrir comandos e parâmetros por nome ou por verbo. Get-Member revela propriedades e métodos de objetos retornados por um cmdlet.

Uso sugerido: Get-Help Get-Process -Examples e Get-Command -Verb Get para explorar.

Onde vou aplicar isso: você consultará a ajuda para entender parâmetros de Export-Csv, Select-Object e Where-Object durante o passo a passo.

5) Execução segura de scripts (ExecutionPolicy)

A ExecutionPolicy controla como scripts são carregados. Perfis comuns: Restricted (não permite scripts), RemoteSigned (scripts locais rodam; remotos precisam de assinatura) e Bypass (sem bloqueios). Em laboratório, usamos configurações seguras e temporárias por escopo (Process, CurrentUser).

Nunca altere políticas globalmente sem necessidade. Em VM, prefira escopo CurrentUser ou Process para evitar riscos.

Onde vou aplicar isso: você definirá uma política segura (RemoteSigned em CurrentUser) para testar scripts do inventário.

6) Exportação e formatos (CSV)

CSV é prático para relatórios e pode ser aberto em planilhas. Export-Csv cria o arquivo com cabeçalhos de colunas baseados nas propriedades dos objetos. O parâmetro -NoTypeInformation omite metadados de tipo no topo do arquivo.

Também é possível converter para JSON (ConvertTo-Json) quando necessário para integrações.

Onde vou aplicar isso: você exportará o inventário para CSV, garantindo colunas claras e padronizadas.

Passo a Passo — Inventário do sistema via PowerShell com exportação em CSV

Objetivo desta etapa:

Coletar informações do sistema (SO, hardware, rede e processos), manipular com pipeline e exportar para um arquivo CSV legível.


Pré-requisitos e preparação

  1. Abrir sua VM Windows 11 (VirtualBox) e garantir snapshot “antes do capítulo”.
  2. Abrir PowerShell com privilégios de usuário padrão (sem necessidade de admin para este roteiro).
  3. Verificar versão do PowerShell: 
    $PSVersionTable
  4. Checar ajuda e atualizar conteúdo de ajuda (opcional): 
    Get-Help Get-Process -Examples

# Update-Help

1) Navegação e exploração com providers

Liste itens do diretório atual e navegue entre pastas.

# listar conteúdo
Get-ChildItem
# mudar de pasta (ex.: Documentos do usuário)
Set-Location "$HOME\Documents"
# explorar variáveis de ambiente
Get-ChildItem Env:
Dica: Use Tab para autocompletar caminhos e nomes de comandos.

2) Diferença entre CMD e PowerShell (prática rápida)

Compare um comando clássico no CMD e o equivalente em PowerShell.

:: CMD - lista de processos em texto
tasklist
# PowerShell - objetos de processo
Get-Process | Select-Object Name, Id, CPU | Sort-Object CPU -Descending

3) Coletar informações do sistema

Use cmdlets nativos e WMI/CIM para obter dados estruturados.

# Sistema operacional
$os = Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, BuildNumber, OSArchitecture

# CPU e memória
$cpu = Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors, MaxClockSpeed
$mem = Get-CimInstance Win32_ComputerSystem | Select-Object Manufacturer, Model, TotalPhysicalMemory

# Adaptadores de rede (ativos)
$net = Get-NetIPConfiguration | Where-Object { $_.IPv4Address -ne $null } |
       Select-Object InterfaceAlias, IPv4Address, IPv4DefaultGateway, DNSServer

# Top 5 processos por uso de CPU
$topProc = Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 Name, Id, CPU

4) Montar objeto consolidado e exportar CSV

Crie um objeto com colunas padronizadas e exporte. Para listas (ex.: DNS), junte em uma string.

# Preparar campos
$dnsAll = ($net.DNSServer.ServerAddresses | Where-Object { $_ } | Select-Object -Unique) -join '; '
$ipv4    = ($net.IPv4Address.IPAddressToString | Where-Object { $_ }) -join '; '
$gw      = ($net.IPv4DefaultGateway.NextHop | Where-Object { $_ }) -join '; '

# Converter memória total para GB (aprox.)
$memGB = [math]::Round(($mem.TotalPhysicalMemory/1GB), 2)

$report = [PSCustomObject]@{
  Hostname      = $env:COMPUTERNAME
  SO            = $os.Caption
  Versao        = $os.Version
  Build         = $os.BuildNumber
  Arquitetura   = $os.OSArchitecture
  CPU           = $cpu.Name
  Cores         = $cpu.NumberOfCores
  Logicos       = $cpu.NumberOfLogicalProcessors
  MemoriaGB     = $memGB
  IPv4          = $ipv4
  Gateway       = $gw
  DNS           = $dnsAll
  DataColeta    = (Get-Date).ToString('yyyy-MM-dd HH:mm')
}

# Exportar relatório (pasta Documentos)
$outDir = Join-Path $HOME 'Documents'
$outCsv = Join-Path $outDir ('inventario_' + $env:COMPUTERNAME + '.csv')

$report | Export-Csv -Path $outCsv -NoTypeInformation -Encoding UTF8

# Exportar top 5 processos em CSV separado
$outProc = Join-Path $outDir ('processos_top5_' + $env:COMPUTERNAME + '.csv')
$topProc | Export-Csv -Path $outProc -NoTypeInformation -Encoding UTF8

"Relatórios gerados:"; $outCsv; $outProc

5) Uso de Get-Help e documentação

Explore ajuda e exemplos para refinar seus comandos e parâmetros.

Get-Help Export-Csv -Online
Get-Help Select-Object -Examples
Get-Command *Process*

6) ExecutionPolicy em laboratório (seguro)

Defina política por usuário (CurrentUser) para permitir scripts locais. Crie e execute um script simples.

# Ver política atual
Get-ExecutionPolicy -List

# Definir segurança razoável para laboratório:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force

# Criar script de teste
$script = @'
Write-Host "Inventário rápido:" -ForegroundColor Cyan
Get-Process | Select-Object -First 3 Name, Id, CPU
'@
$path = Join-Path $HOME 'Documents\teste.ps1'
$script | Set-Content -Path $path -Encoding UTF8

# Executar script (observe a política aplicada)
& $path
Em ambientes de produção, altere políticas somente com aprovação e políticas institucionais claras.

7) Validação do CSV

Abra o CSV no Excel/LibreOffice ou visualize no PowerShell.

Import-Csv $outCsv | Format-Table -AutoSize
Import-Csv $outProc | Sort-Object CPU -Descending | Format-Table -AutoSize
