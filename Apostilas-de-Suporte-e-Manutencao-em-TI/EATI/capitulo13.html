Capítulo 13 — Programação básica em C/C++ no Arduino

Carga: 4 h

Projeto-base: Botão com debounce que alterna um LED e envia logs pela Serial

Stack fixa: Arduino Uno, IDE Arduino, linguagem C/C++ (sketch), Monitor Serial

Resultados de aprendizagem deste capítulo:

  • Declarar e usar tipos de dados, variáveis e operadores em sketches Arduino.
  • Implementar estruturas de decisão (if/else, switch) e repetição (for, while) com boas práticas.
  • Criar e reutilizar funções para modularizar o código e melhorar a legibilidade.
  • Ler entradas digitais (botões) e acionar saídas (LED), aplicando debounce por software.
  • Realizar depuração básica usando a porta Serial (logs) e comentar o código de forma clara.

Competências e Habilidades

  • Entender a estrutura de um sketch (setup/loop) e o ciclo de execução em sistemas embarcados.
  • Selecionar tipos e operadores adequados para resolver problemas simples.
  • Aplicar estruturas de controle de fluxo para tomada de decisão.
  • Desenvolver funções e boas práticas de organização e comentários.
  • Integrar leitura digital com acionamento de saída e registro via Serial.

Parte Teórica (explicação do conteúdo)

1) Estrutura de um sketch: setup() e loop()

Um sketch Arduino é composto por duas funções obrigatórias: setup(), executada uma vez na inicialização (configurações iniciais), e loop(), executada continuamente enquanto a placa estiver ligada. Esse modelo reflete o funcionamento de sistemas embarcados, que reagem em tempo real a entradas e atualizam saídas.

No setup(), tipicamente definimos o modo dos pinos (pinMode) e inicializamos a porta Serial (Serial.begin). No loop(), lemos sensores, tomamos decisões e acionamos atuadores. O fluxo é cíclico e determinístico.

Onde vou aplicar isso: no passo a passo, ao configurar pinos do LED e do botão e ao escrever a lógica de debounce que roda continuamente.

2) Tipos de dados, variáveis e constantes

Variáveis armazenam informações temporárias enquanto o programa executa. No Arduino (C/C++), os tipos mais comuns são: bool (verdadeiro/falso), byte (0 a 255), int (inteiro 16 bits no Uno), unsigned int, long, float (ponto flutuante), e char (caractere).

Use const para constantes (ex.: número do pino) e #define para macros. Prefira const por respeitar o escopo e o tipo. Nomeie variáveis de forma clara e documente a unidade de medida quando fizer sentido.

Onde vou aplicar isso: definir pinos como constantes, variáveis para estados do LED e do botão, e temporizações para o debounce.

3) Operadores e expressões

Operadores aritméticos (+, -, *, /, %), relacionais (==, !=, <, >, <=, >=) e lógicos (&&, ||, !) são usados para calcular e comparar valores. Tenha atenção a tipos com sinal e sem sinal, e a divisões inteiras que descartam a parte fracionária.

O operador de atribuição composta (+=, -=, etc.) ajuda a escrever código mais compacto. Para leitura de pinos digitais, a função digitalRead retorna HIGH ou LOW, que você pode comparar diretamente.

Onde vou aplicar isso: na lógica que detecta transições de estado do botão e alterna o LED.

4) Controle de fluxo: if/else, switch, for, while

if/else permite executar blocos condicionais; switch é útil para múltiplos casos discretos; for e while repetem ações conforme uma condição. Em microcontroladores, prefira laços curtos e evite bloqueios longos (ex.: delay exagerado) para manter o sistema responsivo.

No debounce, uma abordagem comum é verificar se o estado do botão se mantém estável por um intervalo (ex.: 30–50 ms) antes de confirmar a mudança.

Onde vou aplicar isso: usar if/else para confirmar leituras estáveis do botão e switch/if para gerenciar modos simples, caso queira estender o projeto.

5) Funções: modularização e reaproveitamento

Funções agrupam instruções que realizam uma tarefa específica, melhorando legibilidade, manutenção e testes. Defina parâmetros e retornos adequados. Em Arduino, você pode criar funções para ler o botão com debounce, alternar LED e registrar mensagens na Serial.

Boas práticas: funções curtas, nomes autoexplicativos, evitar efeitos colaterais inesperados e comentários que expliquem “por que” (não apenas o “o que”).

Onde vou aplicar isso: criaremos leBotaoDebounced() e alternarLed() para separar responsabilidades.

6) Entrada digital e debounce por software

Botões mecânicos produzem “ruído” (oscilações) no momento do pressionamento/soltura. O debounce filtra essas oscilações para evitar múltiplos acionamentos indesejados. Duas abordagens comuns: temporização simples (aguardar estabilidade por X ms) e janela de tempo com verificação de estabilidade usando millis().

Utilize um resistor de pull-down ou ative o INPUT_PULLUP interno, lembrando que a lógica inverte (pressionado = LOW). Sempre documente a convenção adotada.

Onde vou aplicar isso: implementaremos debounce com millis() e INPUT_PULLUP para robustez.

7) Serial para depuração (debug)

Serial.begin(9600) inicializa a comunicação; Serial.print/println ajudam a inspecionar valores e eventos em tempo real. Evite imprimir em excesso no loop() para não atrasar o programa. Use mensagens claras com contexto.

Onde vou aplicar isso: emitiremos logs quando o botão for confirmado e quando o LED alternar de estado.

Passo a Passo — Botão com debounce que alterna LED e registra logs

Objetivo desta etapa:

Montar um circuito simples com LED e botão, programar leitura digital com debounce por software, alternar o LED a cada clique confirmado e registrar eventos no Monitor Serial.


Materiais

  • Arduino Uno (ou compatível) e cabo USB
  • Protoboard e jumpers
  • 1 LED e 1 resistor de 220 Ω (limitador de corrente do LED)
  • 1 botão tátil

Esquema de ligações (sugestão)

  • LED: anodo no pino 13 via resistor de 220 Ω; cátodo ao GND.
  • Botão: um lado ao GND; o outro lado ao pino 2. Configuraremos INPUT_PULLUP (logo, pressionado = LOW).

1) Esqueleto do sketch e constantes

Crie um novo sketch na IDE Arduino e defina pinos e variáveis globais.

// Capítulo 13 — Botão com debounce e alternância de LED
// Convenção: INPUT_PULLUP => pressionado = LOW; solto = HIGH

const uint8_t PINO_LED   = 13;   // LED no pino 13 (com resistor)
const uint8_t PINO_BOTAO = 2;    // Botão entre pino 2 e GND

// Parâmetros de debounce (em milissegundos)
const unsigned long DEBOUNCE_MS = 40;

// Estado do sistema
bool ledLigado = false;

// Variáveis para debounce
bool estadoEstavel = HIGH;               // estado "confiável" atual do botão
bool leituraAnterior = HIGH;             // última leitura bruta
unsigned long instanteMudanca = 0;       // quando a leitura bruta mudou

void setup() {
  pinMode(PINO_LED, OUTPUT);
  pinMode(PINO_BOTAO, INPUT_PULLUP);     // pull-up interno
  digitalWrite(PINO_LED, LOW);

  Serial.begin(9600);
  while(!Serial) { /* aguarda serial (opcional em placas nativas) */ }

  Serial.println(F("Inicializado. Pressione o botao para alternar o LED."));
}

void loop() {
  // Em breve: leitura com debounce e alternância do LED
}

2) Função de leitura com debounce

Esta função verifica mudanças de leitura e só confirma após estabilidade pelo tempo definido.

// Retorna true se houve "transicao de borda de pressao" (HIGH->LOW) confirmada
bool leBotaoDebounced() {
  bool leitura = digitalRead(PINO_BOTAO);

  if (leitura != leituraAnterior) {
    leituraAnterior = leitura;
    instanteMudanca = millis(); // registramos quando a leitura mudou
  }

  // Confirma a mudança se permanecer diferente por DEBOUNCE_MS
  if ((millis() - instanteMudanca) >= DEBOUNCE_MS) {
    if (leitura != estadoEstavel) {
      estadoEstavel = leitura;
      // Detecta borda de descida (pressionou)
      if (estadoEstavel == LOW) {
        return true;
      }
    }
  }

  return false;
}

3) Função para alternar LED e registrar logs

void alternarLed() {
  ledLigado = !ledLigado;
  digitalWrite(PINO_LED, ledLigado ? HIGH : LOW);
  Serial.print(F("LED: "));
  Serial.println(ledLigado ? F("LIGADO") : F("DESLIGADO"));
}

4) Loop principal integrando tudo

void loop() {
  if (leBotaoDebounced()) {
    Serial.println(F("Clique confirmado (debounced). Alternando LED..."));
    alternarLed();
  }

  // (Opcional) pequena pausa para reduzir jitter de leitura/prints
  delay(1);
}

5) Teste e depuração

  • Envie o sketch e abra o Monitor Serial (9600 baud).
  • Pressione e solte o botão: a cada clique confirmado, o LED deve alternar e o log deve aparecer.
  • Se o LED alternar múltiplas vezes por clique, aumente DEBOUNCE_MS (ex.: 60 ms).

6) Extensões rápidas (opcional)

Substitua o delay por laço totalmente não bloqueante e inclua um “timeout” de duplo-clique como desafio.

Versão completa do sketch (consolidada)

// Capítulo 13 — Projeto-base completo: Botão com debounce e LED toggle
const uint8_t PINO_LED   = 13;
const uint8_t PINO_BOTAO = 2;
const unsigned long DEBOUNCE_MS = 40;

bool ledLigado = false;
bool estadoEstavel = HIGH;
bool leituraAnterior = HIGH;
unsigned long instanteMudanca = 0;

bool leBotaoDebounced() {
  bool leitura = digitalRead(PINO_BOTAO);

  if (leitura != leituraAnterior) {
    leituraAnterior = leitura;
    instanteMudanca = millis();
  }

  if ((millis() - instanteMudanca) >= DEBOUNCE_MS) {
    if (leitura != estadoEstavel) {
      estadoEstavel = leitura;
      if (estadoEstavel == LOW) {
        return true; // borda de descida (pressionou)
      }
    }
  }
  return false;
}

void alternarLed() {
  ledLigado = !ledLigado;
  digitalWrite(PINO_LED, ledLigado ? HIGH : LOW);
  Serial.print(F("LED: "));
  Serial.println(ledLigado ? F("LIGADO") : F("DESLIGADO"));
}

void setup() {
  pinMode(PINO_LED, OUTPUT);
  pinMode(PINO_BOTAO, INPUT_PULLUP);
  digitalWrite(PINO_LED, LOW);

  Serial.begin(9600);
  Serial.println(F("Iniciado. Pressione o botao para alternar o LED."));
}

void loop() {
  if (leBotaoDebounced()) {
    Serial.println(F("Clique confirmado."));
    alternarLed();
  }
  // Sem delays longos; manter responsivo
}

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar estruturas de decisão/repetição, modularização com funções e boas práticas de comentários e depuração.

  1. Contador com botão: cada clique confirmado incrementa um contador (0–9) e imprime no Serial. Ao atingir 9, volta para 0. Dica: use if e operador módulo.
  2. LED “hold-to-toggle”: só alterna o LED se o botão permanecer pressionado por pelo menos 500 ms. Dica: armazene o instante de pressão confirmado e valide duração com millis().
  3. Estados com switch: implemente três estados (0 = LED apagado, 1 = pisca lento, 2 = pisca rápido). A cada clique, avance para o próximo estado, usando switch e funções para cada comportamento.

  • Registros no Monitor Serial claros e objetivos.
