Capítulo 15 — Automação e IA aplicadas ao Suporte

Carga: 4h (teórico-prática)

Projeto-base: Service Desk escolar com protótipo de triagem automática

Stack fixa: Ferramenta ITSM (GLPI/OTRS/Zammad/Jira Service Management simulado), planilhas/CSV, scripts em Python ou JavaScript, wiki/drive

Resultados de aprendizagem deste capítulo:

  • Identificar casos de uso de automação e IA no ciclo de chamados (categorização, roteamento, respostas sugeridas).
  • Configurar um fluxo simples de triagem automática baseado em regras e textos do usuário.
  • Integrar a triagem a um formulário/CSV e registrar a sugestão de categoria e prioridade no ticket.
  • Avaliar riscos e vieses e propor salvaguardas e governança para uso responsável de IA no suporte.

Competências e Habilidades

  • Aplicar pensamento sistêmico na automação de tarefas repetitivas do Service Desk.
  • Modelar regras de classificação e priorização a partir de descrições de usuários.
  • Documentar procedimentos (POP) e evidências de testes de automação.
  • Analisar métricas de eficiência pós-automação (tempo de resposta e taxa de roteamento correto).
  • Reconhecer limitações, vieses e controles necessários no uso de IA.

Parte Teórica (explicação do conteúdo)

Casos de uso de automação/IA no Service Desk

Automação e IA podem reduzir tempo de triagem, padronizar respostas e melhorar a experiência do usuário. Casos comuns incluem: categorização automática de chamados, sugestão de prioridade com base em impacto/urgência, roteamento para a fila correta, preenchimento de templates e respostas sugeridas com links de base de conhecimento.

Automação baseada em regras é apropriada para começar: palavras-chave, padrões (regex) e mapeamentos simples. Para cenários mais complexos, modelos de linguagem podem sugerir categorias, mas exigem governança e validação humana.

Onde vou aplicar isso: você usará regras e scripts para sugerir categoria e prioridade no formulário de ticket, reduzindo retrabalho na triagem.

Integração com ferramentas ITSM e chatbots

Ferramentas ITSM (como GLPI, OTRS, Zammad, Jira Service Management) permitem criar gatilhos ao abrir um chamado. Um serviço externo (webhook/script) pode ler a descrição e devolver categoria/priority sugeridas. Chatbots no portal de autoatendimento podem coletar informações com prompts e já rotular o ticket corretamente.

O fluxo típico: usuário submete → gatilho chama script → script analisa e devolve rótulos → sistema grava em campos do ticket e registra a “sugestão da automação” para auditoria.

Onde vou aplicar isso: no passo a passo, simularemos o “gatilho” com um script local e uma planilha/CSV representando os tickets.

Modelagem de regras de categorização e priorização

Comece com um dicionário de palavras-chave por categoria (ex.: “impressora, toner, papel” → Categoria: Impressão). Para prioridade, traduza impacto e urgência com regras: se conter “não consigo trabalhar”, “parado geral”, “sala inteira”, classifique como alta.

Inclua exceções e sinônimos. Use normalização (minúsculas, remoção de acentos) para maior robustez. Registre cobertura e casos fronteira para iterar.

Onde vou aplicar isso: construiremos um mapa de palavras-chave e uma função que retorna categoria e prioridade sugeridas.

Riscos, vieses e governança de IA

Automação e IA podem errar e introduzir vieses. Boas práticas: manter humano no loop para alterações críticas; registrar a recomendação e a decisão final; medir taxa de acerto; permitir override fácil; não expor dados sensíveis a serviços externos sem autorização; seguir políticas de segurança.

Defina critérios de aceitação (ex.: 85% de acurácia antes de autopreencher), logs de auditoria e revisão periódica das regras/modelos. Documente fontes, versões e mudanças (POP e controle de versão).

Onde vou aplicar isso: ao final, você registrará evidências, taxa de acerto e uma seção de riscos/controles no POP do protótipo.

Passo a Passo — Protótipo de triagem automática (regras)

Objetivo desta etapa:

Construir um script que lê a descrição de chamados e sugere categoria e prioridade, salvando a recomendação em um CSV e exibindo os resultados para validação.

3) Implementar o classificador (Python)

Script que normaliza texto (minúsculas, sem acentos), busca palavras-chave e retorna categoria e prioridade sugeridas. Salva a recomendação em um novo CSV.

import csv
import json
import unicodedata
from pathlib import Path

def normalizar(txt: str) -> str:
    if not txt:
        return ""
    txt = txt.lower()
    txt = unicodedata.normalize("NFD", txt)
    return "".join(ch for ch in txt if unicodedata.category(ch) != "Mn")

def sugerir_categoria(descricao_norm, regras):
    melhor_cat = "Geral"
    melhor_score = 0
    for categoria, termos in regras["categorias"].items():
        score = sum(1 for t in termos if t in descricao_norm)
        if score > melhor_score:
            melhor_score = score
            melhor_cat = categoria
    return melhor_cat

def sugerir_prioridade(descricao_norm, regras):
    # Ordem: alta > média > baixa
    for nivel in ["alta", "média", "baixa"]:
        termos = regras["prioridade"][nivel]
        if any(t in descricao_norm for t in termos):
            return nivel.capitalize()
    return "Média"

def processar(in_csv="tickets.csv", out_csv="tickets_saida.csv", regras_json="regras.json"):
    with open(regras_json, "r", encoding="utf-8") as f:
        regras = json.load(f)

    Path(out_csv).unlink(missing_ok=True)
    with open(in_csv, newline="", encoding="utf-8") as fin, \
         open(out_csv, "w", newline="", encoding="utf-8") as fout:
        reader = csv.DictReader(fin)
        fieldnames = reader.fieldnames + ["categoria_sugerida", "prioridade_sugerida"]
        writer = csv.DictWriter(fout, fieldnames=fieldnames)
        writer.writeheader()
        for row in reader:
            desc_norm = normalizar(row.get("descricao", ""))
            cat = sugerir_categoria(desc_norm, regras)
            pri = sugerir_prioridade(desc_norm, regras)
            row["categoria_sugerida"] = cat
            row["prioridade_sugerida"] = pri
            writer.writerow(row)
    print(f"Arquivo gerado: {out_csv}")

if __name__ == "__main__":
    processar()

4) Alternativa em JavaScript (Node.js)

Se preferir, use Node.js para ler o CSV e gerar o arquivo de saída com sugestões.

import fs from 'node:fs';
import { parse } from 'node:path';

const normalizar = (txt = '') => {
  return txt
    .toLowerCase()
    .normalize('NFD')
    .replace(/\p{Mn}/gu, '');
};

const carregarCSV = (caminho) => {
  const linhas = fs.readFileSync(caminho, 'utf-8').split(/\r?\n/).filter(Boolean);
  const header = linhas.shift().split(',');
  return linhas.map(l => {
    // split simples; para CSV complexo, use uma lib (csv-parse)
    const cols = l.split(',');
    const obj = {};
    header.forEach((h, i) => obj[h] = cols[i]);
    return obj;
  });
};

const salvarCSV = (caminho, header, linhas) => {
  const out = [header.join(',')].concat(linhas.map(o => header.map(h => o[h] ?? '').join(','))).join('\n');
  fs.writeFileSync(caminho, out, 'utf-8');
};

const main = () => {
  const regras = JSON.parse(fs.readFileSync('regras.json', 'utf-8'));
  const tickets = carregarCSV('tickets.csv');
  const header = Object.keys(tickets[0] ?? {}).concat(['categoria_sugerida','prioridade_sugerida']);

  const classificados = tickets.map(t => {
    const desc = normalizar(t.descricao || '');
    let melhorCat = 'Geral', melhorScore = 0;
    for (const [cat, termos] of Object.entries(regras.categorias)) {
      const score = termos.reduce((acc, termo) => acc + (desc.includes(termo) ? 1 : 0), 0);
      if (score > melhorScore) { melhorScore = score; melhorCat = cat; }
    }
    const niv = (()=>{
      if (regras.prioridade['alta'].some(k => desc.includes(k))) return 'Alta';
      if (regras.prioridade['média'].some(k => desc.includes(k))) return 'Média';
      if (regras.prioridade['baixa'].some(k => desc.includes(k))) return 'Baixa';
      return 'Média';
    })();
    return { ...t, categoria_sugerida: melhorCat, prioridade_sugerida: niv };
  });

  salvarCSV('tickets_saida.csv', header, classificados);
  console.log('tickets_saida.csv gerado.');
};

main();

6) Testes, métricas e documentação (POP)

Crie um POP contendo: objetivo, escopo, pré-requisitos, passos (execução do script), validação (amostra de 10 tickets), rollback (voltar a triagem manual) e anexos (CSV antes/depois).

# POP — Triagem Automática por Regras
Objetivo: sugerir categoria e prioridade com base na descrição do chamado.
Escopo: tickets abertos pelo portal interno.
Pré-requisitos: Python 3 (ou Node.js), regras.json, tickets.csv.
Passos: (1) atualizar regras; (2) executar script; (3) importar sugestões no ITSM; (4) analista valida.
Validação: taxa de acerto alvo ≥ 80% em amostra de 10 tickets.
Rollback: desativar gatilho e retornar à triagem manual.
Auditoria: registrar sugestão, decisão do analista e motivo em campo apropriado.
