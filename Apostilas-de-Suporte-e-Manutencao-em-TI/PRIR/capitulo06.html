Plano de Aula (Capítulo 06)

Contexto: Dando continuidade ao Cap. 05 (IPv4 básico), este capítulo aprofunda o planejamento de sub-redes e o uso de VLSM para otimização de endereços.

Objetivos específicos: (1) Praticar subnetting manual; (2) Planejar VLSM para diferentes setores; (3) Construir a tabela de endereçamento; (4) Implementar e validar em simulação.

Estratégia didática: Exposição dialogada com exemplos, seguida de exercício guiado e implementação no Packet Tracer. Registro técnico dos cálculos e testes.

Recursos: Quadro, slides, calculadora de sub-rede (opcional), Packet Tracer/GNS3.

Avaliação formativa: Correção dos cálculos, verificação da tabela de endereçamento e validação de ping entre hosts das sub-redes planejadas.

Parte Teórica (explicação do conteúdo)

1) Revisão rápida: IPv4, máscara e CIDR

Um endereço IPv4 possui 32 bits e é usualmente representado em notação decimal pontuada (ex.: 192.168.10.5). A máscara de sub-rede define quantos bits são usados para identificar a rede e quantos ficam para hosts. Em notação CIDR, indicamos a quantidade de bits de rede como um sufixo (ex.: /24 equivale à máscara 255.255.255.0).

Onde vou aplicar isso no passo a passo: você utilizará essa base para calcular redes, broadcasts e faixas de hosts em cada etapa do planejamento.

2) Subnetting: por que e como

Subnetting é o processo de dividir uma rede maior em redes menores (sub-redes) para melhorar organização, segurança e uso eficiente de endereços. Em um /24 (256 endereços totais), ao “emprestar” bits da porção de host para rede, criamos múltiplas sub-redes menores, cada uma com seu próprio endereço de rede e broadcast.

Ao calcular sub-redes, é essencial determinar: (a) quantas sub-redes são necessárias; (b) quantos hosts por sub-rede são exigidos; (c) a máscara adequada; (d) a sequência de incrementos (saltos) de rede.

Onde vou aplicar isso no passo a passo: você fará o cálculo de sub-redes para três setores com tamanhos diferentes, justificando a máscara escolhida.

3) Endereço de rede, broadcast e faixa de hosts

Em cada sub-rede, o primeiro endereço é o endereço de rede (todos os bits de host em 0) e o último é o broadcast (todos os bits de host em 1). Os endereços entre eles são atribuíveis a hosts. Ex.: em 192.168.10.0/26, a primeira sub-rede é 192.168.10.0–63, sendo 192.168.10.0 a rede, 192.168.10.63 o broadcast e 192.168.10.1–62 os hosts.

Onde vou aplicar isso no passo a passo: você identificará rede, broadcast e reservará IPs específicos (gateway, servidores, impressoras).

4) VLSM (Variable Length Subnet Mask)

VLSM permite usar máscaras de comprimentos diferentes dentro de um mesmo bloco, alocando sub-redes “sob medida”. A técnica otimiza o uso do espaço de endereços, evitando desperdícios (por exemplo, não usar /24 para um setor com apenas 20 hosts).

O método clássico é ordenar as necessidades do maior para o menor número de hosts, atribuindo primeiro as sub-redes maiores e depois subdividindo o que restar para as menores.

Onde vou aplicar isso no passo a passo: você organizará setores por tamanho e aplicará VLSM para atender cada um com a menor máscara possível.

5) Tabela de endereçamento e convenções

Uma tabela de endereçamento bem feita documenta: sub-rede, máscara/CIDR, rede, broadcast, faixa de hosts, gateway padrão e reservas (servidores, impressoras, câmeras). Definir convenções (por exemplo, “.1” como gateway; “.10–.20” servidores) facilita manutenção e troubleshooting.

Onde vou aplicar isso no passo a passo: você criará a tabela, aplicará no simulador e validará com testes ICMP.

6) Boas práticas e validação

Registre todos os cálculos, rotule dispositivos e portas no diagrama, e valide cada sub-rede com ping, ARP e tabelas de roteamento (quando houver roteador). Pequenos erros de máscara ou gateway invalidam a conectividade.

Onde vou aplicar isso no passo a passo: você seguirá um roteiro de testes escalonado e registrará evidências.

Passo a Passo — Planejamento e Implementação de Sub-redes IPv4 com VLSM

Objetivo desta etapa:

Planejar sub-redes com VLSM para três setores, criar a tabela de endereçamento e implementar em simulação (Packet Tracer), validando a conectividade.


Etapa 1 — Coletar requisitos e ordenar necessidades

Considere a empresa fictícia “AlphaTech” e o bloco disponível 192.168.50.0/24. Setores e necessidades (hosts úteis):

  • Administração: 50 hosts
  • Suporte: 30 hosts
  • Diretoria: 10 hosts

Ordene do maior para o menor: Administração (50), Suporte (30), Diretoria (10).

Dica: hosts úteis = 2^(bits_host) − 2. Escolha a menor máscara que comporte o total de hosts do setor.

Etapa 2 — Calcular máscaras por setor (VLSM)

Para cada setor, encontre a menor sub-rede possível:

  • Administração (50): precisa de no mínimo 62 hosts úteis → /26 (máscara 255.255.255.192)
  • Suporte (30): precisa de no mínimo 30 hosts úteis → /27 dá 30? 2^5−2 = 30 → /27 (255.255.255.224)
  • Diretoria (10): precisa de no mínimo 10 hosts úteis → 2^4−2 = 14 → /28 (255.255.255.240)

Agora vamos alocar dentro do 192.168.50.0/24 começando pela maior sub-rede.

Bloco base: 192.168.50.0/24

1) Administração /26
   Incremento do /26: 64
   Sub-redes possíveis: .0/26 (.0–.63), .64/26 (.64–.127), .128/26 (.128–.191), .192/26 (.192–.255)
   Vamos reservar a primeira: 192.168.50.0/26
   Rede:      192.168.50.0
   Broadcast: 192.168.50.63
   Hosts:     192.168.50.1–62

2) Suporte /27
   Incremento do /27: 32
   A próxima faixa livre após .0/26 é .64–.255
   Sub-redes /27 a partir de .64: .64/27 (.64–.95), .96/27 (.96–.127), ...
   Vamos reservar: 192.168.50.64/27
   Rede:      192.168.50.64
   Broadcast: 192.168.50.95
   Hosts:     192.168.50.65–94

3) Diretoria /28
   Incremento do /28: 16
   Próxima faixa livre começa em .96
   Sub-redes /28 a partir de .96: .96/28 (.96–.111), .112/28 (.112–.127), ...
   Vamos reservar: 192.168.50.96/28
   Rede:      192.168.50.96
   Broadcast: 192.168.50.111
   Hosts:     192.168.50.97–110

Etapa 3 — Definir convenções e tabela de endereçamento

Convenções sugeridas:

  • Gateway padrão: sempre o menor host (.1 da sub-rede)
  • Servidores: .10–.20 (se houver)
  • Impressoras: .30–.39 (se houver)
  • Demais hosts: restante da faixa
Tabela (resumo)
- Admin (192.168.50.0/26):    GW 192.168.50.1, hosts 192.168.50.2–62
- Suporte (192.168.50.64/27): GW 192.168.50.65, hosts 192.168.50.66–94
- Diretoria (192.168.50.96/28): GW 192.168.50.97, hosts 192.168.50.98–110

Etapa 4 — Montar a topologia no Packet Tracer

Crie 3 switches (um por setor) e um roteador com 3 interfaces (ou subinterfaces) para atuar como gateway das VLANs/segmentos. Alternativa simples: usar um roteador com 3 portas FastEthernet.

  1. Adicione um roteador (ex.: 2811) e 3 switches (2960).
  2. Conecte cada switch a uma interface do roteador.
  3. Adicione 2 PCs por setor para testes iniciais.
Em ambientes com VLANs, você poderia usar subinterfaces (router-on-a-stick). Aqui, foque no endereço IP/máscara corretos.

Etapa 5 — Configurar endereços nos PCs

Exemplo (Windows CMD) para configurar IP estático em laboratório real. Em simulação, use a interface gráfica do PC no Packet Tracer para definir IP/máscara/gateway:

# Exemplo de configuração (Windows PowerShell elevado)
# PC de Administração (coloque conforme sua faixa)
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.50.2 -PrefixLength 26 -DefaultGateway 192.168.50.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 8.8.8.8

Repita para os PCs dos setores Suporte e Diretoria, usando as faixas definidas e seus gateways.

Etapa 6 — Configurar o roteador (endereços nas interfaces)

No Packet Tracer (CLI do roteador):

enable
configure terminal
! Interface para Administração
interface fastEthernet0/0
 ip address 192.168.50.1 255.255.255.192
 no shutdown
exit
! Interface para Suporte
interface fastEthernet0/1
 ip address 192.168.50.65 255.255.255.224
 no shutdown
exit
! Interface para Diretoria
interface fastEthernet0/2
 ip address 192.168.50.97 255.255.255.240
 no shutdown
end
write memory
Ajuste nomes das interfaces conforme o modelo do roteador disponível no simulador.

Etapa 7 — Validar conectividade e registrar evidências

Teste ping entre hosts do mesmo setor e entre setores (através do roteador). Registre resultados e, em caso de falhas, verifique máscara, gateway e cabeamento.

# Testes básicos (em cada PC)
ipconfig    # (Windows) conferir IP/máscara/gateway
ifconfig    # (Linux) conferir IP/máscara
ping 192.168.50.1     # ping no gateway do setor
ping 192.168.50.66    # ping em host de outro setor (exemplo)
arp -a                # observar resolução ARP

Etapa 8 — Documentar a tabela de endereçamento

Finalize uma tabela com as colunas: Setor, Sub-rede, Máscara/CIDR, Endereço de rede, Broadcast, Gateway, Intervalo de hosts, Reservas. Essa documentação fará parte dos entregáveis do capítulo.
