Capítulo 07 — IPv6: Fundamentos e Endereços

Carga: 4h (teoria e prática)

Projeto-base: LAN didática com duplo stack (IPv4/IPv6) em simulação (Packet Tracer/GNS3)

Stack fixa: Windows/Linux, Cisco IOS, ICMPv6, SLAAC, NDP

Resultados de aprendizagem deste capítulo:

  • Explicar o formato de endereços e prefixos IPv6 e sua notação abreviada.
  • Diferenciar tipos de endereços IPv6: global unicast, ULA e link-local, e reconhecer seus escopos.
  • Configurar endereços IPv6 estáticos em hosts e dispositivos de rede.
  • Habilitar e verificar autoconfiguração SLAAC e vizinhança via NDP/ICMPv6.
  • Comparar aspectos práticos de IPv4 vs. IPv6 em testes de conectividade (ping, traceroute).

Competências e Habilidades

  • MSI03: Identificar e aplicar endereçamento IP adequado ao projeto.
  • MSI07: Configurar dispositivos de rede e validar conectividade.
  • MSI18: Documentar planos de endereçamento e resultados de testes.
  • Habilidades: planejamento de prefixos, execução de testes ICMPv6, análise de NDP.

Parte Teórica (explicação do conteúdo)

1) Por que IPv6?

O IPv6 surgiu para resolver a escassez de endereços públicos do IPv4 e simplificar operações de rede. Ele oferece um espaço de endereçamento muito maior (128 bits), autoconfiguração mais robusta e melhorias em protocolos de descoberta e ICMP.

Além da quantidade de endereços, o IPv6 padroniza mecanismos como SLAAC e Neighbor Discovery Protocol (NDP), facilitando a configuração automática de hosts e a descoberta de roteadores.

Onde vou aplicar isso: ao planejar sua LAN com suporte a IPv6 e ao comparar comportamentos de conectividade com IPv4.

2) Formato de endereços IPv6 e notação

Um endereço IPv6 tem 128 bits, representados em oito grupos de 16 bits (hexadecimal), separados por dois-pontos. Exemplo: 2001:0db8:0000:0000:0000:0000:0000:0001/64.

Abreviações permitidas: remover zeros à esquerda em cada grupo e usar “::” uma única vez para substituir sequência de grupos 0. Ex.: 2001:db8::1/64 é equivalente ao exemplo anterior.

Prefixo indica a parte de rede (semelhante à máscara no IPv4). Um /64 é comum em LANs, permitindo IIDs (identificadores de interface) de 64 bits.

Onde vou aplicar isso: ao escrever/ler endereços em configurações estáticas e ao validar se o prefixo foi atribuído corretamente na LAN.

3) Tipos de endereços e escopos

Global Unicast (2000::/3): roteáveis na Internet; utilizados para comunicação externa. ULA (fc00::/7, comumente fd00::/8): endereços locais não roteáveis na Internet, úteis para redes internas. Link-local (fe80::/10): válidos apenas no enlace (não roteados), criados automaticamente, usados para NDP e roteamento local.

O escopo define onde o endereço é válido: link-local (somente no enlace), site (ULA) e global (Internet). Um host pode ter múltiplos endereços simultaneamente.

Onde vou aplicar isso: ao escolher endereços para laboratório (ULA em testes internos), ao verificar conectividade local (link-local) e ao planejar acesso externo (global).

4) SLAAC, ICMPv6 e NDP

O SLAAC (Stateless Address Autoconfiguration) permite que hosts formem endereços automaticamente a partir de anúncios de roteador (Router Advertisements, RAs) enviados via ICMPv6. O NDP inclui mensagens RS/RA, Neighbor Solicitation/Advertisement (NS/NA) e substitui ARP do IPv4.

Com SLAAC, um roteador anuncia o prefixo (ex.: 2001:db8:acad:1::/64) e os hosts criam seus próprios IIDs, além de definirem gateway padrão automaticamente.

Onde vou aplicar isso: ao habilitar IPv6 em um roteador Cisco (RAs) e validar se os PCs receberam endereços e gateway via SLAAC.

5) Comparação IPv4 vs IPv6 (visão prática)

No IPv4, usamos máscaras e ARP; no IPv6, usamos prefixos e NDP. O broadcast é substituído por multicast bem definido. Em testes, ping vira ping6 (ou ping -6) e vizinhança é consultada com ip -6 neigh.

O roteamento e a noção de gateway existem em ambos, mas a descoberta e a autoconfiguração são mais padronizadas no IPv6.

Onde vou aplicar isso: ao executar ping6 e traceroute6 e ao comparar tabelas de vizinhança ARP (IPv4) vs NDP (IPv6).

Passo a Passo — Configurando IPv6 (estático e SLAAC) e validando com ICMPv6/NDP

Objetivo desta etapa:

Configurar IPv6 em hosts e roteador, habilitar SLAAC, e comprovar conectividade e vizinhança por meio de comandos práticos.


Cenário

Topologia simples: PC-A e PC-B conectados a um switch, que se conecta a um roteador (R1). O R1 anunciará o prefixo 2001:db8:acad:1::/64 na VLAN/LAN. Você fará testes com endereços ULA alternativos fd12:3456:789a:1::/64 para laboratório interno.

1) Configuração IPv6 estática em hosts

Escolha ULA para laboratório: prefixo fd12:3456:789a:1::/64. Defina endereços e gateway para PC-A e PC-B. Em Linux, use o ip; em Windows, netsh.

Linux (ex.: interface enp0s3)

# verificar interfaces e IPv6
ip -6 addr show
# adicionar endereço estático
sudo ip -6 addr add fd12:3456:789a:1::10/64 dev enp0s3
# definir gateway padrão (link-local do roteador provisório)
sudo ip -6 route add default via fe80::1 dev enp0s3
# validar
ip -6 addr show dev enp0s3
ip -6 route show
ping -6 fd12:3456:789a:1::11 -c 4

Windows (PowerShell/Prompt como Admin)

# listar interfaces
netsh interface ipv6 show interfaces
# adicionar endereço estático (ajuste o nome da interface)
netsh interface ipv6 add address "Ethernet" fd12:3456:789a:1::10
# adicionar rota default via gateway link-local (ajuste a interface index)
netsh interface ipv6 add route ::/0 "Ethernet" fe80::1
# testar
ping -6 fd12:3456:789a:1::11
tracert -6 fd12:3456:789a:1::11
Dica: endereços link-local começam com fe80::/10 e são necessários para gateway quando a vizinhança ainda não está aprendida.

2) Habilitar IPv6 e SLAAC no roteador (Cisco IOS)

No R1, habilite IPv6 globalmente, configure a interface conectada à LAN com um endereço do prefixo global e/ou ULA e ative a emissão de RAs (normalmente automática ao configurar IPv6 em interface L3).

enable
configure terminal
ipv6 unicast-routing

interface g0/0
 description LAN
 ipv6 address 2001:db8:acad:1::1/64
 ipv6 address fd12:3456:789a:1::1/64
 no shutdown
exit

! Opcional: anunciar apenas um prefixo em laboratório
! interface já envia RA por padrão com ipv6 unicast-routing
end
write memory
Observação: Com ipv6 unicast-routing habilitado e um endereço IPv6 na interface, o roteador envia RAs periodicamente, permitindo SLAAC nos hosts.

3) Receber endereço via SLAAC nos hosts

Deixe a interface dos PCs em modo automático para IPv6. Em Linux, reinicie a interface para forçar RS/RA; no Windows, desative/ative a interface.

# Linux
sudo ip link set enp0s3 down
sudo ip link set enp0s3 up
sleep 2
ip -6 addr show dev enp0s3 | grep "scope global"

# Windows (PowerShell)
Disable-NetAdapter -Name "Ethernet" -Confirm:$false
Enable-NetAdapter -Name "Ethernet"
Get-NetIPConfiguration | Select-Object -ExpandProperty IPv6Address

Espere ver endereços 2001:db8:acad:1::/64 e/ou fd12:3456:789a:1::/64 além de um link-local fe80::. O gateway padrão deve apontar para o roteador anunciado via RA.

4) Testes de conectividade e NDP

Verifique conectividade entre PCs, gateway e, se houver, outras sub-redes. Examine tabela de vizinhança (equivalente ao ARP do IPv4).

# Linux
ping -6 2001:db8:acad:1::1 -c 4
ip -6 neigh show
traceroute -6 2001:db8:acad:1::1

# Windows
ping -6 2001:db8:acad:1::1
netsh interface ipv6 show neighbors
tracert -6 2001:db8:acad:1::1

5) Troubleshooting comum

  • Sem endereço global: confirme que o roteador está com ipv6 unicast-routing e endereço /64 na interface.
  • Sem gateway: verifique se há RA chegando (sniffer/simulador) e se o link-local do roteador é alcançável.
  • Prefixo incorreto: valide o /64; em clientes estáticos, confira notação e interface correta.
# Cisco IOS — verificação
show ipv6 interface g0/0
show ipv6 neighbors
show running-config | section interface g0/0
