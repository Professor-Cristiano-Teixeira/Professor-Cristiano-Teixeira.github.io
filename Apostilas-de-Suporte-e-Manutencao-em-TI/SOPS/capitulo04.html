Capítulo 04 — Instalação do Windows Server 2025 e pós-instalação

Carga: não definida no plano; sugestão: 4–6h (laboratório)

Projeto-base: Laboratório de domínio em VMs (Servidor + Cliente)

Stack fixa: VirtualBox, Windows Server 2025, Ferramentas MMC/RSAT

Resultados de aprendizagem deste capítulo:

  • Realizar a instalação do Windows Server 2025 em VM com boas práticas.
  • Configurar hostname, IP estático, DNS e NTP de forma padronizada e segura.
  • Aplicar atualizações, drivers e ajustes de firewall pós-instalação.
  • Diferenciar Server Core de Desktop Experience e selecionar a edição adequada ao cenário.
  • Utilizar ferramentas locais e remotas (MMC/RSAT) para administração básica do servidor.
  • Documentar cada etapa com capturas de tela e registros técnicos.

Competências e Habilidades

  • Instalar e configurar sistemas operacionais de servidores seguindo padrões.
  • Executar hardening inicial e manutenção pós-instalação.
  • Gerenciar rede básica do servidor (IPv4, DNS, NTP, firewall).
  • Operar consoles administrativas locais e remotas.
  • Registrar evidências técnicas e validar funcionamento.

Plano de Aula (Capítulo 04)

  1. Abertura (10 min): objetivos, requisitos, topologia de laboratório (VirtualBox: 1 VM Servidor, 1 VM Cliente).
  2. Conceitos (25–35 min): edições, Server Core vs Desktop, roles/features, rede, NTP, atualizações, firewall, MMC/RSAT.
  3. Demonstração (20–30 min): instalação guiada e pós-instalação essencial.
  4. Prática guiada (60–90 min): alunos executam o passo a passo completo com registro de evidências.
  5. Validação (15–20 min): testes de conectividade, atualização, logs e tarefas administrativas.
  6. Fechamento (10 min): checklist, atividades propostas e entrega parcial do Projeto Integrador (bimestre 1).

Parte Teórica (explicação do conteúdo)

1) Edições do Windows Server 2025 e papéis (roles/features)

O Windows Server 2025 possui edições com escopos distintos, geralmente Standard e Datacenter. A escolha impacta recursos como virtualização (direitos de VM), Storage Replica, Shielded VMs e funcionalidades avançadas. Além disso, a adição de papéis (roles) e recursos (features) transforma o servidor em serviços específicos, como AD DS, DNS, DHCP, File Services, Print Services, entre outros.

Entender as diferenças evita sobrecusto e subdimensionamento. Para um laboratório didático e pequenas implantações, a edição Standard costuma atender. A seleção de roles e features deve seguir um planejamento de requisitos, segurança e manutenção.

Onde vou aplicar isso: na seleção da mídia/edição e durante a pós-instalação ao decidir quais roles/features serão instalados no projeto.

2) Server Core vs Desktop Experience

O Server Core é uma instalação mínima, sem GUI completa, focada em segurança, menor superfície de ataque, menos atualizações e melhor performance. A edição com Desktop Experience provê interface gráfica completa, facilitando curva de aprendizado e compatibilidade de ferramentas legadas.

Para ambientes de produção, o Core é recomendado quando possível. Em contextos educacionais ou de migração, a Desktop Experience pode acelerar a adoção. Avalie também o uso de administração remota (RSAT) para gerenciar servidores Core.

Onde vou aplicar isso: na tela de seleção de imagem/instalação, definindo entre Core ou Desktop de acordo com o objetivo do laboratório e requisitos do projeto.

3) Pós-instalação: hostname, IP estático, DNS e NTP

Após instalar, padronize o nome do host (hostname) seguindo convenções: localização-função-sequência (ex.: SRV-DC01). Configure endereço IPv4 estático, máscara, gateway e DNS com base no plano de endereçamento. Servidores não devem usar DHCP para IP principal.

Sincronize tempo via NTP para garantir integridade de logs e funcionamento de serviços como Kerberos (AD). Utilize fontes confiáveis ou um concentrador interno.

Onde vou aplicar isso: no passo a passo ao renomear o servidor, definir IP e apontar DNS/NTP, validando com testes de rede e tempo.

4) Atualizações, drivers e firewall

Atualizações reduzem riscos e corrigem bugs. Ajuste Windows Update para checar e instalar patches de segurança. Drivers atualizados garantem estabilidade, especialmente de rede e armazenamento.

O firewall do Windows Server deve permanecer ativo. Crie exceções mínimas necessárias aos serviços. Evite desativar o firewall na totalidade; prefira regras específicas e documentadas.

Onde vou aplicar isso: na execução de Windows Update, instalação de drivers e criação de regras no firewall conforme os serviços futuros (ex.: DNS, DHCP, File Server).

5) Ferramentas de gerenciamento local e remoto (MMC/RSAT)

As Consoles MMC (Microsoft Management Console) permitem administrar roles, serviços e políticas. O RSAT (Remote Server Administration Tools) no Windows 10/11 habilita administração remota de AD, DNS, DHCP e mais, centralizando a gestão.

Conhecer snap-ins (Services.msc, Event Viewer, Server Manager) e o uso do PowerShell é essencial para automação e padronização. Em servidores Core, a administração remota torna-se ainda mais relevante.

Onde vou aplicar isso: ao validar serviços, checar logs, usar Server Manager e configurar RSAT no cliente para administrar o servidor de laboratório.

Passo a Passo — Instalação do Windows Server 2025 e configuração pós-instalação

Objetivo desta etapa:

Instalar o Windows Server 2025 em uma VM, aplicar configurações essenciais (hostname, IP estático, DNS, NTP, updates, firewall) e preparar o ambiente para os próximos capítulos (AD, DNS, DHCP).


Pré-requisitos (laboratório)

  • VirtualBox instalado; ISO do Windows Server 2025 disponível.
  • Topologia mínima: 1 VM Servidor (2 vCPU, 4–6 GB RAM, 60 GB disco), 1 VM Cliente (Windows 10/11).
  • Rede VirtualBox: Host-only para comunicação interna; NAT opcional para acesso à Internet.
  • Plano de endereçamento (exemplo): 192.168.56.0/24. Servidor: 192.168.56.10; Cliente: 192.168.56.20; Gateway (se necessário): 192.168.56.1; DNS inicial: 192.168.56.10 (futuro DC) ou DNS público temporário.

1) Criar VM do Servidor no VirtualBox

  1. Novo > Nome: SRV-BASE01; Tipo: Microsoft Windows; Versão: Windows 2022/2025 (64-bit).
  2. Memória: 4096–6144 MB; CPUs: 2; Habilitar I/O APIC e EFI se necessário.
  3. Disco: VDI dinamicamente alocado com 60 GB.
  4. Rede: Adaptador 1 = Host-only; Adaptador 2 = NAT (opcional para updates).
  5. Anexar ISO do Windows Server 2025 na unidade óptica da VM.

Comandos úteis (host):

# Listar redes Host-only do VirtualBox
VBoxManage list hostonlyifs

# Criar um Host-only (se precisar) e configurar DHCP desativado
VBoxManage hostonlyif create
VBoxManage hostonlyif ipconfig "vboxnet0" --ip 192.168.56.1 --netmask 255.255.255.0

2) Instalação do Windows Server 2025

  1. Inicialize a VM e siga o assistente de instalação.
  2. Selecione edição adequada (Standard) e a variação (Server Core ou Desktop Experience). Para aprendizagem, escolha Desktop Experience.
  3. Instalação limpa (Custom), selecione o disco e prossiga.
  4. Defina a senha do usuário Administrador ao final.

Dica: documente com capturas de tela as telas principais (edição, tipo de instalação, particionamento).

3) Configuração inicial: hostname e IP estático

Faça logon como Administrador e abra o Windows Terminal ou PowerShell.

Renomear computador e reiniciar:

# Executar no PowerShell elevado
Rename-Computer -NewName "SRV-BASE01" -Restart

Definir IP estático (após reinício):

# Identificar nome do adaptador
Get-NetAdapter | Where-Object {$_.Status -eq "Up"} | Format-Table -Auto

# Exemplo: definir IPv4 estático no adaptador "Ethernet"
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.56.10 -PrefixLength 24 -DefaultGateway 192.168.56.1

# DNS primário (temporário se ainda sem AD)
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 1.1.1.1,8.8.8.8

# Verificar
ipconfig /all
Resolve-DnsName microsoft.com

Padronize o hostname seguindo a convenção definida no plano da organização.

4) Sincronização de tempo (NTP)

Configurar tempo é essencial para autenticação e logs coerentes.

# Ver o status do serviço de tempo
w32tm /query /status

# Definir servidores NTP externos confiáveis (exemplo)
w32tm /config /manualpeerlist:"time.windows.com,0x9 pool.ntp.org,0x9" /syncfromflags:manual /update
net stop w32time & net start w32time
w32tm /resync

# Consultar configuração
w32tm /query /configuration

Quando promover o servidor a DC, a hierarquia de tempo muda (PDC Emulator como autoridade). Revisitaremos no capítulo de AD.

5) Atualizações do sistema e drivers

Mantenha a VM conectada a Internet (adaptador NAT). Aplique atualizações de segurança.

# Windows Update via PowerShell (precisa do módulo PSWindowsUpdate em alguns cenários)
# Em GUI: Configurações > Windows Update > Verificar atualizações

# Instalar drivers (se apropriado, como Guest Additions do VirtualBox)
# No VirtualBox: Dispositivos > Inserir imagem de CD dos Additions
# Em seguida, executar o instalador dentro do SO convidado

Após instalar Additions, confira melhoria de vídeo, integração de mouse e rede.

6) Firewall do Windows: manter ativo e criar regras pontuais

O firewall deve permanecer habilitado. Ajuste regras apenas quando necessário.

# Listar perfis e status
Get-NetFirewallProfile | Format-Table Name, Enabled

# Exemplo: permitir ICMP (ping) para diagnóstico
New-NetFirewallRule -DisplayName "ICMPv4 Echo-In" -Protocol ICMPv4 -IcmpType 8 -Direction Inbound -Action Allow

# Exemplo: habilitar regra para serviço específico (DNS quando instalado)
# As roles costumam criar suas próprias regras; evite criar duplicadas sem necessidade

Documente toda exceção com justificativa, porta, protocolo e periodo de vigência.

7) Ferramentas de administração local e remota (MMC/RSAT)

No servidor, abra o Server Manager, Services.msc e Event Viewer para explorar. No cliente Windows 10/11, instale RSAT para administração remota.

# No Windows 10/11 (cliente) - instalar RSAT via Features on Demand
Get-WindowsCapability -Name RSAT* -Online | Select-Object Name, State
Get-WindowsCapability -Name RSAT* -Online | Where-Object State -eq NotPresent | Add-WindowsCapability -Online

# Habilitar WinRM no servidor para administração remota
Enable-PSRemoting -Force

# Testar conexão remota de PowerShell (no cliente)
Test-WsMan -ComputerName 192.168.56.10

Valide snap-ins como “Computer Management” e “Event Viewer” apontando para o servidor.

8) Validação e documentação

  • Ping entre cliente e servidor.
  • ipconfig /all e Resolve-DnsName operando.
  • Hora sincronizada (w32tm /query /status).
  • Firewall ativo e com regras mínimas necessárias.
; Modelo de registro (trecho) em texto
[Identificação]
Hostname=SRV-BASE01
IP=192.168.56.10/24
Gateway=192.168.56.1
DNS=1.1.1.1;8.8.8.8 (temporário)

[Validações]

DNSResolucao=OK
NTP=OK
Updates=OK

Guarde capturas e este registro em seu repositório de evidências.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar a instalação e a configuração inicial do servidor, praticando padronização, segurança e documentação.

  1. Variante Core: Repita a instalação usando Server Core. Configure hostname, IP, DNS e NTP via PowerShell. Compare consumo de RAM e quantidade de updates com a edição Desktop.
  2. Templates de VM: Crie um snapshot “Pós-Instalação Limpa”. Em seguida, generalize a VM (sysprep /generalize) e crie um template para futuros servidores de laboratório.
  3. Administração Remota Completa: No cliente, instale RSAT e conecte-se ao servidor para gerenciar Services, Event Viewer e Firewall. Salve evidências e um checklist das ações realizadas.

Projeto Integrador — Entrega 1 (fim do 1º bimestre)

Entregue uma VM Windows Server 2025 instalada e configurada (hostname padrão, IP estático, NTP, atualizações aplicadas, firewall ativo) e um relatório técnico com evidências. Este artefato será base para os próximos serviços (AD DS, DNS, DHCP).

  • VM funcional com rede Host-only e NAT (opcional para updates).
  • Registro técnico contendo: parâmetros de rede, comandos usados e prints.
  • Snapshot “Pós-Instalação Validada”.

Critérios de Avaliação

  • Padronização e conformidade (nomenclatura, IP, DNS, NTP) — 30%.
  • Segurança e boas práticas (firewall ativo, mínimos privilégios) — 30%.
  • Qualidade técnica das evidências e documentação — 25%.
  • Funcionamento validado (testes de rede, tempo e updates) — 15%.

Pesquisas complementares (sugestões)

  • Comparativo detalhado entre Server Core e Desktop Experience no Windows Server 2025.
  • Boas práticas de endereçamento IPv4 para serviços de diretório e DNS internos.
  • Hierarquia de tempo no AD (PDC Emulator) e impactos do NTP.
  • Estratégias de hardening inicial em servidores Windows recém-instalados.
  • Uso do RSAT em Windows 11: módulos e limitações comuns.

Entregáveis ao final do Capítulo 04
