Capítulo 12 — Backup, restauração e continuidade de negócios

Carga: não definido

Projeto-base: Laboratório de domínio e serviços (AD DS, DNS, Arquivos) em VMs

Stack fixa: Windows Server 2025, PowerShell, wbadmin, VirtualBox, VSS

Resultados de aprendizagem deste capítulo:

  • Planejar políticas de backup alinhadas a objetivos de negócio (RPO/RTO).
  • Configurar Windows Server Backup para rotinas Full, Incremental e System State.
  • Executar testes de restauração (arquivos, pasta, System State) com segurança em VM separada.
  • Documentar procedimentos de DR/BCP e validar retenção e cópias offsite.

Competências e Habilidades

  • Selecionar estratégia de backup conforme requisitos de disponibilidade e risco.
  • Automatizar e monitorar jobs de backup e seus relatórios.
  • Realizar restores seguros e verificáveis em ambiente controlado.
  • Aplicar boas práticas de retenção, rotação de mídias e cópias offsite.

Plano de Aula (Capítulo 12)

- Aquecimento (10 min): revisar riscos comuns (falha de disco, erro humano, malware) e impacto em serviços do domínio.
- Teoria (40–60 min): modelos de backup (full, incremental, diferencial), RPO/RTO, VSS, Windows Server Backup, retenção e offsite, DR/BCP.
- Demonstração (20 min): configurar Windows Server Backup, criar job e executar primeiro backup.
- Laboratório guiado (60–90 min): configurar backup do System State, realizar backup de dados, simular restauração de arquivos e de System State em VM separada.
- Registro de evidências (contínuo): capturas de tela, logs, scripts e anotações de problemas/soluções.
- Encerramento (10 min): checklist de lições aprendidas e próximos passos (integração com monitoramento).
- Avaliação: relatório técnico com plano de backup/DR e evidências de restore.

Parte Teórica (explicação do conteúdo)

1) Objetivos de Backup: RPO e RTO

RPO (Recovery Point Objective) define quanto de dado você pode perder entre o último backup válido e um incidente. RTO (Recovery Time Objective) define o tempo máximo aceitável para restaurar o serviço após uma falha. Essas metas orientam a frequência dos backups, a tecnologia escolhida e os procedimentos de restauração.

Onde aplicar: na definição da agenda de backups e na escolha de modelos e retenção no passo a passo.

2) Modelos de backup: Full, Incremental e Diferencial

Backup Full copia todos os dados selecionados. É simples para restaurar, porém consome mais tempo e espaço. Backup Incremental copia apenas o que mudou desde o último backup (de qualquer tipo), acelerando execuções diárias e economizando armazenamento, mas exigindo cadeia de incrementais na restauração. Backup Diferencial copia o que mudou desde o último Full; restaura com o Full + último Diferencial.

Onde aplicar: na configuração de agendas no Windows Server Backup e planejamento de retenção.

3) VSS (Volume Shadow Copy Service)

O VSS permite criar snapshots consistentes de volumes em uso, garantindo que arquivos bloqueados ou serviços críticos (como AD DS) sejam copiados de forma íntegra. Writers VSS de aplicações (como o do System State/AD) coordenam a consistência.

Onde aplicar: ao executar backups em produção e realizar restores consistentes do System State.

4) Windows Server Backup (WSB)

Ferramenta nativa do Windows Server que realiza backups em disco, volume, pasta/arquivo e System State. Permite agendamento, retenção automática em discos dedicados e restauração granular. Também possui interface PowerShell via cmdlets/wbadmin.

Onde aplicar: configuração do recurso, criação de job agendado e execução do primeiro backup.

5) System State e AD DS

O System State inclui componentes críticos como Registry, Boot files, COM+, e, em Controladores de Domínio, a base do Active Directory. Restaurar o System State de DCs exige procedimentos específicos (Directory Services Restore Mode – DSRM), evitando corrupção de replicação.

Onde aplicar: no laboratório de restauração de System State em VM separada, simulando um DC.

6) Retenção, rotação e cópia offsite

Defina políticas que atendam compliance e riscos: quanto tempo manter (retenção), quantos pontos de restauração, esquema de rotação (por exemplo, GFS — diário/semanal/mensal) e armazenamento fora do site (offsite) para desastres físicos. Em ambientes simples, discos externos rotativos com criptografia já elevam a resiliência.

Onde aplicar: ao definir destinos de backup e política de troca de mídias/unidades no passo a passo.

7) DR/BCP: Recuperação de Desastres e Continuidade

DR foca na restauração de serviços de TI após incidentes severos; BCP cobre continuidade do negócio como um todo. Tenha runbooks com contatos, prioridades de sistemas, inventário e passos de recuperação. Testes periódicos de restore validam seu plano na prática.

Onde aplicar: na criação do runbook, no teste de restore e na documentação final do capítulo.

Passo a Passo — Backup do System State e Dados com Teste de Restore

Objetivo desta etapa:

Configurar o Windows Server Backup para proteger dados e o System State de um servidor (preferencialmente DC em laboratório), executar um primeiro backup, e validar o processo restaurando arquivos e o System State em VM separada, documentando resultados.


Preparação do laboratório

  1. Abra sua topologia no VirtualBox com ao menos: 1 VM Servidor (Windows Server 2025) e 1 VM clone para testes de restore (desligada). Mantenha snapshots para rollback.
  2. Provisione um disco adicional virtual (VHD/VMDK) para a VM Servidor dedicado ao backup, ou conecte um disco externo virtual. Evite usar o disco do SO como destino.
  3. Confirme espaço livre suficiente: para o primeiro Full, considere no mínimo 1,5–2x do tamanho dos dados protegidos, principalmente para System State + dados.

Instalar o recurso Windows Server Backup

Use o Server Manager (Add Roles and Features) ou PowerShell:

# Executar em PowerShell elevado
Install-WindowsFeature -Name Windows-Server-Backup -IncludeManagementTools

# Verificar instalação
Get-WindowsFeature Windows-Server-Backup

Onde vou aplicar: habilita a interface e os cmdlets necessários para agendar e executar backups.

Primeiro backup manual — System State

Execute um backup de System State para validar o VSS e conferir o tempo de execução.

# Ajuste a letra da unidade de backup (ex.: E:)
$destino = "E:"
wbadmin start systemstatebackup -backuptarget:$destino -quiet

# Verificar histórico
wbadmin get versions
Nunca execute restauração de System State em produção sem janela e plano formal. Use VMs de laboratório.

Onde vou aplicar: cria ponto de recuperação crítico para AD/registro/serviços.

Backup de dados — compartilhamentos/pastas

Inclua pastas de dados (por exemplo, D:\Departamentos). Você pode optar por Full/Incremental com wbadmin:

# Backup de volume ou pastas específicas (ex.: D:\Dados)
$destino = "E:"
wbadmin start backup -backuptarget:$destino -include:D: -quiet

# Para pastas específicas
wbadmin start backup -backuptarget:$destino -include:"D:\Dados;D:\Perfis" -quiet

Alternativa via GUI: Windows Server Backup > Backup Once > Custom > Add Items > selecione volumes/pastas e destino.

Onde vou aplicar: protege arquivos do servidor, preparando o teste de restauração granular.

Agendar backups recorrentes

Crie política alinhada a RPO/RTO. Exemplo: Full semanal + Incremental diário.

# Exemplo com agendamento usando a GUI:
# Windows Server Backup > Backup Schedule >
# - Selecionar Itens: System State + Volumes/Pastas
# - Horário: Diário 22:00
# - Destino: Disco dedicado (recomendado) e permitir WSB gerenciar a retenção.

# Com Task Scheduler e wbadmin (modelo):
$acao = New-ScheduledTaskAction -Execute "wbadmin.exe" -Argument 'start backup -backuptarget:E: -include:D: -quiet'
$trigger = New-ScheduledTaskTrigger -Daily -At 22:00
Register-ScheduledTask -Action $acao -Trigger $trigger -TaskName "Backup_Dados_Diario" -Description "Backup diário de dados" -User "SYSTEM" -RunLevel Highest

Onde vou aplicar: garante execução automática e previsível do backup.

Teste de restauração — arquivo/pasta

  1. Crie um arquivo de teste em D:\Dados\LAB\excluir_me.txt e faça backup.
  2. Exclua o arquivo e faça a restauração granular do item.
# Listar versões de backup
wbadmin get versions

# Restaurar arquivo/pasta (ajuste versão e caminho)
# Observação: o parâmetro -version aceita o carimbo listado em get versions.
wbadmin start recovery -version:2024-05-28-220000 -itemType:File -items:"D:\Dados\LAB\excluir_me.txt" -recoveryTarget:"D:\Dados\LAB" -quiet

Onde vou aplicar: valida recuperação rápida para incidentes simples (erro humano, ransomware após isolamento, etc.).

Teste de restauração — System State em VM separada

  1. Clone a VM do DC de laboratório ou use a VM separada. Isole a rede (Host-only sem outros DCs) para evitar replicação indevida.
  2. Anexe o disco de backup à VM de teste (somente leitura se possível).
  3. Inicialize a VM de teste em Modo de Restauração dos Serviços de Diretório (DSRM) quando necessário.
  4. Restaure o System State na VM de teste:
# Em PowerShell elevado na VM de teste
wbadmin get versions

# Restaurar System State
wbadmin start systemstaterecovery -version:2024-05-28-220000 -quiet

# Após a restauração, reinicie conforme instruções, mantenha a VM isolada para validações.
Verifique serviços do AD (dcdiag), DNS, e logins. Não reintroduza este DC na rede de produção de laboratório para evitar conflitos de USN/replicação.

Onde vou aplicar: valida o plano de DR para AD/serviços críticos.

Retenção, rotação e cópias offsite

  • Implemente rotação de mídias (por exemplo, GFS: diárias, semanais, mensais).
  • Criptografe mídias e armazene uma cópia offsite (cofre, nuvem, outro prédio).
  • Documente calendário de trocas e responsável.
# Exemplo (Linux host) para copiar disco de backup montado para um repositório offsite via rclone:
rclone sync /mnt/backup empresa-offsite:backups/SRV-DC01 --checksum --bwlimit 4M --log-file=rclone.log

Onde vou aplicar: aumenta resiliência contra desastres físicos e ataques generalizados.

Documentação e evidências

  • Registre versão do SO, escopo de backup, destinos, janelas e retenção.
  • Anexe capturas do WSB, saídas do wbadmin, horários e duração.
  • Inclua resultados de testes de restore (arquivos e System State) com validações.
  • Atualize o runbook de DR/BCP com contatos e priorização de serviços.
# Exportar eventos do Windows Server Backup
wevtutil epl Microsoft-Windows-Backup/Operational C:\Temp\WSB.evtx

# Gerar relatório simples de versões disponíveis
wbadmin get versions > C:\Temp\backup_versions.txt

Onde vou aplicar: facilita auditorias, repetições do processo e melhoria contínua.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar o domínio de políticas de backup, execução e restauração validada, além de documentação técnica.

  1. Projetar uma política GFS mínima para o seu laboratório (diário/semanal/mensal), indicando RPO/RTO estimados e capacidade de armazenamento requerida.
  2. Criar dois agendamentos: um para System State e outro para dados, em horários distintos. Entregar capturas da configuração e logs de execução.
  3. Executar um “restore drill”: restaurar uma pasta excluída acidentalmente e registrar o tempo total de recuperação e lições aprendidas.

Critérios de Avaliação

  • Correta aplicação de conceitos (modelos de backup, VSS, System State).
  • Execução técnica: agendamentos funcionais, logs e evidências claras.
  • Restauração bem-sucedida e validação consistente.
  • Documentação objetiva: RPO/RTO, runbook de DR/BCP e conclusões.

Pesquisas complementares (sugestões)

  • Boas práticas de rotação de mídias e o esquema GFS em ambientes SMB.
  • Uso avançado do wbadmin e integração com scripts PowerShell para relatórios.
  • Consistência de aplicações com VSS Writers (AD, SQL Server, Exchange — visão conceitual).
  • Estratégias de offsite e 3-2-1 backup (3 cópias, 2 mídias, 1 offsite).

Entregáveis ao final do Capítulo 12

  • Plano de backup com RPO/RTO, retenção e esquema de rotação.
  • Capturas e logs do Windows Server Backup (instalação, jobs e primeira execução).
  • Evidências de restauração de arquivos/pastas e validações.
  • Relatório de teste de restauração de System State em VM isolada.
  • Runbook atualizado de DR/BCP com lições aprendidas.
  • Projeto Integrador (2º bimestre) — Entrega incremental: Integrar DHCP/Arquivos/Backup/Automação, incluindo scripts de verificação de backup e relatório diário.
