Capítulo 14 — Automação com PowerShell para administração

Carga: —

Projeto-base: Laboratório em VMs com Windows Server 2025 e cliente Windows, domínio de teste

Stack fixa: Windows Server 2025, Active Directory, PowerShell 5.1/7.x, RSAT, VirtualBox

Resultados de aprendizagem deste capítulo:

  • Configurar execução segura e trabalhar com módulos e remoting no PowerShell.
  • Automatizar tarefas de AD, arquivos, serviços e backup com cmdlets.
  • Escrever scripts com boas práticas, tratamento de erros e logging.
  • Produzir um script que cria usuários em massa a partir de arquivo CSV e aplica grupos/permissões.

Competências e Habilidades

  • Automatizar rotinas administrativas com PowerShell.
  • Aplicar segurança, execução remota e gerenciamento de módulos.
  • Manipular objetos do AD, sistema de arquivos, serviços e tarefas agendadas.
  • Registrar logs, documentar e versionar scripts de forma organizada.

Plano de Aula (Capítulo 14)

Objetivo geral do capítulo: Automatizar tarefas recorrentes de administração de servidores com PowerShell, com foco em execução segura, remoting, manipulação de objetos do Active Directory, arquivos, serviços e rotinas de backup, aplicando boas práticas de script e logging.

Pré-requisitos recomendados: Conceitos de Windows Server, AD DS, permissões, redes TCP/IP, logs, segurança e noções de PowerShell (variáveis, loops, funções).

Estrutura sugerida (laboratório em VMs):

  1. Contextualização e revisão rápida de cmdlets, pipeline e objetos.
  2. Execução segura: políticas, assinatura e módulos.
  3. PowerShell Remoting: habilitação, sessões, Invoke-Command.
  4. Cmdlets de AD, arquivos e serviços (demonstrações e mini-desafios).
  5. Boas práticas de script: parâmetros, Try/Catch/Finally, log, idempotência.
  6. Atividade principal: script CSV → criação de usuários, grupos e pastas com permissões.
  7. Validação, evidências e registro (diário de bordo, prints, logs).

Avaliação formativa: entrega do script funcional, evidências de execução (prints/logs) e breve relatório explicando decisões e boas práticas adotadas.

Parte Teórica (explicação do conteúdo)

1) Execução segura, módulos e remoting

O PowerShell é orientado a objetos e oferece recursos avançados de automação. Para utilizá-lo com segurança, é necessário entender a política de execução (ExecutionPolicy), assinatura de scripts e o gerenciamento de módulos. A ExecutionPolicy define como scripts podem ser executados localmente, equilibrando praticidade e proteção contra execução indevida.

Módulos são pacotes de cmdlets, funções e recursos. Instalar e importar módulos corretos (por exemplo, ActiveDirectory) amplia a capacidade do shell. O PowerShellGet permite buscar e instalar módulos do repositório PSGallery de forma controlada, respeitando políticas de segurança e proxies corporativos, quando aplicável.

O PowerShell Remoting (WS-Man/WinRM) possibilita execução remota de comandos e scripts em múltiplos servidores simultaneamente. É base para padronização e manutenção em larga escala. O remoting deve ser habilitado e configurado com atenção a firewall, autenticação e escopo de segurança.

Onde vou aplicar isso: antes de rodar scripts de automação em produção, você definirá a política de execução adequada, instalará módulos necessários e usará remoting para alcançar vários servidores.

2) Cmdlets para AD, arquivos, serviços e backups

Cmdlets de Active Directory (módulo ActiveDirectory) fornecem operações de CRUD para usuários, grupos e OUs: New-ADUser, Set-ADUser, Add-ADGroupMember, New-ADOrganizationalUnit, entre outros. Eles aceitam objetos e pipelines, facilitando automação em massa.

Para arquivos e pastas, Get-Item, New-Item, Copy-Item e Remove-Item, combinados com gerenciamento de ACLs (Get-Acl e Set-Acl), garantem distribuição e segurança de dados. Em serviços, Get-Service, Start-Service e Set-Service auxiliam a padronizar estados desejados.

Para backups, Windows Server expõe ferramentas gráficas e de linha de comando. Com PowerShell, é possível agendar jobs, validar logs e integrar verificações periódicas, aumentando previsibilidade e conformidade com políticas de continuidade de negócios.

Onde vou aplicar isso: no script do capítulo, você criará usuários a partir de CSV, atribuirá grupos e provisionará pastas pessoais com permissões NTFS e logs de auditoria.

3) Boas práticas de scripts e logging

Boas práticas tornam scripts confiáveis, reutilizáveis e seguros: cabeçalho com metadados, parâmetros tipados e validados, funções modulares, tratamento de erros com Try/Catch/Finally, e logs detalhados com níveis (Info, Warning, Error). Idempotência e checagens de pré-condições evitam efeitos colaterais em execuções repetidas.

Outros pontos: usar -WhatIf e -Confirm quando disponíveis; registrar transcrições (Start-Transcript); não codificar senhas em texto plano; preferir SecureString/credenciais seguras e variáveis de ambiente; documentar dependências e pré-requisitos.

Onde vou aplicar isso: você implementará parâmetros, validações e logs no script CSV → AD, com suporte a -WhatIf e relatório final de execução.

Passo a Passo — Automação: criação em massa de usuários via CSV com grupos e pastas

Objetivo desta etapa:

Escrever e executar um script PowerShell que leia um arquivo CSV, crie usuários no AD, adicione aos grupos corretos, crie pastas pessoais com permissões NTFS e registre logs. Toda a sequência considera execução segura, módulos e prática de remoting.


Pré-configurações e ambiente

  1. Utilize duas VMs: uma com Windows Server 2025 (Controlador de Domínio) e uma estação cliente ingressada no domínio. Certifique-se que o AD DS está funcional (capítulos anteriores).
  2. Abra o Windows PowerShell (como administrador) no DC ou em uma estação com RSAT e conectividade ao DC.

1) Execução segura e módulos

Defina uma política de execução apropriada para o laboratório e garanta a disponibilidade do módulo ActiveDirectory.

# Ver políticas atuais (escopos)
Get-ExecutionPolicy -List

# Para laboratório (apenas se necessário e ciente dos riscos), defina:
# Revertível após o término. Prefira o escopo CurrentUser.
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force

# Verifique se o módulo ActiveDirectory está disponível
Get-Module -ListAvailable ActiveDirectory

# Se estiver em uma estação com RSAT, importe o módulo
Import-Module ActiveDirectory

# Opcional: configurar repositório e instalar módulos adicionais (auditoria/relatórios)
# Register-PSRepository -Name PSGallery -SourceLocation "https://www.powershellgallery.com/api/v2" -InstallationPolicy Trusted
# Install-Module -Name ImportExcel -Scope CurrentUser -Force
Nota: Em ambientes corporativos, alinhe a política de execução e a instalação de módulos com a equipe de segurança e conformidade.

2) Estrutura do CSV

Crie um arquivo CSV com os campos necessários. Exemplo (salve como C:\Lab\usuarios.csv):

# Conteúdo do CSV (exemplo)
# SamAccountName,GivenName,Surname,DisplayName,UPN,OU,Groups,HomeDrive,HomeDirectory
# j.silva,Joao,Silva,Joao Silva,j.silva@lab.local,OU=Alunos,DC=lab,DC=local,"GRP_Alunos;GRP_Lab",H:,\\FS01\Homes\j.silva
# m.souza,Maria,Souza,Maria Souza,m.souza@lab.local,OU=Alunos,DC=lab,DC=local,"GRP_Alunos",H:,\\FS01\Homes\m.souza

Adapte os valores de domínio, OUs, grupos e paths conforme seu ambiente.

3) Script principal com boas práticas e logging

Crie o script C:\Lab\New-UsersFromCsv.ps1 com o conteúdo abaixo. Ele inclui parâmetros, validação, criação de usuários, grupos, pastas e permissões, além de log e suporte a -WhatIf.

<#
.SYNOPSIS
  Cria usuários em massa a partir de CSV, adiciona a grupos e configura pasta pessoal.
.DESCRIPTION
  Lê um CSV e provisiona contas no AD, aplica grupos, mapeia HomeDrive/HomeDirectory e define ACLs.
.PARAMETER CsvPath
  Caminho do arquivo CSV.
.PARAMETER DefaultPassword
  Senha padrão segura para as contas.
.PARAMETER LogPath
  Caminho do arquivo de log (texto).
.EXAMPLE
  .\New-UsersFromCsv.ps1 -CsvPath C:\Lab\usuarios.csv -DefaultPassword (Read-Host -AsSecureString) -LogPath C:\Lab\exec.log -WhatIf
#>

[CmdletBinding(SupportsShouldProcess)]
param(
  [Parameter(Mandatory)]
  [ValidateScript({ Test-Path $_ -PathType Leaf })]
  [string]$CsvPath,

  [Parameter(Mandatory)]
  [System.Security.SecureString]$DefaultPassword,

  [Parameter()]
  [ValidateScript({
    $dir = Split-Path $_ -Parent
    if(-not (Test-Path $dir)){ New-Item -ItemType Directory -Path $dir -Force | Out-Null }
    $true
  })]
  [string]$LogPath = "C:\Lab\exec.log"
)

function Write-Log {
  param([string]$Message, [ValidateSet('INFO','WARN','ERROR')] [string]$Level = 'INFO')
  $ts = (Get-Date).ToString('yyyy-MM-dd HH:mm:ss')
  $line = "[$ts] [$Level] $Message"
  Add-Content -Path $LogPath -Value $line
  if($Level -eq 'ERROR'){ Write-Error $Message } else { Write-Host $line }
}

Start-Transcript -Path ($LogPath -replace '\.log$','.transcript.txt') -Append | Out-Null

try {
  Import-Module ActiveDirectory -ErrorAction Stop
  Write-Log "Módulo ActiveDirectory importado." "INFO"

  $entries = Import-Csv -Path $CsvPath
  Write-Log "Registros carregados: $($entries.Count)" "INFO"

  foreach($row in $entries){
    $sam  = $row.SamAccountName
    $gn   = $row.GivenName
    $sn   = $row.Surname
    $disp = $row.DisplayName
    $upn  = $row.UPN
    $ouDn = "$($row.OU),$($row.DC)"

    $homeDrive = $row.HomeDrive
    $homeDir   = $row.HomeDirectory
    $groups    = @()
    if($row.Groups){ $groups = $row.Groups -split ';' | ForEach-Object { $_.Trim() } }

    if([string]::IsNullOrWhiteSpace($sam)){ Write-Log "Registro sem SamAccountName. Ignorado." "WARN"; continue }

    $exists = Get-ADUser -Filter "SamAccountName -eq '$sam'" -ErrorAction SilentlyContinue
    if($exists){
      Write-Log "Usuário '$sam' já existe. Atualizando propriedades básicas..." "WARN"
      if($PSCmdlet.ShouldProcess("ADUser:$sam","Set-ADUser")) {
        Set-ADUser -Identity $sam -GivenName $gn -Surname $sn -DisplayName $disp -UserPrincipalName $upn -ErrorAction Continue
      }
    } else {
      Write-Log "Criando usuário '$sam' em $ouDn" "INFO"
      if($PSCmdlet.ShouldProcess("OU:$ouDn","New-ADUser $sam")){
        New-ADUser -Name $disp -SamAccountName $sam -GivenName $gn -Surname $sn `
          -DisplayName $disp -UserPrincipalName $upn -Path $ouDn `
          -Enabled $true -ChangePasswordAtLogon $true -AccountPassword $DefaultPassword -ErrorAction Stop
      }
    }

    # Grupos
    foreach($g in $groups){
      if([string]::IsNullOrWhiteSpace($g)) { continue }
      $grp = Get-ADGroup -Identity $g -ErrorAction SilentlyContinue
      if($null -eq $grp){ Write-Log "Grupo '$g' não encontrado. Pulei associação para $sam." "WARN"; continue }
      Write-Log "Adicionando '$sam' ao grupo '$g'." "INFO"
      if($PSCmdlet.ShouldProcess("Group:$g","Add-ADGroupMember $sam")){
        Add-ADGroupMember -Identity $g -Members $sam -ErrorAction SilentlyContinue
      }
    }

    # Pasta pessoal e ACL
    if($homeDir){
      $server, $share, $userFolder = $null, $null, $null
      # Ex: \\FS01\Homes\j.silva
      if($homeDir -match '^\\\\[^\\]+\\[^\\]+\\.+'){
        # tentativa de criar via UNC a partir do servidor de arquivos
        Write-Log "Provisionando pasta: $homeDir" "INFO"
        if($PSCmdlet.ShouldProcess($homeDir,"Criar pasta e ACL")){
          New-Item -ItemType Directory -Path $homeDir -Force | Out-Null
          $acl = Get-Acl $homeDir
          $id  = New-Object System.Security.Principal.NTAccount("$env:USERDOMAIN\$sam")
          $rule = New-Object System.Security.AccessControl.FileSystemAccessRule($id,"Modify", "ContainerInherit,ObjectInherit", "None", "Allow")
          $acl.SetAccessRuleProtection($true,$false) # Protege contra herança
          $acl.SetAccessRule($rule)
          Set-Acl -Path $homeDir -AclObject $acl
        }
      } else {
        Write-Log "HomeDirectory inválido: $homeDir" "WARN"
      }

      Write-Log "Definindo HomeDrive/HomeDirectory para $sam ($homeDrive $homeDir)" "INFO"
      if($PSCmdlet.ShouldProcess("ADUser:$sam","Set-ADUser HomeDir")){
        Set-ADUser -Identity $sam -HomeDrive $homeDrive -HomeDirectory $homeDir -ErrorAction Continue
      }
    } else {
      Write-Log "Sem HomeDirectory para '$sam'. Pulando provisionamento de pasta." "WARN"
    }
  }

  Write-Log "Processo concluído." "INFO"
}
catch {
  Write-Log "Falha: $($_.Exception.Message)" "ERROR"
}
finally {
  Stop-Transcript | Out-Null
}
Dica: Execute primeiro com -WhatIf para simular mudanças sem aplicá-las. Remova -WhatIf após validar.

4) Execução do script e validações

Execute o script indicando o CSV e uma senha segura. Exemplo:

$sec = Read-Host "Digite a senha padrão" -AsSecureString
.\New-UsersFromCsv.ps1 -CsvPath C:\Lab\usuarios.csv -DefaultPassword $sec -LogPath C:\Lab\exec.log -WhatIf

# Se tudo estiver OK, execute de fato removendo -WhatIf:
.\New-UsersFromCsv.ps1 -CsvPath C:\Lab\usuarios.csv -DefaultPassword $sec -LogPath C:\Lab\exec.log

Valide resultados:

# Conferir usuário
Get-ADUser -Identity j.silva -Properties * | Select-Object SamAccountName,Enabled,HomeDrive,HomeDirectory

# Conferir grupos
Get-ADUser -Identity j.silva -Properties MemberOf | Select-Object -ExpandProperty MemberOf

# Conferir pasta e ACL
Get-Acl \\FS01\Homes\j.silva | Format-List

5) PowerShell Remoting (opcional)

Para aplicar em múltiplos servidores:

# Habilitar remoting (no servidor de destino)
Enable-PSRemoting -Force

# Executar comando remoto
Invoke-Command -ComputerName FS01 -ScriptBlock {
  New-Item -ItemType Directory -Path "D:\Shares\Homes" -Force
}

# Sessão persistente
$s = New-PSSession -ComputerName FS01
Invoke-Command -Session $s -ScriptBlock { Get-Service | Where-Object Status -eq 'Running' }
Remove-PSSession $s
Em redes com firewall restritivo, ajuste regras para WinRM/WS-Man e use credenciais com privilégios mínimos necessários.

6) Tratamento de erros, transcrição e auditoria

O script já inicia uma transcrição e registra logs. Garanta armazenamento seguro dos logs e inclua evidências no relatório.

# Exemplo de uso de Try/Catch isolado
try {
  New-ADUser -Name "Teste Erro" -SamAccountName "teste.erro" -ErrorAction Stop
} catch {
  Write-Warning "Falha ao criar usuário: $($_.Exception.Message)"
} finally {
  Write-Host "Limpeza ou ações finais aqui."
}
