Capítulo 08 — Agrupamentos e Agregações

Carga: 4h (laboratório com prática guiada)

Projeto-base: Caso de vendas (clientes, produtos, pedidos, itens)

Stack fixa: MySQL + MySQL Workbench; Python (opcional para testar consultas)

Resultados de aprendizagem deste capítulo:

  • Aplicar funções de agregação (COUNT, SUM, AVG, MIN, MAX) em consultas SQL.
  • Utilizar GROUP BY e HAVING para produzir relatórios consolidados.
  • Gerar métricas por período (ex.: faturamento mensal) e rankings (ex.: top 5 clientes).
  • Interpretar corretamente NULL, duplicidades e filtros em consultas agregadas.
  • Preparar consultas que serão usadas em integrações e relatórios do projeto.

Competências e Habilidades

  • Organizar e analisar dados para tomada de decisão.
  • Elaborar consultas SQL eficientes usando agrupamentos.
  • Validar resultados e tratar casos especiais (valores ausentes e outliers).
  • Documentar consultas e comunicar resultados por indicadores.

Parte Teórica (explicação do conteúdo)

Funções de agregação

Funções de agregação calculam valores a partir de conjuntos de linhas. As mais comuns são: COUNT (contagem), SUM (soma), AVG (média), MIN (mínimo) e MAX (máximo). Elas são utilizadas em SELECT para produzir métricas.

Exemplo: contar clientes, somar valores de pedidos ou medir o ticket médio. Em geral, são combinadas com GROUP BY para gerar resultados por categoria, período ou qualquer atributo de interesse.

Onde vou aplicar isso: no passo a passo, você usará SUM e COUNT para encontrar faturamento mensal e a quantidade de pedidos por cliente.

GROUP BY: agrupando linhas

O GROUP BY permite consolidar linhas que compartilham um ou mais valores iguais em determinadas colunas. Para cada grupo, as funções de agregação calculam métricas. Sem GROUP BY, uma agregação considera todas as linhas como um único conjunto.

Regra importante: quando há GROUP BY, todas as colunas no SELECT devem ser agregadas ou aparecer no GROUP BY. Caso contrário, o SGBD não saberá como reduzir as linhas.

Onde vou aplicar isso: criaremos relatórios por mês (agrupar por ano/mês) e por cliente (agrupar pelo id/nome do cliente).

HAVING: filtrando grupos

HAVING filtra o resultado após a formação dos grupos, diferentemente de WHERE, que filtra linhas antes do agrupamento. Use WHERE para restrições de linhas (ex.: datas do ano corrente) e HAVING para restrições sobre agregados (ex.: clientes com SUM(valor) > 1000).

Onde vou aplicar isso: para listar apenas clientes cujo total de compras supere um limite, combinado com ORDER BY para gerar um ranking.

Tratamento de NULL e duplicidades

Valores NULL são ignorados por SUM, AVG, MIN e MAX, mas COUNT(*) conta linhas, enquanto COUNT(coluna) não conta NULLs. Duplicidades nas colunas de agrupamento podem surgir por problemas de modelagem ou joins incorretos. Valide sempre a chave do grupo e a granularidade dos dados.

Onde vou aplicar isso: ao calcular médias e contagens, decidiremos entre COUNT(*) e COUNT(coluna), e validaremos a consistência dos resultados.

Agrupando por expressões e múltiplas colunas

Você pode agrupar por expressões derivadas, como YEAR(data) e MONTH(data), e também por várias colunas ao mesmo tempo (ex.: cliente e mês). Cuidado com funções que dependem de timezone ou formatação: mantenha a lógica clara e documentada.

Onde vou aplicar isso: construindo relatórios “ano-mês” e rankings por cliente no período selecionado.

Passo a Passo — Relatórios com GROUP BY e Agregações

Objetivo desta etapa:

Criar consultas SQL para: (1) faturamento por mês; (2) top 5 clientes por total de pedidos; (3) métricas complementares com HAVING e ordenação.


1) Preparar o ambiente (se necessário)

Caso ainda não tenha o banco “vendas” criado nos capítulos anteriores, execute rapidamente o script mínimo abaixo para montar um cenário de testes. Se já possui as tabelas, pule para a etapa 2.

-- Banco e tabelas mínimas para os exercícios
CREATE DATABASE IF NOT EXISTS vendas CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE vendas;

-- Clientes
CREATE TABLE IF NOT EXISTS clientes (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL
);

-- Produtos
CREATE TABLE IF NOT EXISTS produtos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  preco DECIMAL(10,2) NOT NULL
);

-- Pedidos
CREATE TABLE IF NOT EXISTS pedidos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  cliente_id INT NOT NULL,
  data_pedido DATE NOT NULL,
  CONSTRAINT fk_pedidos_clientes FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

-- Itens do pedido
CREATE TABLE IF NOT EXISTS itens_pedido (
  id INT AUTO_INCREMENT PRIMARY KEY,
  pedido_id INT NOT NULL,
  produto_id INT NOT NULL,
  quantidade INT NOT NULL,
  preco_unitario DECIMAL(10,2) NOT NULL,
  CONSTRAINT fk_itens_pedidos FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  CONSTRAINT fk_itens_produtos FOREIGN KEY (produto_id) REFERENCES produtos(id)
);

2) Faturamento por mês (SUM e GROUP BY com expressões)

O faturamento de um pedido geralmente é a soma de quantidade × preço_unitário dos itens. Vamos consolidar mês a mês usando YEAR(data_pedido) e MONTH(data_pedido).

USE vendas;

-- Faturamento por ano-mês
SELECT
  YEAR(p.data_pedido) AS ano,
  MONTH(p.data_pedido) AS mes,
  SUM(ip.quantidade * ip.preco_unitario) AS faturamento
FROM pedidos p
JOIN itens_pedido ip ON ip.pedido_id = p.id
GROUP BY YEAR(p.data_pedido), MONTH(p.data_pedido)
ORDER BY ano, mes;

Valide se a soma faz sentido comparando com alguns pedidos específicos. Dica: experimente filtrar por um mês com WHERE para conferir manualmente.

Onde vou aplicar isso: geração de relatórios periódicos (mensal, trimestral, anual) para o negócio.

3) Top 5 clientes por total de pedidos

Queremos um ranking de clientes por valor total comprado. Agrupamos por cliente e somamos o valor dos itens. Depois ordenamos do maior para o menor e limitamos a 5.

-- Top 5 clientes por faturamento total
SELECT
  c.id AS cliente_id,
  c.nome AS cliente,
  SUM(ip.quantidade * ip.preco_unitario) AS total_gasto
FROM clientes c
JOIN pedidos p       ON p.cliente_id = c.id
JOIN itens_pedido ip ON ip.pedido_id = p.id
GROUP BY c.id, c.nome
ORDER BY total_gasto DESC
LIMIT 5;

Se quiser considerar apenas um período, adicione WHERE p.data_pedido BETWEEN ... AND ... antes do GROUP BY.

Onde vou aplicar isso: priorização de clientes, campanhas e acompanhamento de metas.

4) Filtrando grupos com HAVING

Para listar apenas clientes cujo total supere um determinado valor (por exemplo, R$ 500), use HAVING. Lembre-se: WHERE filtra linhas antes do group; HAVING filtra após a agregação.

-- Clientes com compras acima de R$ 500
SELECT
  c.nome,
  SUM(ip.quantidade * ip.preco_unitario) AS total_gasto
FROM clientes c
JOIN pedidos p       ON p.cliente_id = c.id
JOIN itens_pedido ip ON ip.pedido_id = p.id
GROUP BY c.nome
HAVING SUM(ip.quantidade * ip.preco_unitario) > 500
ORDER BY total_gasto DESC;
Onde vou aplicar isso: segmentações para relatórios e painéis de gestão.

5) Métricas complementares: quantidade de pedidos e ticket médio

Podemos combinar várias agregações no mesmo SELECT e criar métricas derivadas, como ticket médio (total/quantidade de pedidos distintos).

-- Total gasto, número de pedidos e ticket médio por cliente
SELECT
  c.nome AS cliente,
  SUM(ip.quantidade * ip.preco_unitario) AS total_gasto,
  COUNT(DISTINCT p.id) AS qtd_pedidos,
  ROUND(SUM(ip.quantidade * ip.preco_unitario) / NULLIF(COUNT(DISTINCT p.id), 0), 2) AS ticket_medio
FROM clientes c
JOIN pedidos p       ON p.cliente_id = c.id
JOIN itens_pedido ip ON ip.pedido_id = p.id
GROUP BY c.nome
ORDER BY total_gasto DESC;

NULLIF evita divisão por zero quando o denominador é 0. Use ROUND para melhorar a apresentação.

Onde vou aplicar isso: criação de indicadores-chave (KPIs) para gestão.

6) Conferência e validação dos resultados

Cheque se um cliente específico tem total coerente somando manualmente os itens de seus pedidos. Experimente também comparar o faturamento de um mês específico calculando com e sem filtros para confirmar consistência.

-- Exemplo: conferir os itens do cliente 'Ana'
SELECT p.id AS pedido, p.data_pedido, ip.produto_id, ip.quantidade, ip.preco_unitario,
       (ip.quantidade * ip.preco_unitario) AS subtotal
FROM pedidos p
JOIN itens_pedido ip ON ip.pedido_id = p.id
JOIN clientes c      ON c.id = p.cliente_id
WHERE c.nome = 'Ana'
ORDER BY p.data_pedido, ip.id;
Onde vou aplicar isso: auditoria interna e depuração de relatórios.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Objetivo: Consolidar o uso de GROUP BY, HAVING e funções de agregação produzindo relatórios úteis ao caso de vendas.

Atividade 1 — Faturamento por produto e mês

Crie uma consulta que apresente, para cada produto e mês, o faturamento total e a quantidade vendida. Ordene por ano, mês e faturamento descrescente.

Atividade 2 — Clientes com pelo menos 3 pedidos

Liste os clientes que realizaram 3 ou mais pedidos no período inteiro. Mostre o total gasto, a quantidade de pedidos e o ticket médio, usando HAVING para filtrar o grupo.

Atividade 3 — Top produtos por receita no trimestre

Considerando um trimestre específico (ex.: 2024-Q1), gere um ranking dos 3 produtos com maior receita. Dica: filtre datas com WHERE e use LIMIT 3.

Critérios de avaliação

  • Corretude das agregações e filtros (WHERE vs HAVING).
  • Organização e legibilidade do SQL (aliases claros, ordenação adequada).
  • Validação dos resultados com consultas auxiliares e números de conferência.
  • Documentação breve explicando cada métrica (comentários no SQL).

Pesquisas complementares (sugestões)

  • Documentação oficial do MySQL: funções de agregação e sintaxe de GROUP BY/HAVING.
  • Boas práticas de modelagem para relatórios: granularidade de fatos e dimensões.
  • Diferença entre COUNT(*), COUNT(1) e COUNT(coluna) em diferentes SGBDs.
  • Uso de índices para acelerar agregações e filtros por data.
