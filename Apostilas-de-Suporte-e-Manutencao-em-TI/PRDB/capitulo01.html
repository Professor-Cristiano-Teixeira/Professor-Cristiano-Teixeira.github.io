Capítulo 01 — Introdução a Programação e Banco de Dados

Carga: Não especificada

Projeto-base: Configuração de ambiente e leitura de CSV com estatísticas básicas

Stack fixa: Python, Thonny, MySQL, MySQL Workbench, MongoDB, MongoDB Compass

Resultados de aprendizagem deste capítulo:

  • Explicar a diferença entre dado, informação, banco de dados e SGBD.
  • Reconhecer características de bancos relacionais e NoSQL e quando utilizá-los.
  • Revisar tipos, estruturas de controle e estruturas de dados em programação com foco em manipulação de dados.
  • Instalar e validar o ambiente: Thonny, MySQL/Workbench e MongoDB/Compass.
  • Executar um script Python que lê um CSV e produz estatísticas básicas de forma autônoma.

  • Compreender conceitos fundamentais de armazenamento e gerenciamento de dados.
  • Operar ferramentas de desenvolvimento e SGBDs no laboratório.
  • Aplicar lógica de programação para leitura, processamento e resumo de dados.
  • Documentar e validar o funcionamento do ambiente e do script com evidências (prints/logs).

Parte Teórica (explicação do conteúdo)

1) Dado, informação, banco de dados e SGBD

Dado é um valor bruto, isolado de contexto (por exemplo, “42” ou “2024-05-01”). Informação é o dado interpretado, com significado para tomada de decisão (por exemplo, “42 vendas em maio de 2024”). Um banco de dados é uma coleção organizada de dados relacionados, estruturados para facilitar armazenamento e recuperação. O SGBD (Sistema Gerenciador de Banco de Dados) é o software que implementa mecanismos de definição, manipulação, segurança, transações e consulta a esses dados.

Os SGBDs controlam concorrência, integridade e persistência, liberando o desenvolvedor de reinventar mecanismos de armazenamento. Exemplos: MySQL (relacional) e MongoDB (documentos). Eles oferecem linguagens (SQL/MQL), APIs de acesso, usuários/permissões e ferramentas gráficas.

Onde vou aplicar isso: na prática, compreender o que é um CSV comparado a uma tabela/coleção e por que, futuramente, usaremos MySQL ou MongoDB ao invés de apenas arquivos.

2) Panorama: Relacional vs. NoSQL

No modelo relacional (ex.: MySQL), os dados são organizados em tabelas com linhas e colunas, e a integridade é garantida por chaves e restrições. Consultas são expressas em SQL, com forte consistência e estrutura rígida de esquema. Esse modelo é excelente para relacionamentos claros, integridade referencial e relatórios consistentes.

Em NoSQL (ex.: MongoDB), dados podem ser armazenados como documentos flexíveis (JSON/BSON), coleções sem esquema rígido e escalabilidade horizontal facilitada. É indicado quando o formato dos dados varia com frequência, para ingestão rápida e quando se deseja agilidade em prototipagem de estruturas semiestruturadas.

Não existe “o melhor” universal: a decisão depende do problema. Muitas organizações combinam os dois (arquitetura híbrida), usando relacional para dados transacionais e NoSQL para dados semiestruturados, logs ou catálogos flexíveis.

Onde vou aplicar isso: ao instalar MySQL e MongoDB e reconhecer, nos próximos capítulos, quando é mais natural consultar via SQL ou MQL.

3) Revisão de Programação com foco em dados

Tipos básicos (int, float, str, bool) e estruturas (listas, tuplas, dicionários) são base para representar registros e coleções. Controle de fluxo (if, for, while) permite filtrar e iterar dados. Funções encapsulam lógica de transformação e validação. O tratamento de exceções (try/except) é importante para lidar com arquivos ausentes, linhas malformadas ou conversões inválidas.

Leitura e escrita de arquivos: abrir caminhos corretos, saber a diferença entre modos (r, w, a), encoding e separadores (CSV). Strings exigem cuidados com strip, split, replace e conversões numéricas com validação.

Onde vou aplicar isso: diretamente no script que abre um CSV, percorre linhas, converte campos e calcula estatísticas, lidando com erros de forma segura.

4) Ambiente: Thonny, MySQL/Workbench, MongoDB/Compass

O Thonny é um IDE leve para Python, ideal para iniciantes. O MySQL Workbench facilita a modelagem e execução de SQL. O MongoDB Compass auxilia na navegação por coleções/consultas em documentos. Ter o ambiente funcionando evita gargalos quando integrarmos código e banco nas próximas aulas.

Durante a instalação, atente-se a permissões de pasta, portas padrão e criação de usuários no MySQL, bem como ao serviço do MongoDB. Verifique se você consegue abrir ambos os clientes (Workbench e Compass) e listar conexões locais.

Onde vou aplicar isso: já neste capítulo, validando instalações e executando o script Python no Thonny; nos capítulos seguintes, usaremos Workbench/Compass para praticar consultas.

Passo a Passo — Ambiente e Leitura de CSV com Estatísticas

Objetivo desta etapa:

Configurar o ambiente (Python/Thonny, MySQL/Workbench, MongoDB/Compass) e implementar um script Python que lê um arquivo CSV e imprime estatísticas básicas com tratamento de erros.


1) Preparar o ambiente do projeto

  1. Crie uma pasta de trabalho, por exemplo: C:\PRDB\cap01 (Windows) ou ~/PRDB/cap01 (Linux).
  2. Abra o Thonny e defina essa pasta como o diretório do seu projeto (Menu: File > Open... > navegue até a pasta).
  3. Verifique a instalação do Python no Thonny (Menu: Help > About > veja a versão do Python).
  4. Abra o MySQL Workbench. Tente conectar ao servidor local. Se não existir, registre uma conexão “Local instance”.
  5. Abra o MongoDB Compass. Faça uma conexão padrão local (mongodb://localhost:27017) e verifique se carrega as bases padrão.

Terminal (opcional): checagem rápida

# Verificar versão do Python
python --version
# Verificar se o MySQL está acessível (exemplo no Windows com mysql.exe no PATH)
mysql --version
# Verificar serviço do MongoDB (Linux systemd, por exemplo)
systemctl status mongod

2) Preparar um arquivo CSV de exemplo

Crie um arquivo chamado dados.csv dentro da pasta do projeto com o conteúdo a seguir. É um dataset simples com cabeçalho:

produto,quantidade,preco
Caneta,10,2.50
Caderno,5,12.00
Lápis,20,1.20
Borracha,8,1.80
Caderno,7,12.00
Caneta,3,2.50

Dica: sempre mantenha a primeira linha como cabeçalho (nomes das colunas). Evite vírgulas extras ou linhas em branco no fim do arquivo.

3) Criar o script Python (leitura e estatísticas)

No Thonny, crie um arquivo chamado leitor_csv.py e cole o código abaixo. Ele:

  • Lê o CSV com o módulo csv;
  • Valida e converte quantidade/preço;
  • Calcula contagem de linhas, soma, mínimo, máximo e média por coluna numérica;
  • Gera estatísticas por produto (agregação simples).
import csv
from statistics import mean

def carregar_csv(caminho):
    linhas = []
    try:
        with open(caminho, mode='r', encoding='utf-8') as f:
            reader = csv.DictReader(f)
            for row in reader:
                # Limpeza básica
                produto = (row.get('produto') or '').strip()
                qtd_str = (row.get('quantidade') or '').strip()
                preco_str = (row.get('preco') or '').strip()

                # Conversões com validação
                try:
                    quantidade = int(qtd_str)
                except ValueError:
                    print(f'Aviso: quantidade inválida "{qtd_str}" - pulando linha.')
                    continue

                try:
                    preco = float(preco_str.replace(',', '.'))
                except ValueError:
                    print(f'Aviso: preço inválido "{preco_str}" - pulando linha.')
                    continue

                if not produto:
                    print('Aviso: produto vazio - pulando linha.')
                    continue

                linhas.append({'produto': produto, 'quantidade': quantidade, 'preco': preco})
    except FileNotFoundError:
        print('Erro: arquivo CSV não encontrado. Verifique o caminho.')
    except PermissionError:
        print('Erro: sem permissão para ler o arquivo.')
    except Exception as e:
        print(f'Erro inesperado: {e}')
    return linhas

def estatisticas_basicas(registros, campo):
    valores = [r[campo] for r in registros if isinstance(r.get(campo), (int, float))]
    if not valores:
        return {'contagem': 0, 'soma': 0, 'min': None, 'max': None, 'media': None}
    return {
        'contagem': len(valores),
        'soma': sum(valores),
        'min': min(valores),
        'max': max(valores),
        'media': mean(valores)
    }

def agregado_por_produto(registros):
    # Total por produto (quantidade total e valor total)
    resumo = {}
    for r in registros:
        p = r['produto']
        resumo.setdefault(p, {'qtd_total': 0, 'valor_total': 0.0})
        resumo[p]['qtd_total'] += r['quantidade']
        resumo[p]['valor_total'] += r['quantidade'] * r['preco']
    return resumo

if __name__ == '__main__':
    caminho = 'dados.csv'
    dados = carregar_csv(caminho)
    if not dados:
        print('Nenhum dado processado.')
    else:
        print('--- Estatísticas globais ---')
        est_qtd = estatisticas_basicas(dados, 'quantidade')
        est_preco = estatisticas_basicas(dados, 'preco')
        print(f"Registros válidos: {len(dados)}")
        print(f"Quantidade: contagem={est_qtd['contagem']} soma={est_qtd['soma']} min={est_qtd['min']} max={est_qtd['max']} média={est_qtd['media']:.2f}")
        print(f"Preço: contagem={est_preco['contagem']} soma={est_preco['soma']:.2f} min={est_preco['min']:.2f} max={est_preco['max']:.2f} média={est_preco['media']:.2f}")

        print('\\n--- Agregado por produto ---')
        agg = agregado_por_produto(dados)
        for produto, info in agg.items():
            print(f"{produto}: qtd_total={info['qtd_total']}, valor_total=R$ {info['valor_total']:.2f}")

Execute o script no Thonny (Run ▶). Corrija mensagens de aviso ajustando o CSV se necessário.

4) Boas práticas e validações

  • Mantenha nomes de colunas consistentes no CSV.
  • Trate erros de conversão e linhas inválidas para evitar que o programa pare.
  • Versione seu script (copias incrementais) e salve prints de execução como evidências.

5) Validação do ambiente MySQL e MongoDB (visual)

Abra o MySQL Workbench e clique em sua conexão local. Caso carregue sem erros, anote a versão do servidor. No MongoDB Compass, conecte em localhost e liste as bases. Esses passos confirmam que, nos próximos capítulos, você poderá criar tabelas/coleções e executar consultas.
