Capítulo 16 — Integração, Relatórios e Caso Introductório de IoT

Carga: —

Projeto-base: Ingestão de leituras IoT simuladas com relatórios híbridos (MySQL + MongoDB)

Stack fixa: Python, MySQL, MySQL Workbench, MongoDB, MongoDB Compass

Resultados de aprendizagem deste capítulo:

  • Integrar MySQL (relacional) e MongoDB (documentos) em um mesmo fluxo de aplicação.
  • Implementar ingestão de dados simulados de sensores (IoT) com persistência e consultas.
  • Gerar relatórios consolidados combinando agregações SQL e MQL/lookup.
  • Aplicar boas práticas de transações, tratamento de erros e segurança básica (parametrização).
  • Documentar o pipeline de dados de ponta a ponta e publicar resultados.

Competências e Habilidades

  • Modelar e integrar diferentes fontes e modelos de dados.
  • Programar rotinas de ETL/ELT simples com Python.
  • Elaborar consultas e relatórios com métricas e agrupamentos.
  • Testar, depurar e registrar erros (logging) no pipeline.
  • Comunicar resultados técnicos por meio de documentação clara.

Plano de Aula (Capítulo 16)

Contexto: Encerramento com integração entre MySQL e MongoDB para ingestão de dados simulados de IoT e geração de relatórios consolidados.

  1. Arranque (15 min): Visão geral do pipeline híbrido (relacional + NoSQL) e objetivos de entrega.
  2. Teoria guiada (35–45 min): Quando usar cada SGBD; padrões de integração; estratégias de relatório; noções de lookups no MongoDB e joins no MySQL.
  3. Prática dirigida (90–120 min): Criar esquema relacional para cadastro de dispositivos e leituras agregadas; configurar coleção de eventos de sensores em MongoDB; escrever scripts de ingestão; gerar relatórios.
  4. Validação (30 min): Testes com dados simulados, análise de logs, checagem de consistência entre as bases.
  5. Fechamento (20 min): Exportar relatório final (CSV/JSON) e checklist de documentação do projeto integrador.

Parte Teórica (explicação do conteúdo)

Integração híbrida: quando usar MySQL e quando usar MongoDB

MySQL organiza dados estruturados com esquema definido e garante integridade por chaves, constraints e transações. É ideal para cadastros, referências e relatórios tabulares consistentes. MongoDB armazena documentos flexíveis em JSON/BSON, ótimo para eventos, logs e dados semiestruturados que podem variar de formato. Em cenários IoT, costuma-se manter o cadastro de dispositivos, usuários e regras no relacional; enquanto leituras de sensores (eventos volumosos e variáveis) ficam em uma coleção de documentos.

Onde vou aplicar isso: no passo a passo, vamos criar tabelas de dispositivos e um histórico consolidado no MySQL, enquanto as leituras brutas de sensores irão para uma coleção no MongoDB.

Padrões de integração e sincronização de dados

Três padrões simples: (1) Dual-Write: a aplicação grava nos dois bancos na mesma operação (exige cuidado com transações e idempotência); (2) ETL/ELT periódico: importar/exportar em lotes, agregando leituras para relatórios; (3) Consulta federada: combinar resultados em memória na aplicação, consultando MySQL e MongoDB separadamente e unindo os dados.

Onde vou aplicar isso: no passo a passo faremos um dual-write simplificado (cadastrar dispositivo no MySQL e coleção de referência no MongoDB) e consultas federadas no Python para compor relatórios.

Relatórios consolidados: SQL (joins/aggregations) e MQL (pipelines/lookup)

No MySQL, usamos GROUP BY, funções de agregação e JOINs para relacionar tabelas e produzir métricas por dispositivo, por período ou por status. No MongoDB, pipelines de agregação permitem filtrar, projetar, agrupar e calcular estatísticas de eventos. O estágio $lookup realiza junções entre coleções, útil para enriquecer leituras com metadados.

Onde vou aplicar isso: vamos gerar métricas de média, mínimo e máximo de temperatura por dispositivo e por dia, usando SQL no MySQL e um pipeline de agregação no MongoDB, além de combinar resultados no Python.

IoT introdutório: modelagem e ingestão de leituras

Um pipeline básico de IoT inclui: cadastro de dispositivos, coleta de leituras (timestamp, sensor, valor, unidade), persistência, validação e geração de insights. Para ambiente acadêmico, simulamos leituras com geradores pseudoaleatórios. É essencial incluir timestamps padronizados (ISO 8601) e unidades (°C, %, etc.).

Onde vou aplicar isso: implementaremos um simulador em Python que gera leituras temporizadas, validará dados e gravará nos SGBDs, com logs de execução e tratamento de exceções.

Confiabilidade: transações, tratamento de erros e idempotência

Ao escrever em múltiplos destinos, falhas parciais podem ocorrer. Utilize transações no MySQL para manter consistência e, quando possível, operações atômicas no MongoDB. Registre tentativas e resultados com logging. Em reprocessamentos, garanta idempotência usando chaves únicas ou verificações antes da inserção.

Onde vou aplicar isso: no passo a passo usaremos parâmetros seguros nas queries, verificações de existência de dispositivo e logs. Mostraremos uma estratégia simples para reprocessar um lote sem duplicar dados.

2) Modelo relacional (MySQL)

Crie tabelas para cadastro de dispositivos e uma tabela opcional para agregados diários.

USE iot_prdb;

CREATE TABLE IF NOT EXISTS dispositivos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  uid VARCHAR(64) NOT NULL UNIQUE,
  nome VARCHAR(100) NOT NULL,
  localidade VARCHAR(100),
  criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS agregados_diarios (
  id INT AUTO_INCREMENT PRIMARY KEY,
  dispositivo_uid VARCHAR(64) NOT NULL,
  data DATE NOT NULL,
  temp_min DECIMAL(5,2),
  temp_max DECIMAL(5,2),
  temp_avg DECIMAL(5,2),
  leituras INT DEFAULT 0,
  UNIQUE KEY uk_dispositivo_data (dispositivo_uid, data),
  FOREIGN KEY (dispositivo_uid) REFERENCES dispositivos(uid)
);

Boas práticas: chaves únicas para evitar duplicidade em agregações; tipos numéricos adequados.

5) Utilitários de banco (Python)

# arquivo: db_utils.py
import mysql.connector
from mysql.connector import Error
from pymongo import MongoClient
from config import MYSQL_CONF, MONGO_URI, MONGO_DB

def get_mysql_conn():
    return mysql.connector.connect(**MYSQL_CONF)

def get_mongo_col():
    cli = MongoClient(MONGO_URI)
    return cli[MONGO_DB]["leituras"]

def ensure_dispositivo(uid, nome="Dispositivo", localidade=None):
    """Idempotente: cria se não existir."""
    conn = get_mysql_conn()
    try:
        cur = conn.cursor()
        cur.execute("SELECT uid FROM dispositivos WHERE uid=%s", (uid,))
        if not cur.fetchone():
            cur.execute(
                "INSERT INTO dispositivos (uid, nome, localidade) VALUES (%s, %s, %s)",
                (uid, nome, localidade)
            )
            conn.commit()
        cur.close()
    except Error as e:
        print("[ERRO MYSQL]", e)
        conn.rollback()
        raise
    finally:
        conn.close()

6) Simulador de leituras (Python)

Gera leituras com timestamps e grava no MongoDB. O cadastro do dispositivo é garantido no MySQL.

# arquivo: simulador.py
import random, time, datetime as dt
from db_utils import get_mongo_col, ensure_dispositivo

def gerar_leitura(uid: str):
    return {
        "dispositivo_uid": uid,
        "sensor": "temp",
        "valor": round(random.uniform(18.0, 30.0), 2),
        "unidade": "C",
        "ts": dt.datetime.utcnow(),
        "meta": {"fonte": "simulador", "versao": "1.0"}
    }

def rodar_simulacao(uid="dev-001", n=20, intervalo=0.3):
    ensure_dispositivo(uid, nome="Sensor Temp Lab", localidade="Sala 1")
    col = get_mongo_col()
    inseridos = 0
    for _ in range(n):
        doc = gerar_leitura(uid)
        col.insert_one(doc)
        inseridos += 1
        print(f"Inserido: {doc['valor']}C @ {doc['ts'].isoformat()} uid={uid}")
        time.sleep(intervalo)
    print(f"Total inserido no MongoDB: {inseridos}")

if __name__ == "__main__":
    rodar_simulacao()

7) Agregações e relatórios — MongoDB

Calcular métricas por dia e dispositivo no lado do MongoDB:

# arquivo: relatorios_mongo.py
from pymongo import MongoClient
from config import MONGO_URI, MONGO_DB

def agregados_por_dia(uid="dev-001"):
    cli = MongoClient(MONGO_URI)
    col = cli[MONGO_DB]["leituras"]
    pipe = [
        {"$match": {"dispositivo_uid": uid, "sensor": "temp"}},
        {"$group": {
            "_id": {"dia": {"$dateToString": {"format": "%Y-%m-%d", "date": "$ts"}}},
            "temp_min": {"$min": "$valor"},
            "temp_max": {"$max": "$valor"},
            "temp_avg": {"$avg": "$valor"},
            "leituras": {"$sum": 1}
        }},
        {"$project": {
            "_id": 0, "data": "$_id.dia",
            "temp_min": 1, "temp_max": 1,
            "temp_avg": {"$round": ["$temp_avg", 2]},
            "leituras": 1
        }},
        {"$sort": {"data": 1}}
    ]
    return list(col.aggregate(pipe))

if __name__ == "__main__":
    for row in agregados_por_dia():
        print(row)

8) Persistência dos agregados no MySQL

Sincronize as métricas diárias calculadas no MongoDB para a tabela agregados_diarios no MySQL (idempotente por uid+data).

# arquivo: sync_agregados.py
import datetime as dt
from mysql.connector import Error
from db_utils import get_mysql_conn
from relatorios_mongo import agregados_por_dia

def upsert_agregado(uid: str, data: str, temp_min, temp_max, temp_avg, leituras):
    conn = get_mysql_conn()
    try:
        cur = conn.cursor()
        cur.execute("""
            INSERT INTO agregados_diarios (dispositivo_uid, data, temp_min, temp_max, temp_avg, leituras)
            VALUES (%s, %s, %s, %s, %s, %s)
            ON DUPLICATE KEY UPDATE
              temp_min=VALUES(temp_min), temp_max=VALUES(temp_max),
              temp_avg=VALUES(temp_avg), leituras=VALUES(leituras)
        """, (uid, data, temp_min, temp_max, temp_avg, leituras))
        conn.commit()
        cur.close()
    except Error as e:
        print("[ERRO MYSQL]", e)
        conn.rollback()
        raise
    finally:
        conn.close()

def sincronizar(uid="dev-001"):
    for row in agregados_por_dia(uid):
        upsert_agregado(uid, row["data"], row["temp_min"], row["temp_max"], row["temp_avg"], row["leituras"])

if __name__ == "__main__":
    sincronizar()

9) Relatórios SQL finais (MySQL)

Gere relatórios tabulares a partir dos agregados persistidos.

-- Média de temperatura por dispositivo nos últimos 7 dias
SELECT dispositivo_uid,
       ROUND(AVG(temp_avg), 2) AS media_semana,
       SUM(leituras) AS total_leituras
FROM agregados_diarios
WHERE data >= (CURRENT_DATE - INTERVAL 7 DAY)
GROUP BY dispositivo_uid
ORDER BY media_semana DESC;

-- Top dispositivos por variação (max - min) no período
SELECT dispositivo_uid,
       ROUND(AVG(temp_max - temp_min), 2) AS variacao_media
FROM agregados_diarios
GROUP BY dispositivo_uid
ORDER BY variacao_media DESC
LIMIT 5;

10) Exportação de resultados (Python)

Exporte CSV/JSON consolidando o que foi calculado no MySQL.

# arquivo: exportar.py
import csv, json
from db_utils import get_mysql_conn

def consulta_agregados():
    conn = get_mysql_conn()
    try:
        cur = conn.cursor(dictionary=True)
        cur.execute("""
            SELECT dispositivo_uid, data, temp_min, temp_max, temp_avg, leituras
            FROM agregados_diarios
            ORDER BY dispositivo_uid, data
        """)
        rows = cur.fetchall()
        cur.close()
        return rows
    finally:
        conn.close()

def exportar_csv_json(rows, base="relatorio_agregados"):
    with open(base + ".csv", "w", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=rows[0].keys())
        w.writeheader()
        w.writerows(rows)
    with open(base + ".json", "w", encoding="utf-8") as f:
        json.dump(rows, f, ensure_ascii=False, indent=2)
    print("Exportado:", base + ".csv", "e", base + ".json")

if __name__ == "__main__":
    dados = consulta_agregados()
    if dados:
        exportar_csv_json(dados)
    else:
        print("Sem dados para exportar.")
