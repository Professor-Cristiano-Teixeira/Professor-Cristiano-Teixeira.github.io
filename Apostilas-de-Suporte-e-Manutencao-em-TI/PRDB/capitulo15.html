Capítulo 15 — NoSQL e MongoDB Básico

Carga: 4h (2 encontros)

Projeto-base: Caso de vendas: clientes, pedidos e itens

Stack fixa: MongoDB Server, MongoDB Compass, Python (opcional, via PyMongo)

Resultados de aprendizagem deste capítulo:

  • Explicar os tipos de bancos NoSQL e identificar quando utilizá-los.
  • Modelar documentos e coleções iniciais para um cenário simples (vendas).
  • Executar operações básicas no MongoDB: inserção, consulta com filtros e projeções, atualização e remoção.
  • Aplicar operadores MQL para filtrar por campos, intervalos, arrays e objetos aninhados.
  • Criar e verificar um índice simples para melhorar consultas.
  • Operar o MongoDB Compass com segurança e interpretar os resultados das consultas.

  • Compreender paradigmas de persistência de dados (relacional x NoSQL).
  • Organizar informações semiestruturadas em documentos.
  • Executar operações CRUD e interpretar resultados de consultas.
  • Utilizar ferramentas de apoio (Compass) e comandos básicos de MQL.
  • Aplicar raciocínio lógico na definição de filtros e projeções.

Parte Teórica (explicação do conteúdo)

1) O que é NoSQL e por que usar

NoSQL é um termo guarda-chuva para bancos de dados que não seguem o modelo relacional tradicional. Eles surgiram para lidar com grandes volumes, variedade e velocidade de dados (conceito de 3Vs), com esquemas mais flexíveis e escalabilidade horizontal. Em vez de tabelas rígidas e JOINs, muitos NoSQL utilizam documentos, pares chave-valor, colunas amplas ou grafos para modelar informações.

Não se trata de substituir completamente bancos relacionais: cada modelo atende melhor a um tipo de problema. Quando você precisa de flexibilidade de esquema e trabalha com dados semiestruturados (por exemplo, catálogos de produtos com atributos variáveis), bancos de documentos como o MongoDB são especialmente úteis.

Onde vou aplicar isso no passo a passo: logo no início, você criará uma base “vendas” no MongoDB e verá como inserir documentos com campos variáveis sem migrações complexas.

2) Tipos NoSQL: documento, chave-valor, coluna e grafo

- Chave-valor: extremamente simples e rápido, ideal para cache ou sessões (ex.: Redis).
- Coluna larga: armazena dados por colunas, eficiente para analíticas (ex.: Cassandra).
- Grafo: foca em relações complexas entre entidades (ex.: Neo4j).
- Documento: armazena JSON/BSON com hierarquia e arrays (ex.: MongoDB).

No modelo de documento, cada registro é um documento autônomo, geralmente em BSON (uma forma binária do JSON). Ele pode conter arrays, objetos aninhados e campos opcionais, facilitando representar estruturas reais do domínio sem “explodir” em muitas tabelas relacionadas.

Onde vou aplicar isso no passo a passo: ao modelar cliente, pedido e itens dentro de um documento de pedido, usando subdocumentos e arrays.

3) Documentos, coleções e BSON (MongoDB)

Em MongoDB, os dados são organizados em bases (databases) que contêm coleções (collections). Cada coleção possui documentos (semelhantes a linhas), mas cada documento pode ter estrutura diferente. O identificador padrão é _id, único por documento. O formato de armazenamento é BSON, que suporta tipos como datas, ObjectId, números e arrays.

Essa flexibilidade evita esquemas rígidos, porém exige disciplina de modelagem para manter consistência lógica entre documentos e facilitar consultas e índices.

Onde vou aplicar isso no passo a passo: criaremos a base “vendas”, a coleção “pedidos” e inseriremos documentos com cliente, itens e total.

4) MQL (MongoDB Query Language) básico

MQL utiliza objetos JSON-like para definir filtros (em find()), projeções (quais campos retornar), atualizações (updateOne/updateMany com operadores $set, $inc, etc.) e remoções (deleteOne/deleteMany).

Operadores como $gt, $lt, $in, $and, $or, $elemMatch permitem criar filtros poderosos. Ordenações usam sort() (1 asc, -1 desc). Limite e “páginas” usam limit() e skip().

Onde vou aplicar isso no passo a passo: criaremos filtros por data e total, buscaremos itens em arrays e devolveremos apenas campos necessários com projeção.

5) Modelagem em documentos: embutir x referenciar

Embutir (subdocumentos/arrays) favorece leitura rápida de um “agregado” (por exemplo, um pedido com todos os itens). Referenciar (guardar apenas _id de outro documento) é útil quando há reuso intenso ou crescimento descontrolado do subdocumento.

Regra prática: dados que “nascem e morrem juntos” tendem a ser embutidos; dados altamente reutilizados e compartilhados tendem a ser referenciados.

Onde vou aplicar isso no passo a passo: pedidos terão itens embutidos; clientes podem estar embutidos com snapshot de nome/email ou referenciados por clienteId (mostramos ambas abordagens).

6) Índices introdutórios

Índices aceleram consultas ao custo de espaço e maior custo em escrita. Em MongoDB, criamos com createIndex({campo: 1}) e verificamos com getIndexes(). Planeje índices de acordo com os filtros mais usados. Evite criar muitos índices sem necessidade.

Onde vou aplicar isso no passo a passo: criaremos um índice em data e outro em cliente.email para acelerar buscas comuns.

Passo a Passo — MongoDB Básico com Compass e MQL

Objetivo desta etapa:

Configurar uma base “vendas”, inserir documentos de pedidos e praticar consultas, projeções, ordenação, paginação, atualizações, remoções e criação de índices.


1) Preparação do ambiente

  1. Certifique-se de que o MongoDB Server está instalado e em execução no laboratório.
  2. Abra o MongoDB Compass e conecte no servidor local: URI padrão mongodb://localhost:27017.
  3. Crie a database “vendas” e a coleção “pedidos”.

Dica: se preferir terminal, o cliente mongosh pode ser usado. Exemplos abaixo.

# Conectar com mongosh (se instalado)
mongosh "mongodb://localhost:27017"

# Dentro do shell, selecione/crie a base
use vendas

# Crie a coleção (opcional, será criada ao inserir)
db.createCollection("pedidos")

2) Inserindo documentos (Compass ou mongosh)

Modelo de documento para “pedidos” (com cliente embutido e itens embutidos):

{
  "data": {"$date": "2024-05-20T10:30:00Z"},
  "cliente": {
    "nome": "Ana Souza",
    "email": "ana.souza@example.com"
  },
  "itens": [
    {"sku": "P100", "descricao": "Teclado Mecânico", "qtd": 1, "preco": 250.00},
    {"sku": "P200", "descricao": "Mouse Óptico", "qtd": 2, "preco": 80.00}
  ],
  "total": 410.00,
  "status": "pago",
  "tags": ["ecommerce", "perifericos"]
}

Insira alguns documentos variados para enriquecer as consultas:

// mongosh (MQL)
use vendas
db.pedidos.insertMany([
  {
    data: ISODate("2024-05-20T10:30:00Z"),
    cliente: { nome: "Ana Souza", email: "ana.souza@example.com" },
    itens: [
      { sku: "P100", descricao: "Teclado Mecânico", qtd: 1, preco: 250.00 },
      { sku: "P200", descricao: "Mouse Óptico", qtd: 2, preco: 80.00 }
    ],
    total: 410.00,
    status: "pago",
    tags: ["ecommerce", "perifericos"]
  },
  {
    data: ISODate("2024-06-02T14:10:00Z"),
    cliente: { nome: "Bruno Lima", email: "bruno.lima@example.com" },
    itens: [
      { sku: "P300", descricao: "Headset", qtd: 1, preco: 180.00 }
    ],
    total: 180.00,
    status: "pendente",
    tags: ["ecommerce", "audio"]
  },
  {
    data: ISODate("2024-06-10T09:05:00Z"),
    cliente: { nome: "Carla Dias", email: "carla.dias@example.com" },
    itens: [
      { sku: "P100", descricao: "Teclado Mecânico", qtd: 1, preco: 240.00 },
      { sku: "P400", descricao: "Mousepad XL", qtd: 1, preco: 50.00 }
    ],
    total: 290.00,
    status: "pago",
    tags: ["loja-fisica", "perifericos"]
  }
])

Onde aplicar: prática de inserção para consolidar o modelo de documentos.

3) Consultas básicas: filtros e projeções

Busque todos os pedidos “pago” e retorne apenas cliente e total:

// Filtro + projeção (1 inclui, 0 exclui)
db.pedidos.find(
  { status: "pago" },
  { _id: 0, "cliente.nome": 1, total: 1 }
)

Filtros por intervalo de datas e total mínimo:

// Data >= 2024-06-01 e total >= 200
db.pedidos.find({
  data: { $gte: ISODate("2024-06-01T00:00:00Z") },
  total: { $gte: 200 }
})

Pesquisa por campo aninhado e arrays:

// Cliente por email (campo aninhado)
db.pedidos.find({ "cliente.email": "ana.souza@example.com" })

// Algum item com sku P100 (qualquer elemento do array)
db.pedidos.find({ "itens.sku": "P100" })

// Condição no array usando $elemMatch (qtd >= 2)
db.pedidos.find({ itens: { $elemMatch: { qtd: { $gte: 2 } } } })

Onde aplicar: entender como selecionar campos relevantes e reduzir transferência de dados com projeção.

4) Ordenação e paginação

Ordene por data desc, limite 2 e pule 0 (primeira “página”):

db.pedidos.find({}, { _id: 0, data: 1, total: 1 })
  .sort({ data: -1 })
  .limit(2)
  .skip(0)

Segunda “página” (próximos 2):

db.pedidos.find({}, { _id: 0, data: 1, total: 1 })
  .sort({ data: -1 })
  .limit(2)
  .skip(2)

Onde aplicar: construir listagens amigáveis com navegação entre páginas.

5) Atualizações e remoções

Atualize status para “enviado” quando “pago” e data <= uma data de corte:

db.pedidos.updateMany(
  {
    status: "pago",
    data: { $lte: ISODate("2024-06-05T00:00:00Z") }
  },
  { $set: { status: "enviado" } }
)

Incrementar o total (ex.: ajuste de frete) em um pedido específico:

// Substitua pelo _id real
const id = db.pedidos.findOne({ "cliente.email": "bruno.lima@example.com" })._id;
db.pedidos.updateOne({ _id: id }, { $inc: { total: 15.00 } })

Remover pedidos “pendente” muito antigos:

db.pedidos.deleteMany({
  status: "pendente",
  data: { $lt: ISODate("2024-01-01T00:00:00Z") }
})

Onde aplicar: manutenção de dados e correções pontuais.

6) Índices básicos

Criar índice por data e por email do cliente:

// Índice simples por data
db.pedidos.createIndex({ data: -1 })

// Índice em campo aninhado (cliente.email)
db.pedidos.createIndex({ "cliente.email": 1 })

Verificar índices e planos de execução:

// Listar índices
db.pedidos.getIndexes()

// Explains (checar se está usando índice)
db.pedidos.find({ "cliente.email": "ana.souza@example.com" }).explain("executionStats")

Onde aplicar: acelerar consultas usadas com frequência.

7) (Opcional) Acessando MongoDB via Python

Exemplo simples com PyMongo para consulta com filtro e projeção. Execute em um ambiente com Python instalado e a biblioteca pymongo.

pip install pymongo
from pymongo import MongoClient
from datetime import datetime

client = MongoClient("mongodb://localhost:27017")
db = client["vendas"]
pedidos = db["pedidos"]

filtro = {
    "status": "pago",
    "data": {"$gte": datetime(2024, 6, 1)}
}
projecao = {"_id": 0, "cliente.nome": 1, "total": 1}

for doc in pedidos.find(filtro, projecao).sort("total", -1).limit(5):
    print(f"Cliente: {doc['cliente']['nome']} - Total: R$ {doc['total']:.2f}")

Onde aplicar: integração simples com aplicações Python para relatórios.

Atividades Práticas para o(a) aluno(a) (desenvolver por conta própria)

Atividade A — Catálogo de Produtos

Atividade B — Relatórios simples

  • Liste os 5 maiores pedidos (por total) e traga somente cliente.nome, total e data.
  • Busque pedidos que contenham um item específico (por sku) e ordene por data desc.
  • Crie e use um índice adequado para acelerar a consulta acima.

Atividade C — Manutenção

  • Atualize o status de pedidos pendentes com mais de 30 dias para “cancelado”.
  • Remova pedidos de teste (identificados por tag “teste” em tags).
  • Registre, em um arquivo texto, os comandos executados e os resultados observados.

Critérios de avaliação (rubrica)

  • Corretude das consultas e atualizações (filtros e projeções adequados).
  • Organização e clareza dos documentos inseridos (consistência de campos).
  • Uso apropriado de índices e interpretação do explain.
  • Documentação breve das decisões e comandos (passo a passo reprodutível).

Pesquisas complementares (sugestões)

  • Boas práticas de criação de índices e impactos em escrita.
