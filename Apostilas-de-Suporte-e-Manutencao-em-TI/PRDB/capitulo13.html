Capítulo 13 — CRUD Completo com Tratamento de Erros e Transações

Carga: 6h

Projeto-base: Miniaplicação de linha de comando para gerenciar produtos

Stack fixa: Python 3, mysql-connector-python, MySQL, MySQL Workbench

Resultados de aprendizagem deste capítulo:

  • Implementar operações Create, Read, Update e Delete de forma modular e reutilizável.
  • Aplicar transações (COMMIT/ROLLBACK) e tratamento de exceções no acesso ao banco.
  • Utilizar consultas parametrizadas para prevenir SQL Injection e validar entradas.
  • Exibir mensagens de erro úteis e códigos de retorno em uma CLI simples.
  • Testar cenários de falha e garantir consistência dos dados com transações.

Competências e Habilidades

  • Modelar e implementar operações de persistência de dados.
  • Gerenciar transações e lidar com exceções em aplicações de dados.
  • Escrever código limpo, modular e seguro no acesso ao SGBD.
  • Realizar testes de mesa e verificar efeitos no banco após falhas.

Parte Teórica (explicação do conteúdo)

1) O que é CRUD e por que importa

CRUD é o acrônimo de Create, Read, Update e Delete — quatro operações fundamentais para sistemas que manipulam dados. Elas representam o ciclo de vida padrão das informações em bancos relacionais e também em diversos sistemas NoSQL. Dominar CRUD significa saber implementar a persistência de dados de forma confiável.

Na prática, um sistema está a todo momento inserindo, consultando, atualizando e removendo registros. Quando essas rotinas são bem projetadas, o restante da aplicação ganha previsibilidade e segurança.

Onde vou aplicar isso no passo a passo: você criará funções dedicadas para cada operação (criar, listar/buscar, atualizar, apagar) e as conectará a um menu de linha de comando.

2) Consultas parametrizadas e segurança

Consultas parametrizadas usam placeholders (ex.: %s no MySQL Connector/Python) para separar a lógica SQL dos valores fornecidos pelo usuário. Isso ajuda a prevenir SQL Injection e a padronizar o tratamento de tipos.

Além da segurança, consultas parametrizadas melhoram legibilidade e manutenção do código. Evite concatenar strings para montar SQL.

Onde vou aplicar isso no passo a passo: todas as funções CRUD usarão parâmetros nas instruções SQL, com validação de entrada antes da chamada.

3) Transações e consistência

Uma transação é uma unidade lógica de trabalho que agrupa operações; ou tudo é confirmado (COMMIT) ou tudo é revertido (ROLLBACK). Ela garante as propriedades ACID, principalmente atomicidade e consistência.

Em operações que envolvem múltiplas tabelas ou passos, transações evitam estados intermediários incoerentes. Mesmo em operações simples, usar transações e pontos de restauração pode simplificar a recuperação de falhas.

Onde vou aplicar isso no passo a passo: você controlará commit() e rollback() explicitamente ao inserir, atualizar e excluir produtos.

4) Tratamento de exceções

Exceções podem ocorrer por problemas de conexão, violação de constraints, tipos inválidos, entre outros. Um bom tratamento captura a exceção, registra detalhes e comunica ao usuário uma mensagem clara, sem expor informações sensíveis.

Utilize blocos try/except e, quando necessário, finally para garantir a liberação adequada de recursos. Defina uma política: se falhar, faça rollback() e retorne um indicador de erro.

Onde vou aplicar isso no passo a passo: todas as funções de acesso ao banco terão try/except e retornarão status/mensagens adequadas para a CLI.

5) Modularização e camadas

Separar a camada de dados (funções que falam com o SGBD) da camada de interface (CLI) facilita testes e manutenção. Cada função deve fazer uma coisa só e bem definida, com assinatura clara de entrada/saída.

Uma camada de serviço pode encapsular regras de negócio e validação. Isso torna o código menos acoplado e mais fácil de evoluir.

Onde vou aplicar isso no passo a passo: vamos criar um módulo para banco (conexão e CRUD) e outro para a interface (menu e fluxo do usuário).

6) Mensagens de erro e códigos de retorno

Ao programar uma CLI, indique ao usuário o que aconteceu: sucesso, erro e por quê. Evite termos técnicos excessivos. Para o código, padronize retornos: por exemplo, (ok: bool, msg: str, data: Optional).

Essa padronização simplifica a exibição das mensagens e facilita testes automatizados no futuro.

Onde vou aplicar isso no passo a passo: toda função do CRUD retorna uma tupla padronizada consumida pelo menu principal.

Passo a Passo — CRUD de Produtos com Transações e Tratamento de Erros

Objetivo desta etapa:

Construir uma miniaplicação de linha de comando que realiza CRUD em uma tabela de produtos no MySQL, usando funções modulares, consultas parametrizadas, transações explícitas e tratamento de exceções.


Preparar o banco de dados e a tabela de produtos

Caso ainda não exista, crie o banco e a tabela. Use tipos e constraints adequados (PK, NOT NULL, UNIQUE se necessário).

CREATE DATABASE IF NOT EXISTS loja;
USE loja;

CREATE TABLE IF NOT EXISTS produtos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  preco DECIMAL(10,2) NOT NULL CHECK (preco >= 0),
  estoque INT NOT NULL CHECK (estoque >= 0),
  criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Opcional: índice para busca por nome
CREATE INDEX idx_produtos_nome ON produtos (nome);
Valide no Workbench se a tabela foi criada corretamente. Se o MySQL da sua versão não suportar CHECK, mantenha a validação do lado da aplicação.

Instalar dependência e configurar conexão

Instale o conector oficial e crie um módulo dedicado à conexão (reutilizável em todo o projeto).

pip install mysql-connector-python

Arquivo: db.py

import mysql.connector
from mysql.connector import Error

def get_connection():
    return mysql.connector.connect(
        host="localhost",
        user="root",
        password="sua_senha",
        database="loja",
        autocommit=False  # importante para controlar transações
    )

def test_connection():
    try:
        cnx = get_connection()
        print("Conexão bem-sucedida!")
    except Error as e:
        print(f"Erro de conexão: {e}")
    finally:
        try:
            cnx.close()
        except:
            pass

if __name__ == "__main__":
    test_connection()

Camada de dados: funções CRUD parametrizadas

Crie um módulo com funções focadas no banco. Cada função retorna uma tupla padronizada: (ok: bool, msg: str, data: Any).

Arquivo: produtos_repo.py

from typing import Any, Tuple, Optional, List, Dict
from mysql.connector import Error
from db import get_connection

ReturnType = Tuple[bool, str, Any]

def criar_produto(nome: str, preco: float, estoque: int) -> ReturnType:
    if not nome or preco is None or estoque is None:
        return False, "Dados obrigatórios ausentes.", None
    if preco < 0 or estoque < 0:
        return False, "Preço e estoque não podem ser negativos.", None
    sql = "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)"
    params = (nome.strip(), preco, estoque)
    cnx = None
    try:
        cnx = get_connection()
        cur = cnx.cursor()
        cur.execute(sql, params)
        cnx.commit()
        new_id = cur.lastrowid
        return True, f"Produto criado com ID {new_id}.", new_id
    except Error as e:
        if cnx:
            cnx.rollback()
        return False, f"Erro ao criar produto: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass

def listar_produtos() -> ReturnType:
    sql = "SELECT id, nome, preco, estoque, criado_em FROM produtos ORDER BY id"
    try:
        cnx = get_connection()
        cur = cnx.cursor(dictionary=True)
        cur.execute(sql)
        rows = cur.fetchall()
        return True, f"{len(rows)} produto(s) encontrado(s).", rows
    except Error as e:
        return False, f"Erro ao listar produtos: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass

def buscar_por_id(pid: int) -> ReturnType:
    sql = "SELECT id, nome, preco, estoque, criado_em FROM produtos WHERE id = %s"
    try:
        cnx = get_connection()
        cur = cnx.cursor(dictionary=True)
        cur.execute(sql, (pid,))
        row = cur.fetchone()
        if not row:
            return False, "Produto não encontrado.", None
        return True, "Produto encontrado.", row
    except Error as e:
        return False, f"Erro na busca: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass

def atualizar_produto(pid: int, nome: Optional[str], preco: Optional[float], estoque: Optional[int]) -> ReturnType:
    campos = []
    valores = []
    if nome is not None:
        if not nome.strip():
            return False, "Nome não pode ser vazio.", None
        campos.append("nome = %s"); valores.append(nome.strip())
    if preco is not None:
        if preco < 0:
            return False, "Preço não pode ser negativo.", None
        campos.append("preco = %s"); valores.append(preco)
    if estoque is not None:
        if estoque < 0:
            return False, "Estoque não pode ser negativo.", None
        campos.append("estoque = %s"); valores.append(estoque)

    if not campos:
        return False, "Nada para atualizar.", None

    sql = f"UPDATE produtos SET {', '.join(campos)} WHERE id = %s"
    valores.append(pid)

    cnx = None
    try:
        cnx = get_connection()
        cur = cnx.cursor()
        cur.execute(sql, tuple(valores))
        if cur.rowcount == 0:
            cnx.rollback()
            return False, "Produto não encontrado para atualização.", None
        cnx.commit()
        return True, f"{cur.rowcount} registro(s) atualizado(s).", cur.rowcount
    except Error as e:
        if cnx:
            cnx.rollback()
        return False, f"Erro ao atualizar produto: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass

def deletar_produto(pid: int) -> ReturnType:
    sql = "DELETE FROM produtos WHERE id = %s"
    cnx = None
    try:
        cnx = get_connection()
        cur = cnx.cursor()
        cur.execute(sql, (pid,))
        if cur.rowcount == 0:
            cnx.rollback()
            return False, "Produto não encontrado para exclusão.", None
        cnx.commit()
        return True, f"{cur.rowcount} registro(s) excluído(s).", cur.rowcount
    except Error as e:
        if cnx:
            cnx.rollback()
        return False, f"Erro ao excluir produto: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass

Camada de interface (CLI): menu e fluxo

A CLI deve ler entradas, invocar funções do repositório e exibir mensagens amigáveis. Mantenha validações simples.

Arquivo: app.py

from typing import Optional
from produtos_repo import (
    criar_produto, listar_produtos, buscar_por_id,
    atualizar_produto, deletar_produto
)

def input_float(msg: str) -> Optional[float]:
    try:
        return float(input(msg).replace(",", ".").strip())
    except:
        print("Valor inválido.")
        return None

def input_int(msg: str) -> Optional[int]:
    try:
        return int(input(msg).strip())
    except:
        print("Valor inválido.")
        return None

def menu():
    print("\n==== Gerenciador de Produtos ====")
    print("1) Criar produto")
    print("2) Listar produtos")
    print("3) Buscar por ID")
    print("4) Atualizar produto")
    print("5) Excluir produto")
    print("0) Sair")

def acao_criar():
    nome = input("Nome: ").strip()
    preco = input_float("Preço: ")
    if preco is None: return
    estoque = input_int("Estoque: ")
    if estoque is None: return
    ok, msg, data = criar_produto(nome, preco, estoque)
    print(msg)

def acao_listar():
    ok, msg, rows = listar_produtos()
    print(msg)
    if ok and rows:
        for r in rows:
            print(f"[{r['id']}] {r['nome']} | R$ {r['preco']:.2f} | estoque: {r['estoque']}")

def acao_buscar():
    pid = input_int("ID do produto: ")
    if pid is None: return
    ok, msg, row = buscar_por_id(pid)
    print(msg)
    if ok:
        print(row)

def acao_atualizar():
    pid = input_int("ID do produto: ")
    if pid is None: return
    print("Deixe em branco para manter o valor atual.")
    nome = input("Novo nome: ").strip()
    nome = nome if nome != "" else None
    preco_txt = input("Novo preço: ").strip()
    preco = float(preco_txt.replace(",", ".")) if preco_txt else None
    estoque_txt = input("Novo estoque: ").strip()
    estoque = int(estoque_txt) if estoque_txt else None

    ok, msg, _ = atualizar_produto(pid, nome, preco, estoque)
    print(msg)

def acao_excluir():
    pid = input_int("ID do produto: ")
    if pid is None: return
    confirma = input(f"Confirma excluir ID {pid}? (s/n): ").strip().lower()
    if confirma != "s":
        print("Operação cancelada.")
        return
    ok, msg, _ = deletar_produto(pid)
    print(msg)

def main():
    while True:
        menu()
        opc = input("Escolha uma opção: ").strip()
        if opc == "1":
            acao_criar()
        elif opc == "2":
            acao_listar()
        elif opc == "3":
            acao_buscar()
        elif opc == "4":
            acao_atualizar()
        elif opc == "5":
            acao_excluir()
        elif opc == "0":
            print("Saindo...")
            break
        else:
            print("Opção inválida.")

if __name__ == "__main__":
    main()

Testes de transação e simulação de falhas

Para validar a atomicidade, force uma falha no meio de uma operação e verifique se o banco reverteu corretamente.

Exemplo: inclua intencionalmente um erro após o execute e antes do commit para checar o rollback().

# Exemplo didático (NÃO deixar em produção)
def criar_produto_com_falha(nome, preco, estoque):
    from db import get_connection
    cnx = None
    try:
        cnx = get_connection()
        cur = cnx.cursor()
        cur.execute("INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)", (nome, preco, estoque))
        # Falha proposital
        raise ValueError("Erro simulado antes do commit")
        cnx.commit()
        return True, "OK", cur.lastrowid
    except Exception as e:
        if cnx:
            cnx.rollback()
        return False, f"Rollback executado: {e}", None
    finally:
        try:
            cur.close()
            cnx.close()
        except:
            pass
Após executar a função com falha, verifique no banco se o registro não foi inserido. Isso confirma o funcionamento do rollback.

Boas práticas finais

  • Valide entradas: tipos, intervalos, campos obrigatórios.
  • Use consultas parametrizadas e nunca concatene SQL com dados do usuário.
  • Controle transações explicitamente: commit no sucesso, rollback no erro.
  • Separe camadas: repositório (dados) e interface (CLI).
  • Padronize retornos e mensagens; facilite a manutenção e os testes.
