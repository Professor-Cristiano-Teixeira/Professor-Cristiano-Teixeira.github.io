Capítulo 16 — Introdução ao Versionamento com Git e Integração de Conteúdos

Carga: N/D

Projeto-base: Mini-projeto “Conversor e Relatórios”

Stack fixa: Python 3.x + Thonny IDE + Git (local)

Resultados de aprendizagem deste capítulo:

  • Criar e inicializar um repositório Git local para um projeto Python.
  • Realizar commits significativos com mensagens claras e rastreáveis.
  • Organizar um mini-projeto integrando E/S, condicionais, laços, listas/dicionários e funções.
  • Aplicar validação básica, depuração e boas práticas durante a evolução do projeto.
  • Gerar relatórios simples a partir de dados processados.

Plano de Aula (Capítulo 16)

1) Abertura e objetivos (10 min): contextualização do versionamento, benefícios individuais e em equipe. 2) Conceitos essenciais (25–35 min): repositório, snapshot, staging area, commit, histórico, .gitignore, boas mensagens. 3) Demonstração (20–30 min): preparar pasta do mini-projeto “Conversor e Relatórios”, inicializar Git, criar .gitignore, realizar commits incrementais. 4) Mão na massa guiada (60–90 min): implementar funcionalidades com E/S, condicionais, laços, listas/dicts e funções, registrando commits. 5) Verificação e testes (20–30 min): rodar o projeto, validar entradas, corrigir erros. 6) Encerramento (15 min): gerar relatório simples, revisar histórico de commits, checklist do capítulo e registro dos entregáveis.

Parte Teórica (explicação do conteúdo)

1) O que é controle de versão (Git)?

Git é um sistema de controle de versão distribuído. Ele registra “fotografias” (commits) do estado do seu projeto ao longo do tempo. Com isso, você pode avançar, comparar e até voltar para versões anteriores de forma segura, sem perder trabalho.

Um repositório (repo) é a pasta do seu projeto com um subdiretório oculto .git. É ali que o Git guarda o histórico, metadados e referências aos commits.

Onde vou aplicar isso: no mini-projeto, você criará um repositório local, fará commits a cada pequena evolução (ex.: criar arquivos, implementar funções, corrigir bugs).

2) Três áreas: diretório de trabalho, staging (index) e repositório

No Git, você edita arquivos no diretório de trabalho. Em seguida, seleciona o que quer “fotografar” usando a staging area (git add). Por fim, registra a foto com git commit, que entra no repositório (histórico).

Essa separação permite preparar commits limpos e coesos, agrupando mudanças relacionadas.

Onde vou aplicar isso: ao finalizar cada tarefa (ex.: função nova), você fará git add nos arquivos relevantes e depois git commit com uma mensagem clara.

3) Commits atômicos e mensagens claras

Commits atômicos contêm uma única ideia/alteração. Isso facilita entender o histórico, reverter problemas e revisar o código. Mensagens devem explicar o “que” e, quando útil, “por quê”.

Padrão simples: no imperativo, curto na primeira linha e, opcionalmente, detalhes no corpo. Ex.: “Implementa função de conversão C→F”.

Onde vou aplicar isso: em cada evolução do projeto, como criar o arquivo principal, implementar conversões, adicionar relatórios e corrigir validações.

4) .gitignore e organização do projeto

O arquivo .gitignore lista arquivos/pastas que não devem ir para o histórico (ex.: arquivos temporários, __pycache__/, ambientes virtuais, dados sensíveis). Manter um repositório limpo reduz ruído e conflitos.

Onde vou aplicar isso: você criará um .gitignore básico para Python e manterá uma estrutura de pastas simples para o mini-projeto.

5) Benefícios práticos para estudo e trabalho em equipe

Para estudo, o Git permite experimentar sem medo: se algo quebrar, volte a um commit anterior. Em equipe, cada pessoa trabalha em partes diferentes, integrando alterações com histórico rastreável.

Onde vou aplicar isso: ao integrar os conteúdos vistos no curso num único projeto, mantendo histórico que evidencie sua evolução técnica.

6) Integração de conteúdos no mini-projeto

O “Conversor e Relatórios” combina E/S, condicionais, laços, listas/dicts e funções para processar dados e gerar resumos. Você implementará incrementos e testará a cada etapa, consolidando os capítulos anteriores.

Onde vou aplicar isso: implementando conversões numéricas, registrando dados em listas/dicionários, percorrendo-os com laços e modularizando com funções reutilizáveis.

Passo a Passo — Mini-projeto “Conversor e Relatórios” com Git

Objetivo desta etapa:

Construir um mini-projeto Python que realiza conversões e gera relatórios simples, versionando cada incremento com Git e aplicando boas práticas.


1) Preparar a pasta do projeto e inicializar o Git

Crie uma pasta dedicada e inicialize o repositório. Em seguida, crie um .gitignore básico para Python.

mkdir conversor_relatorios
cd conversor_relatorios

# inicializa o repositório local
git init

# cria ambiente básico
echo "# Conversor e Relatórios (PRAL Cap. 16)" > README.md

# .gitignore simples para Python
cat << 'EOF' > .gitignore
__pycache__/
*.pyc
*.pyo
.venv/
.env
.DS_Store
EOF

# primeiro commit
git add .
git commit -m "Inicia repositório: README e .gitignore"
Onde aplicar: capítulo usa o Git desde o início. Cada novo arquivo/feature vira um commit.

2) Estrutura inicial e entrada/saída

Crie o arquivo principal com um menu simples (laço while) e funções de saída. Use condicionais para navegar.

# arquivo: app.py

def mostrar_menu():
    print("\n=== Conversor e Relatórios ===")
    print("1) Converter temperaturas (C ↔ F)")
    print("2) Registrar valores e gerar relatório")
    print("3) Sair")

def ler_opcao():
    opc = input("Escolha uma opção (1-3): ").strip()
    return opc

def main():
    historico = []  # lista de dicts: cada registro de operação
    while True:
        mostrar_menu()
        opc = ler_opcao()
        if opc == "1":
            converter_temperaturas(historico)
        elif opc == "2":
            registrar_e_relatar(historico)
        elif opc == "3":
            print("Encerrando... até a próxima!")
            break
        else:
            print("Opção inválida. Tente novamente.")

if __name__ == "__main__":
    # Funções serão definidas no próximo passo
    def converter_temperaturas(h):  # stub temporário
        print("[WIP] Conversão em desenvolvimento.")
    def registrar_e_relatar(h):     # stub temporário
        print("[WIP] Registro/Relatório em desenvolvimento.")
    main()
# registre a estrutura no histórico
git add app.py
git commit -m "Cria estrutura inicial: menu, laço principal e stubs"
Onde aplicar: laços (while), E/S (input/print), condicionais (if/elif/else) — capítulos 06, 07, 09 e 10.

3) Funções de conversão (funções e validação)

Implemente conversão Celsius ↔ Fahrenheit, com validação simples. Registre cada operação no histórico (lista de dicionários).

# substitua os stubs em app.py por implementações reais

def c_para_f(c):
    return (c * 9/5) + 32

def f_para_c(f):
    return (f - 32) * 5/9

def ler_float(msg):
    while True:
        txt = input(msg).strip().replace(",", ".")
        try:
            return float(txt)
        except ValueError:
            print("Valor inválido. Tente novamente (use números).")

def converter_temperaturas(historico):
    print("\n-- Conversão de Temperaturas --")
    print("a) Celsius -> Fahrenheit")
    print("b) Fahrenheit -> Celsius")
    escolha = input("Escolha (a/b): ").strip().lower()
    if escolha == "a":
        c = ler_float("Informe °C: ")
        f = c_para_f(c)
        print(f"{c:.2f} °C = {f:.2f} °F")
        historico.append({"tipo": "conv_temp", "de": "C", "para": "F", "entrada": c, "saida": f})
    elif escolha == "b":
        f = ler_float("Informe °F: ")
        c = f_para_c(f)
        print(f"{f:.2f} °F = {c:.2f} °C")
        historico.append({"tipo": "conv_temp", "de": "F", "para": "C", "entrada": f, "saida": c})
    else:
        print("Opção inválida.")
git add app.py
git commit -m "Implementa conversões C↔F com validação e registro no histórico"
Onde aplicar: funções (cap. 14), validação e tratamento de erro simples (cap. 15).

4) Registrar números e gerar relatório (listas/dicts, laços e condicionais)

Permita que o usuário registre valores (ex.: temperaturas convertidas ou números quaisquer) e gere um relatório com mínimo, máximo, média e contagem.

def registrar_e_relatar(historico):
    print("\n-- Registrar valores e gerar relatório --")
    valores = []
    while True:
        txt = input("Digite um valor (ou ENTER para sair): ").strip()
        if txt == "":
            break
        try:
            v = float(txt.replace(",", "."))
            valores.append(v)
        except ValueError:
            print("Valor inválido, tente novamente.")

    if not valores:
        print("Nenhum valor informado.")
        return

    # relatório simples
    qtd = len(valores)
    mn = min(valores)
    mx = max(valores)
    media = sum(valores) / qtd

    print("\nResumo:")
    print(f"Quantidade: {qtd}")
    print(f"Mínimo: {mn:.2f} | Máximo: {mx:.2f}")
    print(f"Média: {media:.2f}")

    historico.append({
        "tipo": "relatorio",
        "qtd": qtd,
        "min": mn,
        "max": mx,
        "media": media
    })
git add app.py
git commit -m "Adiciona registro de valores e geração de relatório estatístico básico"
Onde aplicar: listas e dicionários (cap. 12 e 13), for/while (cap. 10 e 11), expressões e operadores (cap. 07).

5) Refatorar em funções puras e organizar commits

Extraia funções utilitárias para aumentar a coesão e facilitar testes. Faça commits atômicos para cada refatoração.

# exemplo de função pura para resumo estatístico
def resumo_estatistico(valores):
    if not valores:
        return None
    return {
        "qtd": len(valores),
        "min": min(valores),
        "max": max(valores),
        "media": sum(valores) / len(valores)
    }

# no registrar_e_relatar, troque pelos retornos da função pura
def registrar_e_relatar(historico):
    print("\n-- Registrar valores e gerar relatório --")
    valores = []
    while True:
        txt = input("Digite um valor (ou ENTER para sair): ").strip()
        if txt == "":
            break
        try:
            valores.append(float(txt.replace(",", ".")))
        except ValueError:
            print("Valor inválido, tente novamente.")

    dados = resumo_estatistico(valores)
    if not dados:
        print("Nenhum valor informado.")
        return

    print("\nResumo:")
    print(f"Quantidade: {dados['qtd']}")
    print(f"Mínimo: {dados['min']:.2f} | Máximo: {dados['max']:.2f}")
    print(f"Média: {dados['media']:.2f}")

    historico.append({"tipo": "relatorio", **dados})
git add app.py
git commit -m "Refatora: extrai resumo_estatistico() e simplifica registrar_e_relatar"
Onde aplicar: funções e modularização (cap. 14), legibilidade e pequenos passos (cap. 15).

6) Conferir histórico e revisar mensagens

Use os comandos abaixo para verificar o histórico de commits e garantir que cada mensagem descreve bem a mudança.

# ver histórico resumido
git log --oneline --graph --decorate

# detalhes do último commit
git show

# status atual do diretório
git status
Onde aplicar: validação final do trabalho. Históricos claros são parte da avaliação do bimestre.

7) Testar, depurar e registrar correções

Execute o programa, faça testes com entradas válidas e inválidas. Em caso de erro, depure no Thonny e registre um commit com a correção.

# executar
python app.py

# após corrigir um bug identificado
git add app.py

Onde aplicar: depuração (cap. 15), testes manuais e correção incremental.

8) Opcional: separar utilitários em módulo

Crie um arquivo utils.py e mova funções puras para lá, importando-as no app.py. Faça um commit dedicado a essa reorganização.

# utils.py
def resumo_estatistico(valores):
    if not valores:
        return None
    return {
        "qtd": len(valores),
        "min": min(valores),
        "max": max(valores),
        "media": sum(valores) / len(valores)
    }
# app.py (trecho)
from utils import resumo_estatistico
git add app.py utils.py
git commit -m "Organiza: extrai utilitários para módulo separado"
