Capítulo 14 — Funções e Modularização

Carga: 2 aulas (100–120 min)

Projeto-base: Refatoração de um programa anterior usando funções puras e módulos

Stack fixa: Python 3.x no Thonny IDE

Resultados de aprendizagem deste capítulo:

  • Definir funções em Python com parâmetros e valores de retorno.
  • Explicar e aplicar escopo de variáveis (local vs. global) com segurança.
  • Refatorar um script sequencial em um conjunto de funções coesas e reutilizáveis.
  • Organizar o código em módulos simples, importando funções conforme necessidade.
  • Planejar e executar testes simples de funções (dry run e impressão de resultados).

Competências e Habilidades

  • Raciocínio lógico e decomposição de problemas em subproblemas.
  • Uso de funções para reuso, legibilidade e manutenção.
  • Baixo acoplamento e alta coesão ao modularizar soluções.
  • Testes simples e verificação de correção de componentes.
  • Documentação breve (docstrings) e nomes significativos.

Plano de Aula (Capítulo 14)

Componentes: Programação Aplicada e Lógica (PRAL) — Capítulo 14: Funções e Modularização

Objetivos: introduzir definição de funções, parâmetros, retorno e escopo; refatorar um programa anterior em funções puras; organizar o código em módulos simples e testar as funções.

Pré-requisitos: capítulos 05–13 (Python/Thonny, E/S, operadores, condicionais, laços, listas, tuplas e dicionários).

Recursos: Thonny IDE; Python 3.x; exercícios do aluno dos capítulos anteriores; material de apoio.

Estratégia didática (100–120 min):

  1. Exposição dialogada (20 min): por que funções? reuso, coesão, escopo, assinatura e retorno.
  2. Exemplos guiados (25 min): criar 3 funções puras (cálculo, validação e formatação) e testar.
  3. Refatoração prática (35 min): escolher um script anterior (ex.: lista de tarefas ou conversor) e extrair funções.
  4. Modularização (10–15 min): separar em dois arquivos .py; importar e executar.
  5. Fechamento (10 min): checklist, quiz e atividades sugeridas.

Avaliação formativa: observação do passo a passo, testes de funções, clareza dos nomes e docstrings.

Parte Teórica (explicação do conteúdo)

1) Por que usar funções?

Funções são blocos nomeados de código que executam uma tarefa específica. Elas ajudam a dividir um problema em partes menores (decomposição), facilitam o reuso e tornam o programa mais legível e testável. Em vez de repetir o mesmo trecho várias vezes, escrevemos uma função e a chamamos quando necessário.

Ao separar responsabilidades, diminuímos o acoplamento (dependências fortes entre partes do código) e aumentamos a coesão (cada parte faz bem uma coisa). Isso simplifica manutenção e correção de erros.

Onde vou aplicar isso no passo a passo? Vamos extrair funções de um script anterior (cálculo, validação e formatação) e comprovar reuso, clareza e testes independentes.

2) Definição, parâmetros e retorno

No Python, definimos uma função com def, especificando nome, parâmetros (opcionais) e um return (opcional). Parâmetros são dados de entrada; o retorno é o resultado para uso posterior.

def soma(a, b):
    """Retorna a soma de a e b."""
    resultado = a + b
    return resultado

total = soma(2, 3)  # total = 5
print(total)

Funções podem ter parâmetros com valor padrão, tornando-os opcionais na chamada.

def potencia(base, expoente=2):
    return base ** expoente

print(potencia(3))     # 9 (usa expoente padrão 2)
print(potencia(3, 3))  # 27

Onde vou aplicar isso no passo a passo? Criaremos funções com 0, 1 e 2+ parâmetros (incluindo valores padrão) e retornos claros para compor o programa principal.

3) Escopo de variáveis (local vs. global)

Variáveis criadas dentro de uma função têm escopo local: só existem dentro dela. Evite modificar variáveis globais dentro das funções; prefira retornar valores. Isso diminui efeitos colaterais e facilita testes.

mensagem_global = "Bem-vindo"

def gera_saudacao(nome):
    # nome e saudacao são locais
    saudacao = f"{mensagem_global}, {nome}!"
    return saudacao

print(gera_saudacao("Ana"))

Se for realmente necessário escrever em uma variável global, existe a palavra-chave global, mas seu uso é desaconselhado em projetos educacionais iniciais por dificultar testes e manutenção.

Onde vou aplicar isso no passo a passo? Evitaremos variáveis globais, retornando resultados e passando dados como parâmetros.

4) Funções puras e efeitos colaterais

Funções puras produzem o mesmo resultado para as mesmas entradas e não alteram estados externos (sem ler/escrever variáveis globais, arquivos, etc.). Isso facilita testes e previsibilidade.

# Função pura
def calcula_imc(peso, altura):
    return peso / (altura ** 2)

# Função com efeito colateral (ex.: print e input são efeitos visíveis)
def ler_peso_usuario():
    valor = float(input("Peso: "))
    return valor

Não significa que nunca usaremos E/S nas funções, mas separar a lógica pura da E/S torna o código mais limpo. Ex.: uma função pura de cálculo e outra para entrada/saída.

Onde vou aplicar isso no passo a passo? Separaremos funções de cálculo/validação (puras) das de interação (E/S) para refatorar um programa anterior.

5) Documentação (docstrings) e nomes significativos

Docstrings descrevem o que a função faz, parâmetros e retorno. Use nomes que indiquem claramente a responsabilidade da função. Isso melhora a leitura e a manutenção por você e por colegas.

def classifica_imc(imc):
    """Classifica o IMC conforme faixas padronizadas.
    Parâmetros:
      imc (float): índice de massa corporal
    Retorna:
      str: rótulo da classificação
    """
    if imc < 18.5:
        return "Abaixo do peso"
    elif imc < 25:
        return "Peso normal"
    elif imc < 30:
        return "Sobrepeso"
    else:
        return "Obesidade"

Onde vou aplicar isso no passo a passo? Escreveremos docstrings curtas em todas as funções criadas.

6) Modularização: organizando em múltiplos arquivos

Módulos são arquivos .py que podem ser importados. Organize funções relacionadas em um módulo e use import no script principal. Isso melhora a manutenibilidade e permite reuso em outros projetos.

# arquivo: util_calculos.py
def media(numeros):
    """Retorna a média de uma lista de floats."""
    return sum(numeros) / len(numeros)

# arquivo: app.py
from util_calculos import media

print(media([7.5, 8.0, 9.0]))

Onde vou aplicar isso no passo a passo? Criaremos um módulo com funções puras e um script principal que importa e usa essas funções.

7) Testes simples de funções

Antes de integrar, teste funções isoladamente: chame a função com entradas de exemplo e confira o retorno. Você pode usar prints temporários ou um bloco if __name__ == "__main__": no módulo para rodar testes rápidos.

# dentro de util_calculos.py
def soma(a, b):
    return a + b

if __name__ == "__main__":
    # testes rápidos
    print("Teste soma(2, 3) == 5:", soma(2, 3) == 5)

Onde vou aplicar isso no passo a passo? Validaremos as funções com entradas típicas e casos-limite (ex.: listas vazias, zeros, valores extremos).

Passo a Passo — Refatorando um programa com funções e módulos

Objetivo desta etapa:

Transformar um script sequencial (por exemplo, “Lista de Tarefas” do Capítulo 12 ou “Contador de Vogais” do Capítulo 11) em um programa modular com funções puras e um módulo utilitário, mantendo a mesma funcionalidade com melhor organização e testes.


Etapa 1 — Escolher o programa base e listar responsabilidades

Escolha um programa que você já fez. Exemplo aqui: “Lista de Tarefas” (adicionar, listar, remover por índice). Liste responsabilidades separáveis:

  • Validar entrada (índices, strings vazias).
  • Adicionar tarefa.
  • Remover tarefa.
  • Listar tarefas formatadas.
  • Interagir com o usuário (menu, input, print).
Dica: Separe lógica de negócio (pura) da E/S. Funções puras recebem dados e retornam resultados, sem usar input() ou print().

Etapa 2 — Criar funções puras de lógica

Crie um arquivo novo chamado todo_utils.py com funções de manipulação da lista de tarefas.

# arquivo: todo_utils.py

def validar_titulo(titulo):
    """Retorna True se o título for não vazio após strip()."""
    return isinstance(titulo, str) and len(titulo.strip()) > 0

def adicionar_tarefa(lista, titulo):
    """Retorna nova lista com a tarefa adicionada (imutável)."""
    if not validar_titulo(titulo):
        return lista  # sem efeito se inválido
    # retorna cópia com novo item
    return lista + [titulo.strip()]

def remover_tarefa_por_indice(lista, indice):
    """Retorna nova lista com item removido se o índice for válido; caso contrário, retorna a lista original."""
    if not isinstance(indice, int) or indice < 0 or indice >= len(lista):
        return lista
    return [t for i, t in enumerate(lista) if i != indice]

def formatar_lista(lista):
    """Retorna uma string formatada da lista de tarefas."""
    if not lista:
        return "Nenhuma tarefa."
    linhas = [f"[{i}] {t}" for i, t in enumerate(lista)]
    return "\n".join(linhas)

if __name__ == "__main__":
    # Testes rápidos
    base = []
    base = adicionar_tarefa(base, " Estudar funções ")
    base = adicionar_tarefa(base, "")
    print(formatar_lista(base))
    base = remover_tarefa_por_indice(base, 0)
    print(formatar_lista(base))

Observe que estas funções não fazem print nem input. São fáceis de testar.

Etapa 3 — Criar o aplicativo principal com E/S

No arquivo app_todo.py, importe e use as funções. Este arquivo cuida da interação com o usuário.

# arquivo: app_todo.py
from todo_utils import (
    adicionar_tarefa,
    remover_tarefa_por_indice,
    formatar_lista,
)

def menu():
    print("\n=== Lista de Tarefas ===")
    print("[1] Adicionar")
    print("[2] Remover por índice")
    print("[3] Listar")
    print("[0] Sair")

def ler_opcao():
    try:
        return int(input("Opção: "))
    except ValueError:
        return -1

def main():
    tarefas = []
    while True:
        menu()
        opc = ler_opcao()

        if opc == 1:
            titulo = input("Título da tarefa: ")
            tarefas = adicionar_tarefa(tarefas, titulo)
            print("OK: tarefa processada.")
        elif opc == 2:
            try:
                idx = int(input("Índice para remover: "))
            except ValueError:
                idx = -1
            tarefas = remover_tarefa_por_indice(tarefas, idx)
            print("OK: remoção processada.")
        elif opc == 3:
            print("\n" + formatar_lista(tarefas))
        elif opc == 0:
            print("Encerrando...")
            break
        else:
            print("Opção inválida.")

if __name__ == "__main__":
    main()

Aqui, a lógica de menu e E/S está separada da lógica de listas (pura), tornando o código modular.

Etapa 4 — Testes e casos-limite

Teste manualmente e por chamadas diretas em um console do Thonny:

>>> from todo_utils import adicionar_tarefa, remover_tarefa_por_indice, formatar_lista
>>> lista = []
>>> formatar_lista(lista)
'Nenhuma tarefa.'
>>> lista = adicionar_tarefa(lista, "Ler documentação")
>>> formatar_lista(lista)
'[0] Ler documentação'
>>> lista = remover_tarefa_por_indice(lista, 5)  # índice inválido
>>> formatar_lista(lista)
'[0] Ler documentação'

Casos-limite: título vazio, índice negativo, lista vazia. Tudo deve se comportar sem erros.

Etapa 5 — Alternativa: refatorando “Contador de Vogais”

Se preferir, use o programa do Capítulo 11. Separe funções puras de contagem e de normalização:

# arquivo: texto_utils.py
def normalizar(frase):
    """Retorna frase em minúsculas sem espaços extras nas pontas."""
    return frase.strip().lower()

def contar_vogais(frase):
    """Conta vogais na frase (a, e, i, o, u)."""
    vogais = set("aeiou")
    return sum(1 for ch in frase if ch in vogais)

if __name__ == "__main__":
    print(contar_vogais(normalizar(" Olá Mundo ")))  # 4

E o script principal apenas faz E/S e chama essas funções:

# arquivo: app_texto.py
from texto_utils import normalizar, contar_vogais

def main():
    frase = input("Digite uma frase: ")
    frase = normalizar(frase)
    total = contar_vogais(frase)
    print(f"Vogais: {total}")

if __name__ == "__main__":
    main()
