Projeto Integrador 1 (B1) — Plano de Laboratório Padronizado

No suporte de TI, o maior inimigo é o improviso. Antes de instalar e mexer no Windows, você vai entregar um plano padronizado do laboratório (baseline) para que qualquer pessoa consiga reproduzir seu ambiente e para que você tenha um ponto de retorno seguro. Este PI consolida os Capítulos 01–04 e prepara o Capítulo 05 (instalação).

Host/VM e recursos Edição do Windows Rede (NAT) e nome padrão Disco e partições (planejamento) Snapshot (ponto limpo) Checklist de validação

Objetivos e pré‑requisitos

Objetivos de aprendizagem

  • Planejar um laboratório Windows com padrões (nomes, pastas e versões).
  • Definir um baseline (especificações e decisões) para reproduzir o ambiente.
  • Estabelecer um ponto de retorno seguro (snapshot/backup) antes das práticas.
  • Entregar um pacote com documentação + checklist + evidências mínimas.

Pré‑requisitos

  • Cap. 01–02: conceitos de sistema operacional e componentes.
  • Cap. 03: virtualização (host/guest/snapshot).
  • Cap. 04: versões/edições do Windows e planejamento para instalação.
Onde vou aplicar isso: esse plano será usado como referência em todos os capítulos práticos seguintes.

Conceitos essenciais (e onde vou aplicar isso)

Baseline (linha de base)

Baseline é a descrição do seu ambiente em um “estado conhecido e bom”: versão, recursos, configurações principais. Onde vou aplicar isso: você vai escrever a ficha do ambiente (host, VM, Windows, rede e disco) no relatório.

Padronização

Padronizar é reduzir variação (nomes, pastas, versões), facilitando suporte e correção. Onde vou aplicar isso: você vai definir um padrão de nomes e uma estrutura de pastas para evidências.

Evidência

Evidência é qualquer prova do que foi feito (print, log, arquivo). Sem evidência, não há auditoria. Onde vou aplicar isso: você vai anexar pelo menos 2 prints e um arquivo de checklist preenchido.

Snapshot / Ponto de retorno

Snapshot (na VM) é um ponto de retorno do estado da máquina. Não substitui backup de dados, mas evita retrabalho no laboratório. Onde vou aplicar isso: criar snapshot “ponto limpo” antes do Cap. 05.

Resumo do método: planejar → documentar baseline → padronizar → criar ponto de retorno → validar com checklist.

Entregável e critérios mínimos

Você vai entregar

  • Relatório (PDF ou TXT): plano do laboratório + decisões justificadas.
  • Checklist de validação (8+ itens) preenchido.
  • Evidências: pelo menos 2 prints (ex.: configurações da VM + tela de winver ou equivalente).
  • Estrutura de pastas padronizada para o curso.

Critérios mínimos (para não perder ponto)

  • Escolha e justificativa da edição (ex.: Pro para laboratório técnico).
  • Estratégia de conta (preferência por conta local no laboratório).
  • Disco planejado (tamanho + ideia de C: sistema / D: dados).
  • Rede definida (NAT no laboratório) e nome padrão do ambiente.
  • Ponto de retorno (snapshot se VM) descrito.
Nota prática: neste PI você não precisa instalar ainda — você está preparando e documentando.

Passo a passo para montar e entregar

Siga a ordem para não esquecer nada e para facilitar correção.

Criar a pasta do PI e subpastas

mkdir C:\FGSO\PI_B1
mkdir C:\FGSO\PI_B1\evidencias
mkdir C:\FGSO\PI_B1\evidencias\prints
mkdir C:\FGSO\PI_B1\evidencias\docs

Se você usa D:, pode adaptar para D:\DADOS\FGSO\PI_B1.

Preencher a ficha do ambiente (baseline)

  • Registre dados do host: CPU, RAM, armazenamento.
  • Se usar VM: vCPU, RAM, disco, rede (NAT), nome da VM.
  • Defina a edição do Windows (Home/Pro/etc.) e justifique.
Baseline (exemplo)
- Host: i5 / 16GB / SSD 512GB
- VM: 2 vCPU / 4GB RAM / 60GB disco / NAT
- Windows: 11 Pro (laboratório técnico)
- Nome padrão: FGSO-W11-VM01
- Rede: NAT (acesso internet sem expor serviços)

Planejar conta, disco e segurança

  • Conta: local (por que) e senha mínima.
  • Disco: planeje C: (sistema) e D: (dados/backups) — mesmo que seja criado no Cap. 06.
  • Segurança: rotina de snapshots (antes/depois de práticas).
Onde vou aplicar isso: evita perda de trabalho quando algo dá errado durante instalação e manutenção.

Definir checklist de validação (8+ itens)

  • Crie um arquivo checklist.txt e preencha com pelo menos 8 itens.
echo CHECKLIST PI B1 > C:\FGSO\PI_B1\evidencias\docs\checklist.txt
echo [ ] VM criada com nome padrao >> C:\FGSO\PI_B1\evidencias\docs\checklist.txt
echo [ ] NAT configurado >> C:\FGSO\PI_B1\evidencias\docs\checklist.txt
echo [ ] Disco planejado (C/D) >> C:\FGSO\PI_B1\evidencias\docs\checklist.txt
echo [ ] Snapshot ponto limpo definido >> C:\FGSO\PI_B1\evidencias\docs\checklist.txt

Complete até 8–10 itens (você pode adaptar o modelo do Cap. 04).

Coletar evidências (prints mínimos)

  • Print 1: configurações da VM (RAM/vCPU/disco/rede) ou configurações do PC.
  • Print 2: qualquer evidência de versão/planejamento (ex.: ISO selecionada, edição escolhida, etc.).
  • Salve com nomes padronizados: 01_vm_config.png, 02_edicao_plano.png.

Escrever o relatório final e empacotar

  • Crie relatorio_PI_B1.txt (ou PDF) em docs.
  • Inclua: baseline, decisões (edição/conta/disco/rede), checklist e como você vai usar snapshots.
  • (Opcional) Compacte em ZIP para enviar:
Compress-Archive -Path "C:\FGSO\PI_B1\*" -DestinationPath "C:\FGSO\PI_B1.zip" -Force

Rubrica de avaliação

Critério Básico Bom Excelente
Baseline Incompleto Completo e claro Detalhado e reproduzível por terceiros
Padronização Sem padrão Nomes e pastas padronizados Padrão + justificativa + organização exemplar
Checklist < 8 itens 8–10 itens coerentes 10+ itens com critérios de validação claros
Evidências 1 print solto 2+ prints + checklist Evidências bem nomeadas + relatório bem escrito
Segurança (ponto de retorno) Não menciona Menciona snapshot Define rotina (antes/depois) e justificativa

Atividades práticas (2–3) — sem entregar o projeto completo

Atividade 1 — Padrão de nomes

Defina um padrão de nomes para VMs e pastas do curso (ex.: FGSO-W11-VM01). Explique no relatório por que isso ajuda no suporte.

Atividade 2 — Plano de disco

Desenhe (texto) como ficará seu disco: C: sistema, D: dados/backups. Defina tamanho mínimo e por quê.

Atividade 3 — Checklist melhorado

Transforme seu checklist em 12 itens, adicionando critérios objetivos (ex.: “rede NAT testada com ping”).
