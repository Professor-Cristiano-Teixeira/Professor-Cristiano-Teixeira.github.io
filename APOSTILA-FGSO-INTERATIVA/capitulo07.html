Capítulo 07 — Ferramentas de Administração e Manutenção do Windows

Neste capítulo você aprende a usar as principais ferramentas nativas do Windows para administrar, diagnosticar e manter o sistema. A proposta é simples: em vez de “clicar sem entender”, você vai aprender qual ferramenta usar em cada tipo de problema e vai praticar um roteiro completo de checagem (processos, serviços, logs, desempenho, confiabilidade, drivers e segurança).

Task Manager Services Event Viewer PerfMon/ResMon Device Manager msconfig Windows Security

Objetivos e pré‑requisitos

Ao final deste capítulo você será capaz de:

  • Escolher a ferramenta certa para cada cenário: lentidão, travamento, erro, driver, boot, segurança.
  • Usar: Configurações, Painel de Controle, Task Manager, Services, Event Viewer, Reliability Monitor, PerfMon, Resource Monitor, Device Manager, Task Scheduler, msconfig e Regedit (com cuidado).
  • Coletar evidências: prints, export de logs e informações do sistema.
  • Executar uma rotina básica de manutenção sem depender do professor.

Pré‑requisitos

  • Windows 11 instalado e funcionando (Cap. 05).
  • Disco e partições organizadas (Cap. 06) — recomendado.
  • Conta local com permissões administrativas (laboratório).
Importante: neste capítulo você vai observar e diagnosticar. Evite mudanças agressivas em serviços e registro.

Mapa mental: qual ferramenta usar?

Use este mapa como “GPS” de suporte. Quando surgir um problema, você começa por aqui.

Lentidão / travamento

  • Task Manager (CPU/RAM/Disco)
  • Resource Monitor (detalhe)
  • PerfMon (contadores)
  • Reliability Monitor (histórico)

Erros e falhas

  • Event Viewer (logs)
  • Reliability Monitor (linha do tempo)
  • Windows Update (falhas de atualização)

Hardware / drivers

  • Device Manager
  • System Information (msinfo32)
  • Windows Security (isolamento/driver bloqueado)

Boot e inicialização

  • Task Manager → Startup
  • msconfig (modo seguro / boot)
  • Task Scheduler (tarefas iniciando)

Rede e internet (básico)

  • Configurações (Wi‑Fi/Ethernet)
  • Event Viewer (eventos de rede)
  • Windows Security (firewall)

Segurança

  • Windows Security
  • Firewall / proteção contra vírus
  • Windows Update (correções)
Como usar: comece com a ferramenta mais simples (Task Manager / Reliability Monitor) e aprofunde (Event Viewer / PerfMon) se necessário.

Teoria: ferramentas de administração e manutenção (com “onde vou aplicar isso”)

Configurações x Painel de Controle settings vs cpl

Conceito: O Windows tem duas “portas” principais de configuração. Configurações é a interface moderna; o Painel de Controle é a interface clássica (ainda muito usada).

Onde vou aplicar: você vai abrir os dois e localizar ajustes de sistema, rede, atualização e programas.

Gerenciador de Tarefas (Task Manager) processos • desempenho

Conceito: mostra processos, consumo de CPU/RAM/Disco/Rede e permite encerrar tarefas travadas. Também controla apps de inicialização.

Onde vou aplicar: você vai identificar o que está consumindo recursos e registrar uma evidência (print/relatório simples).

Serviços (services.msc) serviços em 2º plano

Conceito: serviços são programas que rodam em segundo plano (ex.: update, impressão, rede). Eles podem iniciar automaticamente ou manualmente.

Onde vou aplicar: você vai localizar serviços críticos e entender status (Executando/Parado) sem desativar aleatoriamente.

Visualizador de Eventos (eventvwr.msc) logs

Conceito: o Windows registra eventos (informações, avisos e erros). Log é “o histórico do que aconteceu”.

Onde vou aplicar: você vai filtrar erros recentes e exportar um log para evidência.

Monitor de Confiabilidade (Reliability Monitor) linha do tempo

Conceito: apresenta uma linha do tempo com falhas de aplicativos, falhas do Windows e instalações/atualizações.

Onde vou aplicar: você vai localizar “picos de instabilidade” e associar com eventos/atualizações.

PerfMon e Resource Monitor contadores e detalhe

Conceito: PerfMon mede contadores de desempenho (CPU, memória, disco). Resource Monitor mostra detalhes de processos e uso por recurso.

Onde vou aplicar: você vai abrir os dois e identificar gargalo (CPU 100%, disco 100%, RAM pressionada).

Gerenciador de Dispositivos (devmgmt.msc) drivers

Conceito: lista hardware e drivers. Ícones de alerta indicam driver ausente ou com problema.

Onde vou aplicar: você vai verificar se há dispositivo com aviso e registrar propriedades do driver.

msconfig e Regedit (com cuidado) config avançada

Conceito: msconfig ajuda em diagnóstico de boot/inicialização. Regedit altera o Registro do Windows (configurações internas). O Registro pode quebrar o sistema se alterado sem método.

Onde vou aplicar: você vai abrir e reconhecer a ferramenta, mas evitar alterações profundas. Em laboratório, alterações só com backup/snapshot.

Agendador de Tarefas (taskschd.msc) automação nativa

Conceito: o Windows agenda tarefas automáticas (limpeza, update, manutenção) e também permite agendar scripts e ações.

Onde vou aplicar: você vai localizar tarefas que rodam no logon e entender por que algumas coisas iniciam sozinhas.

Windows Security e Windows Update segurança e correções

Conceito: segurança moderna depende de correções (updates), proteção contra malware, firewall e configurações de proteção.

Onde vou aplicar: você vai checar status do Defender, firewall e atualizações pendentes.

Passo a passo prático (roteiro completo de administração e manutenção)

Este roteiro é pensado para você executar sozinho, gerando evidências. Ao final, você terá um “pacote” de diagnóstico: prints, anotações e um log exportado.

Antes de começar: crie um snapshot 07-antes-ferramentas (se estiver em VM). Em máquina real, evite mudanças em serviços/registro.

Identificar versão do Windows e nome do PC

  • Abra Executar: Win + R → digite winver.
  • Anote a versão/compilação.
  • Vá em Configurações → Sistema → Sobre e registre o nome do dispositivo.

Task Manager: identificar consumo (CPU/RAM/Disco)

  • Abra: Ctrl + Shift + Esc (ou taskmgr).
  • Na aba Processos, ordene por CPU e depois por Memória.
  • Tire um print (ou anote) dos 3 processos que mais consomem.
  • Na aba Inicializar (Startup), identifique apps habilitados.
Onde aplicar: lentidão e travamentos quase sempre começam aqui.

Services: entender serviços essenciais (sem desativar aleatoriamente)

  • Abra: services.msc.
  • Localize e observe (status e tipo de inicialização):
    • Windows Update
    • Serviços de Rede (variam)
    • Spooler de Impressão (se existir)
  • Escolha 1 serviço e apenas abra Propriedades para ver descrição e dependências.
Regra do laboratório: só pare/inicie serviços quando você souber o impacto e tiver snapshot.

Event Viewer: localizar erros recentes e exportar log

  • Abra: eventvwr.msc.
  • Vá em Logs do Windows → Sistema.
  • À direita, clique em Filtrar Log Atual... e marque Crítico e Erro.
  • Anote 1 erro (ID do evento, fonte e descrição curta).
  • Exportar: Salvar todos os eventos como... (formato .evtx) e salve em C:\FGSO\logs (crie a pasta se necessário).
Onde aplicar: logs ajudam a provar o que aconteceu, quando e qual componente falhou.

Reliability Monitor: associar falhas na linha do tempo

  • Abra Executar: Win+R → digite perfmon /rel.
  • Observe a linha do tempo e procure falhas (X vermelhos).
  • Clique em um dia com falha e leia o que ocorreu.
  • Anote: nome do aplicativo/erro e data.

PerfMon e Resource Monitor: encontrar gargalo

  • Abra perfmon e veja o gráfico básico (Monitor de Desempenho).
  • Abra resmon e analise CPU, Memória e Disco.
  • Responda: o gargalo está mais em CPU, RAM ou Disco?
CPU alta constante → processo pesado, antivírus, atualização, VM sem recursos
Memória alta + paginação → pouca RAM / muitos apps
Disco 100% → update, indexação, antivírus, pouca RAM (swap)

Device Manager: verificar drivers

  • Abra: devmgmt.msc.
  • Procure ícones de alerta (triângulo amarelo).
  • Abra Propriedades de um dispositivo e veja a aba Driver (versão e fornecedor).
  • Anote 1 informação do driver (data/versão) como evidência.

Task Scheduler: identificar tarefas automáticas

  • Abra: taskschd.msc.
  • Navegue em Biblioteca do Agendador e procure tarefas com gatilho “No logon”.
  • Abra Propriedades de uma tarefa e veja gatilhos/ações.
  • Anote: nome da tarefa e o que ela executa.

msconfig (diagnóstico de inicialização) — apenas reconhecimento

  • Abra: msconfig.
  • Veja as abas: Geral, Inicialização, Serviços, Inicialização de Programas (pode redirecionar ao Task Manager).
  • Não altere configurações sem orientação/snapshot.
Regra: msconfig é poderoso. Mudanças erradas podem impedir o boot.

Windows Security e Windows Update: checagem de base

  • Abra Segurança do Windows e verifique status de proteção.
  • Abra Windows Update e procure atualizações pendentes.
  • Anote: status “Atualizado” ou “Pendente”.

Organizar evidências (pasta FGSO)

  • Crie C:\FGSO\cap07.
  • Salve: prints, o log .evtx exportado e um texto resumo.txt com suas anotações.
  • Seu resumo deve conter: 1 erro do Event Viewer, 1 falha do Reliability Monitor e 1 gargalo (CPU/RAM/Disco).

Rotina de manutenção (check rápido para usar sempre)

Use como rotina semanal/bimestral. Isso cria hábito de suporte profissional.

Rotina semanal (5–10 min)

  • Windows Update: pendências?
  • Task Manager: CPU/RAM anormais?
  • Reliability Monitor: falhas recentes?
  • Armazenamento: espaço livre suficiente?

Rotina mensal (15–30 min)

  • Event Viewer: erros críticos repetidos?
  • Device Manager: drivers com alerta?
  • Startup apps: algo desnecessário iniciando?
  • Backup/snapshot: ponto de retorno atualizado?
Onde vou aplicar isso: no Cap. 08 (manutenção preventiva) você vai consolidar essa rotina com checklists e boas práticas.

Atividades práticas (2–3) — para você desenvolver

Atividade 1 — Relatório de saúde do sistema

Crie um relatório (1 página) com: top 5 processos, 3 erros do Event Viewer, 2 falhas do Reliability Monitor e uma conclusão.

Atividade 2 — Cenário simulado

Simule “lentidão”: abra vários apps e observe CPU/RAM/disco. Depois explique qual recurso virou gargalo e por quê.

Atividade 3 — Tarefas e inicialização

Liste 5 itens de inicialização e 3 tarefas do Agendador que rodam no logon. Explique qual pode impactar o boot.
