Capítulo 12 — Projeto Integrador (3º Bimestre): Playbook de Suporte e Manutenção (Entrega)

Este capítulo é o fechamento do 3º bimestre com uma entrega profissional: um Playbook de Suporte e Manutenção consolidando tudo que você praticou nos capítulos anteriores. Aqui a teoria é propositalmente curta. O objetivo é te guiar com muito suporte na criação e entrega: estrutura, SOPs, evidências, modelo e rubrica.

Preventiva (Cap. 08) Admin (Cap. 07) Proc/Serv (Cap. 09) Desempenho (Cap. 10) Backup/Restore (Cap. 11) Entrega PI (B3)

Objetivos e pré‑requisitos

Ao final deste capítulo você será capaz de:

  • Produzir um Playbook claro, repetível e auditável (com evidências).
  • Organizar rotinas de manutenção preventiva e corretiva.
  • Documentar GUI + CLI (CMD/PowerShell) nos procedimentos.
  • Empacotar e entregar: PDF + evidências + README + ZIP.

Pré‑requisitos

  • Capítulos 07–11 concluídos (principalmente 08–11).
  • Pasta de trabalho organizada (C:\FGSO ou D:\DADOS\FGSO).
  • Se possível, snapshot “ponto limpo” (Cap. 08/11) para testar rotinas com segurança.
Regra do capítulo: evidência antes → ação → evidência depois (validação).

Agenda (curta): Criptografia e BitLocker

Criptografia protege dados tornando-os ilegíveis sem a chave. No Windows, o BitLocker (ou “Criptografia de dispositivo”) pode criptografar o disco para reduzir risco de vazamento em perda/roubo do equipamento. Onde vou aplicar isso: no Playbook, como um item de segurança (checagem de status e orientação sobre a chave de recuperação).

O que o aluno precisa saber (mínimo)

  • BitLocker protege a unidade (ex.: C:) com criptografia.
  • Sem a chave de recuperação, você pode perder acesso aos dados.
  • Em VM, pode não refletir TPM real; use como aprendizado.

Checagem rápida (sem “mexer”)

Use apenas para consulta e evidência (quando disponível):

manage-bde -status
manage-bde -status C:
Segurança: não exponha chaves reais em prints/documentos públicos.

PI (B3) — O que entregar (visão geral)

Seu entregável é um Playbook de Suporte e Manutenção do Windows. Pense nele como um manual que outra pessoa consegue executar sem precisar falar com você. Ele deve consolidar: gerenciamento, manutenção preventiva, manutenção corretiva e backup/restore.

Entrega obrigatória (pack)

  1. Playbook em PDF (recomendado) — com índice e versão.
  2. Evidências: prints + logs + relatórios (organizados por pasta).
  3. README: explica o que tem em cada pasta e como avaliar.
  4. ZIP com tudo (opcional, mas recomendado).

O que o Playbook precisa conter (mínimo)

  • Rotina preventiva: semanal + mensal (Cap. 08 + 07).
  • 3 SOPs corretivos completos (Cap. 09–10–08).
  • Backup/Restore com teste de restauração (Cap. 11).
  • Um item de segurança (BitLocker: checar status + orientação de chave).
  • Fluxos de decisão (Windows inicia? gargalo?).
Meta de qualidade: seu playbook deve ser “executável” — não só descritivo. Passos, comandos, evidências e validação.

Estrutura do Playbook (modelo pronto — copie e preencha)

Copie este modelo e preencha com o seu laboratório. Ele já está alinhado com o que será avaliado.

Modelo completo (Playbook) copiar/colar 
TÍTULO: Playbook de Suporte e Manutenção — Windows 11 (FGSO)
Versão: 1.0   Data: __/__/____   Autor: __________

0) Sumário

1) Objetivo
- Por que este playbook existe? (padronizar suporte/manutenção)

2) Ambiente (Baseline)
- Host: CPU/RAM/SSD
- VM (se houver): RAM/vCPU/Disco/Rede
- Windows: edição/build (winver)
- Pastas padrão:
  - Evidências: C:\FGSO\PI_B3_Playbook\evidencias
  - Backups: D:\DADOS\Backups (ou C:\FGSO\Backups)

3) Ferramentas
- GUI: Task Manager, services.msc, eventvwr.msc, resmon, perfmon, taskschd.msc, sysdm.cpl
- CMD: tasklist/taskkill, sc/net, schtasks, ipconfig/ping/tracert/netstat, sfc/dism/chkdsk, robocopy
- PowerShell: Get-Process/Stop-Process, Get-Service/Set-Service, Get-Counter, Get-WinEvent, Compress-Archive/Get-FileHash

4) Rotina Preventiva (SOP-PRV)
4.1 Semanal (5–10 min)
- Windows Update → reiniciar → validar
- Windows Security → verificação rápida
- Storage Sense/temporários → liberar espaço
- Evidências: print Update + print Security

4.2 Mensal (15–30 min)
- Reliability (perfmon /rel) → anotar falhas
- Event Viewer → exportar 1 log (.evtx)
- Startup apps/tarefas → revisar itens não essenciais
- Evidências: print Reliability + eventos_sistema.evtx

5) Procedimentos Corretivos (SOP-COR)
(Use sempre o padrão: Sintoma → Diagnóstico (GUI+CLI) → Evidência → Ação mínima → Validação → Rollback)

SOP-COR-01: “PC lento” (gargalo: CPU/RAM/Disco/Rede)
SOP-COR-02: “App travado” (processo)
SOP-COR-03: “Serviço travado” (ex.: spooler)
SOP-COR-04: “Integridade do sistema” (SFC → DISM → SFC)
SOP-COR-05: “Pouco espaço em disco” (Storage → limpeza segura)

6) Backup e Restore (SOP-BKP)
- Estratégia 3-2-1 (adaptada)
- robocopy com log
- ZIP + hash
- TESTE de restauração documentado

7) Segurança (agenda mínima)
- BitLocker: checar status (manage-bde -status)
- Chave de recuperação: onde guardaria? quem acessa?

8) Fluxos de decisão
- Windows inicia? (Sim/Não) → WinRE/Restore/SFC
- Gargalo? (CPU/RAM/Disco/Rede) → evidências → ação mínima

9) Changelog
- v1.0 criação

10) Anexos
- prints/ logs/ relatorios/
Como usar: copie o modelo e preencha. Depois escreva os SOPs com passos e evidências do seu laboratório.

Passo a passo para criar e entregar (com muito suporte)

Se você seguir esta ordem, você não se perde e não esquece evidências.

Montar a estrutura da entrega (pastas)

  • Crie a pasta do PI e subpastas:
mkdir C:\FGSO\PI_B3_Playbook
mkdir C:\FGSO\PI_B3_Playbook\playbook
mkdir C:\FGSO\PI_B3_Playbook\evidencias
mkdir C:\FGSO\PI_B3_Playbook\evidencias\prints
mkdir C:\FGSO\PI_B3_Playbook\evidencias\logs
mkdir C:\FGSO\PI_B3_Playbook\evidencias\relatorios
  • Crie um README.txt explicando a estrutura.
echo PI B3 - Playbook (estrutura) > C:\FGSO\PI_B3_Playbook\README.txt

Escrever o Playbook (primeira versão)

  • Abra Word/Docs/Writer e cole o modelo (seção anterior).
  • Preencha o Baseline (host/VM/winver/rede/pastas).
  • Crie um índice (Sumário) com âncoras ou numeração.
  • Salve como Playbook_FGSO_W11_v1.0.docx (ou similar).
Critério: outra pessoa consegue entender o ambiente (sem te perguntar)? Se sim, ok.

Completar a Rotina Preventiva (semanal + mensal)

  • Escreva a rotina semanal (Update/Security/Storage) com: passos GUI + evidências.
  • Escreva a rotina mensal (Reliability/Event Viewer/Startup) com: passos GUI + evidências.
  • Defina: frequência (ex.: semanal toda sexta; mensal 1º dia útil).
Obrigatório: ao menos 2 prints (Update + Security) e 1 log .evtx do mensal.

Escrever SOPs corretivos (mínimo 3) com estrutura padrão

  • Escolha 3 SOPs: PC lento, App travado, Serviço travado (recomendado).
  • Para cada SOP, preencha:
    • Sintoma
    • Diagnóstico GUI
    • Diagnóstico CLI (CMD e/ou PowerShell)
    • Evidências (o que salvar)
    • Ação mínima
    • Validação (antes/depois)
    • Rollback (como desfazer)

Backup/Restore: documentar e provar (teste de restore)

  • Inclua 3-2-1 adaptado (pasta de backup + zip + evidência).
  • Inclua comando robocopy e caminho do log.
  • Inclua ZIP + hash (opcional, recomendado).
  • Obrigatório: descreva o teste de restauração (apagou/alterou e recuperou).
Regra do suporte: backup sem restore testado não vale.

Segurança (agenda): adicionar seção mínima do BitLocker

  • Adicione no Playbook um item curto “Segurança: BitLocker/Criptografia”.
  • Inclua: como checar status e orientação de chave de recuperação (sem expor segredo).
manage-bde -status

Coletar evidências e organizar (sem bagunça)

  • Crie prints e logs mínimos e salve em:
    • evidencias\prints
    • evidencias\logs
    • evidencias\relatorios
  • Padronize nomes: 01_update.png, 02_security.png, 03_taskmgr.png...
Dica: o avaliador encontra rápido o que precisa? Se sim, você ganhou tempo e pontos.

Exportar PDF e empacotar (entrega final)

  • Exporte o playbook em PDF e salve em playbook.
  • Compacte a pasta toda em ZIP (recomendado):
Compress-Archive -Path "C:\FGSO\PI_B3_Playbook\*" -DestinationPath "C:\FGSO\PI_B3_Playbook.zip" -Force
Checklist final: PDF + evidências + README + ZIP.

SOPs obrigatórios (preventivo e corretivo) — o mínimo para não perder ponto

Preventivo (obrigatório)

  • Semanal: Update + Security + Storage (Cap. 08).
  • Mensal: Reliability + Event Viewer + Startup (Cap. 07/09).
  • Evidências: 2 prints + 1 .evtx.

Corretivo (mínimo 3 SOPs completos)

  • PC lento: gargalo + evidência + ação mínima (Cap. 10).
  • App travado: GUI + CLI (Cap. 09).
  • Serviço travado: services.msc + sc/net (Cap. 09).
  • (Recomendado) Integridade: SFC/DISM/CHKDSK (Cap. 08).
“Cola” de comandos para SOPs (GUI + CLI) pronto

Processos/Serviços

tasklist
taskkill /IM notepad.exe
sc query spooler
net stop spooler
net start spooler

Integridade/Disco

sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
chkdsk C: /scan

Desempenho/Rede

resmon
perfmon
perfmon /rel
ipconfig /all
ping 8.8.8.8
tracert www.microsoft.com
netstat -ano

Backup/Segurança

robocopy "C:\Users\%USERNAME%\Documents" "D:\DADOS\Backups\Documents" /E /R:2 /W:2 /LOG+:"D:\DADOS\Backups\logs\robocopy_docs.log"
manage-bde -status

Evidências: o que coletar e como organizar

Evidência é o que prova execução e validação. Sem evidência, vira “só texto”.

Prints (mínimo 6)

  • Update (status)
  • Security (status/scan)
  • Task Manager (processos/desempenho)
  • Resource Monitor (disco ou rede)
  • services.msc (serviço + propriedades)
  • Pasta de backup (arquivo presente)

Logs (mínimo 2)

  • 1 arquivo .evtx (Event Viewer)
  • 1 log do robocopy (robocopy_*.log)
  • (Opcional) hash do ZIP

Relatórios (mínimo 2)

  • Relatório de desempenho (Cap. 10)
  • Relatório backup/restore (Cap. 11)
  • (Opcional) checagem BitLocker (status.txt)
Padronização: use prefixo numérico: 01_, 02_… facilita correção.

Rubrica de avaliação (como será corrigido)

Use como “check de qualidade”. Se atender a coluna Excelente, tende a nota alta.

Critério Básico Bom Excelente
Estrutura e clareza Confuso, sem padrão Organizado, completo Índice + fluxos + rollback em todos SOPs
Preventiva Lista sem evidência Semanal/mensal + evidências Critérios de validação e periodicidade clara
Corretiva SOP incompleto ≥3 SOPs completos ≥4 SOPs + evidência antes/depois
Backup/Restore Sem restore testado Restore documentado robocopy+log+zip+hash+restore
Evidências Desorganizado Padrão de pastas e nomes Pack completo + README + ZIP
Agenda (BitLocker) Menciona Checagem de status Checagem + orientação de chave (sem expor segredo)
Meta sugerida: entregar no nível Bom e buscar Excelente em evidências + restore.

Atividades práticas (2–3)

Atividade 1 — SOP “PC lento” completo

Escreva o SOP com 4 caminhos (CPU/RAM/Disco/Rede). Para cada caminho, 2 evidências e 1 ação mínima.

Atividade 2 — Restore comprovado

Escolha um arquivo de teste, altere/apague e restaure via robocopy ou ZIP. Registre prints e descreva no playbook.

Atividade 3 — Padronização de evidências

Renomeie suas evidências com prefixos (01_, 02_...). Explique no README a lógica e como localizar itens na correção.
