Capítulo 16 — Implantação e Provisionamento: Sysprep e DISM (Padronização por Imagem)

Aqui você fecha o 4º bimestre com um tema altamente usado em empresas: padronização e implantação. Em vez de instalar Windows do zero em cada máquina, você cria uma máquina de referência, generaliza com Sysprep e captura/aplica uma imagem WIM com DISM. O resultado é um método mais rápido, mais consistente e mais fácil de auditar.

Imagem WIM OOBE × Audit Mode Sysprep /generalize DISM /Capture-Image DISM /Apply-Image bcdboot

Objetivos e pré‑requisitos

Ao final deste capítulo você será capaz de:

  • Explicar o que é implantação/provisionamento por imagem e por que padroniza suporte.
  • Preparar uma máquina de referência e generalizar com Sysprep.
  • Capturar uma imagem WIM com DISM e aplicar em outro disco/VM.
  • Criar um disco bootável após aplicar imagem (bcdboot).
  • Entregar um pacote do PI (B4) com imagem, scripts e runbook.

Pré‑requisitos

  • Cap. 03 (VM e snapshots), Cap. 05 (instalação), Cap. 08 (manutenção), Cap. 11 (backup).
  • Cap. 13–15 (CMD/PowerShell/scripts) para coletar evidências do processo.
  • Uma VM Windows 11 para servir de referência (recomendado).
Recomendação: faça este capítulo em VM para evitar impacto em máquina real.

Conceitos (simples e aplicáveis)

Implantação x Provisionamento

Implantação é colocar o sistema pronto em uma máquina (ou VM). Provisionamento é preparar e configurar a máquina para uso. Onde vou aplicar isso: ao criar a imagem (referência) e aplicar em um “alvo”, você está implantando e provisionando.

Imagem (WIM) e consistência

Uma imagem WIM é um “pacote” do sistema, capturado de uma instalação pronta. Padronizar por imagem reduz diferença entre máquinas. Onde vou aplicar isso: você vai capturar C: da VM de referência em um arquivo .wim e aplicar no disco de outra VM.

OOBE x Audit Mode

OOBE é a experiência inicial (criar usuário, aceitar termos). Audit Mode permite instalar apps e ajustar antes do usuário. Onde vou aplicar isso: você prepara a referência (pode usar Audit) e depois roda Sysprep para voltar ao OOBE.

Generalização (Sysprep)

Sysprep /generalize remove identificadores específicos (SID, drivers específicos, etc.) para a imagem ser usada em outras máquinas. Onde vou aplicar isso: antes de capturar a imagem, você executa Sysprep com /generalize e /oobe.

Captura e aplicação (DISM)

O DISM captura uma partição para WIM (/Capture-Image) e aplica WIM em uma partição vazia (/Apply-Image). Onde vou aplicar isso: você vai capturar do C: da referência e aplicar em um disco alvo, depois criar boot com bcdboot.

Boas práticas: imagem de referência deve estar limpa (sem arquivos pessoais), atualizada e com apps essenciais (somente o necessário).

Sysprep: quando e como usar

Quando usar

  • Quando você quer transformar uma instalação em imagem padrão.
  • Antes de capturar WIM para usar em outras máquinas/VMs.
  • Quando precisa de consistência em laboratório/sala/empresa.
Onde vou aplicar isso: no passo a passo, você “selará” a VM de referência antes de capturar.

Comando essencial (referência)

Execute na VM de referência (como Admin), depois ela vai desligar.

C:\Windows\System32\Sysprep\Sysprep.exe
# GUI: marcar "Generalize" + "Enter System Out-of-Box Experience (OOBE)" + Shutdown

# Alternativa via linha de comando:
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown
Atenção: não capture a imagem antes do Sysprep (generalize) se o objetivo é reutilizar.
Checklist rápido da máquina de referência (antes do Sysprep) recomendado
  • Windows Update aplicado e reiniciado
  • Apps essenciais instalados (somente o necessário)
  • Sem arquivos pessoais (Downloads/Área de Trabalho)
  • Nome padrão (ex.: FGSO-REF) e anotações de versão
  • Snapshot criado antes do Sysprep (para voltar se algo der errado)

DISM: capturar e aplicar imagem (WIM)

Você vai usar DISM para capturar e aplicar imagem. Em laboratório, o jeito mais simples é: bootar pela ISO do Windows (ambiente de instalação) e abrir o CMD com Shift+F10. Assim você consegue capturar/aplicar sem o Windows estar “usando” a partição.

Comandos principais

REM Capturar imagem (ex.: capturar C: para D:\Images\W11_FGSO.wim)
dism /Capture-Image /ImageFile:D:\Images\W11_FGSO.wim /CaptureDir:C:\ /Name:"W11_FGSO" /Compress:max /CheckIntegrity

REM Aplicar imagem (ex.: aplicar WIM em C: do disco alvo)
dism /Apply-Image /ImageFile:D:\Images\W11_FGSO.wim /Index:1 /ApplyDir:C:\

REM Criar boot (UEFI) após aplicar
bcdboot C:\Windows /s S: /f UEFI

O drive S: acima é a partição EFI (FAT32) montada durante o diskpart.

Onde vou aplicar isso

  • Captura: depois do Sysprep, você captura a partição do Windows da referência.
  • Aplicação: em outra VM/disco, você cria partições e aplica o WIM.
  • Boot: você usa bcdboot para tornar o disco inicializável.
Importante: anote as letras das unidades no WinPE/Setup (elas podem mudar!). Use diskpart + list volume.

Passo a passo (VM): criar imagem e provisionar outra VM

Passo a passo detalhado para Técnico Médio. Faça com calma e registre evidências (prints/logs).

Preparar a VM de referência (REF)

  • Crie/Use uma VM Windows 11 chamada FGSO-REF.
  • Instale Windows 11 e aplique atualizações básicas.
  • Instale apenas o essencial para o laboratório (nada pessoal).
  • Tire um snapshot: REF-pronta-antes-sysprep.
Evidência: print das configurações da VM + print do winver.

Rodar Sysprep na VM de referência

  • Abra Prompt como Admin e execute:
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown
  • A VM vai desligar. Não ligue no Windows normalmente antes da captura (para manter estado selado).
Dica: se precisar voltar, restaure o snapshot e repita.

Adicionar um “disco de imagem” (armazenamento) na VM REF

  • No VirtualBox, adicione um segundo disco (ex.: 40–80GB) para armazenar .wim.
  • Alternativa: usar uma unidade compartilhada/ISO de dados, mas o disco extra é mais simples.
Onde vou aplicar isso: o WIM vai para esse disco (ex.: D: no WinPE).

Bootar pela ISO do Windows e abrir CMD (Shift+F10)

  • Monte a ISO do Windows na VM REF.
  • Inicie pela ISO (tela de instalação).
  • Na primeira tela, pressione Shift + F10 para abrir o CMD.
Objetivo: usar DISM sem o Windows estar em execução.

Identificar letras de unidade (diskpart)

diskpart
list volume
exit
  • Identifique:
    • Partição do Windows da referência (geralmente maior, NTFS)
    • Disco/partição para armazenar imagem (segundo disco)
  • Se necessário, crie pasta de imagens no disco de armazenamento:
mkdir D:\Images

Capturar a imagem WIM (DISM /Capture-Image)

Ajuste as letras: aqui assumimos Windows em C: e disco de imagens em D:.

dism /Capture-Image /ImageFile:D:\Images\W11_FGSO.wim /CaptureDir:C:\ /Name:"W11_FGSO" /Compress:max /CheckIntegrity
  • Ao finalizar, valide que o arquivo existe:
dir D:\Images
Evidência: print do comando finalizado + print do dir mostrando o WIM.

Criar VM alvo (TARGET) e preparar o disco (partições)

  • Crie uma nova VM FGSO-TARGET com um disco vazio.
  • Anexe (como segundo disco) o disco que contém D:\Images\W11_FGSO.wim (ou copie o WIM para ela).
  • Boot pela ISO do Windows e abra CMD (Shift+F10).
  • Use diskpart para criar partições UEFI (EFI + MSR + Windows). Exemplo:
diskpart
list disk
select disk 0
clean
convert gpt

create partition efi size=100
format quick fs=fat32 label="SYSTEM"
assign letter=S

create partition msr size=16

create partition primary
format quick fs=ntfs label="Windows"
assign letter=C

exit
Cuidado: o comando clean apaga o disco selecionado. Confirme o disk 0.

Aplicar a imagem no disco alvo (DISM /Apply-Image)

Ajuste o caminho do WIM (ex.: D: ou E: conforme aparecer no list volume).

dism /Apply-Image /ImageFile:D:\Images\W11_FGSO.wim /Index:1 /ApplyDir:C:\
  • Depois, crie arquivos de boot:
bcdboot C:\Windows /s S: /f UEFI
  • Reinicie e remova a ISO. O Windows deve iniciar em OOBE.
Evidência: print do OOBE iniciando na VM alvo (prova de implantação bem-sucedida).

Validação pós-implantação (o mínimo)

  • Ao iniciar o Windows na VM alvo, confirme:
    • OOBE apareceu (imagem generalizada ok)
    • Versão/build (winver)
    • Apps essenciais estão presentes
  • Registre evidências: 2 prints + 1 relatório curto.
winver
Resultado esperado: você consegue criar uma imagem padrão e implantar em outra VM — base de padronização profissional.

Projeto Integrador (B4) — Entrega incremental (implantação/provisionamento)

O PI do 4º bimestre consolida o tema de implantação: você vai entregar um Pacote de Imagem e Runbook. O foco é padronização e repetibilidade (como um mini “deployment kit”).

O que entregar (mínimo)

  • Imagem WIM capturada: W11_FGSO.wim (ou nome equivalente).
  • Runbook (PDF/TXT): passo a passo de Sysprep + DISM + bcdboot.
  • Scripts (opcional recomendado):
    • Um .bat com comandos de captura (comentados)
    • Um .bat com comandos de aplicação (comentados)
  • Evidências: prints do capture/apply + OOBE na VM alvo.
  • Checklist de validação (10+ itens) + README.

Estrutura sugerida (pasta)

C:\FGSO\PI_B4_Implantacao\
  imagem\
    W11_FGSO.wim
  runbook\
    Runbook_Sysprep_DISM.pdf
    checklist_validacao.txt
  scripts\
    capturar_wim.bat
    aplicar_wim.bat
  evidencias\
    prints\
    logs\
  README.txt
Observação: WIM pode ficar grande. Se a plataforma limitar, documente e entregue o runbook + prints + scripts.

Atividades práticas (2–3)

Atividade 1 — Runbook com fluxos

Crie um fluxograma simples: “Captura” e “Aplicação”. Inclua decisões: letras de unidade, UEFI/BIOS e onde salvar o WIM.

Atividade 2 — Scripts comentados

Crie capturar_wim.bat e aplicar_wim.bat com comentários explicando cada etapa e o que pode dar errado.

Atividade 3 — Validação automática

Escreva um PowerShell que verifica se os arquivos esperados existem (WIM, logs, CSVs) e gera um relatório de validação.
