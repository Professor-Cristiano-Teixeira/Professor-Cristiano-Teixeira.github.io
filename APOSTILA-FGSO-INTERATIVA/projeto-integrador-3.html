Projeto Integrador 3 (B3) — Playbook de Suporte e Manutenção (Entrega)

Este PI consolida o 3º bimestre (principalmente Cap. 07–11 + organização do 12): você vai entregar um Playbook de Suporte e Manutenção do Windows — um manual que outra pessoa consegue seguir para executar rotinas preventivas, resolver problemas corretivos e recuperar dados com backup/restore. O avaliador vai olhar: clareza, repetibilidade e evidências.

Admin Tools (Cap. 07) Preventiva (Cap. 08) Proc/Serv (Cap. 09) Desempenho (Cap. 10) Backup/Restore (Cap. 11) Segurança mínima (BitLocker)

Objetivos e pré‑requisitos

Objetivos

  • Transformar seus conteúdos práticos em um playbook executável.
  • Documentar rotinas preventivas e corretivas com GUI + CLI.
  • Organizar evidências (prints/logs/relatórios) em padrão de pastas.
  • Entregar um pacote completo (PDF + evidências + README + ZIP).

Pré‑requisitos

  • VM/ambiente funcional (Cap. 03/05) e ferramentas administrativas (Cap. 07).
  • Manutenção preventiva/corretiva (Cap. 08) e processos/serviços (Cap. 09).
  • Diagnóstico de desempenho (Cap. 10) e backup/restore (Cap. 11).
Dica: use snapshots antes de simular falhas para não perder seu laboratório.

Conceitos essenciais (e onde vou aplicar isso)

Playbook (manual executável)

Um playbook é um conjunto de procedimentos padronizados para atendimento e manutenção. Onde vou aplicar isso: você vai escrever SOPs que outra pessoa consegue repetir sem te chamar.

SOP (Standard Operating Procedure)

SOP é o “passo a passo padrão” de uma tarefa: sintoma → diagnóstico → ação → validação → rollback. Onde vou aplicar isso: seus 3 SOPs corretivos serão avaliados com esse padrão.

Evidências

Evidência prova execução. Pode ser print, log, CSV ou relatório. Onde vou aplicar isso: cada SOP precisa listar quais evidências serão salvas e onde.

Validação e rollback

Validação confirma resultado; rollback define como desfazer se piorar. Onde vou aplicar isso: em todos SOPs, você terá uma seção “validação” e “rollback”.

Segurança mínima (BitLocker — agenda)

BitLocker é criptografia de disco. Aqui entra como item mínimo de segurança: checar status e orientar sobre chave de recuperação. Onde vou aplicar isso: seção curta no playbook: “Segurança: checar BitLocker”.

Regra: se não tem evidência e validação, o procedimento não é “suporte”, é “tentativa”.

Entregável e critérios mínimos

Você vai entregar (pack)

  • Playbook (PDF) com índice e versão.
  • Evidências organizadas: prints, logs e relatórios.
  • README explicando a estrutura e como localizar itens.
  • ZIP do pacote (recomendado).

Conteúdo mínimo do Playbook

  • Baseline do ambiente (host/VM/winver/rede/discos/pastas).
  • Rotina preventiva: semanal + mensal (Cap. 08/07).
  • Corretiva: 3 SOPs completos (recomendado: lento, app travado, serviço travado).
  • Backup/Restore: robocopy + log + teste de restauração (Cap. 11).
  • Segurança mínima: BitLocker (checagem) + orientação de chave.
  • Fluxos de decisão (Windows inicia? gargalo?).
Dica de nota: quanto mais fácil para outra pessoa executar e encontrar evidências, melhor.

Passo a passo para montar e entregar

Este roteiro é o caminho mais seguro para não esquecer nada.

Criar estrutura do PI (pasta de entrega)

mkdir C:\FGSO\PI_B3_Playbook
mkdir C:\FGSO\PI_B3_Playbook\playbook
mkdir C:\FGSO\PI_B3_Playbook\evidencias
mkdir C:\FGSO\PI_B3_Playbook\evidencias\prints
mkdir C:\FGSO\PI_B3_Playbook\evidencias\logs
mkdir C:\FGSO\PI_B3_Playbook\evidencias\relatorios
echo PI B3 - Playbook (estrutura) > C:\FGSO\PI_B3_Playbook\README.txt

Montar o Playbook (versão 1.0)

  • Crie um documento (Word/Docs) e cole o Modelo de Playbook (seção abaixo).
  • Preencha o baseline (winver, disco, rede, pastas padrão).
  • Defina nomes e versões: Playbook_FGSO_W11_v1.0.

Escrever a rotina preventiva (semanal e mensal) + evidências

  • Semanal: Update + Security + limpeza segura.
  • Mensal: Reliability + Event Viewer (exportar 1 .evtx) + revisão de inicialização.
  • Salve prints e logs em evidencias/ com nomes 01_, 02_...

Escrever 3 SOPs corretivos completos (mínimo)

  • Use o padrão: Sintoma → Diagnóstico GUI → Diagnóstico CLI → Evidências → Ação mínima → Validação → Rollback.
  • Recomendado:
    • SOP-COR-01: PC lento (gargalo CPU/RAM/Disco/Rede)
    • SOP-COR-02: App travado (processo)
    • SOP-COR-03: Serviço travado (ex.: spooler)

Backup/Restore: documentar e provar

  • Inclua robocopy com log e descreva teste de restauração.
  • Opcional recomendado: ZIP + hash (Get-FileHash).
robocopy "C:\Users\%USERNAME%\Documents" "D:\DADOS\Backups\Documents" /E /R:2 /W:2 /LOG+:"D:\DADOS\Backups\logs\robocopy_docs.log"

Segurança mínima: BitLocker (checar e orientar)

  • Inclua no playbook: como checar status e onde a chave seria guardada (sem expor segredo).
manage-bde -status

Exportar PDF, revisar e empacotar

  • Exporte o Playbook em PDF para playbook.
  • Confirme que evidências existem e estão nomeadas.
  • Compacte em ZIP (recomendado):
Compress-Archive -Path "C:\FGSO\PI_B3_Playbook\*" -DestinationPath "C:\FGSO\PI_B3_Playbook.zip" -Force
Checklist de evidências mínimas: 6 prints + 2 logs + 2 relatórios (no mínimo).

Modelo de Playbook (copiar/colar)

Copie e preencha. Depois adicione seus SOPs com evidências.

Modelo completo (Playbook) copiar/colar 
TÍTULO: Playbook de Suporte e Manutenção — Windows 11 (FGSO)
Versão: 1.0   Data: __/__/____   Autor: __________

0) Sumário

1) Objetivo
- Para que serve este playbook?

2) Ambiente (Baseline)
- Host/VM: CPU/RAM/Disco
- Windows: edição/build (winver)
- Rede: NAT (laboratório)
- Pastas padrão:
  - Entrega: C:\FGSO\PI_B3_Playbook
  - Evidências: C:\FGSO\PI_B3_Playbook\evidencias

3) Ferramentas
- GUI: Task Manager, services.msc, eventvwr.msc, resmon, perfmon, taskschd.msc
- CLI: CMD/PowerShell (comandos do playbook)

4) Rotina Preventiva (SOP-PRV)
4.1 Semanal
- Update → reiniciar → validar (print)
- Security → verificação rápida (print)
- Limpeza segura (Storage Sense/temporários)

4.2 Mensal
- Reliability (perfmon /rel) (print)
- Event Viewer: exportar 1 log (.evtx)
- Revisão de inicialização/tarefas

5) Procedimentos Corretivos (SOP-COR)
Padrão: Sintoma → Diagnóstico (GUI+CLI) → Evidência → Ação mínima → Validação → Rollback

SOP-COR-01: PC lento (CPU/RAM/Disco/Rede)
SOP-COR-02: App travado (processo)
SOP-COR-03: Serviço travado (ex.: spooler)

6) Backup e Restore (SOP-BKP)
- Estratégia 3-2-1 (adaptada)
- robocopy com log
- TESTE de restauração documentado

7) Segurança (agenda mínima)
- BitLocker: checar status (manage-bde -status)
- Chave de recuperação: onde guardaria? quem acessa?

8) Fluxos de decisão
- Windows inicia? (Sim/Não)
- Gargalo? (CPU/RAM/Disco/Rede)

9) Anexos
- evidencias/prints
- evidencias/logs
- evidencias/relatorios

Rubrica de avaliação

Use como “guia de qualidade” antes de entregar.

Critério Básico Bom Excelente
Estrutura do Playbook Confuso Completo e claro Índice + fluxos + versão + anexos bem referenciados
Preventiva Sem evidência Semanal/mensal + prints/log Periodicidade + critérios de validação + melhorias
Corretiva SOP incompleto 3 SOPs completos 4+ SOPs + validação antes/depois + rollback claro
Backup/Restore Sem restore Restore documentado robocopy+log + zip/hash + restore provado
Evidências Soltas Padrão de pastas e nomes Pack completo + README excelente + ZIP conferido
Segurança mínima Menciona Checa status Checa + orienta chave (sem expor segredo)

Atividades práticas (2–3) — para fortalecer o Playbook

Atividade 1 — SOP “Gargalo” completo

Detalhe os 4 gargalos (CPU/RAM/Disco/Rede) com 2 evidências por caminho e uma ação mínima segura.

Atividade 2 — Padronização exemplar

Crie um README com “mapa” de evidências: quais arquivos comprovam cada seção do playbook.

Atividade 3 — Restore testado

Faça o restore de um arquivo apagado e documente com prints (antes/depois) e log do robocopy.
