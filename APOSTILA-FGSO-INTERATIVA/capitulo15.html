Capítulo 15 — Scripts para Suporte: .BAT (1/3) + PowerShell (2/3)

Agora você vai dar o próximo passo: transformar rotinas repetitivas de suporte em scripts. A ideia não é “virar programador”, e sim aprender um padrão seguro de automação: entrada → checagem → execução → log → validação → rollback. Vamos dividir o foco: 1/3 em scripts .BAT (legado, mas muito presente) e 2/3 em scripts PowerShell (padrão moderno).

Estrutura padrão (SOP → script) Logs (TXT/CSV) Tratamento de erro Execução segura Reversão (rollback)

Objetivos e pré‑requisitos

Ao final deste capítulo você será capaz de:

  • Criar scripts .BAT simples com log, variáveis e checagens.
  • Criar scripts .PS1 com parâmetros, funções, erros e exportação (TXT/CSV).
  • Aplicar o padrão de automação: evidência antes/depois + validação.
  • Organizar entregáveis em pasta padrão (C:\FGSO\cap15).
  • Explicar riscos básicos: privilégios, execução de scripts e rollback.

Pré‑requisitos

  • CMD essencial (Cap. 13) e PowerShell essencial (Cap. 14).
  • Processos/serviços (Cap. 09), desempenho (Cap. 10) e backup (Cap. 11).
  • Conhecimento básico de pastas e logs (Cap. 12/13/14).
Onde vou aplicar isso: seus SOPs do Playbook (Cap. 12) podem virar scripts de apoio com o mesmo padrão.

Conceitos de script (segurança e padrão)

Automação segura (padrão)

Um script de suporte não pode “fazer coisas escondidas”. Ele precisa ser previsível e auditável. Onde vou aplicar: nos dois scripts (BAT e PS) você vai criar uma seção de log e uma validação simples.

Privilégios e impacto

Alguns comandos exigem administrador. Quanto maior o privilégio, maior o risco. Onde vou aplicar: no passo a passo você vai executar scripts em modo normal e entender quando precisa elevar.

Rollback (como desfazer)

Rollback é o plano de reversão caso algo dê errado. Onde vou aplicar: seus scripts vão registrar o estado anterior (ou pelo menos orientar como reverter).

Execução de scripts (ExecutionPolicy)

PowerShell tem políticas de execução para reduzir risco de scripts maliciosos. Onde vou aplicar: você vai consultar a política e usar alternativas seguras (ex.: executar um script local em laboratório).

Regra: scripts sempre geram log em pasta fixa e têm cabeçalho com versão e objetivo.

Scripts .BAT (1/3) — estrutura essencial (CMD)

Scripts .BAT ainda são comuns em suporte por compatibilidade e simplicidade. Aqui você aprende o mínimo que realmente importa: cabeçalho, variáveis, if, errorlevel, log e caminhos. Onde vou aplicar: você vai criar um BAT que coleta evidências e faz backup simples com robocopy.

Estrutura base (template)

@echo off
setlocal EnableExtensions EnableDelayedExpansion

REM ===== METADADOS =====
REM Nome: suporte_coleta.bat
REM Versao: 1.0
REM Objetivo: coletar evidencias e salvar logs
REM Autor: ______

REM ===== CONFIG =====
set "BASE=C:\FGSO\cap15"
set "LOG=%BASE%\logs"

if not exist "%LOG%" mkdir "%LOG%"

echo [%DATE% %TIME%] Iniciando... >> "%LOG%\execucao.log"

REM ===== EXECUCAO =====
whoami > "%LOG%\usuario.txt"
ipconfig /all > "%LOG%\ipconfig.txt"

REM ===== STATUS =====
if %errorlevel% neq 0 (
  echo [%DATE% %TIME%] ERRO: comando falhou. >> "%LOG%\execucao.log"
  exit /b 1
)

echo [%DATE% %TIME%] Finalizado OK. >> "%LOG%\execucao.log"
exit /b 0

Padrões que você deve lembrar

  • @echo off: reduz ruído.
  • setlocal: evita “sujar” variáveis do sistema.
  • set "VAR=valor": evita erro com espaços.
  • if not exist: checa pasta/arquivo antes.
  • %errorlevel%: checa se o comando falhou.
  • >>: append no log (auditoria).
Onde vou aplicar isso: no passo a passo você vai salvar logs e verificar a saída com errorlevel.
Exemplo BAT: backup rápido com robocopy (com log) uso real 
@echo off
setlocal
set "SRC=%USERPROFILE%\Documents"
set "DST=D:\DADOS\Backups\Documents"
set "LOG=D:\DADOS\Backups\logs"

if not exist "%LOG%" mkdir "%LOG%"

robocopy "%SRC%" "%DST%" /E /R:2 /W:2 /LOG+:"%LOG%\robocopy_docs.log"

if %errorlevel% GEQ 8 (
  echo Falha no robocopy. Verifique o log.
  exit /b 1
)

echo Backup concluido. Verifique %LOG%\robocopy_docs.log
exit /b 0

Observação: códigos do robocopy variam. Neste curso, foque em: log sem “ERROR” + resultado esperado + restore testado (Cap. 11).

Scripts PowerShell (2/3) — estrutura essencial (PS1)

PowerShell é a base moderna do suporte: trabalha com objetos, filtros e exportação. Aqui vamos além do “comando solto” e entramos na estrutura de script: parâmetros, funções, logging, erros e validação. Onde vou aplicar isso: você vai criar um script PS1 que coleta evidências (processos/serviços/rede/eventos) e gera relatório.

Template PS1 (mínimo profissional)

<#
Nome: suporte_coleta.ps1
Versao: 1.0
Objetivo: coletar evidencias e gerar relatórios (TXT/CSV)
Autor: ______
#>

[CmdletBinding()]
param(
  [string]$Base = "C:\FGSO\cap15",
  [int]$TopN = 10
)

$LogDir = Join-Path $Base 'logs'
New-Item -ItemType Directory -Force -Path $LogDir | Out-Null

function Write-Log {
  param([string]$Message)
  $line = "[{0}] {1}" -f (Get-Date), $Message
  $line | Out-File (Join-Path $LogDir 'execucao.log') -Append -Encoding UTF8
}

try {
  Write-Log "Início da coleta"

  # Processos (Top por CPU e RAM)
  Get-Process | Sort-Object CPU -Descending | Select-Object -First $TopN Name,Id,CPU,WS |
    Export-Csv -NoTypeInformation -Encoding UTF8 (Join-Path $LogDir 'top_cpu.csv')

  Get-Process | Sort-Object WS -Descending | Select-Object -First $TopN Name,Id,WS |
    Export-Csv -NoTypeInformation -Encoding UTF8 (Join-Path $LogDir 'top_mem.csv')

  # Serviços
  Get-Service | Select-Object Name,DisplayName,Status,StartType |
    Export-Csv -NoTypeInformation -Encoding UTF8 (Join-Path $LogDir 'servicos.csv')

  # Rede
  Get-NetIPConfiguration | Format-List | Out-File (Join-Path $LogDir 'net_ipconfig.txt')
  Get-DnsClientServerAddress | Out-File (Join-Path $LogDir 'dns_servers.txt')

  # Eventos (últimos 30)
  Get-WinEvent -LogName System -MaxEvents 30 |
    Select-Object TimeCreated,Id,LevelDisplayName,ProviderName,Message |
    Export-Csv -NoTypeInformation -Encoding UTF8 (Join-Path $LogDir 'eventos_sistema.csv')

  Write-Log "Coleta finalizada com sucesso"
}
catch {
  Write-Log ("ERRO: {0}" -f $_.Exception.Message)
  throw
}

Esse template já é suficiente para virar um “script de evidências” no seu Playbook (Cap. 12).

O que esse template te ensina

  • param(): entradas do script (Base, TopN).
  • Join-Path: caminho seguro (evita erros com barras).
  • Write-Log: função de log padronizado.
  • try/catch: captura erros e registra.
  • Export-Csv/Out-File: evidência pronta para auditoria.
Onde vou aplicar isso: no passo a passo você vai criar, executar e validar o pacote de logs.
Execução segura e ExecutionPolicy importante

Se o PowerShell bloquear scripts, isso está relacionado à política de execução. No laboratório, o foco é entender e executar com método. Não é necessário “liberar tudo”. 

# Ver política atual
Get-ExecutionPolicy -List

# (Laboratório) Para permitir scripts locais do usuário, sem liberar geral:
# Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Cuidado: não altere políticas em ambiente real sem orientação institucional.
Estrutura recomendada (nível suporte) checklist
  • Cabeçalho (nome, versão, objetivo, autor)
  • param() para entradas (pastas, quantidade, modo)
  • Checagens (existência de pasta, privilégios se necessário)
  • Logs (Write-Log ou Start-Transcript)
  • Execução (coleta/ação)
  • Validação (arquivos existem? tamanho? conteúdo?)
  • Rollback (quando aplicável, orientar ou registrar estado anterior)

Passo a passo prático (BAT + PowerShell) — criar, executar e validar

Você vai criar uma pasta de trabalho, escrever 1 BAT e 1 PS1 e gerar um pacote de evidências. Pasta do capítulo: C:\FGSO\cap15.

Ambiente recomendado: VM. Se estiver em máquina real, não rode nada destrutivo. Aqui é coleta e backup controlado.

Preparar a pasta do capítulo

mkdir C:\FGSO\cap15
mkdir C:\FGSO\cap15\scripts
mkdir C:\FGSO\cap15\logs
  • Crie um arquivo leia-me.txt com objetivo e data (pode ser pelo CMD ou Notepad).

Criar o BAT (coleta rápida) e executar

  • Abra o Bloco de Notas e salve como: C:\FGSO\cap15\scripts\coleta.bat
  • Conteúdo sugerido:
@echo off
setlocal
set "BASE=C:\FGSO\cap15"
set "LOG=%BASE%\logs"
if not exist "%LOG%" mkdir "%LOG%"

echo [%DATE% %TIME%] BAT: inicio >> "%LOG%\bat_execucao.log"
whoami > "%LOG%\bat_usuario.txt"
ipconfig /all > "%LOG%\bat_ipconfig.txt"
tasklist > "%LOG%\bat_tasklist.txt"

echo [%DATE% %TIME%] BAT: fim >> "%LOG%\bat_execucao.log"
exit /b 0
  • Execute no CMD:
C:\FGSO\cap15\scripts\coleta.bat
  • Valide com dir se os arquivos foram criados em C:\FGSO\cap15\logs.

Criar o PS1 (coleta completa) e executar

  • Abra o PowerShell e crie o arquivo: C:\FGSO\cap15\scripts\coleta.ps1
  • Use o template da seção PowerShell (ajuste se necessário).
  • Execute:
Set-Location C:\FGSO\cap15\scripts
# Executar apontando Base para C:\FGSO\cap15
.\coleta.ps1 -Base "C:\FGSO\cap15" -TopN 10
Se der bloqueio: confira Get-ExecutionPolicy -List. Em laboratório, use CurrentUser RemoteSigned apenas se necessário.

Validação (antes/depois e consistência)

  • Confirme que o PS gerou CSVs e TXTs (top_cpu.csv, servicos.csv, eventos_sistema.csv).
  • Abra 1 arquivo CSV e confirme que tem cabeçalho e linhas.
  • Registre no leia-me.txt o que foi gerado e onde está.
Get-ChildItem C:\FGSO\cap15\logs
Import-Csv C:\FGSO\cap15\logs\top_cpu.csv | Select-Object -First 3

Como isso vira entregável (Playbook)

  • No Playbook (Cap. 12), adicione um item: “Script de coleta de evidências”.
  • Inclua: objetivo, como executar, onde salva logs, como validar e como anexar evidências.
Resultado: você transforma SOP em script e ganha velocidade de suporte + qualidade de auditoria.

Atividades práticas (2–3) — sem entregar o projeto completo

Atividade 1 — BAT com menu

Crie um BAT com menu simples: (1) ipconfig, (2) tasklist, (3) netstat, salvando cada saída em logs/ com data/hora.

Atividade 2 — PS1 com funções

Quebre seu script PS em funções: Get-TopProcess, Get-ServicesReport, Get-NetworkReport, Get-EventReport. Logue início/fim de cada função.

Atividade 3 — Validação automática

No PS1, após gerar logs, valide se arquivos existem e têm tamanho > 0. Se falhar, registre erro e retorne exit code.
