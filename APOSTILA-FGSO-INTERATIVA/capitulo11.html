Capítulo 11 — Backup, Restauração e Continuidade (GUI + Linha de Comando)

Backup não é “copiar e torcer”. Backup é um processo: planejar, executar, validar e restaurar quando necessário. Neste capítulo você vai praticar um método completo no Windows 11: backup de arquivos com ferramentas gráficas e com linha de comando, geração de logs e, principalmente, teste de restauração (prova de que o backup funciona).

Objetivos e pré‑requisitos

Ao final deste capítulo você será capaz de:

  • Diferenciar backup, sincronização e snapshot (VM).
  • Aplicar a estratégia 3‑2‑1 e escolher o tipo de backup adequado.
  • Fazer backup de arquivos via GUI e via CLI (robocopy/PowerShell).
  • Gerar evidências: logs, checks e relatório.
  • Executar um teste de restauração (restaurar arquivo apagado/alterado).
  • Definir rotina mínima de backup para laboratório e para uso real.

Pré‑requisitos

  • Windows 11 instalado (Cap. 05).
  • Partição de dados (Cap. 06) é recomendada: D: para backups.
  • Ferramentas administrativas (Cap. 07) e manutenção (Cap. 08) revisadas.
Dica: crie uma pasta padrão: D:\\DADOS\\Backups (ou C:\\FGSO\\Backups se não tiver D:).

Teoria: backup, restauração e continuidade (com “onde vou aplicar isso”)

Backup x Sincronização x Snapshot

Backup é uma cópia independente para recuperar dados depois. Sincronização mantém arquivos iguais em dois lugares (e pode sincronizar erros). Snapshot (na VM) é um ponto de retorno do estado da máquina virtual, útil para laboratório, mas não substitui backup de dados. Onde vou aplicar: você vai usar snapshot para segurança do laboratório e backup (robocopy/zip) para proteger seus arquivos.

RPO e RTO (conceito de continuidade)

RPO (Recovery Point Objective) é quanto você pode perder (ex.: até 24h de trabalho). RTO (Recovery Time Objective) é quanto tempo pode ficar parado. Onde vou aplicar: ao definir rotina diária/semana e ao escolher backup incremental vs completo.

Backup “que nunca foi testado” não é backup

A regra do suporte: se você nunca restaurou, você não sabe se funciona. Por isso, este capítulo inclui um teste de restore obrigatório. Onde vou aplicar: você vai apagar/alterar um arquivo de teste e restaurar a partir do backup.

Meta do capítulo: terminar com um procedimento repetível, evidências salvas e um restore comprovado.

Estratégia 3‑2‑1 e tipos de backup

Regra 3‑2‑1 (simples e poderosa)

  • 3 cópias dos dados (original + 2 cópias)
  • 2 mídias diferentes (ex.: disco interno + externo)
  • 1 cópia fora do computador (ex.: nuvem ou disco externo guardado)

Em laboratório, você pode simular “fora do computador” usando outra pasta/unidade, mas em ambiente real use mídia externa/nuvem.

Tipos de backup (resumo)

  • Completo: copia tudo (mais lento, mais simples).
  • Incremental: copia só o que mudou desde o último backup.
  • Diferencial: copia o que mudou desde o último completo.

Ferramentas diferentes implementam isso de formas diferentes. Robocopy com /MIR replica estado atual (cuidado!).

Atenção: /MIR pode apagar no destino o que não existe na origem. Use com método e com logs.

Ferramentas gráficas (GUI) — o que usar no Windows 11

Histórico de Arquivos

Protege arquivos do usuário com versões ao longo do tempo (quando configurado).

Onde aplicar: restaurar versões anteriores de documentos.

Backup e Restauração (Windows 7)

Ferramenta clássica do Painel de Controle; em alguns cenários permite imagem do sistema.

Onde aplicar: cenários legados e algumas rotinas corporativas.

Ponto de Restauração

Reverte configurações do sistema (não substitui backup de arquivos).

Onde aplicar: depois de driver/update quebrar o sistema.

Como acessar rapidamente atalhos
  • Win+R → control → procure por “Histórico de Arquivos” e “Backup e Restauração (Windows 7)”.
  • Win+R → sysdm.cpl → aba Proteção do Sistema (pontos de restauração).
Onde vou aplicar isso: no passo a passo você fará backup via GUI (cópia/zip e/ou Histórico de Arquivos, conforme disponível) e depois fará restore.

Linha de comando (CMD + PowerShell) — ferramentas profissionais

robocopy (CMD) — padrão de mercado

Ideal para backup de pastas com logs e tolerância a erros.

REM Backup simples (copia arquivos novos/alterados)
robocopy "C:\Users\%USERNAME%\Documents" "D:\DADOS\Backups\Documents" /E /R:2 /W:2 /LOG+:"D:\DADOS\Backups\logs\robocopy_docs.log"

REM Dry-run (simulação) — mostra o que faria sem copiar
robocopy "C:\Users\%USERNAME%\Documents" "D:\DADOS\Backups\Documents" /E /L /R:1 /W:1
Cuidado: evite /MIR sem entender. Ele espelha e pode apagar no destino.

PowerShell — copiar e compactar

# Copiar pasta (simples)
Copy-Item "$env:USERPROFILE\Documents" "D:\DADOS\Backups\Documents_PS" -Recurse

# Compactar em ZIP (backup portátil)
Compress-Archive -Path "$env:USERPROFILE\Documents\*" -DestinationPath "D:\DADOS\Backups\docs_backup.zip" -Force

# Gerar hash do zip (integridade)
Get-FileHash "D:\DADOS\Backups\docs_backup.zip" | Out-File "D:\DADOS\Backups\logs\hash_docs_backup.txt"

Compress-Archive facilita transportar o backup e ajuda a validar integridade com hash.

wbadmin (avançado/compatibilidade) opcional

wbadmin é ferramenta de backup do Windows (mais comum em edições/ambientes compatíveis). Em algumas instalações pode estar limitada. Aqui fica como referência, não como obrigação. 

wbadmin /?
REM exemplo conceitual (não executar sem entender):
REM wbadmin start backup -backupTarget:E: -include:C:\Users\%USERNAME%\Documents -quiet
Use apenas em laboratório e somente após entender parâmetros. Prefira robocopy/zip para este curso.
Onde vou aplicar isso: no passo a passo você vai gerar um backup por robocopy e um zip com hash, e depois restaurar um arquivo apagado.

Passo a passo prático (backup + teste de restauração)

Objetivo: criar backups em D:\\DADOS\\Backups (ou C:\\FGSO\\Backups) e provar que funciona restaurando um arquivo. Você vai produzir evidências em C:\\FGSO\\cap11.

Antes de começar: crie snapshot 11-antes-backup (VM). Depois, crie uma pasta de dados (se ainda não tiver): D:\\DADOS\\FGSO.

Criar pastas padrão

  • Crie C:\\FGSO\\cap11 e C:\\FGSO\\cap11\\logs.
  • Crie destino de backup (escolha um):
    • D:\\DADOS\\Backups\\Documents (recomendado)
    • C:\\FGSO\\Backups\\Documents (se não existir D:)
  • Crie um arquivo de teste em Documentos: teste_backup.txt com um texto qualquer.

Backup via GUI (simples e didático)

  • Abra o Explorador e vá em Documentos.
  • Copie a pasta/arquivos de teste para a pasta de backup (arrastar/soltar ou Ctrl+C/Ctrl+V).
  • Registre um print mostrando o arquivo no destino.
Onde isso ajuda: é o método mais básico. Útil quando você precisa de cópia rápida, mas não registra log automaticamente.

Backup via CLI (robocopy com log)

  • Abra Prompt/Terminal.
  • Execute (ajuste destino se necessário):
mkdir D:\DADOS\Backups\logs
robocopy "C:\Users\%USERNAME%\Documents" "D:\DADOS\Backups\Documents" /E /R:2 /W:2 /LOG+:"D:\DADOS\Backups\logs\robocopy_docs.log"
  • Copie o log para C:\\FGSO\\cap11\\logs (ou referencie o caminho no relatório).
  • Abra o log e procure por “Ended” e estatísticas (Files, Dirs).

Backup portátil: ZIP + Hash (PowerShell)

  • Abra PowerShell e execute:
New-Item -ItemType Directory -Force -Path "D:\DADOS\Backups\logs" | Out-Null
Compress-Archive -Path "$env:USERPROFILE\Documents\*" -DestinationPath "D:\DADOS\Backups\docs_backup.zip" -Force
Get-FileHash "D:\DADOS\Backups\docs_backup.zip" | Out-File "D:\DADOS\Backups\logs\hash_docs_backup.txt"
  • Confirme que o ZIP existe e tem tamanho plausível.
  • Salve print do arquivo ZIP e do hash (ou copie o hash para o relatório).

Teste de restauração (obrigatório)

  • Em Documentos, edite teste_backup.txt e altere o conteúdo.
  • Depois, apague o arquivo (ou renomeie para simular perda).
  • Restaure de uma das formas:
    • Do destino do robocopy: copie o arquivo de volta.
    • Do ZIP: abra o zip e extraia o arquivo para Documentos.
  • Confirme que o arquivo voltou e abra para validar o conteúdo.
  • Registre print do arquivo restaurado + evidência do local de origem.
Se você conseguiu restaurar: parabéns — agora você provou que seu backup é útil.

Relatório final (cap11)

  • Crie C:\\FGSO\\cap11\\relatorio.txt com:
  • 1) Estratégia (3‑2‑1 adaptada ao laboratório)
  • 2) O que foi backupado (quais pastas)
  • 3) Ferramentas usadas (GUI, robocopy, zip+hash)
  • 4) Evidências geradas (prints + logs + hash)
  • 5) Resultado do teste de restauração (funcionou? como?)
Boa prática: depois de ajustar uma rotina, crie snapshot 11-pos-backup (VM) para manter o laboratório estável.

Erros comuns e como evitar

Erros comuns

  • Não testar restauração (descobre tarde demais que falhou).
  • Usar sincronização como backup (sincroniza erro/criptografia).
  • Guardar backup no mesmo disco físico (se o disco falhar, perde tudo).
  • Usar robocopy /MIR sem entender (pode apagar destino).
  • Não registrar logs/evidências (difícil auditar).

Como evitar

  • Obrigatório: teste de restore com arquivo de prova.
  • Separar cópias: pasta dedicada + zip + (em real) mídia externa/nuvem.
  • Usar logs e hash para integridade.
  • Fazer dry-run com robocopy /L antes de mudanças agressivas.
  • Documentar em playbook (vai ajudar no Cap. 12 — PI do bimestre).
Quando o robocopy retorna códigos (RC) interpretação

Robocopy retorna códigos que não são “0 = ok” sempre. Ex.: códigos podem indicar que arquivos foram copiados. O importante é ler o log: erros reais aparecem como “ERROR”.

No laboratório, o foco é: log sem erros + restore funcionando.
