Projeto Avaliativo do 3º Bimestre

Sistema Local Temporizado e Modular • Integração dos capítulos 9, 10 e 11

Neste capítulo, você vai desenvolver um projeto avaliativo que integra os conhecimentos do terceiro bimestre: controle de tempo, uso de funções prontas e programação modular. A proposta é construir um sistema local temporizado no Arduino, capaz de executar comportamentos organizados em módulos e com lógica temporal bem definida.

Projeto avaliativo 3º bimestre Temporização + modularização Arduino + Tinkercad
Produto esperadoProtótipo funcional local com comportamento temporizado, código modular e explicação curta da solução.
Competências mobilizadasOrganizar software embarcado em funções, controlar tempo e integrar saídas em um comportamento previsível.
Tempo sugerido1 aula para planejamento e início da montagem + 1 aula para conclusão, ajustes e entrega.
FerramentasArduino Uno, LEDs, botão opcional, resistores, protoboard, jumpers e Tinkercad.

1. Proposta do projeto

Situação-problema
Desafio: desenvolver um protótipo local que execute uma sequência temporizada com uma ou mais saídas, usando código organizado em funções para tornar o projeto mais claro e fácil de manter.

Possibilidades de projeto

  • Semáforo local temporizado
  • Sistema de alerta com sequência de LEDs
  • Painel visual com padrões de tempo
  • Sequência modular de sinalização
  • Alerta acionado por botão com temporização

O professor pode escolher uma única proposta ou permitir pequenas adaptações controladas.

O que o projeto deve demonstrar

  • Uso correto de tempo no programa
  • Organização modular com funções
  • Montagem funcional com uma ou mais saídas
  • Leitura clara do circuito e do código
  • Capacidade de explicar a lógica temporal
  • Possível uso de botão ou condição de ativação

2. Revisão dos conhecimentos aplicados

Integração do bimestre

2.1 Controle de tempo

O projeto precisa usar temporização para definir quando cada ação deve acontecer. Isso pode aparecer com delay() em uma primeira versão ou com abordagem mais organizada quando o projeto exigir mais flexibilidade.

O importante é que o aluno perceba que o comportamento depende da organização temporal.

2.2 Funções prontas

Durante o desenvolvimento, o programa pode aproveitar funções já conhecidas e comandos que tornam o código mais direto. Isso mostra que programar bem também é saber reutilizar recursos existentes.

Mesmo quando o foco principal do projeto não é cálculo, a lógica de funções prontas e reaproveitamento continua importante.

2.3 Programação modular

O projeto deve dividir responsabilidades em funções, por exemplo: uma função para acender uma sequência, outra para desligar saídas e outra para executar um padrão. Isso ajuda a transformar um código extenso em um sistema mais organizado.

Essa organização também facilita a explicação do aluno durante a entrega.

3. Roteiro do projeto — modelo-base

Execução orientada

O modelo-base sugerido é um mini semáforo local temporizado, com três LEDs controlados por funções específicas. É um projeto simples, visual e adequado ao nível técnico, integrando bem os conteúdos do bimestre.

Objetivo do modelo: acender os LEDs em sequência (verde, amarelo, vermelho) com tempos definidos e código organizado em funções.
1

Planeje a montagem

Liste os componentes: Arduino Uno, três LEDs, três resistores, protoboard e jumpers. Se desejar ampliar o desafio, adicione um botão para iniciar ou pausar a sequência.

Aplicação pedagógica: o planejamento ajuda a visualizar entradas, saídas e a lógica temporal antes do código.

2

Monte os LEDs

Conecte os LEDs a três pinos digitais, como 8, 9 e 10, cada um com seu resistor, e ligue os retornos ao GND. Organize o circuito com clareza para facilitar a leitura durante a avaliação.

Aplicação do conceito: cada LED representará um estado do sistema.

3

Escreva funções para cada estado

Crie funções separadas para acender o LED verde, amarelo e vermelho, desligando os demais. Isso deixa o programa modular e muito mais fácil de compreender.

void verde() {
  digitalWrite(8, HIGH);
  digitalWrite(9, LOW);
  digitalWrite(10, LOW);
}

void amarelo() {
  digitalWrite(8, LOW);
  digitalWrite(9, HIGH);
  digitalWrite(10, LOW);
}

void vermelho() {
  digitalWrite(8, LOW);
  digitalWrite(9, LOW);
  digitalWrite(10, HIGH);
}
4

Monte o programa-base

Organize o restante do código:

void setup() {
  pinMode(8, OUTPUT);
  pinMode(9, OUTPUT);
  pinMode(10, OUTPUT);
}

void verde() {
  digitalWrite(8, HIGH);
  digitalWrite(9, LOW);
  digitalWrite(10, LOW);
}

void amarelo() {
  digitalWrite(8, LOW);
  digitalWrite(9, HIGH);
  digitalWrite(10, LOW);
}

void vermelho() {
  digitalWrite(8, LOW);
  digitalWrite(9, LOW);
  digitalWrite(10, HIGH);
}

void loop() {
  verde();
  delay(3000);
  amarelo();
  delay(1000);
  vermelho();
  delay(3000);
}

Aplicação do conceito: o comportamento temporal está organizado e o código foi dividido em módulos claros.

5

Teste e ajuste

Inicie a simulação e observe a sequência do semáforo. Se algo não funcionar, revise primeiro a ligação física dos LEDs e depois os pinos definidos no código.

Dica de depuração: sempre confira se o pino físico corresponde ao pino definido no programa.

6

Adicione autoria

Depois que o modelo-base funcionar, faça uma pequena adaptação: incluir um botão para controlar o início da sequência, mudar os tempos, adicionar um LED de pedestre ou criar um estado de alerta piscando.

Entrega valorizada: adaptações mostram compreensão e domínio maior do conteúdo.

7

Documente a solução

Registre os componentes usados, a lógica temporal adotada, as funções criadas e o que acontece em cada parte da sequência. Isso será útil na explicação da entrega.

Resultado esperado: um protótipo local temporizado e modular, funcional, organizado e fácil de explicar.

4. Sugestões de variações do projeto

Autoria do aluno

Variações simples

  1. Semáforo com botão: usar botão para iniciar ou pausar a sequência.
  2. Sinalização de pedestre: adicionar um LED extra para pedestre.
  3. Alerta piscante: criar um modo amarelo piscando em determinadas condições.

Variações com mais desafio

  1. Dois modos: modo normal e modo noturno com piscadas.
  2. Padrões modulares: criar funções extras para cada comportamento do sistema.
  3. Sequência personalizada: reorganizar a lógica temporal com base em uma situação simulada.

5. Critérios de avaliação sugeridos

Rubrica

Funcionamento

O protótipo executa corretamente a sequência proposta e respeita a lógica temporal definida.

Modularização

O código está dividido em funções com responsabilidades claras e compreensíveis.

Montagem

O circuito está organizado, com boa identificação das saídas e conexões corretas.

Explicação

O aluno consegue explicar como o tempo, as funções e a montagem se relacionam no projeto.
