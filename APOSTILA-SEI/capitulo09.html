Controle de Tempo em Sistemas Embarcados

Bimestre 3 • Capítulo 9 • Temporização com Arduino

Neste capítulo, você vai estudar como o Arduino lida com o tempo dentro do programa. Em sistemas embarcados, controlar tempo é essencial para criar comportamentos previsíveis, como piscar LEDs em ritmos específicos, executar ações periódicas e evitar que o programa fique “travado” enquanto espera. Aqui vamos trabalhar principalmente com delay(), delayMicroseconds(), millis() e micros().

1. Conceitos fundamentais

Teoria
Ideia central: controlar tempo significa definir quando algo deve acontecer, por quanto tempo deve durar e com que frequência deve se repetir.

delay()

A função delay() pausa o programa por um período em milissegundos. Durante essa pausa, o restante do código não continua a ser executado. Por isso, dizemos que é uma espera bloqueante.

Ela é útil em exemplos iniciais, como LED piscando, mas pode se tornar limitada quando o programa precisa fazer mais de uma coisa ao mesmo tempo.

delayMicroseconds()

Essa função faz uma pausa muito curta, medida em microssegundos. É menos comum em atividades iniciais, mas ajuda a mostrar que algumas ações precisam de tempos bem menores do que 1 milissegundo.

No curso técnico, basta entender que existe essa escala menor e que ela é usada em casos mais específicos.

millis()

A função millis() informa há quanto tempo o programa está rodando, em milissegundos, desde que o Arduino foi iniciado. Isso permite verificar o tempo passado sem interromper totalmente o restante do programa.

Esse recurso é muito importante porque permite criar comportamentos temporizados sem travar a execução, sendo uma forma mais flexível de controlar ações periódicas.

micros()

A função micros() é parecida com millis(), mas retorna o tempo em microssegundos. Assim como no caso de delayMicroseconds(), seu uso costuma aparecer quando o sistema precisa lidar com tempos muito pequenos.

Para este capítulo, o mais importante é reconhecer que existe essa função e saber diferenciá-la de millis().

Espera bloqueante

Uma espera bloqueante acontece quando o programa precisa parar tudo para aguardar um tempo. É o caso de delay(). Enquanto essa espera ocorre, o código não avança para outras verificações ou decisões.

Isso pode ser aceitável em exercícios simples, mas em projetos mais completos pode atrapalhar bastante.

Espera não bloqueante

Uma espera não bloqueante acontece quando o programa continua funcionando enquanto verifica se já passou o tempo necessário. É o caso mais comum com millis().

Essa abordagem é muito útil quando o sistema precisa monitorar entradas e controlar saídas ao mesmo tempo, sem ficar “parado” esperando.

3. Prática guiada — Comparando delay() e millis()

Passo a passo

Nesta prática, você vai observar a diferença entre um LED piscando com delay() e um LED piscando usando millis().

Você vai aplicar: delay(), millis(), comparação de abordagens e organização temporal do programa.
1

Monte o circuito básico

No Tinkercad, monte um circuito com Arduino, protoboard, LED, resistor e jumpers. Conecte o LED a um pino digital, como o 13, e ao GND.

Aplicação do conceito: o LED servirá como referência visual para o comportamento temporal.

2

Teste com delay()

Use o código abaixo para fazer o LED piscar com espera bloqueante:

void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  digitalWrite(13, HIGH);
  delay(1000);
  digitalWrite(13, LOW);
  delay(1000);
}

Observe que o LED acende e apaga corretamente, mas o programa para completamente durante cada espera.

3

Substitua por millis()

Agora experimente um exemplo não bloqueante:

unsigned long tempoAnterior = 0;
const int intervalo = 1000;
int estadoLED = LOW;

void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  unsigned long tempoAtual = millis();

  if (tempoAtual - tempoAnterior >= intervalo) {
    tempoAnterior = tempoAtual;

    if (estadoLED == LOW) {
      estadoLED = HIGH;
    } else {
      estadoLED = LOW;
    }

    digitalWrite(13, estadoLED);
  }
}

Neste caso, o LED também pisca, mas o programa não fica totalmente parado enquanto espera o próximo intervalo.

4

Compare os resultados

Os dois códigos fazem o LED piscar, mas de formas diferentes. Com delay(), o programa “espera parado”. Com millis(), ele continua executando o loop e apenas verifica quando chegou o momento de mudar o estado do LED.

Conclusão: para projetos simples, delay() funciona bem; para projetos com mais ações simultâneas, millis() é mais flexível.

Resultado esperado: compreender que controlar tempo não é apenas esperar, mas escolher a forma certa de organizar o comportamento do sistema.

4. Aplicação futura

Por que isso importa?

Projetos com mais de uma tarefa

Quando o sistema precisa, por exemplo, piscar um LED e ao mesmo tempo ler um botão, o uso de millis() ajuda muito. Assim, o microcontrolador não fica preso em esperas longas enquanto ignora o restante do circuito.

Sistemas mais responsivos

Controlar tempo sem bloquear o programa torna a resposta do sistema mais rápida e organizada. Isso será útil em projetos com sensores, contadores, automação local e outras situações em que várias coisas precisam acontecer ao mesmo tempo.

Desafios de adaptação

  1. Semáforo simples: crie uma sequência temporal curta com dois ou três LEDs.
  2. Botão + tempo: combine uma leitura de botão com um LED temporizado.
  3. Registro de comparação: escreva uma frase comparando quando usar delay() e quando millis() pode ser melhor.
