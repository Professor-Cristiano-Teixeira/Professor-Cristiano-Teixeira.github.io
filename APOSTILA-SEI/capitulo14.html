ESP32 como Servidor Web Simples

Bimestre 4 • Capítulo 14 • Hospedando uma página e recebendo comandos pelo navegador

Neste capítulo, você vai avançar do simples uso do Wi‑Fi para uma aplicação clássica de IoT educacional: transformar o ESP32 em um pequeno servidor web. Isso significa que a própria placa pode responder a requisições HTTP e entregar uma página que será aberta no navegador. A partir dessa página, o usuário pode visualizar informações e até acionar saídas, como um LED.

1. Conceitos fundamentais

Teoria
Ideia central: um servidor web embarcado permite que o próprio dispositivo hospede páginas e responda a requisições, aproximando o projeto de aplicações reais de IoT.

O que é um servidor web?

Um servidor web é um sistema que recebe pedidos de páginas e responde com conteúdos que o navegador consegue exibir. Em um computador comum, isso costuma acontecer em máquinas dedicadas. No caso do ESP32, o próprio microcontrolador pode desempenhar esse papel em projetos pequenos e didáticos.

Isso é interessante porque mostra que um dispositivo embarcado pode fornecer interface de uso sem depender de um servidor externo tradicional.

HTTP e navegador

Quando digitamos um endereço no navegador, ele envia uma requisição HTTP para o dispositivo que está no IP indicado. Se esse dispositivo for um ESP32 com servidor web ativo, ele responderá com uma página ou com um comando processado pelo seu programa.

O aluno não precisa dominar todos os detalhes do protocolo agora, mas é importante compreender a ideia de “pedido e resposta”.

ESP32 como servidor

Ao conectar o ESP32 à rede e iniciar um servidor HTTP, a placa passa a “ouvir” requisições em uma porta, normalmente a porta 80. Quando alguém acessa seu endereço IP no navegador, o programa pode responder com HTML simples ou com ações no hardware.

Esse é um dos exemplos mais visuais da integração entre software, rede e circuito físico.

HTML simples no microcontrolador

Para começar, não é necessário construir páginas complexas. Uma página HTML básica, com título, texto e alguns links ou botões, já é suficiente para demonstrar o conceito. O foco pedagógico está em perceber que o conteúdo exibido no navegador está vindo diretamente do ESP32.

Mais adiante, esse conteúdo poderá ficar mais interativo.

Comandos pela URL

Uma forma simples de controlar o hardware é usar diferentes caminhos na URL, como /H e /L, para ligar ou desligar um LED. O programa interpreta a requisição e executa a ação correspondente.

Esse modelo é didático porque mostra claramente a relação entre o endereço acessado e o comportamento do circuito.

Limites do simulador

Em alguns ambientes de simulação, como Wokwi, um servidor HTTP pode exigir recursos específicos de gateway para ser acessado diretamente pelo navegador. Mesmo assim, o conceito continua válido e o código serve como base de estudo para hardware real ou ambientes compatíveis.

O mais importante, neste momento, é compreender a lógica do servidor e sua estrutura básica.

3. Prática guiada — Página web simples para ligar e desligar LED

Passo a passo

Nesta prática, você vai criar um pequeno servidor HTTP no ESP32 para exibir uma página no navegador e controlar um LED.

Você vai aplicar: Wi‑Fi, WebServer, HTML básico, rotas HTTP e controle de saída digital.
Dica importante: em simulação, o acesso via navegador pode depender de gateway específico. Mesmo assim, siga o passo a passo para compreender a lógica e usar depois em ambiente real ou compatível.
1

Prepare o ambiente

Abra um projeto com ESP32 em um simulador compatível ou no hardware real. Adicione um LED com resistor a um pino digital, como o pino 5, para servir como saída controlada pela página web.

Aplicação do conceito: o navegador não servirá apenas para exibir conteúdo, mas também para influenciar o circuito físico.

2

Inclua as bibliotecas necessárias

Comece o código com as bibliotecas de Wi‑Fi e servidor web:

#include <WiFi.h>
#include <WebServer.h>

Aplicação do conceito: uma biblioteca cuida da conectividade e a outra organiza o comportamento do servidor HTTP.

3

Defina a rede e crie o servidor

Use uma rede adequada ao ambiente de teste. Em simulações compatíveis com Wokwi, um exemplo comum é:

const char* ssid = "Wokwi-GUEST";
const char* password = "";

WebServer server(80);

Aplicação do conceito: o servidor ficará ouvindo requisições HTTP na porta 80.

4

Crie as rotas principais

Organize o comportamento da página e dos comandos:

void handleRoot() {
  server.send(200, "text/html",
    "<html><body><h1>Controle do LED</h1>"
    "<p><a href='/H'>Ligar</a></p>"
    "<p><a href='/L'>Desligar</a></p>"
    "</body></html>");
}

void handleOn() {
  digitalWrite(5, HIGH);
  server.send(200, "text/html", "<h1>LED Ligado</h1><a href='/'>Voltar</a>");
}

void handleOff() {
  digitalWrite(5, LOW);
  server.send(200, "text/html", "<h1>LED Desligado</h1><a href='/'>Voltar</a>");
}

Aplicação do conceito: o caminho acessado no navegador decide o que o ESP32 deve fazer.

5

Complete o setup()

Agora configure a conexão e registre as rotas:

void setup() {
  Serial.begin(115200);
  pinMode(5, OUTPUT);

  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("\nConectado!");
  Serial.println(WiFi.localIP());

  server.on("/", handleRoot);
  server.on("/H", handleOn);
  server.on("/L", handleOff);
  server.begin();
}

Aplicação do conceito: além da conexão Wi‑Fi, o ESP32 agora passa a atender páginas e comandos HTTP.

6

Complete o loop()

O loop do servidor pode ficar simples:

void loop() {
  server.handleClient();
}

Aplicação do conceito: essa linha mantém o servidor respondendo a clientes que acessam a página.

7

Teste no navegador

Com a simulação ou o hardware em execução, abra o endereço IP informado no monitor serial. Ao acessar a página inicial, use os links para ligar e desligar o LED.

Conclusão: aqui o aluno percebe, na prática, que o ESP32 está servindo uma página e controlando o circuito ao mesmo tempo.

Resultado esperado: uma página simples hospedada no ESP32, acessível no navegador, capaz de comandar um LED no circuito.

4. Aplicação futura

Por que isso importa?

Interfaces locais de controle

Com esse modelo, o aluno entende que pode criar pequenas interfaces de controle sem precisar de aplicativo separado. Isso já é um passo importante rumo a sistemas web embarcados.

Monitoramento em tempo real

Nos próximos capítulos, a mesma lógica poderá ser usada para mostrar valores de sensores no navegador, criar botões mais amigáveis e construir aplicações conectadas mais completas.

5. Atividades sugeridas para o aluno

Prática orientada

Atividades de continuação

  1. Dois LEDs: adapte a página para controlar dois LEDs com caminhos diferentes.
  2. Página personalizada: troque o texto da página e adicione um título mais descritivo do projeto.
  3. Botão físico + web: imagine ou implemente uma versão em que o LED possa ser controlado pelo navegador e por um botão local.

Desafios de adaptação

  1. Status na página: mostrar se o LED está ligado ou desligado no conteúdo HTML.
  2. Rota de sensor: criar uma nova rota que exiba um valor simples no navegador.
  3. Registro técnico: explique, com suas palavras, a diferença entre a página inicial e as rotas que executam comando.
