Programação Modular

Bimestre 3 • Capítulo 11 • Organizando melhor o código com funções e procedimentos

Neste capítulo, você vai aprender a organizar melhor seus programas usando programação modular. Em vez de concentrar toda a lógica no loop(), o código pode ser dividido em partes menores, com funções e procedimentos que tornam a solução mais clara, reutilizável e fácil de manter. Também vamos trabalhar o conceito de escopo de variáveis, que ajuda a entender onde cada variável pode ser usada e por quê.

1. Conceitos fundamentais

Teoria
Ideia central: modularizar é dividir um problema maior em partes menores e bem definidas. Isso torna o programa mais legível, menos repetitivo e mais fácil de corrigir.

O que é programação modular?

Programação modular é uma forma de organizar o código em blocos menores, cada um responsável por uma tarefa específica. Em vez de colocar toda a lógica no loop(), podemos criar funções que representem ações bem definidas, como acender um LED, ler um botão ou executar uma sequência de piscar.

Essa abordagem melhora a leitura do programa e ajuda o aluno a entender que um sistema maior pode ser construído a partir de partes menores e bem planejadas.

Funções

Uma função é um bloco de código que executa uma tarefa específica e pode, em muitos casos, retornar um valor. Mesmo em projetos simples, funções ajudam a evitar repetição e a dar nomes mais claros às ações do sistema.

Por exemplo, em vez de repetir várias linhas para piscar um LED, podemos criar uma função chamada piscarLED().

Procedimentos

Em muitos contextos didáticos, chamamos de procedimento uma função que executa uma ação, mas não retorna valor. No Arduino/C++, isso geralmente aparece como uma função do tipo void. O importante, para o aluno, é perceber que existe um bloco criado para executar uma tarefa bem definida.

Assim, mesmo sem aprofundar nomenclaturas, é possível entender a utilidade prática da divisão do código.

Por que modularizar?

Modularizar facilita leitura, manutenção e reaproveitamento. Um código modular é mais fácil de corrigir porque cada parte do problema está mais isolada. Além disso, quando uma ação precisa ser usada em vários pontos do programa, uma função evita reescrever o mesmo bloco diversas vezes.

Na prática, isso ajuda o aluno a desenvolver hábitos melhores de programação desde cedo.

Escopo de variáveis

Escopo é a “região” do programa em que uma variável pode ser usada. Algumas variáveis são criadas para valer apenas dentro de uma função. Outras podem ser globais, ou seja, acessíveis em mais partes do programa.

Entender escopo é importante porque ajuda a evitar confusão, erros de leitura e uso indevido de variáveis em lugares onde elas não existem ou não deveriam ser alteradas.

Variáveis locais e globais

Uma variável local é criada dentro de uma função e só existe ali. Uma variável global é declarada fora das funções e pode ser usada em diferentes partes do programa. Ambas têm utilidade, mas devem ser usadas com consciência.

No início, vale mostrar que variáveis locais ajudam a manter o código mais controlado, enquanto globais podem ser úteis quando várias funções precisam compartilhar um mesmo estado.

3. Prática guiada — Modularizando um LED controlado por botão

Passo a passo

Nesta prática, você vai reorganizar um programa simples em funções menores, separando a leitura da entrada e o controle da saída.

Você vai aplicar: funções do tipo void, variável global simples, variável local e organização do fluxo do programa.
1

Monte o circuito

No Tinkercad, monte um circuito com Arduino Uno, botão, LED, resistor, protoboard e jumpers. O botão será a entrada e o LED a saída.

Aplicação do conceito: o circuito servirá para observar como a lógica modular afeta a organização do código, sem mudar a função final do protótipo.

2

Observe uma versão não modular

Veja um código simples em que toda a lógica está concentrada no loop():

int estadoBotao = 0;

void setup() {
  pinMode(2, INPUT);
  pinMode(13, OUTPUT);
}

void loop() {
  estadoBotao = digitalRead(2);

  if (estadoBotao == HIGH) {
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}

Ele funciona, mas podemos deixá-lo mais organizado.

3

Crie uma função para ler o botão

Agora, crie uma função responsável apenas por devolver o valor da leitura do botão:

int lerBotao() {
  int leitura = digitalRead(2);
  return leitura;
}

Aplicação do conceito: aqui temos uma função que retorna um valor. A variável leitura é local dessa função.

4

Crie uma função para controlar o LED

Separe também a ação de acender ou apagar o LED:

void controlarLED(int estado) {
  if (estado == HIGH) {
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}

Aplicação do conceito: essa função não retorna valor, apenas executa uma ação com base no parâmetro recebido.

5

Monte o programa modular completo

Junte tudo em uma versão mais organizada:

void setup() {
  pinMode(2, INPUT);
  pinMode(13, OUTPUT);
}

int lerBotao() {
  int leitura = digitalRead(2);
  return leitura;
}

void controlarLED(int estado) {
  if (estado == HIGH) {
    digitalWrite(13, HIGH);
  } else {
    digitalWrite(13, LOW);
  }
}

void loop() {
  int estadoBotao = lerBotao();
  controlarLED(estadoBotao);
}

Agora o loop() ficou menor e mais fácil de entender.

6

Teste e compare

Inicie a simulação e observe que o comportamento do circuito continua o mesmo: botão pressionado, LED aceso; botão solto, LED apagado. A diferença está na qualidade da organização do código.

Conclusão: modularizar não muda necessariamente o que o circuito faz, mas melhora muito a forma como o programa é construído.

Resultado esperado: perceber que funções ajudam a dividir responsabilidades e deixam o código mais claro, reutilizável e fácil de manter.

4. Aplicação futura

Por que isso importa?

Projetos maiores

Quanto mais o projeto cresce, mais importante fica separar as responsabilidades do programa. Ler sensores, controlar LEDs, exibir dados e tomar decisões em funções diferentes torna o desenvolvimento muito mais fácil.

Correção e reaproveitamento

Quando uma parte do programa está em uma função separada, fica mais fácil localizar erros, testar comportamentos e reaproveitar aquela lógica em outro projeto futuro.

5. Atividades sugeridas para o aluno

Prática orientada

Atividades de continuação

  1. Função piscarLED(): crie uma função separada para fazer o LED piscar certo número de vezes.
  2. Duas entradas: separe em funções diferentes a leitura de dois botões, mesmo que o circuito ainda seja simples.
  3. Mapa de escopo: destaque no código quais variáveis são locais e quais poderiam ser globais.

Desafios de adaptação

  1. Dois LEDs modulares: crie funções diferentes para controlar cada LED.
  2. Painel organizado: reescreva um código anterior, deixando-o modular.
  3. Registro conceitual: explique, com suas palavras, por que funções ajudam em sistemas embarcados.
