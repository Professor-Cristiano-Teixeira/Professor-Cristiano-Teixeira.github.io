Estrutura do Programa e Primeiros Códigos

Bimestre 2 • Capítulo 5 • Início da programação com Arduino

Neste capítulo, você vai começar a programar o microcontrolador usando a estrutura básica de um programa Arduino. O objetivo é compreender como o código é organizado, qual a função do setup() e do loop(), como acontece a compilação e como um programa simples pode controlar uma saída, como um LED. É o ponto em que a montagem física começa a se integrar com a lógica escrita no código.

1. Conceitos essenciais da programação embarcada

Base teórica
Ideia central: em sistemas embarcados, o programa não é feito para várias tarefas genéricas ao mesmo tempo. Ele é escrito para controlar um comportamento específico do circuito, repetindo certas ações e reagindo às entradas do ambiente.

1.1 O que é um programa embarcado?

Um programa embarcado é um conjunto de instruções que o microcontrolador executa para controlar um dispositivo ou um circuito. Diferentemente de um software comum de computador, aqui o código está diretamente ligado ao comportamento do hardware: ligar um LED, ler um botão, esperar um tempo, acionar um buzzer ou responder a um sensor.

No contexto do curso, isso significa que escrever código não é apenas “mostrar texto na tela”, mas comandar o mundo físico por meio dos pinos da placa e dos componentes conectados ao circuito.

1.2 A função do setup()

No Arduino, a função setup() é usada para configurar o que precisa ser preparado no início da execução. Ela roda uma única vez quando o programa começa. É ali que normalmente definimos quais pinos serão usados como entrada ou saída e inicializamos recursos necessários para o funcionamento do circuito.

Na prática, o setup() prepara o ambiente para que o restante do programa funcione corretamente. Neste capítulo, você vai usá-lo para configurar o pino do LED como saída.

1.3 A função do loop()

A função loop() é o coração da repetição do programa. Depois de executar o setup(), o microcontrolador passa a repetir continuamente o que estiver dentro do loop(). Essa estrutura é muito importante porque os sistemas embarcados costumam funcionar observando ou controlando algo o tempo todo.

No exemplo do LED piscando, é o loop() que fará o LED acender, esperar, apagar, esperar e repetir esse ciclo continuamente.

1.4 Compilação e execução

Quando você escreve um código, ele ainda está em linguagem próxima da compreensão humana. Para que o microcontrolador entenda essas instruções, o código precisa ser compilado, ou seja, traduzido para uma forma executável pela placa. Depois disso, ele pode ser enviado para o microcontrolador e executado.

No simulador Tinkercad, parte desse processo acontece de forma simplificada e mais amigável para o aluno. Mesmo assim, é importante entender que existe uma etapa entre escrever o código e ver o circuito funcionando.

1.5 Pinos, entradas e saídas

O microcontrolador se comunica com o circuito por meio de pinos. Alguns serão usados para receber informações do ambiente e outros para enviar comandos aos componentes. Neste capítulo, o foco está principalmente em uma saída simples: comandar um LED.

Quando você define um pino como OUTPUT, está dizendo ao microcontrolador que ele será usado para controlar algo no circuito. Essa noção será aprofundada nos próximos capítulos com botões, sensores e outras interações.

1.6 Por que começar com um LED piscando?

O exemplo do LED piscando é clássico porque ele é simples, visual e ajuda o aluno a perceber imediatamente a relação entre código e comportamento físico. É uma atividade pequena, mas muito importante para consolidar a ideia de que o software realmente controla o circuito.

Além disso, esse exemplo ajuda a treinar a estrutura básica do programa antes de incluir decisões, variáveis, leituras e outros elementos mais complexos da programação.

2. Estrutura mínima de um programa Arduino

Leitura orientada

Observe a estrutura abaixo. Ela representa o formato básico de um programa no Arduino:

void setup() {
  // configurações iniciais
}

void loop() {
  // ações repetidas continuamente
}

Mesmo antes de dominar cada instrução, já é importante perceber a organização geral: primeiro o microcontrolador se prepara; depois ele entra em um ciclo contínuo de execução.

3. Prática guiada — Primeiro programa: LED piscando

Passo a passo

Nesta prática, você vai montar um circuito simples com LED e escrever seu primeiro programa funcional para fazer o LED piscar.

O que você vai aplicar aqui: estrutura do programa, setup, loop, definição de pino como saída e noção de tempo de espera.
Dica importante: faça uma alteração por vez. Se o circuito parar de funcionar, volte ao passo anterior e observe o que mudou.
1

Monte o circuito básico

No Tinkercad, crie um novo circuito com um Arduino Uno, uma protoboard, um LED, um resistor e jumpers. Monte o LED em série com o resistor e conecte-o a um pino digital e ao GND.

Aplicação do conceito: o LED será a saída visual controlada pelo programa.

2

Abra o editor de código

Entre na área de código do Tinkercad e selecione a visualização em texto, se estiver disponível. Observe que o programa já segue a organização com setup() e loop().

Objetivo pedagógico: associar a montagem física ao espaço onde a lógica será escrita.

3

Digite o código inicial

Insira o seguinte programa:

void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  digitalWrite(13, HIGH);
  delay(1000);
  digitalWrite(13, LOW);
  delay(1000);
}

Aplicação do conceito: aqui o setup() configura o pino 13 como saída e o loop() controla o acendimento e apagamento do LED.

4

Entenda cada parte do código

pinMode(13, OUTPUT); diz que o pino 13 será usado para controlar algo. digitalWrite(13, HIGH); coloca o pino em nível alto, fazendo o LED acender. digitalWrite(13, LOW); coloca o pino em nível baixo, fazendo o LED apagar. Já delay(1000); cria uma espera de aproximadamente 1 segundo.

Conclusão parcial: o código não está apenas “escrevendo instruções”; ele está comandando um comportamento físico do circuito.

5

Inicie a simulação

Execute a simulação e observe o LED piscando. Se não funcionar, verifique se o circuito foi ligado ao pino certo e se o LED foi montado corretamente com resistor e polaridade adequada.

Prática de depuração: sempre compare o pino usado no código com o pino ligado no circuito.

6

Faça uma pequena adaptação

Altere o tempo do delay() para um valor menor, como 500, e observe a diferença. Depois, tente 2000. Isso ajuda a perceber como pequenas mudanças no código produzem efeitos visíveis no comportamento do circuito.

Aplicação do conceito: a lógica do software controla o ritmo da ação física.

Resultado esperado: um LED piscando de forma controlada, mostrando que o aluno conseguiu montar o circuito e compreender a estrutura mínima do programa.

Aplicação futura

5. Atividades sugeridas para o aluno

Prática orientada

Atividades de continuação

  1. Ritmos diferentes: altere o tempo de espera do LED e registre três resultados diferentes.
  2. Dois LEDs alternados: adicione um segundo LED e tente fazer um acender enquanto o outro apaga.
  3. Mapa do programa: destaque no código o que pertence ao setup() e o que pertence ao loop(), explicando por quê.

Desafios de adaptação

  1. Pisca rápido e lento: faça o LED alternar entre duas velocidades diferentes.
  2. Padrão personalizado: crie uma sequência em que o LED fique aceso por mais tempo do que apagado.
  3. Registro de depuração: descreva um erro que você encontrou ao montar ou programar e como resolveu.
