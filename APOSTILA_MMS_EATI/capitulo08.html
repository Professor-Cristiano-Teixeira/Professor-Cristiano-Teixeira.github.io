Simulação/Montagem de Circuitos Digitais e Projeto Integrador 2

Este capítulo fecha o 2º bimestre com prática intensiva: você vai projetar uma lógica a partir de requisitos, simular, montar e diagnosticar falhas típicas (entrada flutuante, inversões, mau contato, regra errada). Ao final, você entrega o Projeto Integrador 2: um Sistema Digital de Decisão Simples com documentação técnica.

Objetivos de aprendizagem

  • Transformar requisitos em tabela verdade e expressão lógica (SOP/POS simples).
  • Montar a lógica usando portas (simulador) ou lógica em Arduino (código) e validar.
  • Aplicar De Morgan e simplificação para reduzir complexidade quando fizer sentido.
  • Realizar diagnóstico: detectar inversão, pino flutuante, ligação errada e regra incorreta.
  • Documentar: diagrama, tabela verdade, testes e conclusões.

Pré-requisitos

  • Cap. 05–07: níveis lógicos/pull-up, portas lógicas, tabelas verdade, álgebra booleana e De Morgan.
  • Noções de segurança/organização (Cap. 04) para evitar curtos e erros de bancada.
Ferramentas sugeridas: Tinkercad Circuits (Switches/Logic Gates/Arduino) + multímetro virtual. Em bancada real: protoboard, botões, LEDs, resistores 220Ω/10kΩ e (opcional) CI 74HCxx.

2) Erros comuns em circuitos digitais (e como identificar)

Na prática, muitos erros são recorrentes. Saber reconhecer os sintomas acelera o diagnóstico.

  • Entrada flutuante: leitura muda sozinha → solução: pull-up/pull-down (Cap. 05).
  • Inversão lógica: botão solto/pressionado invertido (pull-up) → solução: inverter no circuito ou no código.
  • Mau contato: comportamento intermitente → solução: continuidade, refazer jumpers e conferir GND comum.
  • Regra errada: montou OR mas precisava AND (ou vice-versa) → solução: comparar com tabela verdade.
  • Alimentação ausente: CI sem Vcc/GND (em portas 74HCxx) → solução: conferir pinos de alimentação.
Regra de ouro: quando algo “parece aleatório”, suspeite primeiro de entrada flutuante ou mau contato.
Onde vou aplicar isso: no passo a passo (diagnóstico guiado) e na rubrica do Projeto Integrador 2 (testes e evidências).

3) Critérios de qualidade em lógica digital (o que um bom circuito deve ter)

  • Comportamento determinístico: mesma entrada → mesma saída (sempre).
  • Entradas definidas: nada de flutuação; use pull-up/pull-down.
  • Documentação: tabela verdade, expressão e diagrama claros.
  • Testes completos: todas as combinações testadas (2 entradas → 4 testes; 3 entradas → 8 testes).

Passo a passo prático: Sistema de decisão (A e B) com simulação + validação por tabela verdade

Vamos implementar um sistema simples e realista: “Acesso Liberado”.
Entradas: A (credencial válida) e B (biometria ok). Saída: Y (acesso liberado) só quando A AND B. Depois, vamos adicionar uma condição alternativa: Modo emergência (E) que libera com OR. (Opcional, extensão)

Definição do problema

Regra base: Y = A AND B. Se A=1 e B=1, libera. Caso contrário, bloqueia. Isso é comum em TI: duas condições precisam ser verdadeiras para liberar (permissão + autenticação).

ABY = A AND BInterpretação
000Nenhuma condição
010Só biometria
100Só credencial
111Liberado

Montagem no Tinkercad: entradas com pull-up (recomendado)

Monte dois botões (A e B) com pull-up para evitar flutuação.

  • Opção 1 (Arduino): use INPUT_PULLUP e ligue cada botão entre pino e GND (mais simples).
  • Opção 2 (sem Arduino): use resistores 10kΩ como pull-down e conecte o botão ao 5V.
Escolha recomendada: Opção 1 com Arduino porque elimina resistor extra e padroniza o laboratório.

Saída: LED “LIBERADO” com resistor

Conecte um LED com resistor 220Ω para indicar a saída Y.

  • LED Y → pino 9 (Arduino) → resistor 220Ω → LED → GND
Não ligue LED sem resistor (pode danificar o LED ou o pino).

Código: implementar Y = A AND B + validação por tabela verdade

O código abaixo lê A e B, calcula AND e imprime a tabela verdade ao iniciar.

// EATI - Capítulo 08
// Sistema de decisão simples: Acesso Liberado
// Regra: Y = A AND B

const int BTN_A = 2;
const int BTN_B = 3;
const int LED_Y = 9;

bool tabelaImpressa = false;

void printTruthTable(){
  Serial.println("\nTABELA VERDADE: Y = A AND B");
  Serial.println("A B | Y");
  for(int A=0; A<=1; A++){
    for(int B=0; B<=1; B++){
      int Y = (A && B);
      Serial.print(A); Serial.print(" ");
      Serial.print(B); Serial.print(" | ");
      Serial.println(Y);
    }
  }
  Serial.println("-------------------------");
}

void setup(){
  pinMode(BTN_A, INPUT_PULLUP);
  pinMode(BTN_B, INPUT_PULLUP);
  pinMode(LED_Y, OUTPUT);
  Serial.begin(9600);
}

void loop(){
  if(!tabelaImpressa){
    printTruthTable();
    tabelaImpressa = true;
  }

  // Pull-up: solto=1, pressionado=0. Inverter para ficar intuitivo: pressionado=1
  int A = (digitalRead(BTN_A) == LOW) ? 1 : 0;
  int B = (digitalRead(BTN_B) == LOW) ? 1 : 0;

  int Y = (A && B);
  digitalWrite(LED_Y, Y);

  Serial.print("A=" ); Serial.print(A);
  Serial.print(" B=" ); Serial.print(B);
  Serial.print(" | Y=" ); Serial.println(Y);

  delay(200);
}
Onde vou aplicar isso: a saída Y segue a tabela verdade e serve como modelo de decisão do Projeto Integrador 2.

Teste sistemático (4 casos)

Teste as 4 combinações e registre os resultados:

  • 00: nenhum botão pressionado → Y=0
  • 01: apenas B → Y=0
  • 10: apenas A → Y=0
  • 11: A e B → Y=1
Evidência: tire print do circuito + print do Serial Monitor mostrando os 4 casos.

Diagnóstico guiado (simule um defeito e corrija)

Escolha 1 defeito proposital e registre o diagnóstico:

  • Defeito 1: inverter a lógica (usar OR no lugar de AND) → corrigir pelo requisito/tabela.
  • Defeito 2: remover pull-up (pino INPUT) → observar flutuação → corrigir com INPUT_PULLUP ou resistor.
  • Defeito 3: mau contato em GND → comportamento intermitente → corrigir cabos e GND comum.
Meta: mostrar que você sabe “ir do sintoma à causa” usando tabela verdade e inspeção de montagem.

Extensão opcional (nível bônus): modo emergência

Adicione uma entrada E (emergência) que libera acesso mesmo sem A e B:

Y = (A AND B) OR E

Crie a tabela verdade com 3 entradas (8 linhas) e implemente com um terceiro botão.

Segurança: na bancada real, evite curto entre 5V e GND. Organize cabos e use resistores nos LEDs. Se medir corrente, lembre: multímetro em série (Cap. 04).

Projeto Integrador 2 (Bimestre 2)

Entrega do B2 Tema: Sistema Digital de Decisão Simples

1) Proposta

Desenvolver um sistema digital que toma uma decisão a partir de entradas (botões/sensores digitais) e aciona uma saída (LED/buzzer/relé simulado). O sistema deve ser descrito por tabela verdade e expressão lógica e deve ser testado em todas as combinações.

2) Requisitos mínimos

  • No mínimo 2 entradas (A e B) e 1 saída (Y). (Bônus: 3 entradas).
  • Uma tabela verdade completa (2 entradas=4 linhas; 3 entradas=8 linhas).
  • Uma expressão lógica (original) e uma tentativa de simplificação (quando aplicável).
  • Implementação em simulação (Tinkercad) e/ou bancada real.
  • Testes completos com registro (prints/fotos + matriz de testes).
  • Diagnóstico: incluir 1 falha proposital e como você corrigiu.

3) Exemplos de temas (escolha 1)

  • Alarme simples: dispara se (porta aberta OR movimento) AND NOT(modo manutenção).
  • Liberação de acesso: libera se (credencial AND biometria) OR emergência.
  • Verificador de condição: LED verde se “OK” e LED vermelho se “falha” com regras lógicas claras.
  • Intertravamento: só liga um atuador se duas condições de segurança forem verdadeiras.

4) Entregáveis

  • Diagrama (foto/print + legenda dos pinos).
  • Tabela verdade e expressão (original e simplificada).
  • Matriz de testes (todas as combinações) com evidência.
  • Relatório técnico curto (1 página ou 20–30 linhas).
