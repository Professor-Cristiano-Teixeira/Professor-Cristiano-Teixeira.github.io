Estruturas de Repetição (for / while) e Projeto Integrador 3

Neste capítulo você aprende a repetir ações de forma controlada no Arduino, usando for, while e do...while. Além disso, você consolida o 3º bimestre com a entrega incremental do Projeto Integrador 3. O foco é técnico: entender quando cada laço é adequado, evitar loops infinitos, usar contadores e criar sequências (ex.: varredura de LEDs).

Objetivos de aprendizagem

  • Escolher corretamente entre for, while e do...while.
  • Construir contadores e sequências repetitivas com segurança.
  • Entender risco de loop infinito e como garantir condição de saída.
  • Usar break e continue com propósito (sem “gambiarras”).
  • Aplicar repetição em um circuito real com LEDs e botões.
  • Planejar e entregar o Projeto Integrador 3 (3º bimestre).

Pré-requisitos

  • Cap. 10: I/O digital (botões, LEDs, INPUT_PULLUP).
  • Cap. 11: decisões com if/else e operadores lógicos.
Sem imagens: conforme solicitado, este capítulo não usa diagramas. A montagem do passo a passo segue o mesmo padrão do Cap. 10 (LED + resistor; botão com INPUT_PULLUP).

1) O que é repetição em programação embarcada?

Repetição é a execução de um bloco de código múltiplas vezes. Em Arduino, já existe um “loop principal” natural: a função loop() roda continuamente. Os laços (for/while) criam repetições dentro do loop(), para executar uma sequência específica.

Em sistemas embarcados, repetição deve ser usada com cuidado: um laço pode bloquear o programa e impedir leitura de entradas. Por isso, é fundamental garantir condição de saída e planejar tempo de execução.

Onde vou aplicar isso: na varredura de LEDs (for) e em espera controlada por evento (while com saída segura).

2) Estrutura for: repetição com contador

Use for quando você sabe quantas vezes quer repetir. Ele possui três partes: inicialização, condição e incremento. O for é ideal para percorrer arrays (lista de pinos) e criar sequências.

for (inicialização; condição; incremento) { // bloco repetido } Ex.: for (int i=0; i<3; i++) { ... }
Erro comum: condição errada (ex.: i<=3) acessa índice inexistente e causa comportamento imprevisível.
Onde vou aplicar isso: ao percorrer a lista de LEDs e ligar um por vez.

3) Estrutura while: repetição baseada em condição

Use while quando a repetição depende de uma condição que pode mudar durante a execução. O bloco executa enquanto a condição for verdadeira. Em embarcados, while pode ser perigoso se a condição nunca mudar (loop infinito).

while (condição) { // repete enquanto condição for verdadeira }
Boa prática: garanta que algo dentro do while altera a condição ou use timeout (saída por tempo/contador).
Onde vou aplicar isso: ao aguardar um evento (botão) com limite de tempo e sem travar permanentemente.

4) Estrutura do...while: executa pelo menos uma vez

O do...while é parecido com while, mas avalia a condição no final. Isso garante que o bloco execute ao menos uma vez. Ele é útil quando você precisa executar uma ação inicial e depois decidir se repete.

do { // executa pelo menos uma vez } while (condição);
Onde vou aplicar isso: em rotinas que sempre devem rodar uma vez antes de validar (ex.: “mostre status e repita se necessário”).

5) Controle de fluxo: break e continue

break encerra o laço imediatamente. continue pula para a próxima repetição. Esses comandos não substituem lógica bem feita, mas são úteis em casos específicos: encerrar uma busca ao encontrar um item, ou ignorar um caso inválido.

Onde vou aplicar isso: ao interromper a sequência quando um botão de parada for acionado.

6) Loop infinito e travamento: como prevenir

Um loop infinito ocorre quando a condição de saída nunca é atingida. Em Arduino, isso pode “travar” a resposta a entradas e exigir reset. As principais causas são: variável não incrementada, condição impossível, ou depender de um evento que não acontece.

  • Garanta progressão: contador aumenta/diminui em direção à saída.
  • Use limites: timeout por contagem/tempo.
  • Evite while bloqueante quando precisar ler entradas continuamente (ver Cap. 15 para temporização sem delay).
Exemplo de risco: while(digitalRead(BTN)==LOW){} bloqueia o programa se o botão ficar pressionado ou se houver ruído.

Passo a passo prático: sequência de LEDs com for + parada com while

Objetivo: criar uma varredura de 3 LEDs usando for e permitir que um botão pare a sequência. Esta prática integra: I/O digital (Cap. 10), decisão (Cap. 11) e repetição (Cap. 12).

Componentes e ligações (mesmo padrão do Cap. 10)

Use 3 LEDs com resistores em série e 1 botão com INPUT_PULLUP. Sugestão de pinos: LEDs em D9, D10, D11 e botão em D2.

  • LEDs: pino → resistor (220–330Ω) → LED → GND
  • Botão: pino D2 ↔ botão ↔ GND (com INPUT_PULLUP)
  • Importante: GND comum para todos os componentes.

Estratégia do programa (antes de codificar)

1) Guardar os pinos dos LEDs em um array. 2) Usar for para acender um LED por vez (varredura). 3) A cada passo, verificar se o botão foi pressionado; se sim, entrar em um while de “pausa” até soltar.

Por que esperar soltar? evita múltiplos acionamentos (bounce). No Cap. 15 você fará isso sem delay.

Código 1 — Varredura com for e botão de pausa

// EATI - Capítulo 12
// Varredura de LEDs com for + pausa com while

const int BTN = 2;                 // botão (INPUT_PULLUP)
int leds[] = {9, 10, 11};          // lista de pinos
const int N = 3;                   // quantidade de LEDs

void setup(){
  pinMode(BTN, INPUT_PULLUP);
  for(int i=0; i<N; i++){
    pinMode(leds[i], OUTPUT);
    digitalWrite(leds[i], LOW);
  }
}

void loop(){
  // Varre LEDs do 0 ao N-1
  for(int i=0; i<N; i++){
    // Se botão pressionado (LOW), pausa até soltar
    if(digitalRead(BTN) == LOW){
      // Apaga tudo durante a pausa
      for(int j=0; j<N; j++) digitalWrite(leds[j], LOW);

      // while de pausa: espera soltar para continuar
      while(digitalRead(BTN) == LOW){
        // loop vazio proposital (curto)
      }
    }

    // Acende o LED atual
    digitalWrite(leds[i], HIGH);
    delay(200);
    digitalWrite(leds[i], LOW);
  }
}
Onde vou aplicar isso: em sequências como semáforo (Cap. 12) e temporização sem travar (Cap. 15).

Melhoria técnica (opcional): saída segura do while (timeout por contador)

Se o botão travar (defeito), o while pode prender o programa. Uma saída por contador limita o tempo preso no laço. A seguir, um exemplo didático. (No Cap. 15, usaremos millis() para fazer isso melhor.) 

// Ideia: timeout por contagem (didático)
int tentativas = 0;
while(digitalRead(BTN) == LOW && tentativas < 50000){
  tentativas++; // garante saída mesmo se o botão falhar
}
Interpretação: não é tempo real exato; é só uma forma simples de evitar loop infinito.
Segurança: LEDs sempre com resistor. Use GND comum. Evite while infinito em sistemas que precisam responder a eventos.

Projeto Integrador 3 (Entrega do 3º Bimestre)

Objetivo do bimestre: integrar I/O digital + decisão + repetição em um sistema funcional e documentado.

1) Tema e proposta

Desenvolver um sistema sequencial com regras que use entradas (botões/sensores) e saídas (LEDs/buzzer), contendo decisões (if/else) e repetição (for ou while). O sistema deve ter comportamento claro, testável e documentado.

Exemplos de tema: semáforo com botão de pedestre; painel de acesso (liberado/bloqueado); contador de eventos com alerta; sequência de LEDs com modos.

2) Requisitos mínimos (obrigatórios)

  • Usar pelo menos 2 entradas (ex.: 2 botões, ou 1 botão + 1 sensor digital).
  • Usar pelo menos 2 saídas (mínimo 2 LEDs; opcional buzzer).
  • Ter pelo menos 1 decisão com if/else (ou cadeia else if).
  • Ter pelo menos 1 laço de repetição (for ou while) com finalidade clara.
  • Montagem organizada (GND comum, resistores em LEDs) e funcionamento demonstrável.

3) Entregáveis

  • Código comentado (explicando decisões e laços).
  • Foto/print da montagem no Tinkercad ou foto da protoboard real.
  • Relatório curto (12 a 18 linhas): objetivo, entradas, saídas, regras e testes.

4) Critérios de avaliação (rubrica simples)

CritérioO que será observadoPeso
FuncionamentoProjeto executa as regras corretamente e responde às entradas40%
Uso de conceitosAplicação correta de if/else e for/while com propósito30%
MontagemResistores, GND comum, organização e segurança15%
DocumentaçãoCódigo comentado + relatório + evidência (foto/print)15%
Dica de desenvolvimento: comece com um “modo básico” funcionando e depois adicione modos/alertas. Teste cada parte isoladamente.
