Temporização com millis() — Programação sem delay

Neste capítulo você aprende a controlar o tempo no Arduino usando millis(), evitando o uso de delay(). Esse conceito é essencial para sistemas que precisam executar várias tarefas ao mesmo tempo.

Objetivos de aprendizagem

  • Entender por que evitar delay().
  • Usar millis() para controle de tempo.
  • Criar temporizações não bloqueantes.
  • Aplicar millis() em projetos reais.

Pré-requisitos

  • Cap. 09–14: Arduino, decisões, repetição e variáveis.
  • Noções básicas de lógica de programação.

1) Por que evitar delay()

A função delay() pausa completamente o programa. Durante esse tempo, o Arduino não consegue ler sensores nem responder a eventos.

Onde vou aplicar isso: em sistemas que precisam responder a botões enquanto executam outras tarefas.

2) O que é millis()

A função millis() retorna o tempo, em milissegundos, desde que o Arduino foi ligado. Com ela, conseguimos verificar intervalos de tempo sem travar o programa.

Onde vou aplicar isso: para criar temporizadores e piscas sem bloquear o loop.

3) Temporização não bloqueante

Usando millis(), o loop continua rodando normalmente. Isso permite executar várias lógicas ao mesmo tempo.

Dica: millis() é essencial em projetos profissionais e integradores.

Passo a passo prático: LED piscando com millis()

Objetivo: piscar um LED sem usar delay().

Componentes

  • Arduino UNO
  • 1 LED + resistor 220Ω

Ligações

  • LED → pino 9 ↔ resistor ↔ LED ↔ GND

Código

// Capítulo 15 - Temporização com millis

const int LED = 9;
unsigned long tempoAnterior = 0;
const long intervalo = 500;
bool estadoLed = false;

void setup(){
  pinMode(LED, OUTPUT);
}

void loop(){
  unsigned long tempoAtual = millis();

  if(tempoAtual - tempoAnterior >= intervalo){
    tempoAnterior = tempoAtual;
    estadoLed = !estadoLed;
    digitalWrite(LED, estadoLed);
  }
}

Atividades práticas derivadas

  • Criar dois LEDs piscando em tempos diferentes.
  • Adicionar um botão que pause o pisca.
  • Usar millis() para criar um semáforo.
