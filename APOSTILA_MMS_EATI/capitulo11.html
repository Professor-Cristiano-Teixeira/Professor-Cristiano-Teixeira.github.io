Estruturas de Decisão (if / else) no Arduino

Depois de dominar I/O digital (Cap. 10), você precisa transformar leituras em regras. Este capítulo aprofunda if, else e else if, operadores relacionais e lógicos, precedência e boas práticas para decisões seguras em sistemas embarcados.

Objetivos de aprendizagem

  • Escrever decisões simples e múltiplas com if, else e else if.
  • Usar operadores relacionais (==, !=, >, <, etc.) e lógicos (&&, ||, !).
  • Entender precedência e usar parênteses para evitar ambiguidade.
  • Implementar regras de segurança (intertravamento) com múltiplas entradas.
  • Evitar erros comuns: = vs ==, lógica invertida com pull-up, decisões inacessíveis.

Pré-requisitos

  • Cap. 10: INPUT_PULLUP, leitura de botões e saída para LEDs.
  • Cap. 06: lógica AND/OR/NOT e tabela verdade (visão conceitual).
Ferramentas: Tinkercad Circuits ou Arduino UNO + protoboard. Diagramas incluídos para montagem.

1) Decisão em sistemas embarcados: por que if é fundamental

Em sistemas embarcados, o programa roda continuamente (loop). A cada ciclo, ele lê entradas e decide o que fazer. A estrutura if é o mecanismo básico para selecionar ações com base em condições.

Exemplo típico: “Se o botão estiver pressionado, ligue o LED”. Mas em projetos reais, você combina várias entradas, define prioridades (segurança primeiro) e trata estados (ex.: alerta, normal, falha).

Onde vou aplicar isso: no passo a passo, criando regras com 2 botões (AND/OR), e prioridades com else if.

2) Estrutura if, else e else if (decisão simples e múltipla)

if executa um bloco quando a condição é verdadeira. else é o caminho alternativo. else if cria uma cadeia de decisões, útil quando existem vários casos mutuamente exclusivos.

if (condição) { // caminho A } else if (outraCondição) { // caminho B } else { // caminho padrão }
Dica técnica: a ordem do else if importa. O primeiro caso verdadeiro “vence”.
Onde vou aplicar isso: ao implementar prioridades (ex.: emergência > alerta > normal).

3) Operadores relacionais e o erro clássico = vs ==

Operadores relacionais comparam valores e geram verdadeiro/falso. Os mais usados com I/O digital: == (igual) e != (diferente).

Erro comum: usar = (atribuição) no lugar de == (comparação). Isso pode causar comportamento inesperado, porque você altera a variável em vez de comparar.

Onde vou aplicar isso: ao ler botões (LOW/HIGH) e criar a variável booleana pressionado.

4) Operadores lógicos: AND, OR e NOT na prática

Operadores lógicos combinam condições: && (AND) exige que ambas sejam verdadeiras; || (OR) exige que pelo menos uma seja verdadeira; ! (NOT) inverte o valor.

Isso permite implementar regras de segurança e permissões, por exemplo: “Ligar motor apenas se botão A e botão B estiverem pressionados” (duas mãos).

Onde vou aplicar isso: no passo a passo, criando LEDs para AND/OR e um intertravamento de segurança.

5) Precedência e parênteses (evite decisões ambíguas)

Em expressões com vários operadores, existe uma ordem de avaliação (precedência). Em geral, ! vem antes de &&, que vem antes de ||. Comparações (==, !=) ocorrem antes das combinações lógicas.

// Exemplo de ambiguidade: A || B && C // Forma recomendada (explícita): A || (B && C)
Boa prática: use parênteses sempre que houver combinação de AND/OR para evitar dúvidas e bugs.
Onde vou aplicar isso: ao escrever regras compostas no passo a passo (prioridades e permissões).

6) Decisões seguras: prioridade e intertravamento (safety first)

Em automação, decisões têm prioridade. Um exemplo: se um botão de emergência estiver ativo, ele deve vencer qualquer outra condição. Isso é implementado colocando a condição de emergência primeiro em uma cadeia if/else if.

Intertravamento (interlock) é uma regra que impede que uma saída ligue em condição insegura. No ensino técnico, o exemplo clássico é “duas mãos” (AND) ou “porta fechada” (sensor) antes de permitir acionamento.

Onde vou aplicar isso: no passo a passo, criando uma regra de emergência > permitido > bloqueado.

Passo a passo prático: decisões AND/OR + prioridade (else if)

Objetivo: ler dois botões (pull-up) e acender LEDs conforme regras AND/OR, com prioridade de alerta.

Montagem (hardware)

Monte conforme o Diagrama A. Use resistores (220–330 Ω) em todos os LEDs e garanta GND comum.

Programa 1 — AND e OR (dois LEDs)

Aqui você transforma leituras em lógica: A e B são booleans (pressionado=true). AND liga o LED_AND; OR liga o LED_OR. 

// EATI - Capítulo 11
// Programa 1: AND e OR com 2 botões

const int BTN_A = 2;
const int BTN_B = 3;
const int LED_AND = 9;
const int LED_OR  = 10;

void setup(){
  pinMode(BTN_A, INPUT_PULLUP);
  pinMode(BTN_B, INPUT_PULLUP);
  pinMode(LED_AND, OUTPUT);
  pinMode(LED_OR, OUTPUT);
}

void loop(){
  bool A = (digitalRead(BTN_A) == LOW);
  bool B = (digitalRead(BTN_B) == LOW);

  bool condAND = (A && B);
  bool condOR  = (A || B);

  digitalWrite(LED_AND, condAND ? HIGH : LOW);
  digitalWrite(LED_OR,  condOR  ? HIGH : LOW);
}
Onde vou aplicar isso: no Cap. 12 (repetição) você criará sequências baseadas em condições.

Programa 2 — Prioridade com else if (ALERTA vence)

Agora definimos prioridade: se A e B estiverem pressionados ao mesmo tempo, acende ALERTA (D11). Caso contrário, se apenas um estiver pressionado, acende OR. Caso nenhum, tudo apagado. Isso demonstra a lógica de cadeia if/else if/else. 

// EATI - Capítulo 11
// Programa 2: Prioridade com else if

const int BTN_A = 2;
const int BTN_B = 3;
const int LED_AND = 9;
const int LED_OR  = 10;
const int LED_ALERTA = 11;

void setup(){
  pinMode(BTN_A, INPUT_PULLUP);
  pinMode(BTN_B, INPUT_PULLUP);
  pinMode(LED_AND, OUTPUT);
  pinMode(LED_OR, OUTPUT);
  pinMode(LED_ALERTA, OUTPUT);
}

void loop(){
  bool A = (digitalRead(BTN_A) == LOW);
  bool B = (digitalRead(BTN_B) == LOW);

  // Limpa tudo
  digitalWrite(LED_AND, LOW);
  digitalWrite(LED_OR, LOW);
  digitalWrite(LED_ALERTA, LOW);

  if(A && B){
    // Prioridade 1
    digitalWrite(LED_ALERTA, HIGH);
  }
  else if(A || B){
    // Prioridade 2
    digitalWrite(LED_OR, HIGH);
  }
  else{
    // Prioridade 3 (nenhuma condição)
    // Tudo apagado
  }
}
Boa prática: sempre deixe claro a prioridade no código (condições mais críticas primeiro).

Teste e diagnóstico (2 minutos, método técnico)

Verifique estes casos (registre resultado):

  • Nenhum botão pressionado → todos os LEDs apagados
  • A pressionado → LED_OR aceso
  • B pressionado → LED_OR aceso
  • A e B pressionados → LED_ALERTA aceso
Se falhar: confirme INPUT_PULLUP, inversão (LOW=pressionado), GND comum e resistores.
Segurança: LED sempre com resistor. Não ligue cargas pesadas direto em pinos. Intertravamento e prioridade são conceitos de segurança.

Atividades práticas derivadas (para o aluno desenvolver)

  • Regra de permissão: acender LED “PERMITIDO” somente se (A AND B) e um LED “BLOQUEADO” caso contrário.
  • Seleção por prioridade: criar 3 estados (Normal/Alerta/Emergência) e controlar LEDs com else if (sem usar delay).
  • Alarme simples: botão A arma/desarma e botão B dispara alerta (quando armado). Use variáveis de estado (prepara Cap. 14/15).
