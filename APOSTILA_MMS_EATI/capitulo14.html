Variáveis Globais, Locais e Escopo (com foco em sistemas embarcados)

No Arduino, muitos bugs não são “erro de lógica”, e sim erro de estado: variável errada sendo modificada, valor que “some”, contador que “salta” e travamentos por falta de SRAM. Este capítulo explica escopo e tempo de vida de variáveis (globais/locais), o impacto na memória (stack/heap) e técnicas seguras para manter o estado do sistema.

Objetivos de aprendizagem

  • Definir escopo (visibilidade) e tempo de vida (lifetime).
  • Distinguir variáveis globais, locais e de bloco, e quando usar cada uma.
  • Compreender stack/heap/SRAM e por que isso importa no Arduino.
  • Evitar shadowing (sombreamento) e efeitos colaterais.
  • Aplicar const e static para segurança e organização.
  • Entender referência (&) e introdução a volatile (uso correto).

Pré-requisitos

  • Cap. 13: funções e modularização.
  • Cap. 10–12: I/O digital, decisão e repetição.
  • Cap. 09: noções de memória (recomendado).

1) Escopo e tempo de vida: as duas perguntas que evitam 80% dos bugs

Para qualquer variável, responda sempre: (a) Quem consegue ver essa variável? (escopo) e (b) por quanto tempo ela existe? (tempo de vida). Em C/C++, escopo é delimitado por blocos { }. O tempo de vida costuma acompanhar o escopo — com exceções como static.

Em sistemas embarcados, escopo não é só “organização”: ele define segurança do código. Quanto mais variável fica visível, maior a chance de ser alterada por engano.

Onde vou aplicar isso: ao separar variáveis de configuração (const globais) de variáveis temporárias (locais) e de estado (globais controladas).

2) Memória no Arduino (SRAM): stack, heap e por que isso afeta escopo

No Arduino UNO (ATmega328P), a SRAM é limitada. Duas regiões são especialmente relevantes: stack (onde vivem variáveis locais e chamadas de função) e heap (alocações dinâmicas, usadas indiretamente por algumas Strings/bibliotecas). Se stack e heap “se encostam”, o programa pode travar ou reiniciar.

A regra prática é: evite alocação dinâmica e evite criar arrays grandes como variáveis locais. Prefira estruturas pequenas, e use const para valores fixos.

Dica técnica: em projetos maiores, prefira char[] ou textos curtos a String em excesso. Strings podem fragmentar heap.
Onde vou aplicar isso: ao definir listas de pinos como const int[] globais e manter temporários como variáveis locais pequenas.

3) Variáveis globais: quando usar (e como reduzir risco)

Variáveis globais existem durante toda a execução e são visíveis em várias funções. Elas são úteis para: configuração (pinos, limites) e estado do sistema (modo, contador, flags).

O problema é o acoplamento: qualquer função pode alterar e gerar efeitos colaterais. A solução técnica é limitar globais ao mínimo e criar funções específicas para modificar estado (padrão “estado controlado”).

Onde vou aplicar isso: no passo a passo, o contador será global, mas só será alterado por funções que aplicam limites.

4) Variáveis locais e de bloco: por que são preferíveis para temporários

Variáveis locais são criadas quando a função inicia e destruídas ao final. Isso reduz interferência entre partes do programa. Variáveis de bloco (dentro de if, for) têm escopo ainda menor.

No Arduino, variáveis locais também ajudam a controlar consumo de SRAM: se você não precisa que um valor exista o tempo todo, não o mantenha global.

Onde vou aplicar isso: leitura do botão e cálculos intermediários serão locais; somente o estado persistente ficará global.

5) Shadowing (sombreamento): o bug silencioso mais comum

Shadowing acontece quando uma variável local tem o mesmo nome de outra variável em escopo externo. A local “esconde” a externa. O código compila, mas o comportamento fica errado.

int contador = 0; // global void loop(){ int contador = 10; // SOMBRA a global contador++; // altera a local // a global continua 0 }
Boa prática: evite nomes repetidos. Use nomes descritivos (ex.: contadorCliques) ou prefixos para globais.
Onde vou aplicar isso: no passo a passo, você vai observar o erro e corrigir renomeando/organizando escopo.

6) const: deixar claro o que é configuração (e impedir alterações acidentais)

const transforma um valor em “somente leitura” após inicialização. Isso é essencial para pinos e limites. Além de evitar bugs, melhora manutenção: você encontra rapidamente onde estão as configurações do projeto.

const int LED = 9; const int BTN = 2; const int MAX_CONT = 5;
Onde vou aplicar isso: pinos e limites serão const no topo do código.

7) static local: estado persistente sem “poluir” o global

static em variável local faz ela persistir entre chamadas, mas mantém o escopo dentro da função. É perfeito para memorizar o estado anterior de um botão (detectar borda) sem criar global.

bool cliqueBorda(bool atual){ static bool anterior = false; bool clique = (atual && !anterior); anterior = atual; return clique; }
Cuidado: static é “estado escondido”. Use quando for realmente um detalhe interno da função.
Onde vou aplicar isso: detectar clique (borda) para não contar várias vezes por causa de bounce.

8) Referência (&) e volatile: visão técnica no nível certo

8.1 Passagem por referência

Quando você passa por referência, a função altera a variável original. Isso permite atualizar estado de forma centralizada, sem depender de globais acessadas por todo o código.

void incrementarComLimite(int &valor, int max){ if(valor < max) valor++; }
Onde vou aplicar isso: atualizar o contador com limite de segurança (evitar valores inválidos).

8.2 Volatile (introdução)

volatile é usado quando uma variável pode mudar fora do fluxo normal (por exemplo, em uma interrupção). Ele impede otimizações que fariam o programa ler um valor “antigo”. Para leituras comuns de botão com digitalRead(), normalmente não é necessário.

Ponte: se você usar interrupções (conteúdo avançado), volatile passa a ser obrigatório em variáveis compartilhadas.

Passo a passo prático (curto e objetivo): contador de cliques sem bagunça de escopo

Embora este capítulo seja mais conceitual, uma prática curta ajuda a fixar. Você fará um contador de cliques com: const (configuração), estado global controlado (contador) e static (borda do botão).

Montagem (padrão já usado)

Use 1 LED em D9 com resistor e 1 botão em D2 com INPUT_PULLUP. (Sem diagrama, conforme solicitado.)

  • LED: D9 → resistor 220–330Ω → LED → GND
  • Botão: D2 ↔ botão ↔ GND (INPUT_PULLUP)
  • GND comum

Implementação
