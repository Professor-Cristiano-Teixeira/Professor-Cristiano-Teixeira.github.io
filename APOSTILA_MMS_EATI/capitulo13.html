Funções e Organização de Código no Arduino

À medida que seus projetos crescem, copiar e colar código vira fonte de erro. Neste capítulo, você aprende a criar funções para organizar o programa, reduzir repetição, facilitar testes e manutenção. O foco é técnico: assinatura de funções, parâmetros, retorno, protótipos, passagem de dados e boas práticas de refatoração.

Objetivos de aprendizagem

  • Explicar o que é uma função e por que modularizar.
  • Criar funções void e funções com return.
  • Usar parâmetros para tornar rotinas reutilizáveis.
  • Entender protótipos e a ordem das definições no Arduino IDE.
  • Reconhecer passagem por valor e efeitos em arrays (ponteiros).
  • Aplicar boas práticas: nomes, coesão, const, comentários e testes.

Pré-requisitos

  • Cap. 10–12: I/O digital, decisão e repetição.
  • Conhecimento básico de variáveis e tipos (int, bool).
Observação: sem imagens neste capítulo (conforme preferência recente). A prática usa o mesmo padrão de montagem do Cap. 10 (LED + resistor; botão com INPUT_PULLUP).

1) O que é uma função (e por que isso melhora projetos)

Uma função é um bloco de código com um nome, que pode ser executado quando você a chama. Em vez de repetir o mesmo trecho em vários lugares, você cria uma função e reutiliza. Isso melhora legibilidade, reduz erros e facilita manutenção.

Em sistemas embarcados, funções também ajudam a separar responsabilidades: leitura de sensores, cálculo de regras e acionamento de atuadores. Essa separação torna o comportamento mais previsível e simplifica depuração.

Onde vou aplicar isso: no passo a passo, ao transformar a varredura de LEDs e a pausa por botão em funções reutilizáveis.

2) Assinatura da função: retorno, nome e parâmetros

A assinatura de uma função descreve como ela é usada: tipo de retorno + nome + parâmetros. Parâmetros são as “entradas” da função; o retorno é a “saída”.

tipo_retorno nomeDaFuncao(tipo1 p1, tipo2 p2, ...) { // corpo return valor; // quando não for void } // Exemplos: void ligarLed(int pino); bool botaoPressionado(int pino); int limitar(int valor, int min, int max);
Onde vou aplicar isso: criando bool botaoPressionado(...) e void setAll(...) para controlar LEDs.

3) Funções void vs funções com return

Use void quando a função executa uma ação e não precisa devolver um valor (ex.: acender LED, imprimir no serial). Use retorno quando você precisa calcular e devolver um resultado (ex.: estado do botão, validação, conversões).

Boa prática: funções com retorno devem ter caminho de retorno claro em todos os casos; isso evita comportamento indefinido.
Onde vou aplicar isso: retorno booleano para botão e retorno de índice na varredura.

4) Escopo básico e variáveis (ponte para o Cap. 14)

Variáveis declaradas dentro de uma função são, em geral, locais a ela. Isso evita interferência entre partes do código. Variáveis globais (fora das funções) ficam acessíveis em todo o programa, mas podem aumentar acoplamento.

Neste capítulo usamos poucas globais (pinos e estados). No Cap. 14 você vai aprofundar escopo e boas práticas para projetos maiores.

Onde vou aplicar isso: mantendo estados do sistema (ex.: modo) como variáveis globais controladas e cálculos temporários como locais.

5) Protótipos e ordem das funções no Arduino

Em C/C++, uma função precisa ser conhecida antes de ser chamada. O Arduino IDE normalmente gera protótipos automaticamente, mas isso pode falhar em casos específicos (especialmente com tipos complexos). Em projetos mais técnicos, é comum declarar protótipos manualmente no topo.

// Protótipos (declarações) bool botaoPressionado(int pino); void setAll(const int* pinos, int n, bool estado); // Depois: setup(), loop() e as definições completas
Onde vou aplicar isso: no passo a passo, declarando protótipos para deixar o código organizado.

6) Passagem de parâmetros: valor, referência e arrays

Por padrão, tipos simples (int, bool, float) são passados por valor: a função recebe uma cópia. Isso evita que a função altere a variável original, mas pode custar memória em estruturas grandes.

Arrays, na prática, se comportam como ponteiros: ao passar um array, você passa o endereço do primeiro elemento. Isso significa que a função pode modificar o conteúdo do array. Por isso, quando a função não deve alterar, use const.

Onde vou aplicar isso: passando a lista de LEDs como array para funções de varredura e “setAll”.

7) Boas práticas de modularização (nível técnico)

  • Coesão: uma função deve ter uma responsabilidade principal.
  • Nomes claros: verbos para ações (ex.: setAll, sweepLeds), substantivos para dados.
  • Evite “efeitos colaterais” desnecessários: funções que alteram variáveis globais devem deixar isso claro.
  • Const e leitura: marque como const o que não deve ser alterado (pinos, arrays de pinos).
  • Teste por partes: valide cada função isoladamente antes de integrar.
Regra prática: se você está copiando o mesmo bloco 2–3 vezes, provavelmente é hora de criar uma função.

Passo a passo prático: refatorando a varredura de LEDs com funções

Objetivo: transformar um código “monolítico” (tudo dentro do loop) em um código modular. Você vai reaproveitar o padrão do Cap. 12: 3 LEDs (D9, D10, D11) e 1 botão (D2 com INPUT_PULLUP).

Montagem (hardware)

Use o mesmo padrão já consolidado: LED com resistor em série para o GND e botão entre pino e GND. Pinos sugeridos: LEDs em 9, 10, 11 e botão em 2.

  • LEDs: pino → resistor (220–330Ω) → LED → GND
  • Botão: D2 ↔ botão ↔ GND (INPUT_PULLUP)
  • GND comum em toda a montagem

Planejamento das funções

Vamos criar funções com responsabilidades claras:

  • botaoPressionado(pino) → retorna true quando pressionado (trata LOW com pull-up)
  • setAll(pinos, n, estado) → liga/desliga todos os LEDs
  • pausarEnquantoPressionado(pino, pinos, n) → pausa de forma segura (apaga LEDs e espera soltar)
  • sweep(pinos, n, atrasoMs, botao) → faz a varredura
Onde vou aplicar isso: no código final, o loop() ficará pequeno e legível.

Código refatorado (com protótipos e funções)

// EATI - Capítulo 13
// Funções e organização de código (refatoração)

const int BTN = 2;
const int leds[] = {9, 10, 11};
const int N = 3;

// Protótipos (declarações)
bool botaoPressionado(int pino);
void setAll(const int* pinos, int n, bool estado);
void pausarEnquantoPressionado(int pinoBotao, const int* pinos, int n);
void sweep(const int* pinos, int n, int atrasoMs, int pinoBotao);

void setup(){
  pinMode(BTN, INPUT_PULLUP);
  for(int i=0; i<N; i++){
    pinMode(leds[i], OUTPUT);
    digitalWrite(leds[i], LOW);
  }
}

void loop(){
  sweep(leds, N, 200, BTN);
}

// ---------------- Funções ----------------

bool botaoPressionado(int pino){
  // Com INPUT_PULLUP: pressionado = LOW
  return (digitalRead(pino) == LOW);
}

void setAll(const int* pinos, int n, bool estado){
  for(int i=0; i<n; i++){
    digitalWrite(pinos[i], estado ? HIGH : LOW);
  }
}

void pausarEnquantoPressionado(int pinoBotao, const int* pinos, int n){
  // Apaga tudo durante a pausa
  setAll(pinos, n, false);

  // Espera soltar
  while(botaoPressionado(pinoBotao)){
    // laço curto proposital
  }
}

void sweep(const int* pinos, int n, int atrasoMs, int pinoBotao){
  for(int i=0; i<n; i++){
    if(botaoPressionado(pinoBotao)){
      pausarEnquantoPressionado(pinoBotao, pinos, n);
    }

    digitalWrite(pinos[i], HIGH);
    delay(atrasoMs);
    digitalWrite(pinos[i], LOW);
  }
}
Observação: ainda usamos delay(). No Cap. 15 você vai transformar temporização em não-bloqueante com millis().

Validação e diagnóstico

Confirme estes comportamentos:

  • Varredura ocorre em sequência (um LED por vez).
  • Ao pressionar o botão, a varredura pausa e todos os LEDs apagam.
  • Ao soltar o botão, a varredura continua do ponto atual.
Se falhar: revise INPUT_PULLUP (LOW=pressionado), GND comum e resistores em série.
Segurança: LEDs sempre com resistor. Evite while infinito — em projetos maiores, use timeout ou temporização (Cap. 15).

Atividades práticas derivadas (para o aluno desenvolver)

  • Modo de operação: crie uma variável modo (0/1/2) e uma função trocarModo() acionada por botão; cada modo altera a varredura.
  • Debounce modular: implemente bool cliqueConfirmado(...) com debounce simples; depois substitua no código principal.
  • Sequência personalizada: crie uma função sweepBidirecional() (vai e volta) sem duplicar código.
