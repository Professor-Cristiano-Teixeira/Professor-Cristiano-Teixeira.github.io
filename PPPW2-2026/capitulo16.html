Capítulo 16 — Entrega Final (B4): Projeto Completo + Revisão Geral

Chegamos à entrega final! Neste capítulo você consolida o projeto da lanchonete, revisa os principais tópicos do curso (PHP, MySQL, CRUD, sessões, autenticação, API, Fetch e segurança) e prepara uma apresentação objetiva com evidências.

Bimestre 4 Carga: ~100 min Entrega: Projeto final + apresentação

Ao final você será capaz de:

  • Entregar um sistema funcional com CRUD, carrinho, login e API.
  • Apresentar o projeto com evidências (prints/rotas/testes) e roteiro.
  • Aplicar um checklist final de segurança e qualidade.
  • Organizar a entrega com README, script SQL e instruções claras.

Objetivos de aprendizagem

  • Consolidar funcionalidades: Catálogo, Carrinho, Admin (CRUDs), Login/Logout, RBAC e API.
  • Padronizar UI/UX (mensagens, navegação, erros) e evitar regressões.
  • Empacotar entrega: código, banco, evidências e documentação.
  • Aplicar revisão final de segurança (SQLi/XSS/CSRF/sessões/roles).
  • Preparar apresentação com roteiro e demonstração ao vivo.
  • Checklist final com itens obrigatórios e extras.

Onde será aplicado: no pacote de entrega do projeto e na apresentação final do sistema.

Revisão geral (mapa do que foi construído)

Front-end

  • HTML/CSS padrão do curso
  • Fetch/AJAX para ações assíncronas
  • UX: mensagens e navegação

Back-end

  • PHP (funções, sessões, POO)
  • Camadas: DAO / Service / Controller
  • Autenticação e RBAC

Dados e Segurança

  • MySQL + PDO
  • API REST com JSON e status codes
  • Segurança: prepared, esc, CSRF, cookies

Escopo mínimo para entrega final

  • Catálogo público com busca/filtros e paginação.
  • Carrinho em sessão (adicionar/remover/atualizar/total).
  • Admin protegido por login (CRUD de categorias e itens/bebidas).
  • RBAC: pelo menos admin vs usuário comum (ou viewer).
  • API REST do recurso itens (GET/POST/PUT/DELETE) e consumo via Fetch em pelo menos 1 fluxo.
  • Segurança aplicada: SQLi/XSS/CSRF/sessões.

Dica de ouro: a entrega final precisa ser fácil de rodar. Um bom README vale muitos pontos.

Passo a passo — Como finalizar e empacotar o projeto

1) Checklist técnico rápido (antes de empacotar)

  • Verifique links e navegação entre páginas (index, capítulos, admin, catálogo, carrinho).
  • Valide CRUDs: criar/editar/excluir funcionando e com mensagens.
  • Confira login/logout e proteção do admin (sem login não entra).
  • Teste API: GET lista, GET id, POST/PUT/DELETE (se admin).
  • Teste Fetch: adicionar ao carrinho e atualização do resumo sem reload.

2) Checklist de segurança (mínimo)

  • SQLi: nenhum SQL concatenado com entrada do usuário.
  • XSS: todos os prints no HTML com htmlspecialchars (esc).
  • CSRF: formulários sensíveis com token e verificação.
  • Sessão: regeneração de ID no login; cookie HttpOnly e SameSite.
  • RBAC: operações administrativas bloqueadas para não-admin.

4) Crie um database/script.sql confiável

Inclua criação de banco, tabelas, índices e pelo menos 1 usuário admin.

-- database/script.sql (exemplo)
CREATE DATABASE IF NOT EXISTS lanchonete CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE lanchonete;

-- tabelas categoria, item, usuario, usuario_token ...
-- inserts iniciais ...

-- IMPORTANTE: senha_hash deve ser gerado com password_hash no PHP e colado aqui.

5) README (modelo sugerido)

# Projeto Lanchonete — Programação Web 2

## Requisitos
- XAMPP (Apache + MySQL)
- PHP 8.x (ou compatível do XAMPP)
- MySQL 5.7+/8+

## Instalação
1. Copie a pasta `lanchonete/` para `htdocs/`
2. Inicie Apache e MySQL no XAMPP
3. Importe `database/script.sql` no phpMyAdmin
4. Acesse: http://localhost/lanchonete/public/catalogo_db.php

## Acesso Admin
- URL: http://localhost/lanchonete/public/login.php
- Email: admin@exemplo.com
- Senha: admin123

## Rotas principais
- Catálogo: /public/catalogo_db.php
- Carrinho: /public/carrinho.php
- Admin: /public/admin/index.php
- API: /public/api/index.php/itens

## Evidências
- Prints / vídeo curto (opcional)

6) Apresentação (5–8 min)

  1. Problema e objetivo do sistema (30s)
  2. Arquitetura (DAO/Service/Controller) e banco (1min)
  3. Demo: catálogo + carrinho (1–2min)
  4. Demo: login + admin CRUD (1–2min)
  5. Demo: API + Fetch (1min)
  6. Segurança aplicada (1min)
  7. Encerramento e próximos passos (30s)
Resumo: Empacote com clareza (README + SQL), teste os fluxos principais e apresente com foco em valor e evidências.

Entrega Final (B4) — Requisitos e Rubrica

Requisitos mínimos (obrigatórios)

  • Catálogo via MySQL com busca/filtro/paginação.
  • Carrinho por sessão com total e atualização.
  • Login/Logout com password_hash/verify e proteção do Admin.
  • RBAC (admin vs viewer/editor) aplicado no Admin e na API.
  • API REST (itens) com JSON e status codes.
  • Segurança: prepared + escape + CSRF + sessão segura.
  • README e script.sql para reproduzir.

Extras (diferenciais)

  • Export CSV / relatório por categoria
  • Logs de auditoria (quem alterou o quê)
  • Toast notifications e UX refinada
  • CSP mínima aplicada
  • Testes automatizados simples (opcional)

Rubrica (sugestão)

Critério O que será avaliado Peso
Funcionalidade Fluxos completos: catálogo, carrinho, admin, API 40%
Qualidade/Organização Estrutura, camadas, legibilidade, reutilização 20%
Segurança Prepared, esc, CSRF, sessão, RBAC, erros 25%
Documentação README + script SQL + instruções claras 10%
Apresentação Clareza, demonstração e domínio do que foi feito 5%
Entrega: envie um .zip (ou repositório) contendo o projeto completo e o database/script.sql.
