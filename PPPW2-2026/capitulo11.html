Capítulo 11 — Autenticação (Login/Logout), Sessões e Proteção do Admin

Implemente login e logout seguros com password_hash()/password_verify(), controle de sessão, e proteja o Admin com middleware simples de autorização (perfil/role).

Bimestre 3 Carga: ~100 min Entrega (parcial): Autenticação + proteção do Admin
← Cap. 10 Cap. 12 → Índice

Ao final você será capaz de:

  • Criar tabela de usuários e armazenar senhas com password_hash.
  • Implementar login, logout e sessões com segurança básica.
  • Proteger rotas do Admin (somente usuários logados / com perfil).
  • Aplicar boas práticas (CSRF em formulários sensíveis, cookies de sessão seguros, mensagens flash).

Objetivos de aprendizagem

  • Definir a tabela usuario (email único, senha hash, nome, role).
  • Implementar fluxo de login e logout.
  • Configurar e usar sessões com cuidado.
  • Aplicar middleware de proteção de páginas (role-based).
  • Exibir mensagens amigáveis e tratar erros com segurança.

Onde será aplicado: Proteção do menu Admin (Cap. 08/10), exigindo login para acessar CRUDs e ações administrativas.

Conceitos fundamentais

1) Hash de senhas

Senhas nunca devem ser salvas em texto puro. Use password_hash() (padrão bcrypt/argon2i conforme versão do PHP) e valide com password_verify().

2) Sessões

session_start() cria/recupera a sessão. Armazene apenas o essencial (ex.: user_id, email, role). Use regeneração de ID no login para evitar fixação de sessão.

3) Proteção de rotas

Crie funções utilitárias (middleware) para exigir login e, opcionalmente, checar perfil (ex.: admin).

Boas práticas

  • CSRF em formulários sensíveis (ex.: logout, alterações de dados).
  • Mensagens genéricas de erro de login (não revelar se email existe).
  • Cookies de sessão com HttpOnly e, se possível, Secure (em HTTPS).

3) Serviço de autenticação — src/Service/AuthService.php

<!-- src/Service/AuthService.php -->
<?php
declare(strict_types=1);

class AuthService {
  private PDO $pdo;
  public function __construct(PDO $pdo){ $this->pdo = $pdo; }

  public function login(string $email, string $senha): ?array {
    $email = trim(strtolower($email));
    $st = $this->pdo->prepare("SELECT id,nome,email,senha_hash,role FROM usuario WHERE email=:e");
    $st->execute([':e'=>$email]);
    $u = $st->fetch();
    if(!$u){ return null; }
    if(!password_verify($senha, $u['senha_hash'])){ return null; }
    return ['id'=>(int)$u['id'],'nome'=>(string)$u['nome'],'email'=>(string)$u['email'],'role'=>(string)$u['role']];
  }
}

4) Utilitário de sessão/autorização — src/App/Auth.php

<!-- src/App/Auth.php -->
<?php
class Auth {
  public static function start(){ if(session_status()!==PHP_SESSION_ACTIVE) session_start(); }

  public static function setUser(array $u): void {
    self::start();
    session_regenerate_id(true);
    $_SESSION['user'] = ['id'=>$u['id'],'nome'=>$u['nome'],'email'=>$u['email'],'role'=>$u['role']];
  }

  public static function user(): ?array { self::start(); return $_SESSION['user'] ?? null; }
  public static function check(): bool { return self::user() !== null; }
  public static function role(): ?string { $u = self::user(); return $u['role'] ?? null; }

  public static function requireLogin(): void {
    if(!self::check()){ header('Location: /lanchonete/public/login.php'); exit; }
  }

  public static function requireRole(string $role): void {
    self::requireLogin();
    if(self::role()!==$role){ http_response_code(403); exit('Acesso negado'); }
  }

  public static function logout(): void {
    self::start();
    $_SESSION = [];
    if(ini_get('session.use_cookies')){
      $params = session_get_cookie_params();
      setcookie(session_name(), '', time()-42000, $params['path'], $params['domain'], $params['secure']??false, $params['httponly']??true);
    }
    session_destroy();
  }
}

Atividades práticas (para concluir na aula seguinte)

  1. Troca de senha: crie uma página para o usuário alterar a própria senha (pedindo a senha atual + nova + confirmação).
  2. Lembre-me (opcional): implemente um token persistente (cookie seguro + tabela de tokens) para manter sessão entre visitas.
  3. Bloqueio por tentativas: registre tentativas e imponha “cooldown” após N falhas de login.

Dica: mantenha mensagens genéricas em falhas de login (não revele se o email existe).
