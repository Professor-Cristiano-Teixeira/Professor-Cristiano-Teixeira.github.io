Capítulo 03 — HTTP na prática: URL, QueryString, GET/POST e Formulários

Entenda o ciclo request/response, a estrutura de URL, como ler parâmetros via QueryString e como criar formulários GET/POST no projeto da lanchonete.

Bimestre 1 Carga: ~100 min Entrega (parcial): Busca por QueryString + Formulário de Sugestão (POST)
← Cap. 02 Cap. 04 → Voltar ao índice

Ao final você será capaz de:

  • Identificar partes de uma URL e o papel da QueryString.
  • Explicar diferenças práticas entre GET e POST (visibilidade, cache, idempotência).
  • Criar formulários GET (busca/filtragem) e POST (envio de dados) em PHP.
  • Capturar e validar entradas com filter_input() e imprimir respostas de forma segura.

Objetivos de aprendizagem

  • Compreender a estrutura de uma URL (esquema, host, caminho, query, fragment).
  • Reconhecer o fluxo request/response entre navegador e servidor web.
  • Diferenciar GET e POST e quando usar cada um.
  • Criar formulários HTML e tratar dados no PHP.
  • Aplicar validação e sanitização simples no servidor.
  • Usar QueryString para filtros e buscas no cardápio.

Onde será aplicado: Implementaremos uma busca por itens via QueryString (GET) e um formulário de sugestão de item (POST) para a lanchonete.

Conceitos fundamentais

1) Estrutura da URL

Uma URL pode ser dividida em partes, por exemplo: https://exemplo.com.br/caminho/pagina.php?cat=Bebidas&q=suco#secao

  • Esquema (https://) • Host (exemplo.com.br)
  • Caminho (/caminho/pagina.php) • QueryString (?cat=Bebidas&q=suco)
  • Fragment (#secao, interpretado pelo navegador, não chega ao servidor)

2) Request e Response (HTTP)

O navegador envia uma requisição HTTP (request) e recebe uma resposta (response). Requisições incluem método (GET/POST), caminho e cabeçalhos; respostas incluem status code (ex.: 200, 404) e corpo (HTML/JSON).

3) GET vs POST

  • GET: parâmetros vão na URL (QueryString), é mais indicado para consulta/filtro. Em geral é idempotente e pode ser cacheado.
  • POST: parâmetros vão no corpo da requisição. Use para enviar/criar dados. Não é idempotente por padrão e não fica visível na barra de endereços.

4) Parâmetros no PHP

Em PHP, acessamos parâmetros com $_GET e $_POST. Use preferencialmente filter_input() para validar/sanitizar; e, ao imprimir, use htmlspecialchars().


<?php
// Lendo GET
$q = filter_input(INPUT_GET, 'q', FILTER_SANITIZE_SPECIAL_CHARS) ?? '';

// Lendo POST
$nome = filter_input(INPUT_POST, 'nome', FILTER_SANITIZE_SPECIAL_CHARS);

// Saída segura
function esc($v){ return htmlspecialchars((string)$v, ENT_QUOTES, 'UTF-8'); }

Pesquisas complementares sugeridas

  • Métodos HTTP além de GET/POST (PUT, DELETE) e suas semânticas.
  • Tipos de conteúdo de formulários: application/x-www-form-urlencoded (padrão) e multipart/form-data.
  • O que é idempotência e por que evitar efeitos colaterais em requisições GET.

Passo a passo — Busca (GET) e Sugestão de Item (POST)

Contexto

Neste passo a passo, criaremos duas páginas:

  • busca.php: filtra itens do cardápio via QueryString (GET).
  • sugestao.php: formulário para o usuário sugerir um novo item (POST) com validação simples.

1) Busca por itens (GET) — public/busca.php


<!-- public/busca.php -->
<?php
  function esc($v){ return htmlspecialchars((string)$v, ENT_QUOTES, 'UTF-8'); }

  // Base de dados em memória (exemplo)
  $itens = [
    ['nome'=>'Café expresso', 'preco'=>6.00, 'categoria'=>'Bebidas'],
    ['nome'=>'Cappuccino',    'preco'=>9.00, 'categoria'=>'Bebidas'],
    ['nome'=>'X-Salada',      'preco'=>18.90,'categoria'=>'Lanches'],
    ['nome'=>'Suco de laranja','preco'=>9.50, 'categoria'=>'Bebidas'],
    ['nome'=>'Pão de queijo', 'preco'=>5.50, 'categoria'=>'Lanches'],
  ];

  // Lê parâmetro de busca (GET)
  $q = filter_input(INPUT_GET, 'q', FILTER_SANITIZE_SPECIAL_CHARS) ?? '';
  // Normaliza para busca case-insensitive
  $resultado = [];
  if($q !== ''){
    foreach($itens as $i){
      if(mb_stripos($i['nome'], $q) !== false){
        $resultado[] = $i;
      }
    }
  } else {
    $resultado = $itens; // se vazio, mostra todos
  }
?>

2) Formulário de sugestão (POST) — public/sugestao.php

Uma única página que exibe o formulário (GET) e processa os dados (POST), com validação simples.


<!-- public/sugestao.php -->
<?php
  function esc($v){ return htmlspecialchars((string)$v, ENT_QUOTES, 'UTF-8'); }
  $categorias = ['Bebidas', 'Lanches', 'Sobremesas'];

  $erros = []; $ok = false;
  if('POST' === ($_SERVER['REQUEST_METHOD'] ?? '')){
    $nome = trim(filter_input(INPUT_POST, 'nome', FILTER_SANITIZE_SPECIAL_CHARS) ?? '');
    $preco = str_replace(',', '.', (string)($_POST['preco'] ?? '')); // converte vírgula p/ ponto
    $categoria = filter_input(INPUT_POST, 'categoria', FILTER_SANITIZE_SPECIAL_CHARS) ?? '';
    $obs = trim(filter_input(INPUT_POST, 'obs', FILTER_SANITIZE_SPECIAL_CHARS) ?? '');

    if($nome === '' || mb_strlen($nome) < 3){ $erros['nome'] = 'Informe um nome com pelo menos 3 caracteres.'; }
    if(!is_numeric($preco) || (float)$preco <= 0){ $erros['preco'] = 'Preço deve ser um número positivo.'; }
    if(!in_array($categoria, $categorias, true)){ $erros['categoria'] = 'Categoria inválida.'; }

    if(empty($erros)){ $ok = true; }
  }
?>
<!-- HTML -->
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8"/>
  <meta name="viewport" content="width=device-width, initial-scale=1"/>

  <style>
    body{font-family:Segoe UI,Arial,sans-serif;margin:0;padding:0;background:#fafafa;color:#1b1b1b}

    .ok{background:#e8f5e9;border:1px solid #c8e6c9;border-radius:8px;padding:10px}

<body>

    <?php if($ok): ?>
      <div class="ok">
        <strong>Sugestão enviada!</strong><br/>
        Nome: <?= esc($nome) ?> • Preço: R$ <?= number_format((float)$preco,2,",",".") ?> • Categoria: <?= esc($categoria) ?><br/>
        <span class="muted">Observações:</span> <?= esc($obs) ?: '(nenhuma)' ?>
      </div>
    <?php endif; ?>

    <form method="post" action="sugestao.php" novalidate>
      <div>
        <label for="nome">Nome do item</label>
        <input type="text" id="nome" name="nome" value="<?= esc($_POST['nome'] ?? '') ?>" required/>
        <?php if(isset($erros['nome'])): ?><div class="err"><?= esc($erros['nome']) ?></div><?php endif; ?>
      </div>

      <div class="row">
        <div>
          <label for="preco">Preço (R$)</label>
          <input type="number" step="0.01" min="0.01" id="preco" name="preco" value="<?= esc($_POST['preco'] ?? '') ?>" required/>
          <?php if(isset($erros['preco'])): ?><div class="err"><?= esc($erros['preco']) ?></div><?php endif; ?>
        </div>
        <div>

          <select id="categoria" name="categoria" required>
            <option value="">Selecione...</option>

              <option value="<?= esc($c) ?>" <?= (($_POST['categoria'] ?? '') === $c) ? 'selected' : '' ?>><?= esc($c) ?></option>
            <?php endforeach; ?>

  </main>

3) Testes

  1. Acesse http://localhost/lanchonete/public/busca.php e pesquise por “café”, “suco”, etc.
  2. Acesse http://localhost/lanchonete/public/sugestao.php, envie dados válidos e inválidos e observe os erros.
Resumo: você aplicou QueryString para buscas (GET) e criou um formulário (POST) com validação básica e saída segura.

Atividades práticas (para concluir na aula seguinte)

  1. Busca avançada: expanda busca.php para aceitar filtros por categoria e faixa de preço (min e max) via GET.
  2. Validações extras: no sugestao.php, valide tamanho máximo do nome (ex.: 50) e limite de observações (ex.: 200 caracteres).
  3. (Opcional) CSV local: após validar no sugestao.php, grave a sugestão em assets/sugestoes.csv usando fputcsv() e exiba a lista abaixo do formulário.

Lembre-se: GET para consultas/links compartilháveis; POST para dados que alteram estado.
