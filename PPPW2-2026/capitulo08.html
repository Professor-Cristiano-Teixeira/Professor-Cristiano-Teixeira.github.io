Capítulo 08 — Entrega B2: Catálogo Integrado com CRUDs, Paginação, Busca e Segurança

Consolide o módulo de persistência em MySQL integrando os CRUDs de Bebidas e Categorias, aplicando paginação, busca e um checklist de segurança (prepared, escape, CSRF).

Bimestre 2 Carga: ~100 min Entrega: Integração CRUDs + Catálogo
← Cap. 07 Cap. 09 → Índice

Ao final você será capaz de:

  • Integrar os CRUDs (Bebidas e Categorias) em um fluxo administrativo simples.
  • Exibir o catálogo público com dados do banco, paginação e busca.
  • Garantir segurança básica: consultas parametrizadas, escape na saída e CSRF em formulários.
  • Entregar um pacote funcional com script SQL e instruções de execução.

Objetivos de aprendizagem

  • Criar uma home administrativa que aponte para os CRUDs.
  • Centralizar utilitários (escape, preço, flash, CSRF) e aplicar em todas as páginas.
  • Atualizar o catálogo público para permitir “Adicionar ao carrinho (DB)” com preço vindo do servidor.
  • Revisar prepared statements e sanitização (XSS/SQLi) no projeto.
  • Preparar o pacote de entrega B2 com rubrica e checklist.

Onde será aplicado: Integração do admin (CRUDs) com o catálogo público e o carrinho, usando dados reais do MySQL.

Conceitos fundamentais

1) Centralização de utilitários

Para reduzir repetição e aumentar consistência, centralize funções comuns (escape, formatação de preço, flash, CSRF) em src/App/.

<!-- src/App/Util.php -->
<?php
namespace App;
class Util{
  public static function esc($v): string { return htmlspecialchars((string)$v, ENT_QUOTES, 'UTF-8'); }
  public static function preco($n): string { return 'R$ '.number_format((float)$n,2,',','.'); }
}

2) “Fonte de verdade” no servidor

Em vez de confiar no preço enviado pelo cliente, recupere o item pelo id no banco antes de adicionar ao carrinho.

Pesquisas complementares sugeridas

  • Arquitetura em camadas (DAO/Serviço/Controlador) e vantagens da separação de responsabilidades.
  • Erros e exceções no PDO (códigos SQLSTATE) e como exibir mensagens amigáveis ao usuário.
  • Práticas de UX em telas administrativas: mensagens, navegação e confirmações.

2) Atualize o catálogo para “adicionar ao carrinho (DB)”

No catalogo_db.php, inclua um formulário “Adicionar” que envia apenas o id do item:

<!-- (trecho) em public/catalogo_db.php -->
<form method="post" action="add_carrinho_db.php">
  <input type="hidden" name="id" value="<?= (int)$i['id'] ?>"/>
  <input type="number" name="qtd" min="1" value="1" style="width:80px"/>
  <button type="submit">Adicionar</button>
</form>

3) Endpoint seguro — public/add_carrinho_db.php

<!-- public/add_carrinho_db.php -->
<?php
require_once __DIR__.'/../config/db.php';
require_once __DIR__.'/../src/App/SessionCart.php';
use App\SessionCart;

if(($_SERVER['REQUEST_METHOD'] ?? '') !== 'POST'){ http_response_code(405); exit('Método não permitido'); }

$id  = filter_input(INPUT_POST, 'id', FILTER_VALIDATE_INT);
$qtd = max(1, (int)($_POST['qtd'] ?? 1));

if(!$id){ header('Location: catalogo_db.php'); exit; }

try{
  $pdo = pdo();
  $st = $pdo->prepare("SELECT i.id,i.nome,i.preco FROM item i WHERE i.id=:id");
  $st->execute([':id'=>$id]);
  $it = $st->fetch();
  if(!$it){ header('Location: catalogo_db.php'); exit; }

  SessionCart::start();
  SessionCart::add((string)$it['id'], (string)$it['nome'], (float)$it['preco'], $qtd);
  header('Location: carrinho.php');
} catch(Throwable $e){
  http_response_code(500); exit('Erro ao adicionar: '.$e->getMessage());
}

4) Unifique utilitários (importação nos CRUDs)

Adapte seus arquivos para reutilizar utilitários centralizados como App\Util::esc() e App\Util::preco().

5) Checklist de segurança aplicado

  • SQLi: toda consulta/alteração usa prepared statements (sem concatenação direta).
  • XSS: textos exibidos no HTML passam por htmlspecialchars.
  • CSRF: formulários sensíveis (criar/editar/excluir) usam token de CSRF.
  • Método HTTP: ações de escrita usam POST; listagens/filtragem usam GET.
Resumo: Integramos Admin e Catálogo, reforçando segurança e boas práticas de UX.

Atividades práticas (para concluir na aula seguinte)

  1. Export CSV: crie public/export_itens.php que exporta o catálogo atual (com filtros) em CSV (use fputcsv).
  2. Relatório simples: crie uma página public/relatorio_categoria.php que conta itens por categoria (COUNT(*) + GROUP BY).
  3. Confirmação de exclusão: adicione uma tela intermediária (GET) antes do POST de exclusão nos CRUDs.

Dica: mantenha os arquivos organizados em config/, src/DAO/, src/App/ e public/.

Entrega B2 — Catálogo Integrado (Cap. 05–08)

Objetivo: Entregar um sistema funcional da lanchonete com os seguintes requisitos:

  • Banco (MySQL): schema com categoria, item e dados iniciais.
  • Admin: CRUD de Categorias e de Bebidas (com validação, mensagens e proteção CSRF).
  • Catálogo público: listagem paginada, busca e adicionar ao carrinho com preço vindo do banco.
  • Segurança básica: SQL parametrizado, escape de saída e métodos HTTP adequados.

Rubrica (critérios de avaliação)

  • Funcionalidade (40%): CRUDs, catálogo e carrinho funcionando sem erros.
  • Organização (25%): separação de camadas/arquivos, nomes claros, reutilização de utilitários.
  • Segurança (25%): uso consistente de prepared, escape, CSRF e métodos corretos.
  • Documentação (10%): README com instruções de instalação e dump SQL.

Instruções de entrega

  • Suba um .zip ou repositório com as pastas do projeto (lanchonete/), incluindo README.md e script.sql.
  • No README, inclua: requisitos, passo a passo de importação do banco, URLs de acesso e usuários (se houver).
