Programação Web 2

Segundo ano – Curso Técnico em Desenvolvimento de Sistemas
Foco: back-end com PHP, persistência em MySQL, camadas e segurança, integrando a um projeto-guia de lanchonete.

Carga: 100 min/semana Ambiente: XAMPP + VS Code + MySQL Projeto contínuo

Atribuição: Elaborar sistemas de informação para web.
Competência: Desenvolver sistemas para internet com persistência em banco, interface via navegador e programação no lado do servidor.

Ver Sumário por Bimestre Requisitos do Ambiente Plano de Avaliação

Como usar esta apostila

  • Ritmo: alternância de aulas conceituais (com passo a passo) e aulas práticas para concluir as atividades.
  • Projeto: um sistema de lanchonete evolutivo. Cada capítulo adiciona recursos.
  • Capítulos: acesse pelo menu Capítulos (hambúrguer no celular). Os arquivos serão capitulo01.html até capitulo16.html.
  • Ferramentas: Windows, VS Code, XAMPP (Apache/PHP/MySQL) e MySQL Workbench (ou phpMyAdmin).
Começar (Cap. 01) Ver cronograma

Cronograma e organização

As aulas têm 100 minutos por semana. Em geral, a cada tópico novo há uma aula de explicação e guia passo a passo e, na sequência, uma aula focada em prática e conclusão da atividade.

1º Bimestre

Fundamentos de servidor (PHP), HTTP e formulários; sessões/cookies introdutórios; páginas dinâmicas sem banco.

2º Bimestre

Persistência MySQL com PDO/MySQLi; CRUD completo; consultas parametrizadas; defesa contra SQLi e XSS.

3º Bimestre

Modularização e OOP; camadas (Entidades/DAO/Serviços/Controladores); autenticação com sessões; regras de negócio.

4º Bimestre

Comunicação assíncrona (Fetch/AJAX), APIs REST simples e segurança; integração e entrega do projeto final.

Ferramentas e requisitos do ambiente

  • Sistema operacional: Windows
  • IDE/Editor: Visual Studio Code (extensões sugeridas: PHP Intelephense, PHP Namespace Resolver, SQLTools)
  • Servidor local: XAMPP (Apache + PHP + MySQL)
  • Banco de dados: MySQL (MySQL Workbench ou phpMyAdmin)
  • Navegadores: Chrome/Edge/Firefox para testes

Caso necessário, incluem-se utilitários como Git para controle de versão e Postman/Insomnia para testar requisições HTTP/REST (opcional).

Estrutura sugerida de pastas

htdocs/
└── lanchonete/
    ├── public/              # arquivos acessíveis pelo navegador (index.php, assets)
    ├── src/
    │   ├── App/             # controladores, rotas simples
    │   ├── Model/           # entidades de domínio (OOP)
    │   ├── DAO/             # acesso a dados (PDO)
    │   ├── Service/         # regras de negócio (BO)
    │   └── View/            # templates PHP (quando aplicável)
    ├── config/              # config de conexão, constantes
    ├── tests/               # scripts de teste (opcional)
    └── vendor/              # autoload (se usar Composer, opcional)

Plano de avaliação (por bimestre)

  • Atividades práticas semanais: 30%
  • Questionários objetivos (capítulos): 20%
  • Entregas bimestrais (Cap. 04, 08, 12): 30%
  • Projeto final integrado (Cap. 16): 20%

Cada entrega deve demonstrar aplicação dos conceitos do período: camadas, SQL parametrizado, sessões, sanitização e comunicação via HTTP.

Critérios de qualidade (rubrica sintética)

  • Correção funcional: o que foi proposto funciona sem erros
  • Organização: separação em camadas e legibilidade do código
  • Segurança básica: uso de prepared statements, sanitização/escape
  • UX essencial: formulários claros e feedback de ações
  • Documentação mínima: README e comentários pontuais
