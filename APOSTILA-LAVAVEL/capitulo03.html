3) Conteúdo teórico

3.1. CSRF (Cross-Site Request Forgery)

CSRF é um tipo de ataque em que um site malicioso tenta “forçar” o navegador de um usuário autenticado a executar uma ação em outro site (por exemplo, enviar um formulário de exclusão sem o usuário perceber). Para reduzir esse risco, frameworks como o Laravel exigem um token CSRF em formulários.

No Blade, usamos @csrf dentro do <form>. Assim, o Laravel valida se a requisição realmente foi gerada pela aplicação (e não por outra origem).

3.2. Validação no Laravel (inline vs Form Request)

A validação “inline” ocorre quando o controller chama $request->validate([...]) diretamente. É simples e funciona bem para casos pequenos, mas pode deixar o controller “inchado” conforme o projeto cresce.

O Form Request é uma classe dedicada para validar dados de um formulário. Ele centraliza regras, mensagens e (opcionalmente) autorização. O resultado costuma ser um código mais organizado, fácil de manter e reaproveitar.

3.3. Mensagens ao usuário (sucesso/erro) e UX

Uma aplicação fica mais amigável quando mostra feedback claro: mensagens de sucesso após salvar/atualizar/excluir, e mensagens de erro quando há falhas de validação. No Laravel, é comum usar flash messages na sessão (ex.: ->with('sucesso', '...')) e exibi-las em um partial reutilizável.

Para melhorar a experiência, também é importante preservar os valores digitados quando ocorre erro, usando old('campo') nos inputs. Assim, o aluno não precisa “digitar tudo de novo”.

3.4. Blade na prática (diretivas e partials)

O Blade possui diretivas que ajudam muito: @extends, @section, @yield e @include. Elas permitem herança de layout e reutilização de partes comuns (navbar, footer, alerts, formulários).

Outra diretiva essencial é @error('campo'), que facilita mostrar mensagens de validação próximas ao input, deixando o formulário mais claro para o usuário.

4) Passo a passo guiado (Projeto Lanchonete)

Meta do capítulo: converter a validação do CRUD de Categoria para Form Requests, exibir mensagens de sucesso/erro e preservar valores com old().

4.1. Criar o Form Request (CategoriaRequest)

No terminal (dentro do projeto):
Shell
php artisan make:request CategoriaRequest
Edite app/Http/Requests/CategoriaRequest.php:
PHP
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;

class CategoriaRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true; // por enquanto qualquer usuário pode; autorização entra mais adiante
    }

    public function rules(): array
    {
        // Se estiver editando, o model vem pela rota (route model binding)
        $categoriaId = $this->route('categoria')?->id;

        return [
            'nome' => [
                'required',
                'string',
                'max:100',
                Rule::unique('categorias', 'nome')->ignore($categoriaId),
            ],
            'descricao' => 'nullable|string|max:500',
            'ativa' => 'nullable|boolean',
        ];
    }

    public function messages(): array
    {
        return [
            'nome.required' => 'Informe o nome da categoria.',
            'nome.max' => 'O nome deve ter no máximo :max caracteres.',
            'nome.unique' => 'Já existe uma categoria com este nome.',
            'descricao.max' => 'A descrição deve ter no máximo :max caracteres.',
        ];
    }
}

4.2. Atualizar o Controller para usar Form Request

No CategoriaController, troque Request por CategoriaRequest em store/update.
PHP
<?php

namespace App\Http\Controllers;

use App\Models\Categoria;
use App\Http\Requests\CategoriaRequest;

class CategoriaController extends Controller
{
    public function index()
    {
        $categorias = Categoria::orderBy('nome')->get();
        return view('categorias.index', compact('categorias'));
    }

    public function create()
    {
        return view('categorias.create');
    }

    public function store(CategoriaRequest $request)
    {
        $dados = $request->validated();
        $dados['ativa'] = $request->boolean('ativa');

        Categoria::create($dados);

        return redirect()->route('categorias.index')
            ->with('sucesso', 'Categoria criada com sucesso!');
    }

    public function edit(Categoria $categoria)
    {
        return view('categorias.edit', compact('categoria'));
    }

    public function update(CategoriaRequest $request, Categoria $categoria)
    {
        $dados = $request->validated();
        $dados['ativa'] = $request->boolean('ativa');

        $categoria->update($dados);

        return redirect()->route('categorias.index')
            ->with('sucesso', 'Categoria atualizada com sucesso!');
    }

    public function destroy(Categoria $categoria)
    {
        $categoria->delete();

        return redirect()->route('categorias.index')
            ->with('sucesso', 'Categoria excluída com sucesso!');
    }
}

4.3. Melhorar o partial de alertas (sucesso/erro/validação)

Crie (ou edite) resources/views/partials/alerts.blade.php:
PHP
{{-- resources/views/partials/alerts.blade.php --}}

@if (session('sucesso'))
    <div class="alert alert-success alert-dismissible fade show" role="alert">
        {{ session('sucesso') }}
        <button type="button" class="btn-close" data-bs-dismiss="alert" aria-label="Fechar"></button>
    </div>
@endif

@if (session('erro'))
    <div class="alert alert-danger alert-dismissible fade show" role="alert">
        {{ session('erro') }}
        <button type="button" class="btn-close" data-bs-dismiss="alert" aria-label="Fechar"></button>
    </div>
@endif

@if ($errors->any())
    <div class="alert alert-warning" role="alert">
        <strong>Atenção:</strong> verifique os campos do formulário.
    </div>
@endif
Garanta que suas views chamam:
PHP
@include('partials.alerts')

4.4. Preservar valores e exibir erros por campo (old() e @error)

No Cap. 2, o _form.blade.php já usava old() e @error. Confira se está assim (ou ajuste se necessário):
PHP
<input type="text" class="form-control @error('nome') is-invalid @enderror"
       id="nome" name="nome" value="{{ old('nome', $categoria->nome ?? '') }}" maxlength="100" required>

@error('nome')
    <div class="invalid-feedback">{{ $message }}</div>
@enderror

4.5. Teste de validação (erros e sucesso)

· Tentar criar categoria com nome já existente → mensagem de “Já existe uma categoria...”.
· Criar/editar/excluir → deve aparecer mensagem de sucesso no topo.
