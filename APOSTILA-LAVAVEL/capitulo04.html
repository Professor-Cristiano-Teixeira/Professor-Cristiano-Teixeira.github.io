3) Conteúdo teórico

3.1. Paginação (por que e como)

Paginação é a técnica de dividir uma lista grande em páginas menores. Isso melhora a performance (menos dados por requisição) e a experiência do usuário (fica mais fácil encontrar e navegar). No Laravel, podemos paginar com paginate() e renderizar links de página com links() no Blade.

Quando a listagem usa filtros (ex.: busca por nome), é importante manter esses parâmetros na navegação entre páginas. Para isso, usamos withQueryString() na query paginada.

3.2. Busca e filtros por query string

Uma busca simples geralmente é feita por query string (por exemplo, /categorias?q=bebidas). O controller lê o parâmetro com request('q') e monta a query com where e like. O mesmo vale para filtros: categoria_id, ativo, ordem (sort) etc.

Boas práticas: validar/normalizar parâmetros (ex.: limitar tamanhos), evitar concatenação de SQL manual e manter a interface clara (mostrar a busca atual, permitir limpar filtros).

3.3. Segurança básica na entrada e na saída

CSRF: formulários devem conter token (@csrf) para evitar que terceiros disparem ações no seu sistema. XSS: ocorre quando um usuário injeta HTML/JavaScript malicioso em campos e a aplicação renderiza isso sem escapar. No Blade, {{ }} faz escaping automaticamente; já {!! !!} imprime “cru” (evite em dados de usuário).

SQL Injection: acontece quando a aplicação monta SQL por concatenação de strings com entradas do usuário. No Laravel, usando Eloquent/Query Builder com parâmetros, o framework faz o binding e reduz esse risco. Ainda assim, valide e normalize entradas (ex.: inteiros, limites, formatos).

Regra de ouro (nível técnico):
Valide a entrada (Request) e escape a saída (View). Isso resolve grande parte dos problemas comuns.

4) Passo a passo guiado (Projeto Lanchonete)

Meta do capítulo: adicionar paginação e busca por nome em Categorias e Produtos, reforçando segurança básica (CSRF e escaping).

4.1. Ajustar o Controller de Categorias para paginar e buscar

Edite app/Http/Controllers/CategoriaController.php (método index):
PHP
public function index()
{
    $q = request('q');

    $categorias = Categoria::query()
        ->when($q, function ($query) use ($q) {
            $query->where('nome', 'like', "%{$q}%");
        })
        ->orderBy('nome')
        ->paginate(10)
        ->withQueryString();

    return view('categorias.index', compact('categorias', 'q'));
}
Por que withQueryString()?
Ele preserva ?q=... (e outros filtros) ao navegar nas páginas.

4.2. Ajustar a View de Categorias: formulário de busca + links de paginação

Edite resources/views/categorias/index.blade.php e adicione um formulário de busca no topo:

<div class="d-flex flex-wrap justify-content-between align-items-center gap-2 mb-3">

4.3. Preparar Produtos: paginação + busca + filtro por categoria (base)

Se você já fez o CRUD de Produto (atividade do Cap. 2/3), aplique o mesmo padrão. Se ainda não fez, implemente pelo menos a listagem de Produto com filtro por categoria.
Exemplo para ProdutoController@index (paginação, busca e filtro):
PHP
public function index()
{
    $q = request('q');
    $categoriaId = request('categoria_id');

    $produtos = Produto::query()
        ->with('categoria')
        ->when($q, function ($query) use ($q) {
            $query->where('nome', 'like', "%{$q}%");
        })
        ->when($categoriaId, function ($query) use ($categoriaId) {
            $query->where('categoria_id', $categoriaId);
        })
        ->orderBy('nome')
        ->paginate(10)
        ->withQueryString();

    $categorias = Categoria::orderBy('nome')->get();

    return view('produtos.index', compact('produtos', 'categorias'));
}

4.4. Segurança básica: revisar CSRF e escaping no Blade

Checklist rápido (confira no seu projeto):
· Todo <form> que faz POST/PUT/DELETE tem @csrf.
· Para PUT/DELETE: usar @method('PUT') / @method('DELETE').
· Em views: preferir {{ $variavel }} (escapa) e evitar {!! $variavel !!} quando for dado do usuário.
Exemplo de exclusão com CSRF (já parecido com o que você tem):
PHP
<form method="POST" action="{{ route('categorias.destroy', $categoria) }}" class="d-inline"
      onsubmit="return confirm('Tem certeza que deseja excluir?')">
    @csrf
    @method('DELETE')
    <button class="btn btn-sm btn-outline-danger">Excluir</button>
</form>
XSS (exemplo didático)
Se alguém cadastrar o nome como <script>alert('XSS')</script>, então {{ $categoria->nome }} exibirá como texto (seguro), mas {!! $categoria->nome !!} poderia executar o script (perigoso).
