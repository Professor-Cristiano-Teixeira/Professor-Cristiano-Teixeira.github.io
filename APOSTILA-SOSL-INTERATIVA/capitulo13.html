Capítulo 13 — Shell Script (automação no Linux)

Você vai aprender a automatizar tarefas de suporte com scripts Bash: variáveis, argumentos, testes, decisões, loops, funções e logs. O objetivo é produzir rotinas repetíveis e relatórios “ticket-ready”.

bashshebangset -euo pipefail$1..$#if/casefor/whilefunçõestee/log

Objetivos

  • Criar scripts executáveis com shebang e permissões corretas.
  • Usar variáveis e parâmetros ($1, $@, $#).
  • Validar entrada com testes ([ ]) e códigos de saída.
  • Aplicar decisões (if/case) e repetições (for/while).
  • Gerar logs e relatórios com tee e redirecionamento.

Pré-requisitos

  • Cap. 09–10: CLI, pipes/filtros e organização de arquivos.
  • Cap. 11: permissões (executar scripts) e sudo consciente.
  • Cap. 12: diagnóstico (configs/processos/rede) — será automatizado.
Segurança: scripts executam ações em massa. Teste em pasta de laboratório e registre logs.

1) Teoria: por que Shell Script é essencial no suporte

1.1 O que é um script?

Um script é um arquivo de texto com comandos que o shell executa em sequência. Ele padroniza tarefas e reduz erro humano.

Onde vou aplicar isso? No passo a passo você criará um script que gera relatório de diagnóstico automaticamente.

1.2 Shebang e permissão de execução

O shebang indica o interpretador (ex.: #!/usr/bin/env bash). Para executar com ./script.sh, use chmod +x.

Onde vou aplicar isso? Você vai criar diag.sh e torná-lo executável.

1.3 Variáveis, aspas e parâmetros

Variáveis guardam valores (VAR=valor). Use aspas em "$VAR" para preservar espaços. Parâmetros são argumentos: $1, $2, $@ e $#.

Erro comum: esquecer aspas em caminhos com espaço.

1.4 Testes e códigos de saída

Testes com [ ] validam condições (arquivo existe, diretório existe). Códigos de saída: 0 = sucesso; outros = erro.

echo $?   # status do último comando
Onde vou aplicar isso? O script de backup simples vai validar parâmetros e sair com códigos diferentes.

2) Fundamentos do Bash (kit mínimo)

2.1 Estrutura mínima e modo seguro

#!/usr/bin/env bash
set -euo pipefail

echo "Olá"

set -euo pipefail: falha em erros, variáveis não definidas e pipelines quebrados.

2.2 Testes mais usados

TesteSignificadoExemplo
[ -f ARQ ]arquivo existe[ -f /etc/hosts ]
[ -d DIR ]diretório existe[ -d ~/SOSL ]
[ $# -ne 2 ]qtd de argumentos diferente de 2[ $# -ne 2 ]
[ -z STR ]string vazia[ -z "${1:-}" ]

2.3 if e case (decisão)

if [ -f "/etc/hosts" ]; then
  echo "ok"
else
  echo "faltando"
fi

case "${1:-diag}" in
  diag) echo "modo diag";;
  net)  echo "modo rede";;
  *)    echo "uso: script {diag|net}"; exit 2;;
esac

3) Passo a passo prático: scripts de diagnóstico e backup simples

Você vai criar dois scripts em ~/SOSL/cap13/scripts e gerar saídas em ~/SOSL/cap13/saidas.

1 Preparar estruturaSetup
mkdir -p ~/SOSL/cap13/{scripts,saidas}
cd ~/SOSL/cap13
2 Criar diag.sh (relatório automático)Script
cat > ~/SOSL/cap13/scripts/diag.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

OUT_DIR="$HOME/SOSL/cap13/saidas"
mkdir -p "$OUT_DIR"
OUT_FILE="$OUT_DIR/diagnostico_$(date '+%Y%m%d_%H%M%S').txt"

section(){ echo "
==== $* ====" | tee -a "$OUT_FILE"; }
log(){ echo "[$(date '+%F %T')] $*" | tee -a "$OUT_FILE"; }

log "DIAGNÓSTICO (Cap. 13) — host=$(hostname) user=$(whoami)"
section "SO/KERNEL"; { cat /etc/os-release; uname -a; } | tee -a "$OUT_FILE" >/dev/null
section "UPTIME/MEM"; { uptime; free -h; } | tee -a "$OUT_FILE" >/dev/null
section "TOP CPU"; ps aux --sort=-%cpu | head -n 11 | tee -a "$OUT_FILE" >/dev/null
section "TOP MEM"; ps aux --sort=-%mem | head -n 11 | tee -a "$OUT_FILE" >/dev/null
section "REDE"; { ip -br a; ip route; } | tee -a "$OUT_FILE" >/dev/null
section "PING"; (ping -c 2 8.8.8.8 || true) | tee -a "$OUT_FILE" >/dev/null
section "LOGS"; (journalctl -b -p warning..err --no-pager | tail -n 40 || true) | tee -a "$OUT_FILE" >/dev/null
log "Relatório: $OUT_FILE"
EOF

chmod +x ~/SOSL/cap13/scripts/diag.sh
Onde vou aplicar isso? Você roda e anexa o relatório em um chamado.
3 Executar o diagnósticoExecução
~/SOSL/cap13/scripts/diag.sh
ls -t ~/SOSL/cap13/saidas/diagnostico_*.txt | head -n 1
4 Criar backup_simples.sh (validação + log)Backup
cat > ~/SOSL/cap13/scripts/backup_simples.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

USO="Uso: backup_simples.sh ORIGEM DESTINO"
if [ $# -ne 2 ]; then echo "$USO" >&2; exit 2; fi

ORIG="$1"; DEST="$2"
if [ ! -e "$ORIG" ]; then echo "ERRO: origem não existe: $ORIG" >&2; exit 3; fi

mkdir -p "$DEST"
LOG="$HOME/SOSL/cap13/saidas/backup_$(date '+%Y%m%d_%H%M%S').log"
log(){ echo "[$(date '+%F %T')] $*" | tee -a "$LOG"; }

log "Backup iniciado"; log "Origem: $ORIG"; log "Destino: $DEST"
cp -a "$ORIG" "$DEST/"
log "Backup concluído"; log "Log: $LOG"
EOF

chmod +x ~/SOSL/cap13/scripts/backup_simples.sh
Obs.: backup real com retenção e verificação será aprofundado no Cap. 15.
