Capítulo 15 — Backup e Restauração no Linux

Backup não é “copiar e torcer”. É um processo com política, verificação e teste de restauração. Neste capítulo você aprende conceitos (3-2-1), cria backups com tar e rsync, verifica integridade com sha256sum e restaura com evidência.

3-2-1 full/incremental tar (.tar.gz) rsync sha256sum restauração logs/relatório

Objetivos de aprendizagem

  • Explicar o que é backup e por que restauração testada é a parte mais importante.
  • Aplicar a regra 3-2-1 e diferenciar cópia vs backup.
  • Criar backup compactado com tar e manter evidência (hash).
  • Fazer espelhamento/backup incremental com rsync (conceito e prática).
  • Restaurar arquivos e validar integridade com sha256sum.
  • Gerar relatório “ticket-ready” do backup e da restauração.

Pré-requisitos

  • Cap. 10: arquivos/diretórios e pipes (tee).
  • Cap. 11: permissões (o que precisa de sudo e o que não).
  • Cap. 14: manutenção preventiva e registros.
  • Cap. 13 (opcional): automatizar rotina com script.
Segurança: nunca teste backup em pastas do sistema. Use ~/SOSL/cap15 (laboratório). Remoção e restauração devem ser feitas em diretórios de teste.

1) Teoria: backup é processo + prova de restauração

1.1 Cópia x Backup

Cópia é apenas duplicar um arquivo. Backup é um conjunto de cópias planejadas com versão, verificação e restauração. Uma cópia sem verificação pode estar corrompida e você só descobre no dia do desastre.

Onde vou aplicar isso? Você vai gerar um arquivo de hash (.sha256) e validar depois da restauração.

1.2 Regra 3-2-1

A regra 3-2-1 diz: 3 cópias dos dados, em 2 mídias diferentes, com 1 cópia fora do equipamento (offsite). Em laboratório você simula isso com “origem”, “backup local” e “backup externo” (pasta separada).

Onde vou aplicar isso? No passo a passo você cria duas cópias (tar e rsync) e registra onde cada uma fica.

1.3 Tipos: full, incremental e diferencial

Full (completo) copia tudo. Incremental copia apenas o que mudou desde o último backup (pode exigir cadeia para restaurar). Diferencial copia o que mudou desde o último full (cresce ao longo do tempo, restauração mais simples que incremental).

Onde vou aplicar isso? Você fará um backup full com tar e um incremental/espelhamento com rsync.

1.4 Integridade e verificação

Backup bom é verificável. Uma forma simples é gerar hash (sha256sum) do arquivo de backup e conferir antes e depois. Outra prática é testar a restauração em um diretório de teste.

Onde vou aplicar isso? Você vai comparar o hash do arquivo .tar.gz e conferir se o conteúdo restaurado bate com o original.

1.5 O erro clássico: nunca testou restaurar

A maioria dos “backups falhados” é descoberta no dia em que se precisa restaurar. Por isso, toda rotina deve incluir teste de restauração e evidência (log/relatório).

Onde vou aplicar isso? No laboratório, você vai apagar um arquivo de teste e restaurar do backup.

2.1 Exemplos rápidos

# criar tar.gz
# tar -czf saida.tar.gz pasta/

# listar conteúdo do tar.gz sem extrair
# tar -tzf saida.tar.gz | head

# rsync (espelho simples)
# rsync -av --delete origem/ destino/

# hash
# sha256sum saida.tar.gz > saida.tar.gz.sha256
# sha256sum -c saida.tar.gz.sha256
Cuidado com --delete no rsync: ele apaga no destino o que não existe na origem. Use apenas quando você tem certeza do alvo (em pasta de teste).

3) Passo a passo (prático): backup com tar + rsync + restauração validada

Objetivo: criar uma pasta de dados, gerar backups (tar/rsync), apagar algo e restaurar com evidência e verificação.

Resultado final: ~/SOSL/cap15/relatorio-cap15.txt + arquivos de backup em ~/SOSL/cap15/backups.
1 Preparar estrutura do capítuloSetup
mkdir -p ~/SOSL/cap15/{dados,backups,restaurado,espelho}
R=~/SOSL/cap15/relatorio-cap15.txt
: > "$R"
2 Criar dados de teste (origem)Dados
cd ~/SOSL/cap15/dados
mkdir -p docs fotos
printf "Contrato v1
" > docs/contrato.txt
printf "Notas do suporte
" > docs/notas.txt

# simular "foto" como arquivo de bytes (sem depender de imagens reais)
head -c 20480 /dev/urandom > fotos/img01.bin
head -c 10240 /dev/urandom > fotos/img02.bin

ls -lahR ~/SOSL/cap15/dados | tee -a "$R"
Onde vou aplicar isso? Você cria um conjunto de arquivos “realista” para praticar backup e restauração.
3 Backup FULL com tar.gz + hash (integridade)tar
cd ~/SOSL/cap15
TS=$(date '+%Y%m%d_%H%M%S')
BK=~/SOSL/cap15/backups/backup_full_$TS.tar.gz

# criar o tar.gz (full)
tar -czf "$BK" -C ~/SOSL/cap15 dados

# gerar hash para verificação
sha256sum "$BK" > "$BK.sha256"

{
  echo "
[BACKUP FULL - tar.gz]";
  echo "Arquivo: $BK";
  ls -lah "$BK" "$BK.sha256";
  echo "Conteúdo (amostra):";
  tar -tzf "$BK" | head;
  echo "Verificação (sha256):";
  sha256sum -c "$BK.sha256";
} | tee -a "$R"

O hash confirma que o arquivo de backup não mudou/corrompeu.

4 Backup/espelho com rsync (incremental/recorrente)rsync
# espelhar dados para ~/SOSL/cap15/espelho
rsync -av ~/SOSL/cap15/dados/ ~/SOSL/cap15/espelho/ | tee -a "$R"

# conferir
ls -lahR ~/SOSL/cap15/espelho | head -n 40 | tee -a "$R"
Onde vou aplicar isso? Em rotinas recorrentes: rsync copia só o que mudou, economizando tempo.
5 Simular incidente: apagar/alterar arquivo (apenas no laboratório)Incidente
# apagar um arquivo e alterar outro
rm -i ~/SOSL/cap15/dados/docs/notas.txt
printf "Contrato v2 (alterado)
" > ~/SOSL/cap15/dados/docs/contrato.txt

{
  echo "
[INCIDENTE SIMULADO]";
  echo "notas.txt removido e contrato.txt alterado";
  ls -lah ~/SOSL/cap15/dados/docs;
} | tee -a "$R"
Boa prática: incidentes reais pedem evidência antes de ação. Aqui é simulação controlada.
6 Restaurar do tar.gz (full) para diretório restauradoRestore
# escolher o backup mais recente
BK_LAST=$(ls -t ~/SOSL/cap15/backups/backup_full_*.tar.gz | head -n 1)

# restaurar em ~/SOSL/cap15/restaurado
mkdir -p ~/SOSL/cap15/restaurado
rm -rf ~/SOSL/cap15/restaurado/*

tar -xzf "$BK_LAST" -C ~/SOSL/cap15/restaurado

{
  echo "
[RESTAURAÇÃO - tar.gz]";
  echo "Backup usado: $BK_LAST";
  echo "Verificação do hash do backup:";
  sha256sum -c "$BK_LAST.sha256";
  echo "Arquivos restaurados (amostra):";
  ls -lahR ~/SOSL/cap15/restaurado/dados/docs;
} | tee -a "$R"

Repare que restauramos em uma pasta separada. Isso evita sobrescrever dados até você confirmar.

7 Restaurar usando o espelho rsync (opção rápida)rsync
# recuperar arquivos apagados/alterados a partir do espelho
rsync -av ~/SOSL/cap15/espelho/ ~/SOSL/cap15/dados/ | tee -a "$R"

{
  echo "
[RESTAURAÇÃO - rsync]";
  echo "Estado atual de docs após rsync:";
  ls -lah ~/SOSL/cap15/dados/docs;
} | tee -a "$R"
Onde vou aplicar isso? Em recuperação rápida: rsync repõe arquivos sumidos e atualiza os alterados.
8 Encerrar relatório (conclusão e evidências)Final
{
  echo "
[CONCLUSÃO]";
  echo "- Backup FULL criado com tar.gz e verificado por sha256";
  echo "- Espelho criado com rsync";
  echo "- Incidente simulado e restauração testada (tar + rsync)";
  echo "- Próxima melhoria: automatizar e adotar 3-2-1";
} | tee -a "$R"

less "$R"
