Capítulo 10 — CLI (2): Arquivos, Diretórios e Utilitários de Texto

Neste capítulo você aprende a parte mais usada da linha de comando no suporte: manipular arquivos e pastas, localizar coisas e processar texto com filtros (grep, head, tail, wc, sort, uniq, cut), usando redirecionamento e pipes. Isso é a base para logs, automação e diagnóstico.

mkdir / touch cp / mv / rm globbing (* ? []) quoting ("" '') find file / stat cat / less head / tail grep / wc sort / uniq / cut > >> | tee

Objetivos de aprendizagem

  • Criar e organizar estruturas de pastas e arquivos (padrão de curso e de suporte).
  • Copiar, mover e remover com segurança (incluindo opções como -i e -r).
  • Entender e usar curingas (globbing) e aspas (quoting) para evitar erros.
  • Localizar arquivos com find (e quando usar).
  • Inspecionar arquivos: tipo (file), metadados (stat).
  • Ler e “fatiar” texto: cat, less, head, tail.
  • Filtrar e resumir dados: grep, wc, sort, uniq, cut.
  • Encadear comandos com | e salvar saídas com >, >> e tee.

Pré-requisitos

  • Cap. 09: ajuda (man/--help) e inventário básico.
  • Cap. 08: noções do FHS (onde ficam logs e configs).
  • VM Linux Mint funcionando (Cap. 04).
Regra de segurança: evite rm -rf. Aqui você vai treinar opções seguras (rm -i, rm -r com cuidado).

1) Teoria: por que “arquivos + texto” é a alma do Linux

1.1 Tudo vira arquivo (inclusive evidências)

No Linux, muitas informações e configurações são representadas como arquivos (textos em /etc, logs em /var/log, informações em /proc). Por isso, um técnico eficiente precisa dominar leitura, busca e manipulação de arquivos.

Onde vou aplicar isso? No passo a passo você vai criar uma estrutura de laboratório, gerar logs de teste e extrair informações com filtros.

1.2 Globbing (curingas) não é regex: é o shell trabalhando

Quando você digita *.log ou relatorio-??.txt, quem expande isso é o shell antes do comando rodar. Isso se chama globbing. É rápido e útil, mas pode causar erros se você não entender.

  • * → qualquer sequência de caracteres
  • ? → um único caractere
  • [abc] → um caractere entre as opções (a, b ou c)
  • [0-9] → um dígito (0 a 9)
Onde vou aplicar isso? Ao copiar/mover vários arquivos de uma vez e ao filtrar nomes de log. Você verá por que aspas mudam o comportamento.

1.3 Quoting (aspas) e espaços: o erro mais comum de iniciante

Espaços separam argumentos. Se um arquivo se chama Meu Arquivo.txt, o shell entende como dois argumentos. Para tratar como um único nome, use aspas: "Meu Arquivo.txt". Aspas simples ' ' evitam expansão (úteis para texto literal).

Onde vou aplicar isso? No passo a passo você vai criar um arquivo com espaço no nome e ver como copiar/mover corretamente.

1.4 Operações de risco: remoção e recursão

rm remove arquivos; rm -r remove pastas e tudo dentro; rm -rf remove sem perguntar. Em suporte, a prática é usar -i (interativo) e conferir o alvo com ls antes.

Regra de sobrevivência: antes de um rm -r, faça ls no alvo e confirme o caminho.

1.5 Filtros: pequenos comandos que fazem uma coisa muito bem

O estilo Unix é encadear comandos simples. Você pega texto (logs, listas, saídas) e passa por filtros: grep (seleciona linhas), wc (conta), sort/uniq (organiza e resume), cut (recorta colunas).

Onde vou aplicar isso? No passo a passo você vai extrair “erros” de um log e produzir um resumo com contagens.

2) Arquivos e diretórios: comandos essenciais (com mentalidade de suporte)

2.1 Criar e organizar

# criar pastas
mkdir pasta
mkdir -p projeto/subpasta

# criar arquivo vazio
touch arquivo.txt

Use -p para criar estruturas inteiras sem erro se já existir.

2.2 Copiar e mover

# copiar arquivo
cp origem.txt destino.txt

# copiar pasta (recursivo)
cp -r pasta1 pasta2

# mover/renomear
mv antigo.txt novo.txt

2.3 Remover com cuidado

# remover arquivo interativamente
rm -i arquivo.txt

# remover pasta vazia
rmdir pasta_vazia

# remover pasta com conteúdo (cuidado)
rm -r pasta

2.4 Inspecionar: tipo e metadados

# descobrir tipo do arquivo
file arquivo.txt

# ver detalhes (tamanho, datas, permissões)
stat arquivo.txt
Onde vou aplicar isso? Quando alguém diz “não abre”, você confirma se é texto, binário, script, etc.

2.5 Buscar: find (a ferramenta profissional)

find procura arquivos por nome, tipo e outras condições. É mais confiável que “olhar manualmente” em pastas. 

# procurar por nome (case-insensitive) no diretório atual
find . -iname "*.log"

# procurar no /var/log por arquivos recentes (últimos 7 dias)
find /var/log -type f -mtime -7 2>/dev/null | head
Onde vou aplicar isso? Em incidentes: localizar logs e arquivos de configuração rapidamente.

3) Texto e filtros: ler, cortar, contar e resumir

3.1 Ler com segurança: cat vs less

cat imprime tudo (bom para arquivos pequenos). less permite navegar (bom para logs grandes). 

cat arquivo_pequeno.txt
less /var/log/syslog  # se existir

3.2 Pegar apenas o começo/fim: head e tail

head -n 20 arquivo.txt
tail -n 50 arquivo.txt

# acompanhar arquivo crescendo (log em tempo real)
# pressione Ctrl+C para parar
tail -f arquivo.txt

3.3 Filtrar linhas: grep

# procurar linhas que contenham "error" (case-insensitive)
grep -i "error" arquivo.log

# contar quantas linhas bateram
grep -i "error" arquivo.log | wc -l

3.4 Contar: wc

wc -l arquivo.txt   # linhas
wc -w arquivo.txt   # palavras
wc -c arquivo.txt   # bytes

3.5 Ordenar e resumir: sort + uniq

# ordenar e contar repetidos
sort arquivo.txt | uniq -c | sort -n

Muito usado para resumir nomes repetidos, erros recorrentes e IPs.

3.6 Recortar colunas: cut (CSV/colon/space)

# pegar a 1ª coluna separada por ':' (ex.: /etc/passwd)
cut -d: -f1 /etc/passwd | head
Onde vou aplicar isso? Em Cap. 11 (usuários), você vai analisar /etc/passwd e /etc/group.

4) Redirecionamento e pipes: transformar saídas em arquivos (e em evidência)

4.1 Redirecionamento básico

  • > sobrescreve (cria/zera)
  • >> adiciona ao final (append)
echo "linha 1" > saida.txt
echo "linha 2" >> saida.txt

4.2 Pipe (|): saída de um vira entrada do outro

# filtrar e contar
journalctl -b --no-pager | grep -i "error" | wc -l

4.3 tee: mostrar na tela e salvar ao mesmo tempo

# salva e mostra
uname -a | tee inventario.txt

# acrescenta
uname -a | tee -a inventario.txt
Onde vou aplicar isso? Em tickets e relatórios: você gera evidência em arquivo enquanto executa diagnóstico.

5) Passo a passo prático (laboratório): do zero ao relatório com filtros

Objetivo: criar um mini-ambiente de logs e produzir um resumo com grep/wc/sort/uniq/cut + pipes.

Resultado final: você terá uma pasta ~/SOSL/cap10 com arquivos de teste e um relatório resumo-cap10.txt.
1 Criar a área de trabalho do capítuloSetup
mkdir -p ~/SOSL/cap10/{entrada,saida,logs}
cd ~/SOSL/cap10
pwd
ls -lah
2 Criar arquivos de texto (incluindo nome com espaço)Arquivos
cd ~/SOSL/cap10/entrada

echo "INFO: Sistema iniciado" > log1.txt
echo "WARN: Baixa memória" >> log1.txt
echo "ERROR: Falha ao montar /dados" >> log1.txt

echo "INFO: Serviço ok" > log2.txt
echo "ERROR: Timeout de rede" >> log2.txt
echo "ERROR: Timeout de rede" >> log2.txt

# arquivo com espaço no nome
printf "linha A\nlinha B\n" > "meu arquivo.txt"
ls -lah

Observe como usamos aspas para o arquivo com espaço no nome.

3 Copiar/mover usando globbingGlobbing
# copiar todos .txt para a pasta logs
cp *.txt ~/SOSL/cap10/logs/

# mover apenas log?.txt para saida
mv log?.txt ~/SOSL/cap10/saida/

# conferir
ls -lah ~/SOSL/cap10/logs
ls -lah ~/SOSL/cap10/saida
Onde vou aplicar isso? Ao organizar evidências por pasta (entrada/saida/logs) sem copiar um por um.
4 Inspecionar arquivos: file e statInspeção
cd ~/SOSL/cap10/logs
file "meu arquivo.txt"
stat "meu arquivo.txt" | head -n 15
5 Ler e navegar em textoLeitura
cat "meu arquivo.txt"
less "meu arquivo.txt"   # saia com q

# ver começo e fim
head -n 2 "meu arquivo.txt"
tail -n 2 "meu arquivo.txt"
6 Filtrar erros e contar (grep + wc)Filtro
cd ~/SOSL/cap10/saida

# juntar logs em um só
cat log1.txt log2.txt > ../logs/combined.log

# quantas linhas de erro?
grep -i "error" ../logs/combined.log | wc -l

# mostrar as linhas de erro
grep -i "error" ../logs/combined.log
7 Resumir erros por mensagem (sort + uniq)Resumo
# extrair apenas o texto após o nível (ex.: "ERROR:")
# aqui usamos cut com delimitador ':' para pegar a 2ª parte
cut -d: -f2- ../logs/combined.log | sed 's/^ *//' > ../logs/msg.txt

# contar repetidos
sort ../logs/msg.txt | uniq -c | sort -nr

Se o comando com sed parecer novo, não se preocupe: ele apenas remove espaços iniciais. Você verá mais manipulação de texto em capítulos posteriores.

8 Buscar arquivos com findBusca
cd ~/SOSL/cap10

# achar todos .log
find . -iname "*.log"

# achar arquivos com 'arquivo' no nome
find . -iname "*arquivo*"
9 Gerar relatório final com teeRelatório
R=~/SOSL/cap10/resumo-cap10.txt
: > "$R"

{
  echo "RESUMO — CAP. 10 (CLI II)";
  echo "Data: $(date)";
  echo "Pasta: $(pwd)";
  echo "--------------------------------";
  echo "Arquivos .log encontrados:";
  find ~/SOSL/cap10 -iname "*.log";
  echo "--------------------------------";
  echo "Contagem de erros no combined.log:";
  grep -i "error" ~/SOSL/cap10/logs/combined.log | wc -l;
  echo "--------------------------------";
  echo "Top mensagens (msg.txt):";
  sort ~/SOSL/cap10/logs/msg.txt | uniq -c | sort -nr | head -n 10;
} | tee -a "$R"

less "$R"
Parabéns: você criou um relatório automático usando filtros e pipes — exatamente como um técnico faz para evidenciar problemas.

6) Atividades práticas sugeridas (2–3)

  • Atividade 1 — Novo filtro: modifique o relatório para contar também WARN e INFO separadamente (use grep + wc).
  • Atividade 2 — Busca real: use find /var/log para localizar arquivos alterados nos últimos 3 dias e registre 5 caminhos (use -mtime).
  • Atividade 3 — Recorte de colunas: use cut em /etc/passwd para extrair usuário e shell (campos 1 e 7) e gere um arquivo em ~/SOSL/cap10/saida.
