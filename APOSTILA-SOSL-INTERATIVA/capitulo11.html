Capítulo 11 — Usuários, Grupos e Permissões no Linux

A base de segurança do Linux é: quem (usuário), qual equipe (grupo) e o que pode fazer (permissões). Neste capítulo você aprende a diagnosticar e corrigir problemas de acesso com evidência.

UID/GID getent /etc/passwd /etc/shadow /etc/group sudo rwx chmod chown / chgrp umask setgid sticky

Objetivos de aprendizagem

  • Explicar usuário/grupo e identificar UID/GID.
  • Reconhecer arquivos básicos de contas (passwd/shadow/group).
  • Criar usuário/grupo e gerenciar associação em grupos.
  • Interpretar permissões rwx em arquivos e diretórios.
  • Aplicar chmod, chown e chgrp com segurança.
  • Entender umask e bits especiais (setgid/sticky) em nível de suporte.
  • Construir uma pasta compartilhada por grupo (colaboração) com setgid.

Pré-requisitos

  • Cap. 09 e 10: conforto com terminal e arquivos.
  • Cap. 08: noções do FHS (/etc, /home, /srv).
Atenção: evite alterar permissões de pastas do sistema fora dos exemplos. Faça snapshot da VM antes se possível.

1) Teoria: identidade, autorização e controle de acesso

1.1 Usuários, grupos, UID e GID

No Linux, cada usuário é identificado por um número (UID) e cada grupo por um número (GID). O sistema decide permissões usando esses identificadores e a associação do usuário a grupos.

Isso importa no suporte porque muitos erros de acesso ("Permission denied") são resolvidos entendendo: quem é o usuário, quais grupos ele possui e quais permissões o arquivo/pasta exige.

Onde vou aplicar isso? No passo a passo você vai usar id e getent para cruzar UID/GID e grupos.

1.2 /etc/passwd, /etc/shadow, /etc/group (sem editar)

O /etc/passwd lista contas e informações básicas (UID, GID, home, shell). O /etc/shadow guarda hashes de senha e é protegido. O /etc/group lista grupos e seus membros.

Boa prática: não edite manualmente esses arquivos. Use comandos como adduser, usermod, groupadd e passwd.
Onde vou aplicar isso? Você vai consultar com getent e extrair colunas com cut.

1.3 Permissões rwx (u/g/o) e o detalhe do diretório

Permissões são dadas para três classes: dono (u), grupo (g) e outros (o). Cada classe pode ter leitura (r), escrita (w) e execução (x).

Detalhe importante: em diretórios, o "x" significa atravessar/entrar. Sem x, você pode ver o nome mas não acessa o conteúdo.

Regra prática: problema de acesso → ls -ld pasta (permissões do diretório) e depois ls -l arquivo.

1.4 chmod/chown/chgrp e umask

chmod altera permissões; chown altera dono (e grupo) e chgrp altera apenas o grupo. umask define permissões padrão para novos arquivos/diretórios.

Onde vou aplicar isso? No laboratório, você vai criar uma pasta compartilhada por grupo com setgid (2770) e testar com dois usuários.

1.5 Bits especiais: setuid, setgid e sticky (visão de suporte)

setuid faz um programa rodar com o UID do dono; setgid faz rodar com o GID do grupo e, em diretórios, faz novos arquivos herdarem o grupo; sticky evita que usuários apaguem arquivos de outros em diretórios compartilhados (ex.: /tmp).

Atenção: setuid é sensível e não deve ser aplicado sem critério. Aqui o foco prático é setgid em diretório.

3) Permissões: interpretar e aplicar

3.1 Interpretar ls -l

ls -l
# exemplo: -rw-r----- 1 aluno sosl 120 abr 23 21:00 arquivo.txt
# exemplo: drwxr-s--- 2 root  sosl 4096 abr 23 21:05 compartilhado

3.2 chmod simbólico e octal

# simbólico
chmod g+r arquivo.txt
chmod o-w arquivo.txt

# octal (r=4,w=2,x=1)
chmod 640 arquivo.txt
chmod 750 pasta

3.3 Propriedade: chown/chgrp

sudo chown aluno2:sosl arquivo.txt
sudo chgrp sosl arquivo.txt

3.4 setgid em diretório (colaboração)

sudo mkdir -p /srv/sosl-compartilhado
sudo chgrp sosl /srv/sosl-compartilhado
sudo chmod 2770 /srv/sosl-compartilhado
ls -ld /srv/sosl-compartilhado

O "2" (setgid) garante herança do grupo para novos arquivos dentro do diretório.

3.5 sticky bit (conceito)

ls -ld /tmp
# normalmente termina com ...t

4) Passo a passo prático: pasta compartilhada por grupo (setgid)

Objetivo: simular um cenário real de suporte: equipe precisa compartilhar arquivos sem expor para "outros".

Resultado esperado: arquivos criados por dois usuários dentro de /srv/sosl-compartilhado com grupo sosl.
1 Preparar pasta do capítuloOrganização
mkdir -p ~/SOSL/cap11
2 Criar grupo e usuário de testeContas
sudo groupadd sosl 2>/dev/null || true
sudo adduser aluno2
sudo usermod -aG sosl aluno2

getent group sosl
id aluno2

Se aluno2 já existir, pule adduser e apenas garanta o grupo.

3 Criar diretório compartilhado e aplicar setgidPermissões
sudo mkdir -p /srv/sosl-compartilhado
sudo chgrp sosl /srv/sosl-compartilhado
sudo chmod 2770 /srv/sosl-compartilhado

ls -ld /srv/sosl-compartilhado
4 Testar criação de arquivos por dois usuáriosTeste
# como usuário atual
sudo -u "$USER" bash -lc 'cd /srv/sosl-compartilhado && echo "Arquivo do usuario atual" > arq_aluno.txt'

# como aluno2
sudo -u aluno2 bash -lc 'cd /srv/sosl-compartilhado && echo "Arquivo do aluno2" > arq_aluno2.txt'

ls -l /srv/sosl-compartilhado
Verifique: os arquivos aparecem com grupo sosl. Isso prova a herança do setgid.
