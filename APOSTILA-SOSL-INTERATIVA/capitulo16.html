Capítulo 16 — Implantação (deploy) e Entrega Final do Projeto Integrador

Neste último capítulo você junta tudo: prepara uma máquina (ou VM) com um baseline padronizado, aplica hardening básico, valida serviços, cria evidências e exporta uma imagem pronta para entregar. Ao final, você faz a Entrega 4 (final) do Projeto Integrador — seu “kit de suporte Linux”.

baseline pós-instalação padronização hardening básico ufw usuários/permissões scripts backup manutenção export OVA Entrega 4

Objetivos de aprendizagem

  • Entender o que é implantação e por que padronização evita retrabalho.
  • Aplicar um baseline: contas, pacotes essenciais, atualizações, diretórios e scripts.
  • Aplicar hardening básico: firewall, princípio do menor privilégio e evidências.
  • Gerar documentação e relatório de implantação (o que foi feito e por quê).
  • Exportar uma imagem/entrega (por exemplo OVA) para replicar a instalação.
  • Consolidar todo o curso na Entrega 4 do Projeto Integrador.

Pré-requisitos

  • Cap. 04 (VM e instalação), Cap. 06 (pacotes), Cap. 07 (systemd/logs).
  • Cap. 09–12 (CLI + diagnóstico), Cap. 11 (usuários/permissões).
  • Cap. 13 (scripts), Cap. 14 (manutenção) e Cap. 15 (backup/restauração).

1) Teoria: implantação é entregar um padrão pronto para repetir

1.1 O que é implantação (deploy)?

Implantação é o processo de preparar um ambiente (máquina/VM) para uso real: instalar, configurar, validar e documentar. Em suporte, implantação bem feita reduz chamados porque o ambiente nasce padronizado e previsível.

Onde vou aplicar isso? No passo a passo você vai montar um baseline e gerar um relatório de implantação.

1.2 Baseline: o “mínimo aceitável”

Baseline é o conjunto mínimo de configurações e ferramentas que todo ambiente deve ter (ex.: usuário padrão, atualizações, utilitários, scripts de diagnóstico, estrutura de pastas, políticas). Sem baseline, cada máquina vira um “caso único”.

Onde vou aplicar isso? Você vai criar uma estrutura ~/SOSL, instalar pacotes úteis e incluir seus scripts (Cap. 13) e rotinas (Cap. 14/15).

1.3 Hardening básico: reduzir a superfície de ataque

Hardening é aplicar medidas simples que aumentam segurança: manter atualizado, usar firewall, reduzir permissões, desativar serviços desnecessários e registrar alterações. Não é “paranoia”: é prevenção.

Onde vou aplicar isso? Você vai ativar o firewall (ufw), revisar sudo e registrar evidências.

1.4 Documentação e evidência

Implantação sem documentação não é implantável: você não consegue repetir nem auditar. Evidência inclui comandos, versões e resultados (df, systemctl, logs, pacotes instalados).

Onde vou aplicar isso? Você vai gerar um relatório “ticket-ready” e exportar um pacote final da entrega.

1.5 Imagem (golden image) e exportação

Uma imagem padrão (golden image) é uma instalação pronta para replicar. Em VM, uma forma prática é exportar a máquina como OVA. Em ambientes físicos, pode-se usar clonagem/imagens, mas aqui o foco é o conceito e a prática em VM.

Onde vou aplicar isso? Você vai limpar o básico, validar e exportar sua VM (ou gerar evidência de como exportaria).

3) Hardening básico (seguro para laboratório)

3.1 Firewall (ufw) — ativar e conferir

# ver status
sudo ufw status verbose

# habilitar (se já estiver habilitado, ele avisa)
sudo ufw enable

# conferir
sudo ufw status verbose
Observação: em VM de laboratório, isso é seguro. Em servidor real, regras devem ser planejadas (portas necessárias).

3.2 Menor privilégio: usar sudo apenas quando necessário

# ver permissões de sudo do usuário atual
sudo -l

Em suporte, você registra quando usou sudo e por quê (mudança controlada).

3.3 Serviços falhados e logs de erro

systemctl --failed
journalctl -b -p err --no-pager | tail -n 50
Onde vou aplicar isso? Antes de exportar imagem/entrega, você valida que não há falhas óbvias.

4) Imagem/Exportação (conceito + prática em VM)

4.1 O que é OVA?

OVA é um pacote que representa uma VM exportada (config + disco). Serve para distribuir a “máquina pronta” para outra pessoa importar e usar.

Onde vou aplicar isso? Na Entrega 4 você pode anexar a OVA (ou, se o tamanho impedir, anexar evidência do processo e a configuração).

4.2 Pré-export (limpeza mínima e validação)

  • Executar atualização/limpeza (Cap. 14).
  • Validar serviços falhados e erros do journal.
  • Rodar seu script de diagnóstico (Cap. 13) e guardar o relatório.
  • Organizar ~/SOSL e remover arquivos temporários de testes (sem apagar evidências).

4.3 Exportar no VirtualBox (passo conceitual)

  1. Desligue a VM (Power Off).
  2. No VirtualBox: Arquivo → Exportar Appliance.
  3. Escolha a VM e exporte como .ova.
  4. Registre: nome do arquivo, tamanho e data no relatório final.
Nota: se a plataforma de envio tiver limite de tamanho, envie o relatório + scripts + evidências e apenas descreva/print o processo de exportação.

5 Hardening básico: UFW + validação de falhasHardening
{
  echo "
[HARDENING] Firewall (ufw)";
  sudo ufw status verbose || true;
  sudo ufw enable || true;
  sudo ufw status verbose || true;

  echo "
[VALIDAÇÃO] Serviços falhados";
  systemctl --failed;

  echo "
[LOGS] Erros do boot";

6) Atividades práticas sugeridas (2–3)

  • Atividade 1 — Script de baseline: crie baseline.sh que instala ferramentas, ativa UFW e gera um relatório em ~/SOSL/cap16 (use Cap. 13).
  • Atividade 2 — Checklist de importação: escreva um guia (1 página) explicando como importar a OVA e validar o ambiente (comandos).
  • Atividade 3 — Cenário de validação: simule um chamado (rede lenta, disco cheio, permissão) e use seus scripts/relatórios para resolver e documentar.

Pesquisas complementares (2–5)

  • Diferença entre snapshot de VM e backup (quando cada um é adequado).
  • Systemd timers vs cron para rotinas de manutenção.
  • O que é “golden image” e como controlar versões de imagem.
  • Firewall: regras básicas (permitir/negir portas) e auditoria.
  • Inventário automatizado: como gerar relatório padronizado em escala.

7) Projeto Integrador — Entrega 4 (Final • Bimestre 4)

Entrega 4: “Kit de Suporte Linux + Implantação” — consolida todo o curso (Caps 01–16). A ideia é entregar algo que você poderia usar no estágio/empresa: uma VM padronizada + documentação + scripts + evidências.

O que entregar

  • Relatório final (Markdown/PDF): visão geral + evidências.
  • Relatórios técnicos: cap12 (diagnóstico), cap14 (manutenção), cap15 (backup) e cap16 (implantação).
  • Scripts: diag.sh (Cap. 13) + um script de baseline/manutenção/backup (se você criou).
  • Evidências: outputs/prints de terminal (comandos e resultados).
  • Entrega de imagem: OVA exportada (se possível) ou evidência/documentação do export/import.
  • Guia rápido: como usar o kit (5–10 passos) + como restaurar backup.

Critérios (rubrica rápida)

  • Padronização: baseline claro e repetível.
  • Segurança: UFW/menor privilégio e mudanças registradas.
  • Confiabilidade: backup com verificação + teste de restauração.
  • Operação: manutenção com evidência e (opcional) agendamento.
  • Clareza: documentação simples, objetiva e completa.
