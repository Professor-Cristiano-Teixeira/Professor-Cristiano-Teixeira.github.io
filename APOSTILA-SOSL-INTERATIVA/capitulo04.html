Capítulo 04 — Criação de VM + Instalação do Linux Mint no VirtualBox

Aqui começam as práticas de laboratório. Você vai criar uma máquina virtual no VirtualBox, instalar o Linux Mint (Cinnamon), aplicar configurações essenciais e registrar evidências. Este capítulo também contém a Entrega 1 do Projeto Integrador.

VirtualBox Linux Mint Instalação guiada Partições (conceito) Snapshots Entrega 1

Objetivos de aprendizagem

  • Criar uma máquina virtual (VM) no VirtualBox com parâmetros adequados.
  • Instalar o Linux Mint (Cinnamon) em VM de forma correta e reproduzível.
  • Entender conceitos de disco virtual, partições e sistema de arquivos (na prática guiada).
  • Configurar itens essenciais: atualização inicial, idioma/teclado, resolução, integração (Guest Additions quando aplicável).
  • Criar snapshot e organizar evidências para suporte.
  • Entregar a Entrega 1: laboratório Linux padronizado.

Pré-requisitos

  • VirtualBox instalado no computador (host).
  • ISO do Linux Mint (Cinnamon) já baixada (Cap. 03) e, idealmente, checksum conferido.
  • Host com pelo menos 4GB RAM (recomendado 8GB), espaço livre (25GB+).
Importante: use VM para segurança e repetição. Não instale no PC físico do laboratório sem orientação específica.

1) Teoria essencial (aplicada ao laboratório)

1.1 Virtualização: o que é e por que usamos

Virtualização é a técnica de executar um “computador dentro do computador”. O sistema operacional do seu PC é o host. Dentro dele, você cria uma máquina virtual (VM) que roda um sistema convidado (o guest), como o Linux Mint. A VM tem CPU, memória, rede e disco “virtuais”.

Onde vou aplicar isso: ao criar a VM, você define RAM, CPU, disco e placa de vídeo virtual. No suporte, isso permite reproduzir erros com segurança e voltar atrás rapidamente com snapshots.

1.2 Disco virtual e “partições” (conceito + o mínimo necessário)

O disco da VM (por exemplo, um arquivo .vdi) simula um HD/SSD. Durante a instalação, você define como o espaço será usado. Em instalações simples de laboratório, normalmente você deixa o instalador usar o disco inteiro da VM.

Onde vou aplicar isso: no instalador do Mint, você escolherá a opção de apagar o disco virtual e instalar. Isso não apaga o disco do seu computador real — apenas o arquivo do disco da VM.

1.3 Sistema de arquivos (o mínimo para avançar)

Um sistema de arquivos organiza dados no disco (pastas, arquivos, permissões). Em Linux, é comum usar ext4 para a partição principal. Você não precisa dominar todos os detalhes agora; no Cap. 08 (FHS/diretórios) isso ficará mais claro.

Onde vou aplicar isso: ao instalar, você verá escolhas como ext4 e partição swap. Para laboratório, use as opções padrão do instalador.

1.4 Snapshots: “voltar no tempo” com segurança

Snapshot é um ponto de restauração da VM. Se algo der errado em um laboratório futuro, você volta a um estado anterior. É uma das ferramentas mais poderosas para estudo autônomo.

Onde vou aplicar isso: ao final da instalação e configuração inicial, você criará o snapshot “B1-Entrega1” (ou nome similar).

Dica de ouro do laboratório: antes de mudanças grandes, crie snapshot. Depois, teste. Se quebrar, restaure.

2) Passo a passo (prático e detalhado)

Siga na ordem. Ao final, você terá uma VM funcional com Linux Mint atualizado e pronto para os próximos capítulos.

1 Preparar arquivos e requisitosPré-lab
  • Confirme que você tem o VirtualBox instalado.
  • Tenha a ISO do Linux Mint Cinnamon em uma pasta fácil (ex.: SOSL/ISO/).
  • Garanta espaço livre: 25GB (mínimo) só para a VM.
  • Se possível, confirme o checksum (Cap. 03). Se não, siga, mas registre que não confirmou.
2 Criar a VM no VirtualBoxVM
  1. Abra o VirtualBox e clique em New / Novo.
  2. Name: SOSL-LinuxMint (padronize para facilitar suporte).
  3. Type: Linux • Version: Ubuntu (64-bit) (Mint é derivado de Ubuntu).
  4. Memory: 2048 MB (mín.) • recomendado 4096 MB se seu host permitir.
  5. Processors: 2 vCPU (se seu host tiver 4+ núcleos).
  6. Virtual Hard Disk: criar um disco agora.
  7. Tipo: VDI • Armazenamento: dinamicamente alocado.
  8. Tamanho: 25 GB (mín.) • recomendado 30–40 GB para laboratório longo.
Se a opção 64-bit não aparece: veja o Troubleshooting (virtualização desativada na BIOS/UEFI ou conflito com Hyper-V).
3 Ajustes recomendados antes de instalarConfig
  1. Selecione a VM → Settings.
  2. System → Motherboard: Boot Order: Optical primeiro, Hard Disk depois.
  3. System → Processor: 2 CPUs (se possível) e habilite PAE/NX.
  4. Display: Video Memory 128 MB; habilite 3D Acceleration (se houver).
  5. Storage: clique no drive óptico vazio e selecione a ISO do Linux Mint.
  6. Network: NAT (padrão) para ter internet. (Bridge só se o professor pedir.)
4 Iniciar a VM e testar o “modo Live”Live
  1. Clique em Start.
  2. No menu inicial, escolha Start Linux Mint (modo live).
  3. Quando o desktop carregar, confirme:
    • Mouse/teclado funcionam.
    • Resolução está aceitável (pode ajustar depois).
    • Internet funciona (ícone de rede ou abra um site).
Por que usar o Live? Ele permite validar o ambiente antes da instalação definitiva no disco virtual.
5 Instalar o Linux Mint (instalador gráfico)Install
  1. Clique no ícone Install Linux Mint na área de trabalho.
  2. Idioma: Português (Brasil) (se for o padrão do curso).
  3. Layout do teclado: Português (Brasil) ABNT2 (verifique com “ç”).
  4. Multimídia (codecs): pode marcar para instalar (facilita vídeos/áudio).
  5. Tipo de instalação: escolha Apagar disco e instalar o Linux Mint.
    • Esse “disco” é o disco virtual (VDI), não o seu HD real.
  6. Fuso horário: selecione sua região.
  7. Usuário:
    • Nome: seu nome ou “Aluno”
    • Nome do computador: sosl-vmXX (padrão por aluno)
    • Usuário: aluno (sugestão)
    • Senha: crie e anote. (Sem senha não há suporte.)
  8. Conclua e aguarde finalizar.
  9. Quando pedir, clique em Restart Now.
Se a VM não reiniciar corretamente: remova a ISO do drive (VirtualBox → Devices → Optical Drives → Remove disk from virtual drive).
6 Pós-instalação: primeiro boot e atualizaçõesPós
  1. Faça login com o usuário criado.
  2. Abra o Update Manager (Gerenciador de Atualizações) e aplique atualizações.
  3. Reinicie se o sistema solicitar.

Opcional (via terminal, para treinar comandos simples — ainda sem capítulo de CLI):

# Atualizar lista de pacotes e atualizar sistema (opcional)
sudo apt update
sudo apt upgrade -y

Se você não se sentir confortável com terminal ainda, use o Gerenciador de Atualizações (GUI). O terminal será aprofundado no Cap. 09.

7 Integração com o host: resolução, área de transferência e pastas compartilhadasIntegração

Para melhorar a experiência, ative recursos do VirtualBox. Alguns dependem do “Guest Additions”. Em muitos casos, o Mint funciona bem sem ajustes complexos — mas a integração ajuda muito no curso.

  1. VirtualBox (com a VM ligada): menu Devices → Shared Clipboard → Bidirectional.
  2. Drag and Drop → Bidirectional (se funcionar bem no seu host).
  3. Pasta compartilhada: Settings → Shared Folders → +
    • Folder Path: sua pasta SOSL no host
    • Marque Auto-mount e Make Permanent
Onde vou aplicar isso? Nos próximos capítulos, você vai salvar logs, relatórios e scripts. Pasta compartilhada facilita transferir entregas sem “pendrive”.
8 Snapshot (obrigatório para o curso)Snapshot
  1. Desligue a VM (ou deixe em estado consistente).
  2. No VirtualBox, selecione a VM → aba Snapshots → Take.
  3. Nome sugerido: B1-Entrega1-Base
  4. Descrição: “Mint instalado e atualizado; pronto para Cap. 05–08”
Você acabou de criar seu “ponto de retorno”. Se algo der errado nos próximos labs, restaure esse snapshot.
9 Evidências (prints e relatório curto)Evidências

Para suporte e avaliação, registre evidências mínimas:

  • Print da tela “About / Sobre” do sistema (versão do Mint).
  • Print do VirtualBox mostrando a VM (nome + hardware básico).
  • Print do Snapshot criado.
  • Um relatório curto (modelo no Projeto Integrador abaixo).

3) Troubleshooting (problemas comuns e soluções rápidas)

3.1 Não aparece opção 64-bit

  • Verifique se a virtualização está habilitada na BIOS/UEFI (Intel VT-x / AMD-V).
  • No Windows, conflitos podem ocorrer com Hyper-V/WSL2/VBS. Se necessário, desative recursos conforme orientação institucional.

3.2 Tela preta ou travamento na inicialização

  • Reduza aceleração 3D (Settings → Display).
  • Aumente Video Memory para 128MB.
  • Tente 1 CPU (em hosts fracos) e verifique se há RAM suficiente.

3.3 Sem internet dentro da VM

  • Verifique Network → Adapter 1: NAT (padrão).
  • Reinicie a VM e teste novamente.
  • Se o host está sem internet, a VM também ficará.

3.4 Instalador pede remover mídia

  • Remova a ISO do drive óptico virtual (Devices → Optical Drives → Remove disk).
Regra de ouro do suporte: quando algo falhar, registre: o que você fez, o que esperava, o que aconteceu e prints/logs. Isso vira “ticket” e acelera diagnóstico.

4) Atividades práticas derivadas (para treinar autonomia)

Sem entregar o projeto completo: aqui são exercícios para consolidar a instalação e preparação do laboratório.

  • Atividade 1 — Padronização: crie um padrão de nomes para VM, usuário e hostname (ex.: sosl-vm01) e documente o padrão.
  • Atividade 2 — Snapshots inteligentes: crie 2 snapshots (Base e Pós-Update) e descreva quando restauraria cada um.
  • Atividade 3 — Integração: configure pasta compartilhada e copie um arquivo do host para a VM e vice-versa. Registre evidências.

Pesquisas complementares

  • Diferença entre NAT e Bridge em máquinas virtuais (quando usar cada um).
  • O que é “Guest Additions” e quais recursos ele habilita (clipboard, resolução, pastas).
  • Partições: o que é uma partição e por que o instalador cria mais de uma (ex.: swap).
  • Snapshots vs Backups: por que snapshot não substitui backup real.
