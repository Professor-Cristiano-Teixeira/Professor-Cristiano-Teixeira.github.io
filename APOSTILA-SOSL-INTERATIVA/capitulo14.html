Capítulo 14 — Manutenção Preventiva no Linux

Manutenção preventiva evita incidentes: atualizar com segurança, controlar disco e logs, validar serviços e registrar evidências. Você vai executar uma rotina completa e gerar um relatório “ticket-ready”.

apt update/upgradedf/dusystemctl --failedjournalctlautoremove/cleancron/timersrelatório

Objetivos

  • Aplicar uma rotina preventiva (check → ação → validação → relatório).
  • Atualizar e limpar de forma responsável (sem “quebrar” o sistema).
  • Medir e investigar uso de disco (df/du) e controlar crescimento.
  • Checar falhas de serviços e registrar erros relevantes (systemctl/journal).
  • Planejar agendamento com log (cron ou timer).

Pré-requisitos

  • Cap. 06 (pacotes) e Cap. 07 (systemd/journal).
  • Cap. 10 (arquivos/filtros) e Cap. 13 (script — opcional).
Segurança: se possível, crie snapshot antes. Evite remover pacotes sem entender.

1) Teoria: manutenção preventiva é método

1.1 O que é manutenção preventiva?

É um conjunto de rotinas para reduzir falhas e manter estabilidade: atualização, checagem de recursos, controle de logs e validação de serviços. O foco é prevenir incidentes.

Onde vou aplicar isso? No passo a passo você seguirá uma sequência fixa e produzirá evidência em arquivo.

1.2 Atualização segura = mudança controlada

Atualizar é uma mudança. A prática profissional é: snapshot/backup, atualização, validação e registro (antes/depois). Assim você sabe o que mudou e consegue justificar em um ticket.

Onde vou aplicar isso? Você registrará df, serviços falhados e erros do journal antes e depois.

1.3 Disco cheio derruba serviços

Quando o disco enche, atualizações falham e logs não gravam. Use df -h para ver “quanto falta” e du para descobrir “quem está ocupando”.

Onde vou aplicar isso? Você vai listar top diretórios em /var e no seu home, e registrar no relatório.

1.4 Logs são evidência (não apague tudo)

Logs explicam o que aconteceu. Manutenção correta controla tamanho com rotação (logrotate) e limpeza do journal por tempo/tamanho (vacuum), sem perder histórico útil.

Onde vou aplicar isso? Você vai medir journalctl --disk-usage e aplicar um vacuum controlado.

1.5 Agendamento com responsabilidade

Cron e timers automatizam rotinas, mas devem gerar logs. “Rodou e ninguém viu” vira problema.

Onde vou aplicar isso? Você vai criar um exemplo de agendamento para gerar relatório semanal com log.

3) Limpeza responsável

3.1 Limpeza de pacotes (Mint/Ubuntu)

sudo apt autoremove
sudo apt clean
Onde vou aplicar isso? Você vai medir df antes/depois e registrar o impacto.

3.2 Encontrar consumo de disco (du + sort)

sudo du -h --max-depth=1 /var 2>/dev/null | sort -h | tail -n 15

du -h --max-depth=1 ~ 2>/dev/null | sort -h | tail -n 15

Top consumidores comuns: caches, logs, downloads e snapshots de apps.

4) Logs e serviços

4.1 Serviços falhados e erros

systemctl --failed
journalctl -b -p err --no-pager | tail -n 60

4.2 Journal: tamanho e vacuum controlado

journalctl --disk-usage
sudo journalctl --vacuum-time=7d
journalctl --disk-usage
Não use “apagar tudo” como manutenção. Controle é diferente de apagar histórico.

4.3 Identificar logs grandes em /var/log

sudo find /var/log -type f -printf '%s %p
' 2>/dev/null | sort -n | tail -n 10
Onde vou aplicar isso? No passo a passo você vai anexar os maiores logs ao relatório.

5) Agendar rotina (cron)

O cron agenda comandos por horário. Sempre redirecione para log.

crontab -e
# Exemplo semanal (domingo 08:00):
# 0 8 * * 0 /home/$USER/SOSL/cap13/scripts/diag.sh >> /home/$USER/SOSL/cap14/cron.log 2>&1
Boa prática: o log do cron é sua auditoria. Sem isso, você não prova que rodou.

6) Passo a passo: rotina completa + relatório “ticket-ready”

Você vai gerar ~/SOSL/cap14/manutencao-cap14.txt com checagens, ações e validação.

1 Preparar pasta e arquivoSetup
mkdir -p ~/SOSL/cap14
R=~/SOSL/cap14/manutencao-cap14.txt
: > "$R"
2 Checagem antesAntes
{
  echo "MANUTENÇÃO PREVENTIVA — CAP. 14";
  echo "Data: $(date)";
  echo "Usuário: $(whoami)";
  echo "Host: $(hostname)";
  echo "
[ANTES] uptime:"; uptime;
  echo "
[ANTES] df -h:"; df -h;
  echo "
[ANTES] serviços falhados:"; systemctl --failed;
  echo "
[ANTES] erros (boot):"; journalctl -b -p err --no-pager | tail -n 30;
} | tee -a "$R"
3 Atualização seguraUpdate
{
  echo "
[AÇÃO] apt update/upgrade";
  sudo apt update;
  sudo apt -y upgrade;
} | tee -a "$R"

Se houver atualização grande (kernel), registre e reinicie depois (se necessário).

4 Limpeza (autoremove/clean) + df depoisClean
{
  echo "
[AÇÃO] limpeza";
  sudo apt -y autoremove;
  sudo apt clean;
  echo "
[DEPOIS] df -h:"; df -h;
} | tee -a "$R"
5 Análise de consumo (du)Disk
{
  echo "
[ANÁLISE] Top /var:";
  sudo du -h --max-depth=1 /var 2>/dev/null | sort -h | tail -n 15;
  echo "
[ANÁLISE] Top ~:";
  du -h --max-depth=1 ~ 2>/dev/null | sort -h | tail -n 15;
} | tee -a "$R"
6 Logs (tamanho + vacuum)Logs
{
  echo "
[LOGS] journal tamanho:";
  journalctl --disk-usage;
  echo "
[AÇÃO] vacuum 7 dias:";
  sudo journalctl --vacuum-time=7d;
  echo "
[LOGS] journal tamanho após:";
  journalctl --disk-usage;
  echo "
[LOGS] maiores arquivos em /var/log:";
  sudo find /var/log -type f -printf '%s %p
' 2>/dev/null | sort -n | tail -n 10;
} | tee -a "$R"
7 Validação finalDepois
{
  echo "
[DEPOIS] serviços falhados:";
  systemctl --failed;
  echo "
[DEPOIS] erros (boot):";
  journalctl -b -p err --no-pager | tail -n 30;
  echo "
[CONCLUSÃO]";
  echo "- Atualizou?";
  echo "- Limpou?";
  echo "- Melhorou df?";
  echo "- Há falhas?";
  echo "- Próximas ações:";
} | tee -a "$R"

less "$R"
Entrega do capítulo: envie o arquivo manutencao-cap14.txt como evidência.

7) Atividades práticas sugeridas

  • Atividade 1: transforme o passo a passo em um script manutencao.sh (Cap. 13) que gere relatório automaticamente.
  • Atividade 2: simule “disco cheio” criando arquivos grandes em ~/SOSL/cap14 e depois recupere espaço com du/remoção segura.
  • Atividade 3: crie um agendamento cron semanal para rodar o script e gravar log.

Pesquisas complementares
